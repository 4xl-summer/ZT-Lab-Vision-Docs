공개 API · Rust · BlobQuery / BlobAnalysisResult

공개 API의 사용 조건과 결과 해석을 설명합니다.

상위 목차로 돌아가기

공개 API

Rust
impl ImageQuery {
    pub fn find_blobs(self, connectivity: Connectivity) -> BlobQuery;
}
impl BlobQuery {
    pub fn filter(self, expr: Expr) -> ZResult<Self>;
    pub fn order_by(self, expr: Expr, order: SortOrder) -> ZResult<Self>;
    pub fn execute(&self) -> ZResult<QueryExecution<BlobAnalysisResult>>;
}
impl BlobAnalysisResult {
    pub fn blobs(&self) -> &[Blob];
}

공개 API · 핵심 동작

Rust에서 연결 성분 질의는 이미지 계획의 find_blobs로 시작하고, 반환된 BlobQuery의 execute로 계산합니다. 연결 방식은 Connectivity::Four 또는 Connectivity::Eight입니다. 앞 단계가 이미지의 픽셀을 임계값으로 분할했다면 Blob 단계는 그 결과의 0이 아닌 픽셀을 전경으로 취급합니다.

공개 API · 입력과 결과

filter와 order_by는 각각 조건과 정렬식을 계획에 추가하며 Rust 소유권 규칙에 따라 기존 계획값을 소비합니다. 결과를 얻으려면 단순히 계획을 만들기만 해서는 안 되고 실행해야 합니다. 실행 결과의 출력에서 blobs()를 빌려 면적, 사각형, 중심을 읽습니다.

공개 API · 좌표와 소유권

예를 들어 [0,5,5]에 임계값 1과 4연결을 적용하면 마스크는 [0,255,255], 영역 수는 1, 면적은 2입니다. 이때 5는 원본 밝기이며 Blob이 계산하는 면적은 밝기의 합 10이 아니라 전경 픽셀 두 개입니다.

공개 API · 오류와 판단

식이 지원되지 않거나 입력·연산이 유효하지 않으면 ZResult 오류를 처리해야 합니다. 계획의 조건과 실행의 실패를 구분하면 잘못된 파라미터를 단순한 빈 객체 목록으로 오인하지 않습니다.

쿼리 구성과 실제 실행은 구분해서 읽는다. 조건을 설정한 단계만으로 측정 결과가 생겼다고 가정하지 말고 실행 결과에서 성분의 수와 각 속성을 확인한다.

실행한 입력 영상과 설정한 조건을 결과에 함께 기록하면 검사 결과를 재현할 때 유용하다.
