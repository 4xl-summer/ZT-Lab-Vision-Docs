소유권 및 오류

Rust에서 계획 추가는 소비형이며 일부 연산은 오류를 반환합니다. 직접 Blob 분석이 아닌 Query 종료 단계에서 실행하므로 입력 타입 및 계산 중 오류를 별도 확인해야 합니다. 캡처와 실행의 수명은 Query 개념을 참고하세요.

소유권 및 오류 · 핵심 동작

Rust 질의의 단계 추가는 소유권을 소비하는 방식입니다. 이미 다른 단계에 넘긴 계획을 같은 이름으로 다시 사용하려 하면 언어의 소유권 검사에 걸릴 수 있습니다. 분기가 필요할 때는 사용하려는 계획을 복제할 수 있는지 확인하고, 각각의 결과를 명시적으로 보관하십시오. 이는 처리 알고리즘의 실패와 다른 개발 단계 오류입니다.

소유권 및 오류 · 입력과 결과

계획 생성과 실행은 서로 다른 시점입니다. 일부 매개변수나 메타데이터는 단계 추가 중 확인되고, 실제 픽셀을 읽는 연산의 오류는 execute에서 나타날 수 있습니다. 따라서 ZResult를 두 시점 모두 확인해야 합니다. 성공한 실행에서 객체가 0개인 것은 입력에 전경이 없는 정상 결과일 수 있습니다.

소유권 및 오류 · 좌표와 소유권

blobs()가 제공하는 슬라이스는 결과 객체에서 빌린 것입니다. 참조를 사용하는 동안 소유 실행 결과가 유효해야 하며, 값만 별도 보관해야 한다면 필요한 데이터를 소유 형태로 가져와야 합니다. ROI의 전경을 전체 영상의 좌표로 오해하는 문제는 수명과 별개로 처리해야 합니다.

소유권 및 오류 · 오류와 판단

입력에 비영 배경이 남거나 연결성을 잘못 선택하면 오류 없이 예상과 다른 성분이 만들어집니다. 마스크 픽셀과 4·8 연결을 먼저 점검하고, 실패 여부와 검출 결과를 따로 기록하십시오.
