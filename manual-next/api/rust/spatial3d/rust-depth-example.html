Rust 합성 ROI 예제

2×2 격자에서 ROI 원점 x=12, 첫 점 결측, 둘째 점 z=34를 기대합니다.

Rust
use zvision::{DepthMap, LengthUnit, Point3, ZRect};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let depth = DepthMap::new(2, 2, vec![Some(1.), None, Some(3.), Some(4.)],
        2., 3., Point3 { x: 10., y: 20., z: 30. }, LengthUnit::Millimeter, 7)?;
    let roi = depth.roi(ZRect::new(1, 0, 1, 2))?;
    let cloud = roi.to_point_cloud()?;
    assert_eq!(roi.origin().x, 12.);
    assert!(cloud.points()[0].is_none());
    assert_eq!(cloud.points()[1].unwrap().z, 34.);
    Ok(())
}

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

이 예제의 입력은 두 행으로 나뉜 2×2 격자입니다. 첫 행은 Some(1), None이고 둘째 행은 Some(3), Some(4)입니다. ROI (1,0,1,2)는 오른쪽 열을 가리키므로 첫 점은 결측으로 남고 두 번째 점은 높이 4에 원점 Z 30을 더한 34가 됩니다. 원점 X는 10+1×2로 12가 됩니다. 각 assert는 이 기대를 실제 반환값과 비교합니다.

Result를 반환하는 main에서 생성, ROI, 점군 변환의 오류는 ?를 통해 호출자에게 전달됩니다. 정상 결과가 아닐 때 임의의 기본 좌표를 사용하지 않기 때문에 잘못된 폭이나 메타데이터를 조기에 발견할 수 있습니다. 반환된 점 목록은 ROI의 로컬 순서를 따르지만 점 자체는 이동된 원점에 기반한 좌표입니다. 이 입력은 계산식의 재현을 위한 합성이며 센서의 정확도를 측정한 결과가 아닙니다.

ROI의 두 번째 행은 원본의 좌표 (열 1, 행 1)에 해당합니다. X는 10+1×2=12, Y는 20+1×3=23이고, 깊이 4를 Z 원점 30에 더하면 유효 점은 (12,23,34)입니다. 이 값의 단위는 생성할 때 지정한 밀리미터이며 좌표계 식별자는 7입니다. ROI는 총 두 슬롯을 가지지만 첫 슬롯이 결측이므로 유효한 점은 하나입니다. 결측을 (0,0,0)이나 깊이 0으로 바꾸면 실제로 존재하는 원점 또는 깊이 0 측정과 구별할 수 없습니다. 결측 슬롯을 삭제하기까지 하면 배열 순서도 원본 격자와 어긋납니다. 검증할 때에는 Z 값뿐 아니라 X·Y 좌표와 결측 위치도 함께 살펴보십시오.
