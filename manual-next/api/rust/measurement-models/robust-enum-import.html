Rust 손실 열거형 경로

이 소스 버전에서 RobustFitOptions는 zvision에서 재수출하지만 필수 RobustLoss는 재수출하지 않습니다. 타원·사각형 옵션을 직접 구성할 때는 호환되는 동일 SDK 버전의 zvision-ops를 직접 의존성으로 명시하고 zvision_ops::RobustLoss를 사용합니다.

Rust
use zvision::RobustFitOptions;
use zvision_ops::RobustLoss;

타원과 사각형을 생성할 때는 견고 손실의 종류와 그 설정을 함께 전달합니다. 이 SDK 소스 버전에서 옵션 구조체는 상위 Rust 패키지의 공개 경로에 있지만, 그 구조체의 loss에 들어갈 열거형은 보조 패키지 경로를 사용합니다. 따라서 아래 선언은 두 이름의 소속을 보여주는 호출 부분이며, 그대로는 모델을 실행하는 전체 프로그램이 아닙니다.

프로젝트에서 두 패키지를 같은 SDK 버전에 맞춰 구성한 뒤 손실과 모든 수치 필드를 지정하고 모델 생성 결과를 확인하십시오. LeastSquares는 모든 점에 일정한 가중치를 주고 Huber와 Tukey는 큰 잔차의 영향을 다르게 조정합니다. 선택은 입력 점의 분포와 진단에 근거해야 하며, 같은 이름이 보이지 않는 컴파일 오류를 제품이 지원하지 않는 측정 형상으로 해석해서는 안 됩니다.

패키지의 공개 경로를 해결한 후에도 실제 실행을 위해서는 영상, 형상 기하와 프로브 설정이 추가로 필요합니다. 여기의 짧은 선언은 타입 이름을 확인하는 부분이며 완결된 fixture가 아닙니다. 타원 또는 사각형 생성이 실패하면 열거형 가져오기와 수치 조건을 독립적으로 진단하십시오.

적용 순서와 결과 판독

손실 함수를 직접 지정할 때는 열거형이 어느 패키지에 공개되어 있는지와 옵션 구조체의 필드 타입을 함께 확인해야 합니다. 구조체를 제공하는 상위 경로가 모든 보조 열거형도 재공개한다고 가정하면 가져오기 단계에서 실패할 수 있습니다. 손실의 척도와 잔차는 동일한 좌표 단위로 해석하며, 알고리즘이 관측한 에지의 위치 자체를 변경하지는 않습니다. 의존성을 명시한 뒤 같은 관측점으로 손실 선택만 바꾸어 결과를 비교하면 영향 범위를 분리할 수 있습니다.

확인 단계판독과 조치
옵션 구조체공개된 경로에서 타입을 가져옵니다.
손실 열거형실제로 정의된 보조 패키지 경로를 사용합니다.
척도입력점과 같은 좌표 단위로 지정합니다.
결과 비교같은 점 집합에서 손실만 바꿔 확인합니다.
