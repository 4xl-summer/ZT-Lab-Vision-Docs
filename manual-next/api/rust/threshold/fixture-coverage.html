사례는 합성 입력에 대한 기대값입니다. 실행 결과와 실제 장비 조건은 별도로 확인해야 합니다.

적용 상황과 원리

rust-threshold 사례는 3×1 Gray8 값 9,10,11에 임계값 10을 적용합니다. 비교 경계를 포함하므로 손계산 결과는 0,255,255입니다. 이 세 값은 각각 기준보다 작음, 같음, 큼을 대표하여 비교 방향을 점검합니다. 기대 결과는 이미지 표시가 아니라 바이트 배열로 확인할 수 있습니다.

결과를 읽는 방법

이 사례로 회색 일곱 형식 모두와 비유한 오류, 임의 ROI의 원점 보존을 한 번에 검증한 것은 아닙니다. 필요한 입력 형식과 ROI 조건은 별도 경계 사례로 확인해야 합니다. 합성 영상의 단위는 원시 픽셀 값이며 특정 카메라의 조명이나 품질을 대표하지 않습니다. 실제 검사에서는 임계값을 물체와 배경의 데이터에 맞춰 정하고 빈 전경과 오류를 구분해 기록합니다.

추가 점검

이 사례를 다른 임계값으로 확장하려면 먼저 입력 각 값에 대한 비교 결과를 손으로 적고 프로그램 출력을 비교합니다. 영상 값을 변경하지 않은 상태에서 같은 임계값을 다시 적용하면 동일 규칙을 기대할 수 있지만, 실제 조도나 카메라 잡음에 필요한 기준은 별도 데이터로 정합니다. 테스트에 사용한 임계값과 입력 형식은 기대 배열과 함께 기록합니다.

사례의 독립 기대

조건확인할 내용
9 < 100
10 = 10255
11 > 10255

이 사례가 구분하는 조건

제공된 Rust 사례는 같은 9, 10, 11 표본을 Gray8과 GrayF32로 각각 만들고 기준 10에서 두 마스크가 모두 0, 255, 255인지 확인하도록 작성되어 있습니다. 첫 값은 기준 미만이고 둘째는 일치하며 셋째는 초과하므로 세 바이트를 순서대로 보면 포함 경계와 비교 방향을 함께 판독할 수 있습니다. 255는 입력 밝기 255가 아니라 전경을 표시하는 마스크 값입니다.

사례에는 GrayF32의 NaN 표본과 RGB8 입력에 대한 오류 확인도 있습니다. 두 실패 조건을 성공 마스크의 모든 픽셀이 0인 경우와 혼동하지 않아야 합니다. 반면 이 작은 사례만으로 나머지 회색 형식, 모든 임계값, ROI 좌표와 실제 장비의 영상 분포를 포괄할 수는 없습니다. 적용 환경에서는 사용하는 형식과 ROI, 기준 주변 표본을 별도로 준비하여 실행 결과를 확인합니다.
