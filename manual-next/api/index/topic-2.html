호출에서 결과까지 · 언어별 API 안내

호출에서 결과까지의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

호출에서 결과까지

입력 객체 → 옵션·모델 구성 → 즉시 호출 또는 Query 실행 → 결과 필드 확인 → 독립 소유 객체 해제 순서로 읽으세요. 관리형 값 결과 스냅샷에 소유 핸들 해제를 적용하지 않습니다. 각 가이드 마지막에는 관련 클래스의 전체 공개 멤버를 확인할 수 있는 표가 있습니다.

객체 수명 · Query 실행 · 전체 실행 프로젝트

원리와 입력

호출 흐름은 입력 생성, 설정 또는 모델 준비, 직접 실행이나 Query 실행, 결과 확인, 소유 객체 정리의 순서로 나눌 수 있습니다. 입력 영상의 크기와 픽셀 형식을 먼저 확인해야 뒤의 알고리즘이 같은 데이터를 받는지 판단할 수 있습니다. 매칭처럼 학습 모델이 필요한 작업은 모델과 매 검색에 사용하는 설정을 별도로 보유합니다.

적용과 확인

결과가 소유 영상인지 독립 값 스냅샷인지에 따라 종료 방식이 달라집니다. 예를 들어 Threshold는 새 영상을 반환하고 MatchModel.Find는 매치 값 목록을 반환합니다. Query는 실행을 얻은 뒤 필요한 출력과 캡처를 획득하며 각 핸들을 정리해야 합니다. 빈 매치와 실패 예외를 구분하고, ROI 결과를 원본에 표시할 때에는 origin을 확인하세요. 실제 인자와 기본값은 선택한 언어의 선언에서 확인합니다.

읽기와 적용

이 순서를 간단한 임계값 처리에 적용하면 먼저 Gray8 한 행과 기준값을 준비하고 직접 호출의 반환 영상을 얻습니다. 그 영상의 배열을 읽어 [0,255,255]를 기대값과 비교한 뒤 원본과 반환 영상을 각자의 방식으로 정리합니다. 매칭으로 바꾸면 템플릿 학습과 검색 조건이 추가되고, 빈 매치 목록이 가능해집니다. 결과의 종류를 먼저 확인하면 없는 대상을 예외와 혼동하거나 값 스냅샷을 영상 핸들처럼 다루는 실수를 줄일 수 있습니다.
