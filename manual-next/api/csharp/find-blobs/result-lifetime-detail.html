결과 필드와 수명 · 핵심 동작

Area는 전경 픽셀의 수이고 Width와 Height는 이들을 감싸는 축 정렬 사각형의 크기입니다. 예를 들어 3×3 테두리에서 가운데가 배경이라면 면적은 8이고 외접 사각형의 면적은 9입니다. 이 둘을 같은 값으로 취급하면 구멍이나 오목한 형상의 크기를 잘못 판독합니다. 중심은 각 전경 픽셀 중심의 평균이므로 실수 좌표가 자연스럽습니다.

결과 필드와 수명 · 입력과 결과

성분은 ROI의 바깥과 독립적으로 계산되고 반환 좌표는 로컬입니다. 이미지 위에 표시하려면 ROI 원점을 적용해야 하지만, 결과의 면적은 좌표 이동만으로 바뀌지 않습니다. 세계 면적으로 바꾸는 문제는 픽셀 수를 보정하는 별도 단계이며, 투시 보정에서는 하나의 일정 배율을 임의로 가정해서는 안 됩니다.

결과 필드와 수명 · 좌표와 소유권

C# 직접 호출은 결과 필드를 독립적인 읽기 전용 목록으로 복사합니다. 입력 ZImage는 Dispose해야 하지만 BlobAnalysisResult는 값 스냅샷으로 별도 해제가 필요하지 않습니다. 전경이 없으면 빈 목록이 정상이며, 입력 형식이나 연결성 오류는 별도로 발생합니다.

검사 루프에서는 필요한 면적과 좌표를 결과가 유효한 동안 읽어 별도 기록으로 보관한다. 다음 프레임의 결과와 비교할 때는 이전 객체가 재사용된다고 가정하지 말고 두 프레임의 값과 좌표계를 명시한다.

서로 다른 프레임을 추적하려면 별도의 대응 규칙이 필요하며 반환 순서 자체를 물체의 고유 식별자로 취급하지 않는다.
