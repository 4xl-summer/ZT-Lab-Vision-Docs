오류·주의사항

DepthMap과 PointCloud는 IDisposable이며 ToValues/ToPoints는 독립 배열을 반환합니다.

잘못된 치수나 좌표는 처리 초기에 구분하는 편이 좋습니다. FromValues는 양의 폭과 높이를 요구하고 배열 개수는 두 값의 곱과 같아야 합니다. 깊이 결측에는 null을 사용하며, 유효한 숫자와 원점은 유한해야 합니다. 간격이 0 이하이거나 frame이 0이면 좌표 정보를 만들 수 없으므로 호출을 고쳐야 합니다. 평면 피팅은 충분한 유효점이 있어도 기하가 퇴화하면 실패할 수 있습니다.

자원 오류는 값의 오류와 분리해서 확인합니다. Roi와 Share는 별개의 소유 핸들이지만 원본 저장소를 공유합니다. 원본을 먼저 닫더라도 새 핸들을 따로 닫을 책임이 사라지지는 않습니다. ToValues와 ToPoints는 데이터를 복사한 배열이므로, 이 배열을 바꾸어도 영상이나 점군을 수정하는 수단이 되지 않습니다. 실패가 발생한 호출과 입력의 단위·frame·유효점 수를 함께 남기면 자료 문제와 해제 순서 문제를 진단하기 쉽습니다.

입력 오류와 결과 결측

폭 2, 높이 2인 격자에는 네 높이 슬롯이 필요합니다. 배열이 세 개면 치수와 길이가 맞지 않아 생성을 완료할 수 없습니다. 간격은 유한 양수이고 frame은 0이 아니어야 합니다. 깊이가 null인 슬롯은 이와 다른 정상 자료 상태로 저장되며, 숫자 0은 유효한 높이입니다. 유효값에 NaN이나 무한대를 넣어 결측을 대신 표현하지 않습니다.

객체가 생성된 다음에도 각 핸들의 수명을 구분해야 합니다. Roi와 Share는 저장소를 공유하는 별도 소유 핸들이며, 원본을 닫더라도 새 핸들을 따로 정리해야 합니다. ToValues의 배열은 복사값이어서 그 배열을 수정해도 격자를 바꾸는 연산이 아닙니다. 피팅 중 기하가 퇴화한 오류와 값이 없는 null 슬롯을 같은 실패 코드로 뭉치지 말고 호출 위치와 입력 조건을 기록합니다.
