C# 합성 ROI 예제 · C# · Spatial3D

DepthMap/PointCloud의 .NET 소유 핸들과 결과.

상위 목차로 돌아가기

C# 합성 ROI 예제

spatial-depth: 원점 x=12, 첫 점은 결측, 둘째 점 z=34를 기대합니다. 각 소유 객체는 using으로 해제합니다.

C#
using System;
using ZVision;

using var depth = DepthMap.FromValues(2, 2, new double?[] { 1, null, 3, 4 },
    2, 3, new Point3(10, 20, 30), LengthUnit.Millimeter, 7);
using var roi = depth.Roi(1, 0, 1, 2);
using var cloud = roi.ToPointCloud();
var points = cloud.ToPoints();
if (roi.Info.Origin.X != 12 || points[0] != null || points[1]!.Value.Z != 34)
    throw new Exception("Unexpected spatial-depth result");

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

이 코드는 2×2 깊이 격자를 생성하고 오른쪽 한 열만 선택합니다. 값 배열을 행 우선으로 읽으면 첫 행은 1과 null, 둘째 행은 3과 4입니다. 선택한 열의 첫 슬롯은 결측이므로 점군에서도 첫 항목은 null입니다. 둘째 슬롯은 깊이 4에 원점 Z 30을 더해 Z=34가 됩니다. 오른쪽 열의 원점 X는 10+1×2=12이며 Y 원점은 그대로 20입니다.

검사 조건을 한 줄로 묶어 결과가 다르면 예외를 발생시키므로, 실행이 끝났다는 사실만이 아니라 기대한 좌표와 결측을 실제로 비교합니다. depth, roi, cloud는 각각 소유 객체여서 모두 using 범위에 둡니다. ToPoints는 독립 배열을 돌려주므로 그 배열은 핸들을 닫은 뒤에도 값으로 사용할 수 있습니다. 이 입력에는 장비 보정이나 센서 오차가 포함되지 않으므로 결과를 실측 허용오차로 해석하지 않습니다.

검사할 네 슬롯

원본의 행 우선 배열은 첫 행 [1,null], 둘째 행 [3,4]입니다. Roi(1,0,1,2)는 오른쪽 열 두 셀을 선택해 [null,4]가 됩니다. 새 원점은 (12,20,30)이고 두 번째 셀은 ROI에서 y=1이므로 Y=20+3=23, 높이 4에 따라 Z=34입니다. 원본 X 원점 10에 ROI의 시작 열 1×간격 2를 더해 X=12가 됩니다.

코드는 원점 X, 첫 점의 null, 두 번째 점의 Z를 조건으로 확인합니다. 표의 Y=23은 같은 좌표식으로 유도한 추가 판독이며 코드가 직접 assert하는 값과 구분합니다. 각 using 선언은 DepthMap, ROI, PointCloud의 소유 범위를 지정합니다. ToPoints가 돌려준 배열은 독립 복사이므로 그 값을 읽는 것과 닫힌 핸들에 다시 접근하는 것은 다릅니다. 합성 비교는 센서의 실측 오차를 측정하지 않습니다.
