검증 기준

반환된 Roi·Share 및 새 PointCloud도 using/Dispose가 필요합니다.

관련 설명 열기

검증에는 결과 값뿐 아니라 무엇을 측정했는지 기록해야 합니다. 격자 예제에서는 2×2 배열의 오른쪽 열을 잘라 첫 셀이 결측으로 남고 다음 점의 Z가 34가 되는지를 확인합니다. 원점 X가 12로 바뀌는 이유는 ROI 시작 열 1에 간격 2를 곱한 값이 기존 X 원점 10에 더해지기 때문입니다. 이 비교는 숫자 0과 null을 따로 취급하는지도 드러냅니다.

점군 피팅을 검사할 때는 먼저 생성한 점의 단위와 frame을 확인하고, 결과의 inliers 및 total이 어떤 점을 대상으로 하는지 기록합니다. 평면의 RMS와 최대 잔차는 합의점에 대한 통계이므로 개수와 함께 읽어야 합니다. 합성 입력이 산술적으로 기대한 값을 내는 것은 API 경로의 확인이며 센서 노이즈나 실물 정확도에 대한 판정은 아닙니다. 객체가 using 범위를 벗어난 뒤에는 복사해 둔 배열만 사용하고 원래 핸들에 다시 접근하지 않습니다.

실행 결과 확인 순서

2×2 격자의 값이 [1,null,3,4]이고 원점이 (10,20,30), 간격이 (2,3)인 경우를 검증합니다. 오른쪽 열 ROI의 원점 X는 12입니다. 첫 셀은 null이고 둘째 셀의 높이 4는 원점 Z에 더해져 34가 됩니다. 이 두 조건을 같이 확인하면 좌표값이 우연히 맞더라도 슬롯 순서가 뒤바뀐 오류를 찾을 수 있습니다.

그 다음 점군의 Unit과 Frame, 유효점 수를 읽고 피팅 또는 정합의 결과를 확인합니다. 정합에는 초기 변환과 목표 점군이 필요하므로 ROI 좌표 계산의 통과가 정합 정확도를 뜻하지 않습니다. 합성 데이터로 얻은 기대값과 실장비 자료의 오차는 따로 기록합니다. 작업이 끝나면 depth, roi, cloud 등 생성된 소유 객체를 각각 using 또는 Dispose로 정리합니다.
