실패와 대안

잘못된 옵션, 빈 포함 마스크, 크기·원점 불일치, 비유한 영상 값, 상수 NCC 학습 ROI는 오류입니다. 정렬 실패는 Found를 먼저 확인하고 재촬영 또는 검사 불가로 처리하세요. 원본의 차분만 필요하면 정렬을 생략하되 두 영상의 같은 크기와 원점 및 마스크 기하를 보장해야 합니다. 실제 생산 기준과 조명 안정성은 별도 검증이 필요합니다.

정렬이 실패한 경우와 정렬 호출 자체가 오류인 경우는 다르게 처리합니다. 학습 무늬에 맞는 위치가 없거나 최소 유효 비율을 채우지 못하면 발견되지 않은 결과가 돌아올 수 있습니다. 이때 차분을 생략하고 재촬영 또는 검사 불가 상태로 넘겨야 합니다. 발견되지 않은 결과에서 정렬 영상이나 유효 마스크를 바로 꺼내려고 하면 오류가 발생합니다.

반대로 ROI가 비어 있거나 입력 형식과 원점이 맞지 않는 경우, 잘못된 설정 또는 비유한 밝기 값은 입력 오류로 조사합니다. 포함 마스크가 모든 픽셀을 제외해도 비교할 집단이 없어 정상 합격으로 볼 수 없습니다. 실패 지점을 기록할 때에는 원본 영상의 형식과 ROI, 검색 범위, 유효 픽셀 수를 함께 남기고, 이미 소유한 영상과 결과는 예외가 난 경로에서도 정리합니다.

정렬이 안 된 영상을 원본 기준에 바로 비교하면 이동 때문에 넓은 차이가 발생할 수 있습니다. 재촬영 여부는 발견 상태와 입력 조건을 확인한 다음 결정합니다.

발견 실패와 예외를 따로 처리

정렬 호출이 반환되었다는 사실만으로 정렬 영상이 존재하는 것은 아닙니다. 매치가 없거나 기준 전체 격자의 유효 비율이 MinValidFraction보다 낮으면 Found가 false가 될 수 있습니다. 이 분기에서는 Aligned와 ValidMask에 접근하지 않고 입력과 조건을 확인하거나 검사 불가 상태를 반환합니다. 정상적인 Found=false와 잘못된 설정으로 던져진 예외를 같은 빈 결과로 합치지 않습니다.

검증 오류를 조사할 때는 기준 ROI의 양의 크기와 범위, 회색 입력 형식과 유한값부터 확인합니다. 상수 무늬는 NCC의 밝기 분산을 만들지 못합니다. 차분 단계에서는 기준과 입력의 크기·origin, Gray8 포함 마스크의 기하와 선택 픽셀 수가 맞아야 합니다. 표면 후보 추출은 같은 기하의 Gray8 마스크와 GrayF64 점수를 사용하며 전경 점수의 유한성과 비음수 조건도 필요합니다.

using을 단계마다 적용하면 오류 이전에 얻은 결과와 영상이 범위 종료 시 정리됩니다. 예를 들어 정렬 결과는 만들어졌지만 차분 옵션이 유효하지 않아 실패한 경우에도 이미 얻은 Aligned와 ValidMask, AlignmentResult는 각자 정리해야 합니다. 문제 해결 기록에는 실패한 단계와 해당 설정을 남기고 결함 없음으로 기록하지 않습니다.
