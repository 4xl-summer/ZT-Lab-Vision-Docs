관련 검증 사례

정렬 차분 사례는 정상 영상, 이동된 정상 영상, 전체 밝기 변화, 한 점의 결함과 정렬 실패를 구분해 확인합니다. 비대칭 3×3 무늬를 기준과 검사 영상에 배치하고, 이동한 경우에는 변환된 위치와 유효 표본 수를 확인합니다. 점 결함은 학습 무늬 밖에 두어 정렬이 성공한 뒤 결함 추출과 판정의 변화를 따로 살펴볼 수 있습니다. 무늬가 없는 입력에서는 판정을 생략해야 합니다.

확인할 항목은 Found와 ValidCount, 마스크가 선택한 범위, 차분 점수와 후보 개수, 최종 사유입니다. 밝기 보정이 켜진 경우 평균 차이로 보정한 후의 점수와 보정 전 RMS를 같은 값으로 취급하지 않습니다. 이 페이지에 연결된 사례 식별자는 실행 기록에서 입력과 기대값을 찾기 위한 것입니다. 사용 중인 언어의 실행 상태는 검증 기록에서 확인하고 합성 결과를 장비의 실제 성능으로 확대하지 않습니다.

사례의 적용 범위와 기대 출력이 현재 사용하는 입력·설정과 일치하는지 비교한 다음 실행 기록을 해석합니다.

예상 판정은 사용한 임계치와 보정 방식, 유효 비율 및 허용 면적의 조합에 한정됩니다. 특히 무늬가 없는 사례는 판정 결과가 아닌 정렬 미발견으로 분류하므로 표에 합격으로 적어서는 안 됩니다. 적용할 데이터가 바뀌면 그 조건에서 다시 확인합니다.

C# 정렬 검사 결과의 검증

합성 실행의 기준 영상과 입력 영상을 정렬하고 유효 마스크를 차분 단계에 연결합니다. 정상, 한 픽셀 이동 정상, 전체 밝기 변화의 후보는 각각 0개로 기록되었습니다. 점 하나를 바꾼 입력에서는 후보 1개가 나오며 정렬 대상이 없는 입력은 검사 불가로 분기합니다.

검사 불가와 후보 0개는 서로 다른 결과입니다. Found가 거짓이면 차분 영상의 검은 픽셀을 정상 판정의 근거로 사용하지 않고 정렬 실패를 기록합니다. 동일한 이미지나 임계값이 아닌 다른 공정 데이터에는 이 수치를 기대값으로 복사하지 않습니다.

C# 문서의 개별 코드 블록 실행 기록은 오류 없이 끝난 사실을 보여 줍니다. 다섯 입력의 수치 확인은 별도 통합 사례의 단언 결과를 읽습니다. 이 둘을 구분하면 예제의 실행 가능성과 실제 판정값 검증 범위를 정확히 알 수 있습니다.
