합성 예제와 독립 기대값 · C# MatchModel

합성 예제와 독립 기대값에 대한 C# MatchModel 사용 안내

상위 목차로 돌아가기

합성 예제와 독립 기대값

템플릿은 3×2 [3,17,1,8,2,25], 검색 영상은 4×2 [0,3,17,1,0,8,2,25]입니다. 0도, 배율 1에서 동일한 패턴은 좌상단 (1,0)에 있으며 기준점은 (2,0.5)입니다. 원점이 (0,0)이므로 전역 좌표도 같습니다. 기대 결과는 하나, 점수 약 1, 표본 6개입니다. 부동소수점 점수는 허용 오차로 비교하세요. 이 합성 예는 실장비 성능을 뜻하지 않습니다.

C#
using System;
using ZVision;
using var template = ZImage.FromGray8(3, 2, new byte[] {3,17,1,8,2,25});
using var source = ZImage.FromGray8(4, 2, new byte[] {0,3,17,1,0,8,2,25});
using var model = MatchModel.TrainNcc(template);
var spec = new MatchSpec(0, 0, 1, 1, 1, 1, 0.99, 0, 1);
MatchResult result = model.Find(source, spec);
if (result.Best is Match m)
    Console.WriteLine($"({m.Position.X}, {m.Position.Y}): {m.Score}");

적용 상황과 원리

이 예제의 첫 행을 보면 템플릿 세 값이 검색 행의 두 번째 칸부터 이어지고, 두 번째 행도 같은 위치에 배치되어 있습니다. 따라서 패턴의 왼쪽 위는 정수 좌표 1,0이지만 반환점은 그 자리가 아니라 폭 3, 높이 2인 템플릿의 중심입니다. 템플릿 중심 1,0.5를 더하면 2,0.5가 됩니다. 짝수 높이 때문에 y가 반 픽셀인 것은 정상입니다.

결과를 읽는 방법

각도와 배율 범위를 각각 한 점으로 제한했으므로 이 데이터에서 회전이나 크기 변화를 시험하지 않습니다. 검색점의 값은 입력과 동일하므로 분산이 있는 두 벡터의 정규화 상관은 수치 오차 범위에서 1입니다. 비교 시 위치와 표본 수는 각각 2,0.5와 6을 따로 확인하고 점수는 허용 오차로 비교합니다. Find가 정상적으로 끝났더라도 Best가 null일 수 있으므로 운영 코드에서는 검출 실패 분기를 유지합니다.

추가 점검

만약 검색 영상의 원점이 (100, 50)인 ROI라면 동일한 로컬 결과의 전역 기준점은 (102, 50.5)가 됩니다. 이 추가 계산은 입력 패턴을 바꾸지 않고 좌표 변환만 설명합니다. 정수로 반올림하기 전에 반 픽셀을 유지해야 원래 모델 중심을 잃지 않습니다. 두 행의 패턴 시작 열을 각각 비교하면 y 방향 배치가 서로 어긋나지 않았는지도 확인할 수 있습니다.

수작업 좌표 검산

조건확인할 내용
템플릿 기준점(3−1)/2, (2−1)/2 = (1, 0.5)
패턴 왼쪽 위검색 영상 로컬 (1, 0)
반환 기준점(1, 0) + (1, 0.5) = (2, 0.5)
