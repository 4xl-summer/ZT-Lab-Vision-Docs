NCC 매칭 · NCC 검색 예제

적용 상황과 원리

이 모델을 처음 적용한다면 NCC 원리 문서에서 평균 제거와 분산 조건을 확인한 뒤 검색 예제로 넘어가는 순서가 유용합니다. 원리 페이지는 점수가 어떤 밝기 변화에 둔감한지 설명하고, 예제는 작은 템플릿이 더 큰 검색 영상의 어디에 있는지 계산합니다. 두 설명을 함께 읽어야 점수가 높아도 반환 좌표가 템플릿의 왼쪽 위가 아니라 기준점이라는 사실을 놓치지 않습니다.

결과를 읽는 방법

C# API에서는 TrainNcc가 소유 모델을 만들고 Find가 값 결과를 돌려줍니다. 검색 범위를 제한하거나 실패 이유를 조사할 때는 MatchSpec과 결과의 Best, Matches를 함께 살펴봅니다. 템플릿 영상과 모델은 각각 정리하지만 이미 얻은 결과는 독립된 스냅샷입니다. 모델을 나중에 재사용하려면 저장·복원 설명으로 이어가고 설정과 파일을 함께 식별할 방법을 정하세요. 어떤 문서도 실제 생산 데이터에서의 검출률을 대신 보증하지 않습니다.

추가 점검

좌표계와 수명 설명은 다른 검사 단계와 결과를 연결할 때 특히 중요합니다. 검출된 기준점만 다른 ROI의 로컬 좌표와 비교하면 원점 차이만큼 오차가 생깁니다. 각 단계의 전역 좌표로 변환한 다음 비교하고, 결과가 비었을 때는 측정값을 임의의 0으로 대체하지 않습니다.
