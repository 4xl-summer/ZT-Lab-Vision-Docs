검색 설정과 격자

아래 이름은 Rust/Python 표기이며 C#은 PascalCase입니다. 생성자에 아홉 값을 모두 지정합니다. 이 형식에 적용되는 기본값은 없습니다. 검증은 검색 시 수행됩니다.

필드단위와 유효 범위
angle_min, angle_max라디안, −π ≤ 최소 ≤ 최대 ≤ π. 영상 좌표에서 양수는 시계 방향.
angle_step라디안, 유한한 양수
scale_min, scale_max등방 배율, 0 < 최소 ≤ 최대
scale_step배율 간격, 유한한 양수
min_score0..1 포함, 점수 하한
min_distance검색 영상 픽셀, 0 이상인 중심 거리
max_matches양의 정수, 반환 개수 상한

실수 인자는 모두 유한해야 합니다. 각 축은 min + i × step, i = 0 .. floor((max−min)/step)입니다. 최댓값이 격자에 맞을 때만 끝점을 방문하며 부동소수점 반올림에 주의하세요. 각 축은 최대 4096점이고 각도×배율도 최대 4096점입니다. 위치 후보는 보이는 영상의 각 픽셀 격자에 모델 기준점의 소수 부분을 더하여 평가합니다. 이것은 후보 예산 옵션이 아니며 작업량은 대략 영상 픽셀 수 × 각도 수 × 배율 수 × 표본 수에 비례합니다.

적용 상황과 원리

아홉 인자는 순서에 의미가 있으므로 생성할 때 각도 세 값과 배율 세 값을 먼저 묶어 확인합니다. 고정 자세를 찾는 경우에도 간격은 0이 아니라 양수로 지정해야 합니다. 예를 들어 최소각과 최대각을 모두 0으로 놓고 간격을 1로 두면 각도 후보는 0 하나입니다. 배율도 최소와 최대를 1로 놓고 양수 간격을 주면 크기 후보는 하나입니다.

결과를 읽는 방법

최댓값은 무조건 평가되는 것이 아닙니다. 최소가 0, 최대가 1, 간격이 0.4라면 0, 0.4, 0.8이 격자에 들어가고 1은 들어가지 않습니다. 축별 개수와 두 축의 곱은 각각 4096을 넘을 수 없습니다. 여기에 검색 영상의 위치 후보와 학습 표본 수가 곱해져 실제 작업량이 늘어납니다. 최소 점수를 낮추면 후보가 늘 수 있고 최대 결과 수는 반환량을 제한할 뿐 전체 검색의 비용을 직접 제한하지 않습니다.

추가 점검

두 각도와 세 배율 점을 쓰면 위치 한 점마다 최대 여섯 자세를 고려합니다. 영상 전체의 위치와 모델 표본도 함께 평가되므로 격자 수만으로 시간을 예측하지 말고 실제 ROI에서 측정합니다. 각도 축 자체와 배율 축 자체도 각각 한도를 지켜야 합니다. 각도의 양수 방향은 영상에서 아래쪽으로 증가하는 y축을 기준으로 시계 방향입니다. 실수 간격은 유한해야 합니다.

끝점과 억제 예

조건확인할 내용
각도 0..1, 간격 0.4평가하는 각도는 0, 0.4, 0.8
최소 거리 5, 후보 간 거리 5경계와 같으므로 거리 규칙으로 제거하지 않음
최소 거리 5, 후보 간 거리 4먼저 선택된 후보보다 가까워 후속 후보 제거
