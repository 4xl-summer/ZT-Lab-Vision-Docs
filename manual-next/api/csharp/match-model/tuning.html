실무 설정 순서 · C# MatchModel

실무 설정 순서에 대한 C# MatchModel 사용 안내

상위 목차로 돌아가기

실무 설정 순서

  1. 반복되는 배경보다 물체를 식별하는 무늬를 포함하고, 가려지거나 변하는 영역을 학습 마스크에서 제외합니다.
  2. 기구 공차로 가능한 각도·배율을 한정하고 초기 간격을 정합니다. 간격 사이의 자세는 기본 검색이 직접 평가하지 않으므로 허용 오차보다 거칠지 않게 합니다.
  3. 양품·불량과 조명 변동 샘플로 점수 및 오검출을 비교하여 하한을 정합니다. 물체 간 예상 간격으로 중복 거리를 설정하고 결과 수를 제한합니다.
  4. 실제 처리 시간과 누락을 측정합니다. 넓은 범위에서 촘촘한 격자는 비용이 급격히 증가합니다. 피라미드 또는 다른 모델은 별도 API와 제약을 확인한 후 검증합니다.

적용 상황과 원리

검사 범위를 정할 때는 먼저 카메라와 고정 장치가 허용하는 위치와 자세를 파악합니다. 모든 영상 픽셀과 넓은 각도 범위를 무작정 촘촘하게 탐색하면 비용이 증가하므로 물체가 실제로 나타나는 ROI, 회전 범위 및 배율 범위를 근거 있게 제한합니다. 이어서 고정 각도와 배율에서 템플릿이 정상적으로 검출되는지 확인한 뒤 필요한 축만 넓혀 가면 설정 오류를 찾기 쉽습니다.

결과를 읽는 방법

점수 하한은 한 장의 양품에서 얻은 최고값으로 정하지 않습니다. 조명, 위치와 물체의 자연 변동을 담은 양품과 닮은 배경·불량 영상을 모아 누락과 오검출을 같이 비교합니다. 두 물체를 독립 검출해야 한다면 예상 중심 간격보다 지나치게 큰 최소 거리 설정을 피하고, 최대 결과 수가 실제 물체 수를 잘라내지 않는지도 확인합니다. 이 수치들은 데이터와 검사 목적에 맞춰 검증해야 합니다.

추가 점검

예를 들어 기대 물체가 두 개이고 최대 반환 개수를 1로 정하면 둘 다 기준을 통과해도 한 개만 확인할 수 있습니다. 두 중심이 최소 거리보다 가깝다면 최대 개수를 늘려도 억제될 수 있으므로 두 조건을 함께 조정해야 합니다. 기대 물체 수가 변하는 공정이라면 결과 상한을 현장 조건에 맞춰 별도로 검토합니다. 유효 후보의 수와 최상위 점수를 같이 기록합니다.
