저장과 복원

모델의 save/Save는 버전 1 모델 파일을 쓰고 기존 경로를 덮어씁니다. load/Load는 별도 소유 모델을 만듭니다. 파일이 없거나 손상·지원하지 않는 형식이면 로드 오류를 처리하세요. 검색 설정과 검색 결과는 모델 파일에 포함된다고 가정하지 말고 애플리케이션 설정으로 관리하세요. Rust 저장과 로드는 이미지 I/O 기능이 필요합니다.

적용 상황과 원리

save는 학습된 모델을 파일로 기록하고 같은 경로가 있으면 덮어씁니다. load는 저장 파일에서 독립적으로 닫아야 하는 새 모델을 만듭니다. 경로는 호출 환경에서 쓸 수 있어야 하며 존재하지 않는 파일이나 손상된 파일을 읽는 실패는 별도로 잡아야 합니다. 결과가 없는 유효한 검색과 파일 복원 실패는 서로 다릅니다.

결과를 읽는 방법

검사 설정은 모델의 학습 내용과 별개로 보관합니다. 복원 확인에서는 모델 정보의 크기·기준점·표본 수를 먼저 비교한 다음 같은 테스트 영상에 같은 회전·배율·점수·거리 설정을 적용합니다. 위치와 점수 및 결과 수를 원래 결과와 비교하면 잘못된 모델이나 설정을 연결한 문제를 찾을 수 있습니다. 여기서 제공하는 파일은 해당 SDK의 버전 있는 모델 형식이며 외부 모델 형식과의 호환을 뜻하지 않습니다.

추가 점검

운영에서는 파일 교체 시 모델이 어떤 템플릿과 마스크로 만들어졌는지 관리하는 것이 좋습니다. 복원 직후 대표 입력을 검색하여 기준 결과와 비교하면 파일을 잘못 선택한 문제를 조기에 발견할 수 있습니다.

저장 경로를 고정해 사용하는 서비스에서는 기존 파일을 덮어쓰는 동작을 배포 절차에 반영해야 합니다. 복원 실패를 잡은 뒤 오래된 모델이나 빈 결과로 자동 대체할지는 애플리케이션이 명시적으로 결정해야 하며 SDK가 검사 통과를 보장하지 않습니다.
