점군 생성과 수명

PointCloud.from_points(points, unit, frame)는 Point3 또는 None 슬롯으로 생성합니다. info는 프로퍼티이고 to_points()는 점 목록을 반환합니다. 생성한 객체는 context manager로 닫습니다. 깊이 맵에서 생성할 때도 결측 슬롯의 위치를 보존합니다.

Python
from zvision import DepthMap, Point3, LengthUnit

with DepthMap.from_values(3, 2, [1, None, 3, 4, 5, 6],
                          2, 3, Point3(10, 20, 30),
                          LengthUnit.MILLIMETER, 7) as depth:
    with depth.roi(1, 0, 2, 2) as roi, roi.to_point_cloud() as cloud:
        assert roi.info.origin == Point3(12, 20, 30)
        assert cloud.to_points()[1] == Point3(14, 20, 33)

Python의 PointCloud.from_points는 좌표가 존재하는 Point3와 측정이 빠진 None을 같은 순서의 시퀀스로 받습니다. unit과 0이 아닌 frame을 지정해 생성하면 info 프로퍼티에서 전체 슬롯과 유효점 수, 좌표 메타데이터를 읽을 수 있습니다. to_points()는 독립 목록을 반환하므로 그 목록을 수정해도 점군의 저장소를 변경하지 않습니다. 함수 호출과 프로퍼티 접근의 괄호 차이도 구분합니다.

객체는 context manager를 사용해 필요한 범위에서 열고 자동으로 닫는 것이 명확합니다. share나 transform으로 다른 소유 객체를 얻으면 그 객체도 독립적으로 닫아야 합니다. 원근이 아닌 직교 깊이 변환으로 만들어진 점군은 높이 결측의 인덱스를 보존합니다. fit_plane은 유한 양수 거리 임계값을 점군 길이 단위로 받아 모델과 합의점 통계를 돌려주며, 무효 입력이나 퇴화는 빈 평면이 아니라 오류로 처리합니다.

info와 복사 목록 구분

PointCloud.from_points에 [Point3(0,0,0),None,Point3(1,0,0)]을 전달하면 info.count는 3, info.valid_count는 2입니다. None은 슬롯을 차지하지만 유효점이 아니며 Point3(0,0,0)은 실제 원점입니다. info는 괄호 없이 읽는 프로퍼티이고 to_points()는 호출해 독립 목록을 얻는 메서드입니다. 두 결과의 숫자를 함께 보면 원래 인덱스와 유효 데이터 양을 구별할 수 있습니다.

점군에 지정한 unit은 거리와 위치의 단위이고 frame은 좌표계 식별자입니다. 다른 frame으로 보내려면 RigidTransform3의 입력 frame과 단위를 맞추어 transform을 호출합니다. 반환된 점군도 별도 소유 객체이므로 with 또는 close로 닫고, 복사한 Python 목록의 수명과 구분합니다. 잘못된 좌표나 frame이 오류인 상황을 정상 결측 None과 혼동하지 않습니다.
