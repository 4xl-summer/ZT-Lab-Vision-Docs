관련 API

원리와 입력

시작점에서 자주 만나는 공개 객체는 ZImage, MatchModel, ImageQuery와 각 결과입니다. ZImage를 생성해 직접 처리하면 새 영상이 반환될 수 있고, MatchModel 검색은 위치와 점수의 값 스냅샷을 만듭니다. 계획 기반의 ImageQuery는 실행 객체에서 출력과 capture를 얻는 단계를 추가합니다. 반환 타입을 확인하면 각 객체의 수명을 설계하기 쉽습니다.

적용과 확인

ROI를 사용하면 원본 저장소를 공유하면서 부분 영역과 origin을 가집니다. 화면 위치나 보정에 입력할 좌표는 로컬인지 전역인지 확인해야 합니다. 픽셀 형식 및 알고리즘 옵션의 범위는 언어별 선언과 해당 가이드에서 살펴보세요. 먼저 작은 합성 예제의 기대값을 확인하고, 이후 실제 데이터에서 적절한 기준과 환경을 별도로 검증합니다.

읽기와 적용

시작 화면의 API 연결은 작업 전체를 한 번에 선택하는 메뉴라기보다 데이터 흐름을 따라 내려가는 경로입니다. 먼저 생성할 영상의 형식과 크기를 정하고, 바로 처리할지 검색 모델을 학습할지 계획으로 묶을지를 선택합니다. 결과를 그리거나 보정에 사용할 때는 좌표계가 다음 호출의 입력과 맞는지도 확인합니다. 결과를 얻은 후 닫아야 하는 객체와 이미 복사된 값 스냅샷을 구분하면 처리 순서가 명확해집니다.
