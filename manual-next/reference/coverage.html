API 대조 범위와 문서 상태

공개 API의 분모, 선언·상세 설명·실행 검증의 차이와 문서 기준을 확인합니다.

분모를 먼저 고정하는 이유

문서의 완성도를 판단하려면 어떤 SDK 버전과 어떤 공개 표면을 세었는지 먼저 정해야 합니다. 이 매뉴얼의 선언 목록은 ce902e85c3405eb63df40c699ddbdf70ee1d03bd 소스에 고정되어 있습니다. 같은 이름의 재수출, 상속된 공통 멤버와 열거값을 각각 알고리즘 하나로 더하면 수치만 커질 수 있습니다. 이 페이지에서는 언어별 공개 표면과 교육 문서의 페이지 수를 구분하며, 페이지가 세분화되어도 제품의 기능 수가 증가했다고 해석하지 않습니다.

API를 찾았을 때 확인할 연결

첫째 공개 이름과 실제 선언의 연결을 확인합니다. 둘째 함수 입력이 앞 단계의 출력 타입과 맞는지 확인합니다. 셋째 그 조건을 실행한 예제가 있는지 검증 기록에서 확인합니다. 이 세 확인은 서로 대체하지 않습니다. 예를 들어 필드와 기본값을 설명한 페이지가 있어도 특정 카메라에서 해당 설정을 적용한 기록이 없을 수 있습니다. 문서 링크를 찾는 데 성공했다면 다음 판단은 선언의 수가 아니라 자신의 입력 조건과 실행 사례의 차이를 좁히는 것입니다.

재현 가능한 검증과 인수 구분

합성 입력의 장점은 정답을 픽셀 또는 수치로 직접 계산할 수 있다는 점입니다. 임계값 경계의 작은 배열, 알려진 점군 평면, 고정된 색 패치처럼 기대값이 명확한 사례는 호출 계약을 확인하기에 적합합니다. 그러나 실제 생산 영상의 조명 편차, 대상 변형, 센서 잡음과 통신 지연을 모두 대표하지는 않습니다. 검증 기록의 환경과 입력을 그대로 재현한 뒤 실측 자료로 평가 범위를 확장해야 합니다. 자료가 없는 장비 정확도나 생산 판독률은 이 매뉴얼에서도 미검증으로 유지합니다.

무엇을 대조했는가

이 목록은 고정된 SDK 소스에서 빌드하거나 import해 확인한 공개 표면입니다. 페이지 수, 이름 수, 독립 알고리즘 수는 서로 다른 분모입니다. 기존 링크를 유지한 별칭 페이지와 상속·오버로드도 포함하므로 페이지 수를 기능 완성률로 해석하지 않습니다.

문서와 검증 상태를 해석하는 방법

상태읽을 수 있는 정보의미의 한계
가이드·상세 해설원리, 입출력, 설정, 제약, 수명, 실패 분기, 관련 API해당 페이지의 확인된 계약에 한정
실제 선언 참조타입, 생성자, 메서드, 프로퍼티, 필드, 열거값, 정확한 선언주석이 없는 단위·기본값·예외를 새로 보장하지 않음
실행 검증 사례합성 입력, 독립 기대값, 허용오차, 실제 실행 환경생산 정확도·성능·실장비 인수 아님
호출 부분·선언특정 단계 또는 API 형태독립 실행 프로그램과 구별

주요 정확성 수정

DepthMap과 PointCloud의 멤버를 분리하고 info를 프로퍼티로 표시했습니다. Python 구현 본문을 선언처럼 노출하던 방식을 제거했습니다. 관리형 Query는 typed Execute()/execute(), 이미지 값 결과는 소유 핸들과 구별합니다. Rust의 보조 옵션 열거형 일부는 현재 Facade에서 재수출되지 않아 예제에 필요한 zvision-ops 의존성을 명시합니다.

이름이 같다는 이유만으로 언어 간 알고리즘·오류·기본값이 동등하다고 간주하지 않습니다. 문서에 없는 동시 실행 보장이나 GPU·장비 지원도 추가하지 않았습니다.
