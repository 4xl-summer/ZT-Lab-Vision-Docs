공개 API 참조

SDK 선언 색인과 상세 계약, 실행 검증으로 이동합니다.

이 색인을 실제 코드에 연결하기

먼저 결정할 세 가지

API 색인은 객체의 이름을 알고 있을 때 정확한 계약으로 이동하는 출발점입니다. 처음 검사 프로그램을 만든다면 먼저 입력이 영상인지 깊이 맵인지 점군인지 결정하고, 그다음 결과가 새 영상인지 수치 스냅샷인지 구분하세요. 마지막으로 작성할 언어를 고릅니다. 같은 처리 목적을 표현하더라도 Rust의 소유권과 Result, C#의 IDisposable, Python의 컨텍스트 관리자는 호출 형태가 다르므로 한 언어의 선언을 다른 언어에 그대로 옮기면 안 됩니다.

클래스에서 함수로 읽는 순서

타입 페이지에서는 먼저 객체가 무엇을 보유하는지, 어떻게 만들어지는지, 어떤 데이터와 다른 객체를 필요로 하는지 확인합니다. 다음으로 목적에 맞는 메서드 페이지를 열어 입력 타입과 단위, 옵션의 기본값, 반환 객체와 실패 조건을 읽습니다. 필드와 열거값은 소유 타입에 함께 설명되어 있어 인자 하나를 정할 때 전체 설정의 관계를 확인할 수 있습니다. 이름 검색만으로 선택하지 말고 같은 단계의 입력과 출력이 실제로 연결되는지 대조해야 합니다.

검사 한 건을 구성하는 방법

예를 들어 밝은 영역을 세는 작업은 영상 생성 또는 취득, 이진화, 연결 성분 분석, 결과 값 판독이라는 흐름으로 나눌 수 있습니다. 이진화 결과는 후속 분석에 전달할 영상이고, 블롭 결과의 면적이나 개수는 최종 판정에 사용할 값입니다. 중간 영상을 닫는 시점과 결과를 읽는 시점도 순서에 포함하세요. 첫 이미지 예제에서 작은 합성 입력의 기대값을 먼저 확인한 뒤 실제 취득 부분을 교체하면 영상 준비 실패와 알고리즘 설정 실패를 구분하기 쉽습니다.

선언과 검증 기록의 관계

이 색인은 고정된 SDK 소스에서 얻은 선언을 설명합니다. 항목이 존재한다는 사실은 특정 카메라의 지원이나 생산 판독률을 뜻하지 않습니다. 실행 예제 검증 기록에서는 사용한 입력, 기대값과 실행 환경을 별도로 확인할 수 있습니다. 실행 기록이 없는 조건이나 공개 주석에서 확인하지 못한 계약은 그 한계를 유지해 읽어야 합니다. 원리 안내, API 선언, 실행 사례를 함께 확인하면 문서만 보고 작성한 코드에서도 어느 가정을 직접 검사해야 하는지 알 수 있습니다.
