InspectionQuery 멤버와 선언

공개 타입

zvision.InspectionQuery: 패키지 __all__ 공개 이름입니다. 선언 출처: zvision._inspection.InspectionQuery.

Base class for typed lazy inspection query terminals.

이 Query는 변경 가능한 계획입니다. 단계 추가는 같은 객체를 갱신하므로 별칭에도 반영됩니다. 분기하려면 clone()을 사용하고 execute()로 실행합니다. 실행과 Query는 각각 닫아야 합니다. 실패한 단계 추가는 기존 계획을 바꾸지 않습니다.

Python
InspectionQuery()

시그니처와 설명에 없는 반환값, 오류, 제약 조건은 확인되지 않았습니다. 환경별 네이티브 지원 여부와 예제 실행은 별도 검증이 필요합니다.

사용과 결과 해석

InspectionQuery는 타입이 지정된 지연 검사 종단 쿼리의 공통 기반입니다. 정렬, 차분 또는 표면 후보처럼 각 작업에 대응하는 구체 쿼리는 실행 결과의 타입과 획득 방법이 다릅니다. 이 기반 이름만 보고 모든 결과가 동일한 이미지나 즉시 계산된 후보 배열이라고 가정하지 않습니다.

계획을 만들 때 단계 추가가 계산을 즉시 수행하는 것과 실행할 계획을 구성하는 것은 구분됩니다. 다른 조건으로 분기하려면 clone으로 독립 계획을 만든 뒤 각 분기에 작업을 추가하고, 구체 타입의 execute로 결과를 얻습니다. 원래 계획의 설정이 분기에 의해 바뀌지 않는지 작은 입력에서 비교할 수 있습니다.

계획을 닫는 일은 실행 결과에 대한 소유 규칙을 대신하지 않습니다. 구체 결과가 값 스냅샷인지 별도로 획득해 닫는 자원인지 해당 실행 타입을 확인합니다. 정렬이 미발견이면 정상 후보 0개로 간주하지 않고 후속 차분을 생략하는 분기가 필요합니다.

각 구체 종단에서 어떤 소유 결과를 반환하는지 실행 타입의 설명을 확인합니다. 예를 들어 표면 후보는 마스크와 점수의 대응이 필요하며 정렬 결과는 발견 여부가 우선입니다. 계획의 분기와 계산된 결과를 같은 객체로 취급하지 않습니다.
