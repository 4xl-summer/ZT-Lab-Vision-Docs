열거 값

  • NATIVE = 0 · 호스트 바이트 순서입니다.
  • LITTLE = 1 · 리틀 엔디언 바이트 순서입니다.
  • BIG = 2 · 빅 엔디언 바이트 순서입니다.

사용 맥락과 계약

TiffByteOrder는 TIFF 파일의 여러 바이트 값에 적용할 순서를 선택합니다. NATIVE는 저장을 실행하는 호스트의 순서이며 LITTLE과 BIG은 명시적인 리틀 엔디언과 빅 엔디언입니다. save_tiff_pages의 byte_order로 지정하고 생략하면 NATIVE를 사용합니다. 이 선택은 이미지 좌표의 가로 방향이나 채널의 RGB 순서를 바꾸는 설정이 아닙니다.

구체 사례와 판독

예를 들어 16비트 값 0x1234를 표현할 때 리틀 엔디언에서는 낮은 바이트 34가 먼저이고 빅 엔디언에서는 높은 바이트 12가 먼저입니다. 이것은 저장 바이트의 순서를 보여 주는 설명이며 정상적인 TIFF 판독기는 파일의 표기를 읽어 같은 수치로 해석합니다. 파일 헤더를 직접 분석하거나 다른 시스템과 교환할 때는 NATIVE가 어느 순서인지 환경에 따라 달라질 수 있음을 고려하세요.

적용 시 확인

한 바이트 픽셀 값은 바이트 순서의 차이가 눈에 띄지 않을 수 있습니다. 여러 바이트 샘플을 교환할 때 명시적 설정이 특히 유용합니다. 서로 다른 순서로 기록된 두 파일의 바이트는 다를 수 있어도 올바르게 디코딩한 수치가 같아야 합니다. 비교 기준을 파일 바이트와 영상 값 중 무엇으로 할지 먼저 정하세요.
