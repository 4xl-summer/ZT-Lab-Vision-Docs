Python API · save_tiff_pages

save_tiff_pages 멤버와 선언

공개 타입

zvision.save_tiff_pages: 패키지 __all__ 공개 이름입니다. 선언 출처: zvision._io_advanced.save_tiff_pages.

Save ordered pages, preserving each image's supported scalar pixel format.

영상을 지정 순서로 다중 페이지 TIFF에 저장합니다.

Python
save_tiff_pages(images, path, *, big_tiff=False, compression=<TiffCompression.NONE: 0>, byte_order=<TiffByteOrder.NATIVE: 0>, planar=<TiffPlanar.CHUNKY: 0>)

인자 선언

  • images · POSITIONAL_OR_KEYWORD · 기본값 없음
  • path · POSITIONAL_OR_KEYWORD · 기본값 없음
  • big_tiff · KEYWORD_ONLY · 기본값 False
  • compression · KEYWORD_ONLY · 기본값 <TiffCompression.NONE: 0>
  • byte_order · KEYWORD_ONLY · 기본값 <TiffByteOrder.NATIVE: 0>
  • planar · KEYWORD_ONLY · 기본값 <TiffPlanar.CHUNKY: 0>

반환: None

오류: 타입·범위·형식 검증이나 네이티브 연산 실패 시 오류가 전달됩니다.

래퍼에서 발생 가능한 오류: TypeError, ValueError. 네이티브 오류는 별도입니다.

시그니처와 설명에 없는 반환값, 오류, 제약 조건은 확인되지 않았습니다. 환경별 네이티브 지원 여부와 예제 실행은 별도 검증이 필요합니다.

공개 멤버

    사용 맥락과 계약

    save_tiff_pages는 비어 있지 않은 영상들의 순서를 받아 하나의 다중 페이지 TIFF에 기록합니다. images에 넣은 첫 항목이 페이지 0, 둘째 항목이 페이지 1입니다. big_tiff, compression, byte_order, planar는 키워드 옵션으로 지정하며 기본값은 일반 TIFF, 무압축, 호스트 바이트 순서, CHUNKY 배치입니다. 정상 호출은 None을 반환합니다.

    구체 사례와 판독

    예를 들어 두 프레임을 시간순으로 입력하고 나중에 load_tiff_page의 index=1로 읽으면 두 번째 입력을 선택합니다. 페이지 인덱스는 카메라 프레임 번호와 같은 개념이 아니므로 프레임 번호를 보존해야 하면 별도로 기록해야 합니다. 전송 대상 프로그램이 BigTIFF나 선택한 압축과 채널 배치를 지원하는지 확인하고, 실제 저장 파일을 다시 열어 크기와 페이지 순서를 점검하세요.

    적용 시 확인

    입력 목록을 만들 때 순서가 바뀌지 않도록 정렬 기준을 정하고, 출력 파일 경로와 선택 옵션을 함께 보관하면 읽기 순서를 재현할 수 있습니다. 파일 저장에 성공해도 다른 판독 프로그램의 지원 여부까지 입증된 것은 아닙니다. 실제로 교환할 환경에서 선택한 옵션을 한 번 읽어보세요.
