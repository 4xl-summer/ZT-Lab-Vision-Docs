Python API · Expr

Expr 멤버와 선언

공개 타입

zvision.Expr: 패키지 __all__ 공개 이름입니다. 선언 출처: zvision._query.Expr.

Query 조건식의 내부 노드 표현입니다. 직접 코드값을 조합하기보다 Query의 조건식 콜백과 연산자로 구성합니다.

Python
Expr(kind, code=0, value=None, children=())

인자 선언

  • kind · POSITIONAL_OR_KEYWORD · 기본값 없음
  • code · POSITIONAL_OR_KEYWORD · 기본값 0
  • value · POSITIONAL_OR_KEYWORD · 기본값 None
  • children · POSITIONAL_OR_KEYWORD · 기본값 ()

확인된 인자 조건

kind
내부 노드 종류를 나타내는 정수입니다.
code
노드에 따른 내부 연산 또는 필드 코드이며 기본값은 0입니다.
value
리터럴 노드에 사용하는 값이며 기본값은 None입니다.
children
자식 Expr의 튜플이며 기본값은 빈 튜플입니다. 구성된 식은 깊이 64 및 노드 4096 제한을 받습니다.

시그니처와 설명에 없는 반환값, 오류, 제약 조건은 확인되지 않았습니다. 환경별 네이티브 지원 여부와 예제 실행은 별도 검증이 필요합니다.

Expr(kind, code, value, children) 생성자 설명

공개 멤버

    사용 맥락과 계약

    Expr는 Query의 조건과 정렬에 쓰이는 식을 나타내는 노드입니다. 일반 사용자는 내부 kind와 code를 임의로 조립하기보다 Blob 등의 필드를 받는 콜백과 비교·산술·논리 연산자로 식을 구성하는 편이 좋습니다. Python의 and/or처럼 값을 즉시 참 또는 거짓으로 평가하는 연산 대신 문서화된 기호식 연산을 사용해야 계획에 조건이 남습니다. Expr를 bool로 바꾸려고 하면 오류가 발생합니다.

    구체 사례와 판독

    예를 들어 Blob 면적이 일정 기준 이상인 조건은 실행할 때 각 영역의 area에 적용되는 계획이지, 콜백을 작성하는 시점에 하나의 실제 Blob을 즉시 판정하는 계산이 아닙니다. 내부 표현은 깊이 64와 노드 4096 제한을 가지며 정수·실수 리터럴도 범위와 유한성을 검사합니다. 조건을 계획에 넣은 다음 형식별 execute 결과를 확인하세요. C#이나 Rust의 표현식 문법 및 소유권과 Python 코드를 그대로 혼용하지 않아야 합니다.

    적용 시 확인

    조건을 분기해 서로 다른 Query로 발전시키려면 관리형 빌더를 변경하기 전에 clone해야 합니다. 식의 비교는 계획에 기록되는 의미이므로 즉시 계산된 Python 불리언과 혼합하지 말고, 결과를 실행한 뒤 반환된 영역 값을 확인하세요.
