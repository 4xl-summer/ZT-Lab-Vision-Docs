열거 값

  • ACCEPTED = 1 · 프레임이 큐에 수락되었습니다.
  • QUEUE_FULL = 2 · 큐가 가득 차 프레임을 보관하지 못했습니다.
  • DUPLICATE = 3 · 같은 프레임 ID가 다시 제출되었습니다.
  • OUT_OF_ORDER = 4 · 이전보다 작은 프레임 ID입니다.

사용 맥락과 계약

OfferDisposition은 모의 카메라에 프레임을 제출한 뒤 그 제출이 어떻게 처리됐는지 나타냅니다. ACCEPTED는 큐에 보관되었음을, QUEUE_FULL은 유효하게 수신했지만 큐가 가득 차 보관되지 않았음을 뜻합니다. DUPLICATE는 마지막 프레임 ID와 같은 ID의 재제출, OUT_OF_ORDER는 그보다 작은 ID의 제출을 구분합니다. 이 값은 영상의 양품 여부가 아닙니다.

구체 사례와 판독

호출이 반환한 상태를 확인한 다음 취득 큐에서 프레임을 꺼내고 프레임 ID를 점검하세요. 예를 들어 ID 2를 수락한 뒤 다시 ID 2를 제출하면 중복이고, 그보다 작은 ID는 순서 역전으로 분류됩니다. 프레임을 꺼내지 못하는 원인을 모두 카메라 로딩 오류로 취급하면 큐 용량과 제출 순서 문제를 놓칠 수 있습니다. 상태 전이와 시간 조건이 유효하지 않은 경우의 예외도 반환 상태와 별도로 처리합니다.

적용 시 확인

큐에 수락된 프레임과 처리 상태를 같은 변수로 취급하지 마세요. 처리 상태는 제출을 설명하고 프레임은 이후 큐에서 소유 객체로 취득합니다. 취득한 영상과 프레임의 종료 책임도 별도로 확인해야 합니다. 수락 여부와 취득 성공은 다른 단계이며 각각의 결과를 확인해야 합니다.
