사용 맥락과 계약

FrameQueueOffer는 프레임을 큐에 넣으려는 시도의 결과를 설명합니다. 호출자는 성공 여부만 가정하지 말고 반환 상태를 읽어 항목이 들어갔는지, 오래된 항목이 밀렸는지, 큐가 가득 찼는지 또는 대기 시간이 끝났는지 구별해야 합니다. 큐가 닫힌 경우도 정상적으로 입력한 프레임이 처리되었다는 뜻이 아닙니다.

구체 사례와 판독

예를 들어 용량이 찬 큐에서 DROP_OLDEST 정책으로 새 영상을 넣었다면 새 영상은 들어갈 수 있지만 이전 영상 하나는 소비 전에 사라집니다. 반대로 REJECT_NEW라면 기존 항목이 남고 새 항목이 거절됩니다. 상태와 입력 프레임 번호를 함께 기록해야 처리된 영상의 누락을 사후에 추적할 수 있습니다. 큐 수락은 저장이나 검사 완료를 보증하지 않습니다.

적용 시 확인

반환 상태가 나타내는 수락과 제거를 각각 집계하면 큐가 병목인지, 실제 처리 속도가 입력 속도를 따라가는지 알 수 있습니다. 예를 들어 검사 이력이 모든 입력을 포함해야 한다면 오래된 항목이 빠졌다는 결과를 조용히 무시하지 말고 별도 누락 이벤트로 기록합니다. 이후 재시도 여부는 애플리케이션 정책으로 정합니다. 모든 호출에서 동일한 결과가 나올 것이라고 가정하지 말고 반환 상태를 분기 처리하세요.
