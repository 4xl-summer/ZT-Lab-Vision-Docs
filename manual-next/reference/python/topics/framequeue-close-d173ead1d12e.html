FrameQueue.close 공개 계약

close

method · 선언 타입 zvision._frame_queue.FrameQueue

Python
close(self)

큐를 닫고 대기 항목을 폐기하며 대기 중인 호출을 깨운 뒤 소유 핸들을 해제합니다.

반환: None을 반환합니다.

오류: 네이티브 종료 또는 핸들 해제 오류가 발생할 수 있습니다.

Shut down queue, wake all waiters, and release this owning handle.

이 호출의 입력과 객체 맥락

예를 들어 take에서 이미 받은 ZImage를 사용 중이라면 큐를 닫는 것과 그 영상의 close는 별도입니다. 작업 순서를 큐 생산 종료, 소비 결과 처리, 영상 해제, 큐 해제로 정하면 각 핸들의 소유자를 추적하기 쉽습니다. 실패나 예외가 나도 with 블록을 사용해 큐 종료를 보장할 수 있습니다.

큐를 닫아 대기 중인 생산자와 소비자를 깨우고 이 객체의 소유 핸들을 해제합니다. 대기 항목은 폐기되며 이미 꺼낸 영상은 별도 소유 객체로 관리합니다. 실제 이미지와 큐는 서로 다른 소유 객체이므로 take가 반환한 영상을 사용한 뒤에도 그 영상 자체를 close해야 합니다. 같은 객체의 close는 이미 핸들이 해제된 경우 다시 해제하지 않습니다.

종료와 대기 상태

FrameQueue는 용량과 REJECT_NEW, DROP_OLDEST 또는 WAIT 정책으로 생산자와 소비자 사이의 영상을 보관합니다. close는 큐를 닫고 내부 대기 항목을 폐기하며 블록 중인 호출들을 깨운 다음 이 Python 소유 핸들을 해제합니다. 이미 닫은 같은 객체에 다시 close할 때는 핸들을 중복 해제하지 않습니다.

offer와 take는 각자 임시 큐 참조를 사용하며 결과 상태로 추가·가득 참·시간 초과·닫힘 등을 구분합니다. 예를 들어 WAIT 정책에서 공간을 기다리던 생산자와 항목을 기다리던 소비자는 큐 종료를 관찰할 수 있습니다. 깨어난 호출의 상태를 정상적인 영상 항목으로 단정하지 않습니다.

take가 이미 반환한 ZImage는 큐와 별도 소유 객체이므로 close 후에도 호출자가 해당 영상의 수명을 관리합니다. 종료 순서는 생산 중단, 소비 중인 영상 처리와 해제, 큐 종료를 고려해 정합니다. with 블록은 예외가 발생한 경우에도 소유 큐의 종료 경로를 명확히 합니다.
