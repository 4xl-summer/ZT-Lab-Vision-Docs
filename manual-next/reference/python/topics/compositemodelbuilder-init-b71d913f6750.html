빈 설계에서 복합 계측 모델로

이 생성자는 인자를 받지 않으며 좌표계, 형상, 허용치와 영상 측정 설정을 추가할 수 있는 새 설계 객체를 만듭니다. 생성 직후에는 아직 평가할 네이티브 모델이 반환된 상태가 아닙니다. Python 쪽 설계 상태를 먼저 준비하고, 각 추가 호출로 그래프를 구성한 다음 build에서 독립적인 모델을 얻습니다. 추가 과정에서도 그래프 검증을 위해 직렬화·네이티브 호출이 이루어질 수 있으므로, 생성자 한 번의 성공을 전체 SDK 실행 환경의 확인으로 해석하지 마세요.

식별자와 반환 인덱스를 구분하기

예를 들어 첫 고정점의 사용자 식별자를 100, 위치를 (0,0)으로 정하고 다음 고정점은 식별자 200, 위치 (3,4)로 정합니다. 첫 추가 호출의 반환 인덱스는 0, 두 번째는 1입니다. 이후 다른 형상이나 관계가 기존 항목을 참조할 때에는 그 계약이 요구하는 인덱스를 사용하며, 사용자 식별자 100이나 200을 인덱스 대신 넣지 않습니다. 이 두 점 사이의 기하 거리는 √(3²+4²)=5픽셀입니다. 이 거리를 합격·불합격으로 판정하려면 별도의 관계와 허용치를 설계에 추가해야 합니다.

설정과 결과를 분리해 관리하기

좌표는 입력 영상 ROI의 로컬 픽셀 기준이며 x는 오른쪽, y는 아래쪽입니다. 좌표계를 추가해 기준을 바꾸는 작업과 세계 평면 보정은 서로 다른 단계입니다. 선택적인 등방 출력 배율도 임의의 원근이나 렌즈 왜곡을 보정하는 기능으로 해석하지 않습니다. 형상을 추가하기 전에 영상의 ROI 원점과 모델의 기준을 맞추고, 실제 세계 좌표가 필요하면 해당 보정 계약을 함께 적용하세요.

구현은 좌표계 64개, 형상 256개와 허용치 256개의 한도를 검사합니다. 영상 측정의 필터 계수도 별도 누적 예산을 검사하므로 항목 수만 보고 임의 크기의 설계를 허용한다고 가정하지 않습니다. 참조 순서나 옵션이 잘못되어 추가가 실패했다면 예외를 처리하고 설계를 점검합니다. 생성 후 한 번에 모든 형상을 추가하기보다 고정 형상과 파생 형상의 연결을 작은 단계로 확인하면 잘못된 인덱스를 찾기 쉽습니다.

빌더와 build가 반환하는 모델은 역할과 수명이 다릅니다. 빌더에는 이후 설계 항목을 추가할 수 있고, 이미 만든 모델은 생성 시점의 독립 설계입니다. 모델을 사용한 실행 결과와 허용치 판정도 별도의 출력으로 관리하세요. 하나의 빌더를 서로 다른 검사 설계가 함께 수정하면 추가 순서와 참조 인덱스를 혼동하기 쉬우므로 독립 설계에는 각각의 빌더를 두는 구성이 명료합니다. 이 사용 지침은 여러 편집 호출 전체에 대한 원자성이나 동시 실행 성능을 보장하는 의미가 아닙니다.
