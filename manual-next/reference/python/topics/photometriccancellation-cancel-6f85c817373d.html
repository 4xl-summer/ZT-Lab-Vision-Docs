공유된 단발 취소 토큰에 협조적 취소를 요청합니다.

반환: None. 진행 중인 연산이 확인 시 취소를 관찰합니다.

오류: 닫힌 객체 또는 부적합한 입력은 오류입니다.

이 멤버의 추가 계약은 공개 설명에서 확인되지 않았습니다.

이 호출의 입력과 객체 맥락

공유된 일회성 토큰에 협조 취소를 요청합니다. 이를 전달받은 제어형 연산이 취소를 감지하면 해당 연산의 취소 오류를 처리해야 합니다. 예를 들어 복합 계측의 제어형 평가는 취소 시 부분 결과를 반환하지 않습니다. 토큰의 close는 취소 요청과 별개이며, 작업 종료와 토큰 수명도 따로 관리합니다.

협조 취소와 종료 처리

cancel()은 공유된 단발 PhotometricCancellation 토큰에 취소를 요청하고 None을 반환합니다. 제어형 연산은 실행 중 취소를 확인하는 지점에서 요청을 관찰합니다. 이 호출이 끝났다는 사실만으로 작업 스레드가 이미 종료되었거나 완성된 검사 결과가 생겼다고 판단할 수 없습니다.

예를 들어 네 장의 조명 영상을 사용하는 photometric_stereo_controlled에 토큰을 전달하고 다른 제어 흐름에서 cancel을 요청할 수 있습니다. 이후 제어형 호출이 취소 오류로 종료하는지 확인합니다. timeout_ms는 별도의 밀리초 제한이고 0은 제한 없음이므로, 취소 요청과 기한 만료를 같은 설정으로 혼동하지 마세요.

적용과 결과 확인

토큰의 close는 취소 요청과 다릅니다. 작업을 중단하려면 cancel을 요청하고 작업의 종료를 기다린 다음 토큰의 소유권을 정리하세요. 이미 닫힌 객체에 cancel을 호출하면 오류입니다. 단발 토큰을 새 독립 작업에 재사용할 수 있다고 가정하지 말고 필요한 경우 새 토큰을 준비합니다.

협조적 취소는 작업이 관찰 지점에 도달해야 처리될 수 있으므로 cancel 반환 시각과 실제 종료 시각이 같다고 가정하지 마세요. 제어형 작업의 결과를 받는 쪽에서 정상 완료와 취소 오류를 구분하고, 취소된 실행의 불완전한 데이터를 완성된 결과처럼 판정하지 않습니다. 토큰이 공유되었다면 그 토큰을 받은 작업의 범위도 명시해야 다른 작업에 적용된 요청을 혼동하지 않습니다. 토큰 해제 전에는 관련 작업의 종료 흐름을 확인합니다.
