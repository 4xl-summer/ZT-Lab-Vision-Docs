python 공개 선언
JointCameraView(target: object, pixels_a: object, pixels_b: object, board: object) -> None

One simultaneous board observation; board pose is A<-board, axis-angle then translation.

target: 기준판 평면의 대응점들입니다.

pixels_a: 카메라 A 영상에서의 대응점들입니다.

pixels_b: 카메라 B 영상에서의 대응점들입니다.

board: 초기 A←기준판 자세로, 축각 3개 다음 이동 3개입니다. 입력 객체 자체는 자동 깊은 복사를 보장하지 않습니다.

이 호출의 입력과 객체 맥락

JointCameraView는 두 카메라가 동시에 관측한 한 보드의 입력을 묶습니다. target은 보드상의 대응 점, pixels_a와 pixels_b는 각각 두 영상에서의 픽셀 위치이며 board는 보드에서 카메라 A로 가는 초기 자세입니다. 자세는 회전 축각 다음 이동의 표현이므로 픽셀 좌표 배열과 혼동하지 않습니다.

예를 들어 보드의 첫 번째 점을 A와 B 양쪽에서 찾았다면 target, pixels_a, pixels_b의 첫 항목이 모두 같은 물리적 점에 대응해야 합니다. 한 영상에서만 점 순서가 달라지면 공동 최적화에 잘못된 제약이 들어갑니다. 같은 시점의 두 영상을 쓰고 픽셀이 전체 영상 좌표인지 ROI 좌표인지도 일치시켜야 합니다.

두 카메라 대응 뷰

target, pixels_a, pixels_b, board를 묶어 공동 카메라 계산에 전달하는 한 뷰를 구성합니다. board는 A←board 자세로 축-각 다음 이동 성분의 순서입니다. 대상 점과 각 카메라의 관측 픽셀이 올바른 순서로 대응해야 같은 물리 지점을 비교할 수 있습니다.

한 대상 점에 대해 A와 B의 대응 관측이 서로 바뀌거나 순서가 섞이면 계산은 잘못된 짝을 사용하게 됩니다. 각 카메라의 프레임, 렌즈 및 이미지 좌표 기준과 board의 단위를 해당 뷰와 함께 보관합니다.

생성자 호출만으로 카메라 자세가 추정되거나 보정 품질이 검증되지는 않습니다. 실제 연산의 입력 조건을 확인하고, 반환된 잔차와 독립 확인 데이터를 이용해 관측의 일관성을 검토합니다.

두 카메라의 픽셀 배열에서 같은 인덱스가 같은 대상점을 가리키는지 먼저 확인합니다. 예를 들어 대상의 첫 점은 A와 B의 첫 관측에 각각 대응해야 하며 한쪽 배열만 재정렬하면 쌍이 틀어집니다.

각 뷰를 다른 보드 자세에서 얻었다면 그 자세와 관측값을 한 묶음으로 유지합니다. 뒤에 수행되는 최적화의 수렴이나 잔차는 입력의 올바른 대응과 별도로 확인해야 합니다.
