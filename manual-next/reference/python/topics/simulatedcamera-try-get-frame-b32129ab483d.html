try_get_frame(self)

큐 앞에서 취득 프레임을 꺼냅니다.

반환: 호출자가 닫아야 하는 AcquiredFrame 또는 빈 큐에서 None을 반환합니다.

오류: 닫힌 카메라나 허용되지 않은 상태에서는 오류입니다.

이 멤버의 추가 계약은 공개 설명에서 확인되지 않았습니다.

이 호출의 입력과 객체 맥락

예를 들어 두 프레임을 순서대로 보관했다면 take는 먼저 들어온 프레임부터 꺼냅니다. 그다음 호출 결과가 None이라면 빈 큐이므로 이미지 처리 함수를 호출하지 않습니다. 각 프레임의 info로 source_id와 epoch, frame_id를 확인하고 이미지와 프레임의 별도 소유 핸들을 닫습니다.

Acquiring 상태의 큐에서 프레임을 FIFO 순서로 꺼냅니다. 큐가 비어 있으면 오류가 아닌 None이고, 프레임을 꺼낸 경우에만 delivered 통계가 증가합니다. 반환된 AcquiredFrame은 소유 객체이므로 사용 후 close합니다. 프레임에서 얻은 image도 별도 소유 핸들이며 각각 수명을 관리합니다. 반환 프레임은 입력 영상이나 카메라를 해제한 뒤에도 유효합니다.

빈 큐와 프레임 수명

try_get_frame은 Acquiring 상태의 큐에서 가장 먼저 들어온 프레임을 꺼냅니다. 프레임이 있으면 호출자가 닫아야 하는 AcquiredFrame을 반환하고 큐가 비어 있으면 오류가 아닌 None을 반환합니다. 닫힌 카메라나 허용되지 않은 상태의 호출 오류는 빈 큐와 구분합니다.

예를 들어 A와 B가 그 순서로 큐에 있다면 첫 호출에서 A, 둘째 호출에서 B를 받습니다. 둘 다 꺼낸 뒤 새 항목이 없다면 다음 호출은 None입니다. 전달된 프레임이 있을 때 delivered 통계가 증가하며 None을 받은 경우에는 이전 프레임을 재사용해 새 촬영으로 기록하지 않아야 합니다.

실행과 판독에서 확인

프레임의 info에서 source_id, epoch와 frame_id를 확인해 출처와 순서를 보관합니다. 프레임에서 취득한 image는 별도 소유 영상 핸들이며 프레임과 영상 모두 사용 후 close합니다. 반환 프레임은 카메라나 입력 영상의 해제와 별도 수명을 가질 수 있으므로 어떤 객체를 언제 정리하는지 명확히 하세요.
