ModbusTcpError(operation, status, diagnostic)

Modbus TCP 연산의 상태와 진단을 담는 예외입니다. 일반적으로 ModbusTcp 호출이 생성합니다.

operation: 실패한 연산을 나타내는 문자열입니다.

status: 네이티브 상태 정수입니다.

diagnostic: 진단 코드 정수입니다. 1은 입출력, 2는 프로토콜, 3은 연결 해제, 0x100 이상은 예외 응답을 나타낼 수 있습니다.

이 호출의 입력과 객체 맥락

실패한 operation 이름, 네이티브 status, diagnostic을 보관하는 오류 객체입니다. 진단 1은 입출력, 2는 프로토콜, 3은 연결 끊김이며 0x100과 서버 예외 코드를 결합한 값은 예외 응답을 나타냅니다. 통신·프로토콜 오류 뒤에는 명시적 reconnect가 필요할 수 있습니다. 특히 쓰기 중 시간 초과에서는 상대 장치 적용 여부가 불확실하므로 무조건 재전송하지 말고 장치 상태를 확인하세요.

진단 코드와 복구 판단

ModbusTcpError는 실패한 operation 이름, 네이티브 status, diagnostic을 보관하는 RuntimeError입니다. 보통 Modbus TCP 호출이 오류 상태를 확인하면서 만듭니다. 생성자 자체는 장치에 연결하거나 다시 요청하지 않으며 전달된 세 값을 메시지와 속성에 담습니다.

diagnostic 1은 입출력, 2는 프로토콜, 3은 연결 해제를 나타내고 0x100 이상은 서버 예외 응답을 표현할 수 있습니다. 예를 들어 diagnostic 0x102는 0x100과 예외 코드 2의 조합입니다. status와 diagnostic은 서로 다른 필드이므로 오류를 기록할 때 둘 다 남깁니다.

전송 또는 잘못된 프로토콜 응답 이후에는 명시적 reconnect가 필요할 수 있습니다. 특히 단일 레지스터 쓰기 도중 시간 초과라면 장치가 값을 이미 적용했는지 알 수 없으므로 무조건 같은 쓰기를 재전송하지 말고 장치 상태를 확인합니다. 이 예외는 자동 재시도 정책을 제공하지 않습니다.

통신 로그에는 operation과 status뿐 아니라 diagnostic, 대상 unit과 0기반 레지스터 주소, 쓰기 요청 값을 함께 남기면 복구 판단에 도움이 됩니다. 서버 예외 응답과 연결 단절은 원인이 다르며, 예외를 포착한 뒤 같은 요청을 즉시 반복하는 동작은 이 오류 객체에 포함되어 있지 않습니다.
