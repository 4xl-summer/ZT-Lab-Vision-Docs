EnclosingCircle(center: zvision._regions.Point2, radius: float) -> None

Center and nonnegative radius in the same units as the input points.

center: 입력과 같은 좌표계의 원 중심 Point2.

radius: 입력과 같은 단위의 음수가 아닌 반경.

이 호출의 입력과 객체 맥락

입력 점을 포함하는 원의 중심과 음이 아닌 반경을 담는 결과 값입니다. center와 radius는 점을 계산한 동일한 좌표계와 단위를 따릅니다. 예를 들어 점 (0,0)과 (2,0)의 최소 포함 원은 중심 (1,0), 반경 1이며, 두 점 모두 중심에서 거리 1인 경계 위에 있습니다. 단일 점은 반경 0의 유효한 결과가 될 수 있으므로 0을 실패 신호로 사용해서는 안 됩니다. 입력이 ROI 로컬 픽셀이면 중심도 같은 로컬 픽셀이며, 다른 ROI의 결과와 중심을 비교하려면 각각의 ROI 원점을 복원해야 합니다. 평면 세계 좌표로의 변환은 별도 보정 단계의 역할이며 반경 숫자에 단위 이름만 붙이는 것으로 완료되지 않습니다. 원 생성 과정의 입력 오류와 반환된 유효 원은 호출의 성공 여부로 구별하고, 반환값을 확인할 때는 사용한 점들의 좌표와 단위를 함께 보관하십시오. 거의 퇴화하거나 크기가 극단적인 입력에서는 부동소수점 계산의 한계를 고려하여 결과를 검토해야 합니다. 포함 여부를 점검할 때는 각 입력점과 반환 중심의 거리를 반경과 비교합니다. 배치가 바뀌면 가장 멀리 있는 점이나 원의 중심도 바뀔 수 있으므로 과거 반경만 갱신해 재사용하지 말고 현재 점 집합으로 다시 계산하십시오. 좌표를 같은 배율로 바꾸면 중심과 반경을 일관되게 변환해야 합니다.

중심·반지름과 포함 판독

EnclosingCircle은 center인 Point2와 음수가 아닌 radius를 담는 값입니다. 중심과 반지름은 입력 점들과 같은 좌표계와 길이 단위로 해석합니다. 생성자는 center가 Point2인지 검사하지만 반지름의 음수 여부나 임의의 점 집합 포함 여부를 대신 검증하지 않습니다. 직접 구성할 때 호출자가 유효한 반지름을 제공해야 합니다.

예를 들어 점 (0,0)과 (2,0)의 최소 포함 원은 중심 (1,0), 반지름 1입니다. 각 점에서 중심까지의 거리는 1이므로 둘 다 원 경계에 있습니다. 중심 (1,0), 반지름 0.5를 직접 값으로 만들었다면 두 점까지 거리가 1이므로 그 원은 이 두 점을 포함하지 않습니다. 계산 결과와 수동 구성 값을 구분해 검사하세요.

항목의미와 처리

수명과 결과 확인

단일 점을 포함하는 반지름 0도 유효할 수 있으므로 반지름이 0인 것만으로 오류라고 판정하지 않습니다. 점들이 ROI 로컬 픽셀이면 중심도 그 기준으로 읽고, 다른 ROI와 비교할 때는 각 원점을 확인합니다. 물리 단위가 필요할 때는 좌표 보정과 기하 변환을 별도로 적용해야 하며 픽셀 반지름에 단위 이름만 붙이지 않습니다.
