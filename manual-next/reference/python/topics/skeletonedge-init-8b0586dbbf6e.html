SkeletonEdge(start: int, end: int, points: tuple, length: float)

start: 시작 노드 인덱스입니다.

end: 끝 노드 인덱스입니다.

points: 에지를 구성하는 점들입니다.

length: 에지 경로의 길이입니다.

이 호출의 입력과 객체 맥락

SkeletonEdge는 start와 end 노드 인덱스, 경로를 구성하는 points, 그 경로의 length를 담습니다. 시작과 끝의 좌표만을 이은 직선과 실제 골격 경로는 다를 수 있으므로 굽은 가지를 측정할 때는 전체 점 경로와 계산된 길이를 사용합니다.

점이 (0,0), (1,0), (1,1) 순서로 이어지고 두 축의 간격이 1이면 두 인접 이동 길이의 합은 2입니다. 두 끝점을 잇는 직선 거리는 √2로 더 짧습니다. 축 간격이 다른 경우에는 각 방향 이동의 실제 간격을 반영해야 하므로 그래프 생성 옵션도 확인합니다.

간선의 점 사슬과 노드

SkeletonEdge는 시작 노드 인덱스 start, 끝 노드 인덱스 end, 경로 점들 points와 경로 길이 length를 저장합니다. points는 Point2 항목들의 튜플로 정리되고 항목 타입을 검사합니다. start와 end는 같은 SkeletonGraph의 nodes 순서에 대응하는 인덱스로 해석합니다.

예를 들어 경로 점이 (0,0), (1,0), (1,1)이고 두 축 간격이 1이면 인접 구간의 길이 합은 1+1=2입니다. 시작과 끝을 바로 잇는 거리는 √2로 더 짧습니다. 두 숫자를 바꿔 쓰면 꺾인 골격 가지의 길이를 잘못 해석합니다. 간격이 다르면 각 구간의 방향에 맞는 간격을 사용해야 합니다.

적용과 결과 확인

생성자는 전달된 length를 점 목록으로부터 자동 계산하지 않으며 그래프 노드의 존재 관계를 이 값 하나만으로 보장하지 않습니다. 직접 구성한 경우 points, length와 노드 인덱스의 일관성을 호출자가 확인하세요. 닫힌 루프에서는 시작과 끝 인덱스가 같을 수 있으므로 그 숫자만으로 간선이 길이 0이라고 판단하지 않습니다.

점 간격이 x 방향 2, y 방향 3인 경우 같은 세 점 (0,0), (1,0), (1,1)의 두 구간은 각각 2와 3의 길이를 가지므로 합은 5입니다. 단위 간격에서 계산한 2와는 다릅니다. 이는 축에 평행한 예시이며 대각선 구간은 두 방향의 이동을 함께 고려합니다. start와 end가 가리키는 노드 위치와 points의 양 끝도 직접 구성 시 대조해야 그래프 연결과 경로가 같은 대상을 나타냅니다.
