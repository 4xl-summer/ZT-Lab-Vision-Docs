Expr(kind, code=0, value=None, children=())

Query 조건식의 내부 노드 표현입니다. 직접 코드값을 조합하기보다 Query의 조건식 콜백과 연산자로 구성합니다.

kind: 내부 노드 종류를 나타내는 정수입니다.

code: 노드에 따른 내부 연산 또는 필드 코드이며 기본값은 0입니다.

value: 리터럴 노드에 사용하는 값이며 기본값은 None입니다.

children: 자식 Expr의 튜플이며 기본값은 빈 튜플입니다. 구성된 식은 깊이 64 및 노드 4096 제한을 받습니다.

이 호출의 입력과 객체 맥락

Expr는 Query의 조건과 정렬에 쓰이는 식을 나타내는 노드입니다. 일반 사용자는 내부 kind와 code를 임의로 조립하기보다 Blob 등의 필드를 받는 콜백과 비교·산술·논리 연산자로 식을 구성하는 편이 좋습니다. Python의 and/or처럼 값을 즉시 참 또는 거짓으로 평가하는 연산 대신 문서화된 기호식 연산을 사용해야 계획에 조건이 남습니다. Expr를 bool로 바꾸려고 하면 오류가 발생합니다.

예를 들어 Blob 면적이 일정 기준 이상인 조건은 실행할 때 각 영역의 area에 적용되는 계획이지, 콜백을 작성하는 시점에 하나의 실제 Blob을 즉시 판정하는 계산이 아닙니다. 내부 표현은 깊이 64와 노드 4096 제한을 가지며 정수·실수 리터럴도 범위와 유한성을 검사합니다. 조건을 계획에 넣은 다음 형식별 execute 결과를 확인하세요. C#이나 Rust의 표현식 문법 및 소유권과 Python 코드를 그대로 혼용하지 않아야 합니다.

사용 흐름과 결과 판독

Expr는 쿼리에서 조건과 정렬을 표현하는 내부 식 노드입니다. kind는 노드 종류, code는 그 종류에 따른 내부 코드, value는 리터럴의 값, children은 자식 식입니다. 직접 숫자를 조합한 노드를 만드는 대신 필드를 받는 콜백과 지원하는 비교·산술·논리 연산으로 조건을 구성하면 의도한 쿼리 계획에 식이 남습니다.

예를 들어 성분의 area가 특정 한계 이상인 식은 각 성분을 실행 시 평가하는 조건입니다. 콜백 작성 시점에 하나의 실제 성분을 읽어 즉시 True 또는 False로 확정하는 계산이 아닙니다. Python의 and/or는 피연산자를 bool로 평가하므로 기호식에 그대로 쓰는 방식과 다르며 Expr를 bool로 변환하려 하면 오류가 발생합니다. 문서화된 식 연산을 사용해야 합니다.

완성된 표현식에는 깊이 64와 노드 수 4096의 제한이 있고 정수 범위와 실수의 유한성도 검사합니다. 깊이와 노드 수는 서로 다른 한도이므로 짧게 보이는 식이라도 반복적으로 결합하면 제한에 이를 수 있습니다. 조건을 계획에 등록한 후 execute하여 선택 결과를 확인하고 원래 입력의 단위와 비교 기준도 함께 보관합니다.
