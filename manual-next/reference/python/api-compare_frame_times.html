Python API · compare_frame_times

compare_frame_times 멤버와 선언

공개 타입

zvision.compare_frame_times: 패키지 __all__ 공개 이름입니다. 선언 출처: zvision._acquisition.compare_frame_times.

두 프레임 시간을 공통 기준으로 변환하여 비교합니다.

Python
compare_frame_times(a, map_a, b, map_b, tolerance_ns)

인자 선언

  • a · POSITIONAL_OR_KEYWORD · 기본값 없음
  • map_a · POSITIONAL_OR_KEYWORD · 기본값 없음
  • b · POSITIONAL_OR_KEYWORD · 기본값 없음
  • map_b · POSITIONAL_OR_KEYWORD · 기본값 없음
  • tolerance_ns · POSITIONAL_OR_KEYWORD · 기본값 없음

확인된 인자 조건

a
첫 FrameInfo
map_a
첫 ClockMap
b
둘째 FrameInfo
map_b
둘째 ClockMap
tolerance_ns
허용 오차(나노초), 음이 아닌 정수

반환: 변환 시각, 차이, 불확도 및 허용 여부를 담은 ClockComparison

오류: 타입·범위·형식 검증이나 네이티브 연산 실패 시 오류가 전달됩니다.

tolerance_ns: 정수 검사.

래퍼에서 발생 가능한 오류: RuntimeError. 네이티브 오류는 별도입니다.

시그니처와 설명에 없는 반환값, 오류, 제약 조건은 확인되지 않았습니다. 환경별 네이티브 지원 여부와 예제 실행은 별도 검증이 필요합니다.

공개 멤버

    사용 맥락과 계약

    compare_frame_times는 두 프레임에 각각 대응하는 ClockMap을 적용하고 나노초 기준의 시간 차이와 불확도를 계산합니다. a와 map_a, b와 map_b는 각각 소스 ID, clock_domain, epoch와 tick_hz가 일치해야 하며 두 소스는 서로 달라야 합니다. tolerance_ns는 음이 아닌 정수 나노초 허용치입니다. 장치가 같은 도메인 번호를 쓴다는 사실만으로 동기화 여부를 판단하지 않습니다.

    구체 사례와 판독

    반환 ClockComparison의 skew_ns는 변환된 두 시각의 절대 차이이고 total_uncertainty_ns는 두 맵 불확도의 합입니다. 예를 들어 차이 80ns와 불확도 합 20ns는 허용치 100ns에서 통과하지만 99ns에서는 통과하지 않습니다. 이 판단은 제공한 기준점과 불확도가 맞다는 전제의 계산입니다. epoch나 주파수가 맞지 않는 오류는 숫자를 보정해 무시하기보다 프레임에 맞는 매핑을 다시 구성해야 합니다.

    적용 시 확인

    입력 맵이 틀리면 결과 숫자의 정밀한 자릿수는 의미가 없습니다. 먼저 두 소스가 다르고 각 프레임의 세션·도메인·틱 주파수가 자기 맵에 일치하는지 확인한 다음 나노초 판정을 해석하세요.
