열거 값

  • REJECT_NEW = 0 · 큐가 가득 차면 새 항목을 거부합니다.
  • DROP_OLDEST = 1 · 큐가 가득 차면 가장 오래된 항목을 버립니다.
  • WAIT = 2 · 값 2. 큐가 찼을 때 공간이 생기거나 닫히거나 지정 대기 시간이 끝날 때까지 기다립니다.

사용 맥락과 계약

FrameQueuePolicy는 제한된 프레임 큐가 가득 찼을 때 새 항목을 어떻게 다룰지 선택합니다. REJECT_NEW는 새 항목을 거절하고 DROP_OLDEST는 가장 오래된 항목을 제거한 후 새 항목을 받으며 WAIT는 자리가 날 때까지 지정된 조건으로 기다립니다. 정책은 큐 동작에 관한 것이며 카메라의 노출이나 촬영 트리거 설정과는 별개입니다.

구체 사례와 판독

예를 들어 용량 2인 큐에 A와 B가 있을 때 C를 넣으면 REJECT_NEW에서는 기존 A와 B를 유지하고 C가 수락되지 않습니다. DROP_OLDEST에서는 A가 빠져 B와 C가 남습니다. WAIT에서는 소비자가 꺼내 공간을 만들거나 대기 시간이 끝날 때까지 결과가 결정되지 않습니다. 누락 없는 처리와 최신 화면 표시 중 무엇을 우선할지에 맞춰 선택하고 실제 offer 상태를 기록하세요.

적용 시 확인

WAIT는 시간을 무한히 줄 수 있다는 뜻으로 단정하지 말고 호출에 지정한 대기 조건과 종료 처리를 함께 검토하세요. 프레임이 제거되는 경우 생산자가 정상적으로 카메라를 작동했더라도 소비된 영상의 연속성은 깨질 수 있습니다. 그 차이를 모니터링 지표에 반영하세요. 큐 크기도 정책과 함께 정해야 대기와 손실을 해석할 수 있습니다.
