Python API · relabel_blobs

relabel_blobs 멤버와 선언

공개 타입

zvision.relabel_blobs: 패키지 __all__ 공개 이름입니다. 선언 출처: zvision._blob_relabel.relabel_blobs.

Return an independent BlobResult with labels 1..N and unchanged measurements.

영역 측정값을 유지하며 라벨을 1부터 다시 부여합니다.

Python
relabel_blobs(source, work_budget)

인자 선언

  • source · POSITIONAL_OR_KEYWORD · 기본값 없음
  • work_budget · POSITIONAL_OR_KEYWORD · 기본값 없음

확인된 인자 조건

source
입력 BlobResult
work_budget
양의 정수 작업량 상한

반환: 별도로 close할 BlobResult

오류: 입력 타입, 인자 또는 작업 예산이 유효하지 않으면 오류가 발생할 수 있습니다.

래퍼에서 발생 가능한 오류: TypeError. 네이티브 오류는 별도입니다.

시그니처와 설명에 없는 반환값, 오류, 제약 조건은 확인되지 않았습니다. 환경별 네이티브 지원 여부와 예제 실행은 별도 검증이 필요합니다.

공개 멤버

    성분과 레이블

    relabel_blobs는 입력 BlobResult의 영역 측정값을 유지하면서 레이블을 1부터 다시 부여합니다. 레이블은 픽셀이 어느 성분에 속하는지 나타내는 값이며 면적이나 중심과는 다른 정보입니다. 레이블 번호가 바뀌었다는 것만으로 물체의 실제 크기나 위치가 바뀐 것은 아닙니다.

    번호와 배경

    레이블 맵을 판독할 때 배경과 성분 번호를 구별합니다. 예를 들어 이전에 불연속적인 번호가 있었더라도 결과를 연속 번호로 정리하면 순번을 이용한 배열 접근이 편해질 수 있습니다. 다만 기존 번호를 외부 데이터의 영구 식별자로 사용했다면 새 번호와의 대응을 따로 관리해야 합니다.

    입력과 제한

    source에는 BlobResult를 전달하고 work_budget에는 양의 작업량 상한을 지정합니다. 결과 레이블과 원래 측정 결과를 비교할 때에는 동일 성분의 면적 및 위치를 함께 확인합니다. 입력 객체의 번호와 새 레이블을 그대로 같다고 가정해 다른 프레임의 객체를 연결하지 않습니다.

    후속 사용

    재부여한 맵을 이미지에 표시할 때도 ROI와 원본의 좌표 기준을 맞춥니다. 번호 색상만 비교하면 번호가 재할당된 차이를 형상 변경으로 오인할 수 있으므로 전경 마스크와 실제 픽셀 배치도 확인합니다.
