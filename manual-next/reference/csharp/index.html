C# 공개 API 색인

C# 실제 선언에서 클래스·메서드·프로퍼티·필드·열거값을 찾습니다.

이 색인을 실제 코드에 연결하기

어셈블리와 타입의 관계

관리형 색인은 코어 ZVision의 공개 타입 823개, Display의 12개, Inspection의 9개를 구분해 반영합니다. 영상 처리, 화면 표시, 검사 파이프라인은 함께 사용할 수 있지만 책임이 다릅니다. 예를 들어 처리 결과를 얻는 호출과 그 결과를 화면에 배치하는 호출을 같은 단계로 취급하지 마세요. 코드 프로젝트에 어떤 어셈블리가 필요한지 먼저 판단하고, 그 어셈블리의 객체가 받는 입력과 반환하는 결과를 이어 붙이는 방식으로 프로그램을 구성합니다.

생성자와 오버로드 선택

C#은 같은 메서드 이름에 여러 인자 목록을 가질 수 있습니다. 개별 선언에서 타입, 인자 순서, 선택 인자와 반환 타입을 확인하고 사용하는 오버로드를 명확히 고르세요. 설정 구조체와 결과 구조체는 비슷한 필드 이름을 가지더라도 방향이 다릅니다. 설정은 호출 전에 정하는 입력이고 결과 필드는 실행 후 읽는 값입니다. 결과의 값을 입력 설정으로 재사용하려면 좌표계와 단위, 허용 범위가 일치하는지 별도 확인해야 합니다.

Dispose와 복사된 값

IDisposable을 구현한 네이티브 소유 객체는 사용 범위를 using으로 드러내면 예외가 발생한 경로에서도 해제 순서를 이해하기 쉽습니다. 다만 모든 구조체나 스냅샷을 네이티브 핸들처럼 다루지는 않습니다. 결과의 프로퍼티가 복사된 관리형 값인지, 별도의 소유 자원을 반환하는지 각 멤버 계약에서 확인하세요. 화면 표시나 검사 호스트로 넘긴 데이터도 누가 소유하고 언제 읽는지 확인한 뒤 범위를 정해야 불필요한 복사와 해제된 객체 접근을 피할 수 있습니다.

상속 멤버를 읽는 기준

타입 표에는 SDK가 정의한 멤버와 상속되어 보이는 멤버가 함께 나타날 수 있습니다. 공통 Object 멤버의 수를 독립적인 영상 처리 기능 수로 세지 않으며, SDK 고유 호출을 우선 찾아 사용합니다. enum의 CLR 저장 필드 value__는 런타임 표현에 필요한 항목으로, 호출자가 고를 알고리즘 옵션이 아닙니다. 실제 선택은 열거형에 선언된 이름을 기준으로 하고 결과 판정은 실행 사례의 값과 비교하세요. Windows 장비 인수와 Linux 관리형 예제 실행 기록은 서로 다른 검증 범위입니다.

확인 범위와 사용 방법

이 색인은 고정 SDK에서 확인한 선언으로 연결합니다. 타입별 페이지에서 파라미터와 필드, 상속 멤버, 반환과 오류를 확인하세요. 주석과 실제 구현으로 확인하지 못한 계약은 미확인으로 구분하며, 선언 수를 독립 기능 수나 실행 성공률로 세지 않습니다.
