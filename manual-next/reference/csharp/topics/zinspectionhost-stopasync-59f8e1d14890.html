StopAsync

Method · 선언 타입 ZVision.Inspection.ZInspectionHost

System.Threading.Tasks.Task StopAsync()

새 요청을 닫고 실행 및 대기 요청에 취소를 전달한 뒤 모든 임대 정리를 기다립니다. 네이티브 호출은 강제 중단하지 않습니다.

반환: 정리 완료 작업입니다.

이 호출의 입력과 객체 맥락

이 객체의 확인된 공개 생성 경로: ZInspectionHost(System.Int32 capacity = 2, ZVision.Inspection.IZInspectionExecutor executor = null).

비동기 종료

새 요청을 닫고 실행 및 대기 요청에 취소를 전달한 다음 모든 영상 임대 정리가 끝나기를 기다리는 작업을 반환합니다. 진행 중인 네이티브 호출은 강제로 끊지 않습니다.

화면 종료 경로에서는 반환 작업을 await하여 정리를 기다릴 수 있습니다. 이미 수락된 요청의 성공, 취소 또는 오류와 이후 Submit의 Closed 상태를 구분합니다.

요청 종료와 임대 정리

StopAsync는 새 요청의 수락을 닫고 실행 중이거나 대기 중인 요청에 취소를 전달한 뒤 작업자의 정리가 완료될 때 끝나는 Task를 반환합니다. 이미 시작한 네이티브 호출을 강제로 중단하지 않으므로 호출 직후 모든 작업이 끝났다고 판단할 수 없습니다.

예를 들어 요청 A가 네이티브 검사 중이고 B가 대기 중일 때 StopAsync를 호출하면 새 Submit은 Closed로 거절되고 수락된 요청에는 취소가 전달됩니다. A의 네이티브 호출이 바로 반환하지 않으면 종료 Task도 영상 임대 정리가 끝날 때까지 완료되지 않습니다. 각 요청의 완료·취소·오류와 호스트의 종료 완료를 따로 확인하세요.

항목의미와 처리
StopAsync호스트를 닫고 취소 전달
Submit 이후닫힌 호스트는 Closed
대기 요청취소와 정리 대상

Task 완료작업과 영상 임대 정리 후
UI반환 Task를 await

실행과 판독에서 확인

UI 종료 경로에서는 반환 Task를 await하여 비동기적으로 정리를 기다릴 수 있습니다. Dispose는 StopAsync를 동기로 기다리므로 UI 스레드에서는 StopAsync가 적합합니다. 입력 영상의 독립 임대가 정리된 다음 작업이 완료된다는 계약을 이용하고, 이미 제출한 요청의 결과를 새 요청의 Closed 상태와 혼동하지 않습니다.
