ZVision.QueryExecution<ZVision.BarcodeRead> Execute()

계획을 실행하고 바코드 판독 결과를 독립 스냅샷으로 복사합니다.

반환: Dispose해야 하는 실행입니다. Output으로 얻은 스냅샷은 실행 해제 후에도 유효합니다.

사용과 결과 판독

지연 판독 계획을 실행해 독립 바코드 스냅샷을 얻습니다. 실행 핸들은 Dispose해야 하지만 Output 스냅샷은 실행 해제 후에도 유효합니다. 읽기 상태와 텍스트를 함께 살펴 인식 실패와 정상적인 데이터 값을 구별하십시오.

항목확인된 역할
반환Dispose해야 하는 실행입니다. Output으로 얻은 스냅샷은 실행 해제 후에도 유효합니다.

읽은 바코드의 형식, 위치와 상태를 결과 텍스트와 함께 확인합니다. 스냅샷이 독립적으로 남는다는 것은 실행이 끝난 후에도 읽을 수 있다는 의미이지, 판독이 항상 성공한다는 의미는 아닙니다.

호출과 결과 판독

BarcodeQuery.Execute는 지연 판독 계획을 실제로 실행하여 QueryExecution<BarcodeRead>를 만듭니다. 실행 객체는 호출자가 Dispose해야 하지만 Output으로 얻은 판독 스냅샷은 실행을 해제한 후에도 유효합니다. 계획, 실행, 값 스냅샷은 각기 다른 역할입니다.

읽기 결과에서는 상태와 텍스트, 바코드 형식과 위치를 함께 확인하십시오. 예를 들어 화면에 문자열이 표시되지 않는 상황은 후보 미발견과 실행 오류를 구분해야 합니다. 사용한 ROI 및 형식 선택, 회전 시도 조건이 결과 해석의 기준입니다.

원본 또는 복제 계획을 각각 실행했다면 각 실행을 별도로 해제합니다. 독립 스냅샷이 남는다는 사실은 판독이 반드시 성공했다는 뜻이 아니며, 필요한 결과를 어떤 영상에서 얻었는지도 함께 보관해야 합니다.

항목확인할 내용
계획바코드 판독의 지연 계획입니다.
Execute실제 판독을 수행합니다.
Output상태와 데이터의 독립 스냅샷입니다.
좌표검출 위치의 영상 ROI 기준을 기록합니다.
실행 수명호출자가 실행을 Dispose합니다.
스냅샷실행 해제 후에도 값은 유효합니다.

예를 들어 판독 스냅샷이 특정 프레임의 ROI에서 나왔다면 실행을 Dispose하더라도 그 스냅샷에 해당하는 프레임 ID와 ROI를 함께 기록할 수 있습니다. 단일 바코드의 형식이나 읽기 상태가 기대와 다를 때에는 형식 선택과 입력 방향, 대비를 확인합니다. 실행 실패와 읽기 실패는 각기 다른 단계이므로 오류 경로를 결과 문자열과 분리하십시오.
