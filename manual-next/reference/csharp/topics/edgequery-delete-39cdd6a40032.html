C#
void Delete(System.UInt64 label)

Deletes a label permanently.

인자

label: Stable edge label.

이 호출의 입력과 객체 맥락

안정된 양의 label에 해당하는 에지를 영구 삭제합니다. 임시 제외를 다시 포함하는 SetIncluded와 구분해야 합니다. 삭제 뒤에는 포함 목록의 조밀 인덱스가 달라질 수 있으므로 다른 에지의 인덱스를 다시 조회하세요. 이 메서드는 쿼리 객체 전체를 해제하는 Dispose와도 별개입니다.

안정 라벨과 삭제 순서

Delete는 EdgeQuery 안에서 지정한 안정 라벨의 에지를 영구 삭제합니다. label은 양의 에지 라벨이며 현재 목록의 조밀 인덱스나 쿼리 전체 핸들이 아닙니다. 임시로 조회 대상에서 빼는 SetIncluded와 다르게 삭제된 에지를 다시 포함하는 호출로 되돌리는 사용 흐름이 아닙니다.

예를 들어 포함된 에지의 라벨이 10, 20, 30이고 라벨 20을 삭제하면 남은 에지들의 목록 인덱스가 달라질 수 있습니다. 라벨 30을 계속 다루려면 삭제 전의 목록 인덱스를 재사용하지 말고 해당 라벨이나 삭제 후의 목록을 다시 확인하세요. 라벨 20이라는 숫자는 단순히 두 번째 위치라는 뜻이 아닙니다.

항목의미와 처리
label삭제할 안정 에지 라벨
Delete해당 에지의 영구 삭제
SetIncluded일시적인 포함 상태 변경
예시라벨 10,20,30 중 20 삭제
삭제 후남은 조밀 인덱스를 다시 조회
Dispose쿼리 전체 핸들을 별도 해제

적용과 결과 확인

삭제할 라벨을 결과에서 확인한 다음 Delete를 호출하고, 변경 뒤 개수와 남은 에지의 메타데이터를 다시 조회합니다. 제외와 삭제를 비교할 때에는 SetIncluded의 포함 상태 변경과 영구 삭제의 차이를 기록하세요. 작업을 모두 마친 뒤 쿼리 자체는 별도 소유 객체로 Dispose하며, Delete가 Dispose를 대신하지 않습니다.

에지 라벨과 목록 위치를 구분하는 이유는 삭제뿐 아니라 일시 제외에서도 현재 보이는 목록이 달라질 수 있기 때문입니다. 예를 들어 라벨 10을 제외한 상태의 첫 포함 항목과 모든 항목이 포함된 상태의 첫 항목은 다를 수 있습니다. 삭제하려는 대상을 시각화할 때에는 라벨에 해당하는 점 사슬과 현재 포함 상태를 먼저 확인하세요. 삭제된 라벨을 다시 포함시키는 방법을 전제로 복구 절차를 설계해서는 안 됩니다. 필요한 원본 에지는 삭제 전에 별도로 보관할 수 있습니다.
