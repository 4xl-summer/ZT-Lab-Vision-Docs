Clone의 사용과 결과 해석

복제된 계획을 다른 조건의 출발점으로 사용할 수 있습니다. 이후 필터나 정렬을 다르게 설정했다면 두 실행의 조건과 결과를 각각 보관해야 비교가 가능합니다. 선택·정렬·분석 조건을 계획으로 구성한 후 실행합니다. 조건을 바꾸기 전 계획과 이후 계획의 관계는 해당 메서드의 반환 계약에 따르며, 결과의 항목 수와 실제 선택 조건을 함께 확인합니다.

사용 순서와 결과 보관

BlobQuery.Clone은 현재 계획을 독립적으로 변경할 수 있는 새 빌더로 복제합니다. 복제는 연결 성분을 즉시 계산하는 호출이 아니며 실제 결과는 각 계획을 Execute해야 얻습니다. 원본과 복제본은 각각 호출자가 해제할 소유 빌더입니다.

예를 들어 원본 계획을 공통 출발점으로 보관하고 복제본에 면적 조건을 추가하면 두 계획의 선택 기준을 나누어 비교할 수 있습니다. 정렬은 반환 순서를 정하고 필터는 포함할 항목을 선택하므로 두 설정을 구분하여 기록합니다. 실행 결과의 인덱스를 다른 계획의 결과와 연결할 때는 입력과 조건이 동일한지도 확인합니다.

복제한 뒤 원본을 해제하는 일과 복제본의 사용 종료는 별개입니다. 필요한 실행 결과를 얻은 뒤 두 빌더를 각각 Dispose하고, 실행 객체도 그 반환 계약에 맞게 따로 정리합니다. 닫은 빌더로 새 조건을 등록하거나 Execute를 요청하지 않습니다.
