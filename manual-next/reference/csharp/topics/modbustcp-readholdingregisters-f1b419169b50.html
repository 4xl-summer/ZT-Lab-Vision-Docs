ReadHoldingRegisters

Method · 선언 타입 ZVision.ModbusTcp

C#
System.UInt16[] ReadHoldingRegisters(System.UInt16 address, System.UInt16 count)

연속된 보유 레지스터를 읽습니다.

인자

address: 0부터 시작하는 프로토콜 주소입니다.

count: 읽을 개수로 1부터 125까지입니다.

반환: 읽은 레지스터 값입니다.

사용과 결과 해석

지정한 0부터 시작하는 프로토콜 주소에서 연속된 보유 레지스터를 1~125개 읽어 UInt16 배열로 반환합니다. 배열 순서는 요청 주소 순서입니다.

예를 들어 주소 10에서 3개를 요청하면 주소 10, 11, 12의 값을 순서대로 받습니다. 장치 문서가 1부터 시작하는 표기법을 쓴다면 프로토콜 주소와 구별하십시오.

입력과 결과 확인

ReadHoldingRegisters는 0부터 시작하는 프로토콜 주소에서 연속 보유 레지스터를 읽어 UInt16 배열로 반환합니다. address는 첫 주소이고 count는 1~125입니다. 배열의 순서는 요청 주소가 증가하는 순서와 연결됩니다.

예를 들어 address=10, count=3이면 배열의 첫째, 둘째, 셋째는 각각 주소 10, 11, 12의 값입니다. 장치 설명서가 1부터 시작하는 번호나 별도의 보유 레지스터 표기를 쓰면 그 표기와 프로토콜 주소를 구별해 확인해야 합니다.

각 레지스터는 16비트 값 하나입니다. 두 레지스터를 연결해 더 큰 수나 부동소수로 읽는 규칙은 이 메서드의 반환 계약만으로 정해지지 않으므로 해당 장치의 바이트 순서와 자료 정의를 따로 확인하십시오. 통신 오류와 값 0을 동일하게 기록하지 않아야 합니다.

항목확인할 내용
address0부터 시작하는 첫 프로토콜 주소입니다.
count1~125개의 연속 레지스터를 요청합니다.
반환주소 순서의 UInt16 배열입니다.
예시10에서 3개는 10, 11, 12에 대응합니다.
자료 해석여러 레지스터의 조합 규칙은 장치 문서를 따릅니다.
실패통신 오류를 레지스터 값 0으로 대체하지 않습니다.

배열 길이가 count와 일치하는지 확인하고 각 인덱스를 시작 주소에 더해 원래 레지스터에 연결하십시오. 예를 들어 첫 주소 10의 결과에서 인덱스 2는 주소 12입니다. 반환된 UInt16은 0부터 65535까지 표현할 수 있는 한 레지스터의 값이며, 장치가 부호 있는 수나 비트 플래그로 정의한 경우 후속 해석은 해당 장치의 규칙에 따라야 합니다. 번호 표기, 단위와 실제 프로토콜 주소를 함께 기록하면 잘못된 항목을 읽는 문제를 줄일 수 있습니다.

레지스터 값이 정상적인 0일 수도 있으므로 배열을 받지 못한 실패와 값이 0인 성공은 별도의 상태로 보존해야 합니다. 장치가 제공하는 측정 단위도 함께 확인하십시오.
