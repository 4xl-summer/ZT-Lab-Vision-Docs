현재 계획을 독립적으로 변경할 수 있는 새 빌더로 복제합니다. 이후 한쪽의 추가는 다른 쪽에 반영되지 않습니다.

반환: 호출자가 해제해야 하는 독립 빌더입니다.

Clone의 사용과 결과 해석

이미지 처리 계획을 복제하면 공통 초기 단계에서 서로 다른 후속 연산을 비교할 수 있습니다. 복제 이후 두 계획의 변경과 실행 결과를 구분합니다. 선택·정렬·분석 조건을 계획으로 구성한 후 실행합니다. 조건을 바꾸기 전 계획과 이후 계획의 관계는 해당 메서드의 반환 계약에 따르며, 결과의 항목 수와 실제 선택 조건을 함께 확인합니다.

공통 단계에서 독립 분기

ImageQuery의 연산 추가 메서드는 현재 빌더를 갱신하고 같은 객체를 반환합니다. Clone은 그 시점의 계획을 별도 소유 빌더로 복제하므로, 복제 후 한쪽에 추가한 연산은 다른 쪽 계획에 반영되지 않습니다. 단순 변수 대입으로 만든 별칭은 같은 객체를 가리킵니다.

예를 들어 공통 전처리까지 계획한 뒤 Clone하고 한쪽에 임계값 연산을 추가하면 다른 쪽은 복제 당시의 계획을 유지합니다. Clone 자체는 영상을 실행하거나 결과를 만들지 않습니다. 각 계획의 실제 결과는 Run 또는 해당 종단 쿼리의 실행 단계에서 얻습니다.

원본 빌더와 복제 빌더는 사용 후 각각 Dispose해야 합니다. 각 실행 결과와 별도로 얻은 캡처 영상도 자신의 소유권을 가집니다. 두 결과를 비교할 때 공통 단계와 분기 이후에 추가한 단계, 같은 입력 ROI를 기록하면 어떤 차이로 결과가 달라졌는지 해석할 수 있습니다.
