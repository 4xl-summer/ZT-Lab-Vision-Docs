pub fn space(&self) -> ColorSpace

Returns the channel coordinate space.

사용과 결과 해석

이 평면들이 나타내는 ColorSpace를 값으로 반환합니다. 성분의 이름과 의미는 색 공간에 따라 달라집니다.

예를 들어 채널 인덱스만 저장하면 서로 다른 공간의 값을 구별할 수 없습니다. 공간과 채널을 함께 기록하고 필요한 경우 to_rgb로 재구성하십시오.

채널을 색 공간과 함께 읽기

space는 ColorPlanes의 채널 좌표계를 ColorSpace 값으로 반환합니다. 이 객체는 세 채널을 가지며 해당 채널의 뜻은 HSV인지 Lab인지에 따라 다릅니다. space는 색 성분 영상이 아니고 세 채널의 숫자를 어떤 좌표계로 해석해야 하는지 알려 주는 값입니다.

예를 들어 HSV의 세 성분은 색상·채도·명도이고 Lab의 세 성분은 L·a·b입니다. 두 번째 채널이 20이라는 숫자만 저장하면 어느 공간의 성분인지 구분할 수 없습니다. space를 먼저 확인한 뒤 필요한 채널을 인덱스로 취득하고, 공간에 맞는 값 범위와 단위를 사용하세요.

적용과 결과 확인

acquire_channel은 채널 영상의 별도 소유 공유를 반환하며 범위 밖 인덱스는 오류입니다. ColorPlanes와 취득한 ZImage의 수명은 구분합니다. 채널을 다시 RGB로 만들 때에도 원래 공간과 변환 계약을 사용하고, 서로 다른 공간의 값을 단순히 같은 채널 위치에 넣지 않아야 합니다.

같은 세 숫자를 다른 색 공간으로 잘못 해석하면 변환 결과도 달라집니다. 예를 들어 HSV에서 첫 성분은 색상각의 역할을 하지만 Lab에서 첫 성분은 명도 L입니다. 따라서 채널 순번 0만 보고 언제나 같은 물리량이라고 가정하면 안 됩니다. 변환 전후에는 입력 형식과 선택한 색 공간을 확인하고, 채널을 재결합할 때도 같은 공간에 속한 성분들을 사용해야 합니다. 취득한 채널은 독립 소유 영상으로 관리합니다. 예를 들어 HSV의 색상각과 Lab의 L을 같은 밝기 단위의 값으로 비교할 수 없습니다. 세 채널을 가져올 때는 범위 밖 인덱스의 오류를 처리하고, 각 채널의 크기와 원점이 같은 영상 위치를 가리키는지도 확인하세요.
