pub fn read_barcode(self, spec: BarcodeSpec) -> RecognitionResult<BarcodeQuery>

Plans barcode recognition using the existing recognition engine.

바코드 형식과 읽기 결과

Rust의 ImageQuery 호출은 이 처리를 실행 계획에 연결합니다. BarcodeSpec에서 허용 형식 플래그, 회전 시도와 최소 대비를 지정합니다. CODE128과 QR을 함께 허용하려면 해당 플래그를 결합합니다. 형식 선택은 영상의 바코드를 자동으로 모두 찾는다는 보장이 아니므로 입력 영역과 회전 조건을 확인해야 합니다.

계획을 실행해 얻은 결과의 해석에서는 결과의 status와 reasons, format, text, 원시 바이트 및 위치를 함께 읽습니다. NO_READ와 입력 오류는 서로 다른 상황입니다. contrast는 Gray8 (최댓값−최솟값)/255로 정규화한 대비이며 표준 검증기 품질 등급이나 판독 확률이 아닙니다.

이 호출은 Rust의 지연 쿼리 단계입니다. 빌더의 이동과 소유 관계를 확인하고 별도 분기가 필요하면 지원되는 clone을 사용합니다. execute 결과는 반환 타입의 소유 규칙에 따라 다룹니다.

계획부터 결과 확인까지

계획 생성과 실제 판독

read_barcode는 ImageQuery를 값으로 받아 소비하고 BarcodeSpec을 연결한 BarcodeQuery를 반환합니다. 이 시점에는 형식 비트와 최소 대비, 계획의 출력 크기를 검증하지만 바코드 픽셀을 디코딩하지 않습니다. 각각의 후속 계획이 필요하면 호출 전에 ImageQuery를 복제해 분기합니다. 계획 생성의 RecognitionResult에서 Err가 나왔는지 먼저 확인하고 성공한 BarcodeQuery의 execute를 호출합니다.

입력 영역과 대비

실행 단계에서 앞선 영상 쿼리를 평가한 뒤 보이는 Gray8 영상으로 바코드를 최대 하나 읽습니다. ROI를 쓴다면 필요한 코드와 주변 여백이 포함되는 영역을 선택하고 해당 영역의 범위와 영상 형식을 확인합니다. 판독점은 회전 보정을 되돌리고 영상 원점을 더한 좌표이므로 ROI 내부 좌표라고 가정하여 원점을 다시 더하지 않습니다.

설정값의 실제 의미

formats는 Code128, Code39, Ean13, QrCode, DataMatrix의 비트 선택이며 0이나 정의되지 않은 비트는 오류입니다. Code128은 1, QrCode는 8이므로 둘을 선택한 마스크는 9입니다. min_contrast는 유한한 0 이상 1 이하 값입니다. 가시 영역의 최소가 30, 최대가 183이면 대비는 153/255=0.6이고 임계값 0.7보다 낮으므로 디코딩 전에 저대비 거절 결과가 됩니다.

결과 읽기와 진단

execute는 RecognitionResult<QueryExecution<BarcodeRead>>를 반환합니다. Err는 실행 오류이며, Ok 안의 BarcodeRead도 status와 reasons를 확인해야 합니다. 코드 미발견이나 저대비는 정상 실행 결과의 판독 상태로 표현될 수 있습니다. format과 confidence는 Option이므로 값이 없는 경우를 처리하고, points는 백엔드가 반환한 위치로서 반드시 네 모서리를 뜻하지 않습니다. backend_raw_bytes는 백엔드 코드워드이며 일반적인 페이로드 바이트라고 가정하지 않습니다.

회전과 재시도

try_rotate가 참이면 명시적으로 네 방향을 시도하고 quarter_turns에 성공한 명시 회전 횟수를 남깁니다. 거짓이어도 백엔드 자체의 탐색이 회전된 코드를 읽을 수 있으므로 회전 인식을 완전히 끈다는 의미는 아닙니다. 판독이 안 되면 먼저 영역과 코드 형식, 대비와 초점을 확인하고, 추가 회전 시도 여부를 바꾸어 같은 입력으로 결과 상태를 비교합니다.
