pub fn execute(&self) -> RecognitionResult<QueryExecution<RecognitionResult>>

Executes and preserves the actual variant, errors and captures.

실행과 결과

일반 인식 계획을 실행하고 실제 RecognitionResult 변형을 QueryExecution으로 반환합니다. 캡처와 인식 오류가 보존됩니다.

바코드와 OCR 등 결과 종류를 임의로 가정하지 말고 반환된 실제 변형을 확인한 뒤 해당 결과를 읽으십시오. 오류는 빈 성공 결과와 구분해야 합니다.

실제 인식 결과의 분기

RecognitionQuery.execute는 지연 인식 계획을 실행해 RecognitionResult<QueryExecution<RecognitionResult>>를 반환합니다. 안쪽 결과의 실제 변형과 바깥 오류를 구분해야 합니다. 쿼리의 종류가 바코드인지 OCR인지 추측해 결과를 임의로 한 형식으로 읽지 않습니다.

실행이 오류를 반환하는 경우와 실행에 성공했으나 판독 내용이 없는 경우는 서로 다릅니다. 성공한 QueryExecution에서 실제 RecognitionResult 변형을 확인하고 그 형식의 상태, 내용과 위치를 읽습니다. 캡처는 해당 실행의 이름 붙은 영상으로 별도 조회합니다.

항목확인할 내용
계획실행 전의 RecognitionQuery
바깥 결과인식 엔진 오류 또는 실행 객체
안쪽 결과실제 RecognitionResult 변형
캡처실행에 보존된 이름 붙인 영상
빈 판독성공 결과 안의 상태로 구분
좌표입력 ROI와 위치 기준 확인

중간 캡처와 최종 판독을 동일한 입력 ROI 기준에서 비교하면 전처리나 영역 선택의 영향을 진단할 수 있습니다. 실행 결과와 얻은 영상의 소유 관계를 시그니처에 맞게 관리하고, 실행 성공을 문자나 바코드의 정확한 판독으로 자동 간주하지 않습니다.

적용과 판독을 더 살펴보기

인식 쿼리에 앞서 어떤 이미지 전처리와 ROI가 연결되었는지 확인합니다. 같은 바코드라도 대비 조정이나 회전, 잘림이 달라지면 판독 단계의 입력과 결과가 달라질 수 있습니다. 캡처를 지정했다면 그 이름으로 실행 중간의 영상을 얻어 최종 인식 위치와 비교할 수 있습니다. 반환된 인식 변형마다 제공하는 내용과 위치 필드가 다를 수 있으므로 먼저 변형을 확인한 다음 해당 계약을 사용합니다. 바깥 RecognitionResult의 오류는 계획이 성공해 빈 문자열이 반환된 경우와 다릅니다. 오류 원인과 판독 상태를 합쳐 하나의 빈 결과로 저장하면 문제를 진단하기 어렵습니다.
