공유된 취소 플래그

cancel은 공유된 일회성 취소 상태를 true로 설정합니다. 복제한 토큰들도 같은 상태를 관찰하므로 이 호출은 한 복제본의 별도 상태만 바꾸는 것이 아닙니다. 취소 요청은 결과 영상을 만들지 않으며 이미 반환된 결과를 소급해 바꾸지 않습니다.

예를 들어 토큰 T를 복제해 T2를 제어형 검사에 전달한 뒤 T.cancel()을 호출하면 T2도 같은 취소 상태를 관찰합니다. 실행이 언제 멈추는지는 검사 코드가 협조적으로 상태를 확인하는 시점에 달려 있습니다. cancel의 반환만으로 네이티브 작업이 이미 정리되었다고 가정하지 말고 실행의 종료 결과를 확인하세요.

사용과 결과 판독

취소되지 않은 상태로 새 실행을 시작해야 한다면 새 토큰을 생성합니다. 기존 토큰의 clone은 독립된 초기화 상태가 아니라 같은 취소 플래그를 공유합니다. 작업의 성공, 취소 또는 시간 제한 오류는 별도로 처리하고, 취소 요청과 토큰 값의 수명 종료를 혼동하지 않습니다.
