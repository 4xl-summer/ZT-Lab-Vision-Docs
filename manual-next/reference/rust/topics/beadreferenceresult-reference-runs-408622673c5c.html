pub fn reference_runs(&self) -> &[BeadDefectRun]

Returns contiguous reference failure runs.

연속 위반 구간

연속된 기준 위반 구간의 BeadDefectRun 슬라이스를 반환합니다. 구간 개수와 위반한 개별 탐침의 수는 다를 수 있으므로 두 통계를 혼동하지 않습니다.

참조 또는 슬라이스를 반환하는 항목은 BeadReferenceResult의 수명에 묶입니다. 결과를 오래 보관해야 하면 필요한 값을 소유 자료로 복사합니다.

입력과 결과 확인

BeadReferenceResult::reference_runs는 연속된 기준 실패 구간의 BeadDefectRun 슬라이스를 결과에서 빌립니다. 슬라이스의 수는 구간 개수이며 실패한 탐침 개수와 반드시 같지 않습니다. 빌린 참조는 결과 객체보다 오래 사용할 수 없습니다.

구간의 첫째와 마지막 탐침 인덱스는 포함되는 경계입니다. 예를 들어 한 구간이 2부터 4라면 탐침 2, 3, 4의 세 위치를 나타내지만 반환 구간 수는 하나입니다. 원래 경로의 탐침 순서와 사유를 함께 연결해야 실제 위치를 찾을 수 있습니다.

참조 결과를 정리한 뒤에도 진단이 필요하다면 필요한 구간 값을 소유 자료로 복사하십시오. 비드 기준 위반 구간과 전체 통과 여부는 다른 수준의 정보이므로 한쪽만 보고 다른 쪽을 추정하지 않습니다. ROI 좌표 및 사용한 기준 설정도 결과와 함께 기록합니다.

구간 배열이 비어 있으면 보고된 연속 기준 위반 구간이 없다는 의미이며 개별 탐침의 모든 측정값을 이 슬라이스만으로 복원할 수는 없습니다. 원래 경로를 따라 각 탐침의 상태나 폭 차이가 필요한 경우 해당 진단도 별도로 읽어야 합니다. 예시 구간 2~4의 세 탐침에 대해 하나의 구간이 기록되는 점을 생각하면 구간 수와 실패 탐침 수를 구분하기 쉽습니다. 결과의 수명 안에서 값을 읽거나 필요한 항목을 복사하십시오.

구간의 first와 last를 이용해 원래 탐침 경로의 해당 위치를 찾아보면 연속 위반이 어느 부분에서 발생했는지 시각화할 수 있습니다. flags는 구간의 실패 사유를 함께 보존하는 데 사용합니다.

구간마다 사유 비트와 시작·끝을 함께 저장하면 서로 떨어진 위반을 하나의 긴 결함으로 혼동하지 않습니다. 탐침 순서가 바뀌면 같은 인덱스가 다른 위치를 가리킬 수 있습니다.
