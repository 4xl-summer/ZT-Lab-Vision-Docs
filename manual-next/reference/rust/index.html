Rust 공개 API 색인

Rust 실제 선언에서 클래스·메서드·프로퍼티·필드·열거값을 찾습니다.

이 색인을 실제 코드에 연결하기

소스 모듈과 공개 경로

Rust 색인은 고정 SDK에서 기본 full 구성으로 생성한 rustdoc 선언 465개를 기준으로 합니다. 소스에서 타입이 정의된 모듈과 사용자가 import할 공개 경로는 재수출 때문에 다를 수 있습니다. 따라서 소스 파일명만 보고 import 경로를 만들지 말고 타입 페이지의 공개 선언을 확인하세요. 같은 타입의 메서드가 구현 모듈별 설명에 나뉘어 나타나더라도 객체가 별개로 복제된다는 뜻은 아닙니다. 전체 기능 수는 선언 수와 따로 판단해야 합니다.

빌림과 이동을 호출 순서에 반영

메서드 선언의 수신자와 인자에서 빌림인지 소유권 이동인지 먼저 읽습니다. 참조를 받는 호출은 해당 참조의 유효 기간을 유지해야 하고, 소유권을 소비하는 호출은 이후 같은 변수를 다시 사용하는 방식이 달라집니다. 반환값이 새 소유 객체인지 값인지도 확인하세요. 영상 공유와 ROI는 픽셀 저장 공간의 관계를 이해한 뒤 사용하고, 독립된 픽셀 데이터가 필요할 때는 문서에서 보장하는 복사 동작을 선택합니다. 소유권 검사는 좌표계나 픽셀 포맷의 적합성까지 대신 확인해 주지 않습니다.

오류와 기능 구성을 함께 확인

Result를 반환하는 호출은 성공값의 사용과 실패 경로를 모두 코드에 포함합니다. 영상 크기와 포맷, 옵션 범위가 맞지 않는 문제와 파일 또는 모델을 열지 못하는 문제는 조치가 다르므로 하나의 기본 결과로 덮어쓰지 마세요. 이 색인의 확인 범위는 명시된 feature 구성입니다. 다른 feature 조합에서 같은 선언을 사용할 수 있는지 또는 추가 의존성이 필요한지는 해당 구성의 빌드에서 확인해야 합니다. 저수준 옵션을 쓰는 예제는 facade 외에 zvision-ops를 명시적으로 의존하는 경우도 있습니다.

표준 트레이트와 SDK 동작

rustdoc에는 SDK 고유 메서드뿐 아니라 트레이트 구현과 표준 blanket 구현이 표시됩니다. 이들은 타입을 언어 안에서 사용하는 데 필요한 계약이며 모두 별도의 영상 알고리즘은 아닙니다. 처리 목적을 찾을 때는 고유 함수와 연관 함수, 모델 또는 Query의 실행 메서드부터 읽고 표준 변환은 그다음 확인하세요. 예제의 Cargo 의존성과 버전을 유지해 합성 입력을 재현한 뒤 기능을 추가하면 빌드 구성 문제와 수치 알고리즘 문제를 분리해서 검토할 수 있습니다.

확인 범위와 사용 방법

이 색인은 고정 SDK에서 확인한 선언으로 연결합니다. 타입별 페이지에서 파라미터와 필드, 상속 멤버, 반환과 오류를 확인하세요. 주석과 실제 구현으로 확인하지 못한 계약은 미확인으로 구분하며, 선언 수를 독립 기능 수나 실행 성공률로 세지 않습니다.
