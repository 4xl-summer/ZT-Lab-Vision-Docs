      사용과 결과 해석

      서로 다른 두 소스의 프레임 시간차를 공통 호스트 시간 기준으로 비교합니다. 각 FrameInfo와 그 소스에 맞는 ClockMap을 짝지어 전달하며 허용값은 나노초입니다. 두 소스 식별자는 0이 아니고 서로 달라야 합니다. 같은 clock domain이라는 이름만으로 시계가 동기화되었다고 가정하지 않고, 각 맵의 기준 시각과 변환 설정을 명시해야 합니다.

      각 장치 tick을 맵에 따라 나노초로 변환한 뒤 두 시각의 절대 차이를 구합니다. 판정에는 이 차이뿐 아니라 두 맵의 불확도를 더한 상한을 사용합니다. 예를 들어 시각차가 5 ns이고 두 불확도의 합이 3 ns라면 상한은 8 ns입니다. 허용값이 8 ns이면 경계를 포함해 통과하고, 7 ns이면 실패합니다.

      결과에는 변환된 두 시각, 절대 skew, 불확도 합과 허용 여부가 담깁니다. 시계 맵이나 소스의 불일치, 변환 과정의 범위 초과가 있으면 오류가 전달됩니다. 이 함수가 하드웨어 트리거를 동기화하거나 시계 보정을 수행하는 것은 아닙니다. 현장에서 수집한 맵의 품질과 불확도는 호출자가 별도 확인해야 합니다.
