연결 영역 분석에서 확인하는 개수, 면적과 중심은 해당 실행에서 복사된 처리 결과 값입니다. 값을 보관하는 일과 중간 마스크 영상 데이터를 계속 보관하는 일은 별개의 결정입니다. 마스크를 더 이상 사용하지 않는다면 그 영상 데이터의 소유 자원을 정리하고, 이후에도 필요한 값은 독립 스냅샷으로 보관할 수 있습니다. Query 실행에서 캡처 영상 데이터를 획득했다면 그 영상 데이터 역시 별도 소유권을 갖습니다.

후보가 없는 경우에는 첫 번째 항목을 무조건 읽지 말고 먼저 목록의 개수를 살펴봅니다. 잘못된 픽셀 형식 또는 이미 해제된 객체에서의 호출은 정상적인 빈 처리 결과가 아닙니다. 반복 분석에서는 매 프레임의 입력, 처리 처리 결과, 실행과 획득한 캡처를 각 언어의 수명 규칙에 따라 정리해야 실제 필요한 처리 결과만 남길 수 있습니다.

영상 데이터가 필요한 표시 작업과 숫자만 필요한 기록 작업을 구분하면 어떤 객체를 얼마나 오래 보관할지 결정하기 쉽습니다.

분석 값만 이력으로 남긴다면 값 스냅샷에 프레임과 사용한 조건을 함께 연결할 수 있습니다. 나중에 영상 데이터를 다시 표시하려면 이미지를 별도로 보관해야 합니다. 반환 목록이 비어 있는 상황도 유효한 분석 처리 결과로 표현할 수 있어야 합니다.

마스크와 결과를 보관하는 방법

연결 요소 분석이 끝난 뒤 기록에 필요한 것이 후보 수와 면적뿐인지, 나중에 다시 보여 줄 이진 마스크까지 필요한지에 따라 보관할 객체가 달라집니다. 후보에서 복사한 값은 한 실행의 스냅샷으로 기록할 수 있지만, 마스크는 영상 객체이므로 화면이나 후속 처리가 끝날 때까지 자신의 소유권을 유지해야 합니다. 둘 다 필요하다면 같은 프레임 식별자와 조건에 연결합니다.

예제에서 원본 [0,5,5]의 Threshold 결과 [0,255,255]는 별도 소유 영상입니다. 분석이 완료되었다는 이유만으로 결과를 표시할 다른 작업이 영상 사용을 끝냈다고 가정하지 않습니다. 반대로 필요한 값이 이미 독립 스냅샷으로 복사되었다면 단지 숫자를 보관하기 위해 원본 영상 핸들을 계속 열어 둘 필요는 없습니다. 실제 반환 타입의 수명 계약을 먼저 확인해야 합니다.

지연 Query에서는 실행 결과가 중간 캡처를 보유하고, 획득한 캡처 영상은 별도 소유권을 갖습니다. 실행을 닫기 전에 필요한 캡처를 얻은 뒤 각 객체를 정리합니다. 이미 닫힌 실행에서 다시 이미지를 획득하려는 오류와, 전경이 없어 후보 목록이 비어 있는 정상 결과를 구분합니다.
