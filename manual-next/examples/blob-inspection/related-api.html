관련 API

Blob을 얻는 흐름에서는 먼저 입력 영상 데이터에 Threshold를 적용해 Gray8 전경 마스크를 만듭니다. 이어서 FindBlobs 또는 해당 언어의 Query 종료 연산에 연결 방식을 지정해 후보를 계산합니다. 임계값은 전경을 결정하고 연결성은 이미 정해진 전경 픽셀을 묶는 규칙이므로, 원하는 개수가 나오지 않을 때는 어느 단계에서 차이가 생겼는지 나누어 살펴봅니다.

처리 결과의 Blob 값에서 면적과 경계, 중심을 읽을 수 있습니다. 이 값은 현재 뷰의 로컬 픽셀 좌표와 픽셀 수로 해석하며 부모 영상 데이터가나 물리 좌표와는 별도입니다. 입력과 임계값 처리 결과 영상 데이터는 소유 객체이고 값으로 복사된 후보 목록의 수명은 따로 확인해야 합니다. 관련 API 표에서 직접 호출과 지연 Query의 반환 형태를 비교하면 다음 처리에 필요한 타입을 선택할 수 있습니다.

호출마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

후보 개수만 기록하면 영역의 크기나 위치 정보가 사라집니다. 사용 목적이 위치 표시인지 크기 판정인지에 따라 해당 처리 결과 멤버를 함께 읽고, 선택한 연결성과 원점도 분석 기록에 남깁니다.

이 사례에서 필요한 API의 순서

먼저 ZImage 생성에 3×1 Gray8 밝기 [0,5,5]를 전달합니다. Threshold에 1을 지정하면 새 마스크 [0,255,255]가 됩니다. 원래 영상의 5는 밝기 값이고 마스크의 255는 전경을 표시하는 값입니다. 같은 숫자로 보이지 않더라도 분석에 넘기는 객체가 어느 단계의 출력인지 분명히 해야 합니다.

FindBlobs 또는 ImageQuery의 연결 요소 종료 연산은 마스크의 비제로 픽셀을 묶습니다. 이 사례의 4연결은 두 수평 전경을 하나의 후보로 보고 Area 2, Bounds (1,0,2,1), Centroid (1.5,0)을 계산합니다. 마스크에서 후보를 만드는 단계에는 연결 규칙이 필요하며 임계값 자체가 영역 개수를 반환하지 않습니다.

입력과 Threshold 반환은 각각 소유 영상입니다. Query로 실행한다면 계획과 실행, 출력·캡처 영상의 수명을 추가로 구분해야 합니다. 값으로 읽은 후보는 해당 실행의 로컬 좌표로 해석하고, ROI 원본에 표시할 때는 현재 뷰의 origin을 확인합니다. 빈 목록과 유효하지 않은 형식으로 인한 오류도 서로 다른 경로로 처리합니다.
