관련 API

원리와 입력

예제에 공통으로 등장하는 ZImage는 영상 생성과 입력 형식, ROI와 결과 읽기의 기준점입니다. 임계값은 입력을 비교해 새 Gray8 마스크를 만들고, 매칭 모델은 템플릿을 학습해 검색 결과 값을 돌려줍니다. 같은 이름의 결과라도 영상 핸들과 독립 스냅샷은 해제 방식이 다르므로 예제에 표시된 반환 타입을 먼저 살펴보세요.

적용과 확인

Query 예제는 실행 객체에서 출력과 캡처를 획득하는 수명을 보여 줍니다. 공간 예제에서는 DepthMap과 PointCloud의 단위, 원점 및 결측값도 중요합니다. 각 API를 실제 호출 순서에 맞게 읽고 기대값이 왜 나오는지 검산한 뒤 응용 데이터에 적용하세요. 기능의 존재만으로 모든 픽셀 형식과 하드웨어 조합의 지원을 가정해서는 안 됩니다.

예제를 연결하는 API 역할

ZImage는 입력 영상의 크기와 형식, 원점을 가진 소유 객체입니다. Gray8 배열로 영상을 만들고 Threshold로 전경 마스크를 얻는 예제는 입력 검증, 연산, 출력 읽기라는 기본 흐름을 보여 줍니다. 원본 [9,10,11]에 임계값 10을 적용하면 마스크 [0,255,255]를 기대하며, 이 배열과 영상 핸들은 서로 다른 형태의 결과입니다.

Roi와 Share는 별도 영상 객체를 돌려주지만 저장소를 공유할 수 있습니다. 원본을 해제한 후 이미 획득한 공유나 ROI가 자신의 수명을 갖는 경우와 닫힌 원본에서 새 결과를 얻으려는 경우는 다릅니다. Query는 작업 계획을 실행과 구분하고, 획득한 출력 또는 캡처 영상은 별도의 소유권으로 관리합니다. 관리형 가변 빌더의 독립 분기에는 Clone이 필요합니다.

매칭에서는 MatchModel과 MatchSpec이 학습과 검색 조건을 나누어 담당하며, 결과의 Best가 없을 수도 있습니다. 차분 검사에서는 정렬 발견 여부와 유효 마스크를 먼저 살펴봅니다. API 표에서 언어별 정확한 이름과 반환 타입을 확인하고 실행한 사례의 검증 범위는 해당 기록에서 따로 확인하세요.

서로 다른 API의 결과가 모두 화면에 숫자로 표시되어도 위치, 픽셀 수와 점수는 단위가 다릅니다. 후속 계산에 넘기기 전에 결과 필드의 좌표계와 반환 타입을 먼저 읽어야 합니다.
