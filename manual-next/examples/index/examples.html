원리와 입력

예제는 해결할 문제와 필요한 입력 유형을 기준으로 선택합니다. 첫 이미지 처리에서는 Gray8 한 행 [9,10,11]을 사용해 임계값 10에서 [0,255,255]를 기대합니다. ROI 예제는 부분 영역의 로컬 좌표와 원본 origin을 함께 확인할 때 적합하고, NCC 예제는 템플릿 학습과 검색 결과를 구분하는 흐름을 보여 줍니다.

적용과 확인

예제의 일부 코드가 준비된 영상이나 모델을 전제한다면 호출 발췌인지 전체 프로그램인지 먼저 확인하세요. 완전한 실행을 원하면 다운로드 프로젝트와 환경 안내에서 입력 생성부터 실행 순서까지 살펴볼 수 있습니다. 합성 결과가 예상과 다르면 입력 크기, 형식, 값과 실행한 SDK 버전을 기록합니다. 검사 기준이나 실제 설비 성능은 합성 예제 하나만으로 정하지 않습니다.

목적에 맞는 사례 선택

첫 예제는 영상 생성과 임계값을 확인하는 데 적합합니다. 작은 Gray8 배열은 입력과 출력의 차이를 손으로 계산할 수 있어, 런타임 로드가 끝난 뒤 데이터 형식과 처리 순서가 맞는지 살펴보기 좋습니다. 그다음 ROI 예제를 선택하면 부분 영상의 크기와 원점, 현재 뷰에서의 좌표를 확인할 수 있습니다. 전체 영상 결과와 ROI 결과를 같은 좌표로 바로 해석하지 않는 것이 핵심입니다.

연결 영역에 관심이 있다면 이진 마스크에서 전경을 어떻게 묶는지와 면적의 픽셀 단위를 보여 주는 Blob 사례를 선택합니다. 위치를 찾아야 한다면 NCC 예제에서 기준 무늬, 검색 조건, 발견된 위치와 빈 결과를 함께 살펴봅니다. 비슷한 명칭이라도 Threshold는 마스크를 만들고 FindBlobs는 전경을 연결하며 매칭은 학습된 기준을 찾는 별도 단계입니다.

각 예제의 입력은 코드와 사례 설명을 함께 읽고, 결과가 소유 영상인지 복사된 값인지 확인합니다. 합성 예제의 예상값이 자신의 실제 데이터 기준으로 자동 적용되는 것은 아닙니다. 실물 검사 전에 사용하는 형식과 좌표, 연결성 및 허용치를 자신의 입력에서 별도로 검토합니다.

예제의 작은 입력과 실제 영상의 차이를 기록하면 첫 성공 이후 무엇을 추가로 확인해야 할지 결정할 수 있습니다. 기준 이미지를 바꾸거나 ROI를 지정할 때는 새 입력에 맞는 기대 결과도 다시 정합니다.
