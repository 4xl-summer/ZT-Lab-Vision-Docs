저장과 복원

모델의 save/Save는 버전 1 모델 파일을 쓰고 기존 경로를 덮어씁니다. load/Load는 별도 소유 모델을 만듭니다. 파일이 없거나 손상·지원하지 않는 형식이면 로드 오류를 처리하세요. 검색 설정과 검색 결과는 모델 파일에 포함된다고 가정하지 말고 애플리케이션 설정으로 관리하세요. Rust 저장과 로드는 이미지 I/O 기능이 필요합니다.

적용 상황과 원리

합성 배열로 학습한 모델도 파일에 저장하고 나중에 복원해 같은 예제를 다시 실행할 수 있습니다. 저장 호출은 기존 파일을 덮어쓰므로 실험별 파일을 보관하려면 경로를 구분합니다. 복원 모델은 원본 모델과 다른 소유 객체이며 각 언어의 수명 규칙에 따라 정리합니다. Rust에서는 모델 파일 입출력에 해당 기능이 활성화되어 있어야 합니다.

결과를 읽는 방법

복원 전후를 비교할 때는 같은 템플릿의 크기와 선택 표본 수가 유지되는지 먼저 확인합니다. 그다음 같은 영상과 별도로 준비한 검색 설정을 전달하고, 결과 개수와 기준점 2,0.5 및 1에 가까운 점수를 비교합니다. 검색 설정이나 입력 영상이 달라지면 모델만 같아도 결과가 달라질 수 있습니다. 파일이 없거나 손상되어 로드가 실패한 경우는 검색이 성공했지만 후보가 비어 있는 상태가 아닙니다.

추가 점검

복원 직후 같은 예제 검색에서 위치가 다르다면 모델 파일뿐 아니라 검색 영상의 원점과 각도·배율 설정을 먼저 비교합니다. 파일 자체가 잘못되었을 때 발생하는 읽기 오류는 유효한 모델이 다른 조건에서 반환한 빈 결과와 구분합니다. 파일을 바꿔 끼운 후 모델 정보와 기준 사례가 일치하는지 확인합니다. 저장 성공 직후 읽기 권한이 보장된다고 가정하지 말고 복원 오류를 처리합니다.
