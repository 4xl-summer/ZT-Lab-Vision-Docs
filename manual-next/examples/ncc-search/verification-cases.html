적용 상황과 원리

예제의 Rust, C#, Python 코드 블록은 각각 기존 검증 기록에 연결되어 있으며 Linux x64 환경에서 종료 코드 0으로 실행되었습니다. 각 블록은 결과가 있을 때 값을 출력하지만 자체 단언문이 없으므로 실행 성공 기록만으로 출력 비교까지 자동 수행했다고 간주하지 않습니다. 각 언어 블록의 원문은 이 페이지에서 그대로 보존됩니다.

결과를 읽는 방법

별도 ncc-literal 통합 사례는 세 언어에서 기준점 2,0.5와 선택 표본 수 6을 확인합니다. 관리 언어 사례에는 마스크 선택 4표본과 일정 영상의 빈 결과가 포함되고, 저장·복원과 결과 수명 확인도 별도의 단계로 다룹니다. 합성 입력의 기대값은 SDK 갱신 시 회귀 확인에 유용하지만 실장비 조명, 속도, 양산 판정 정확도의 근거는 아닙니다.

추가 점검

동일 입력을 세 언어로 실행하는 이유는 언어별 소유권과 결과 표현이 달라도 좌표 및 표본 수의 기대가 같은지 확인하기 위해서입니다. 그러나 결과를 출력한 코드의 종료 성공과 값 비교를 수행한 통합 사례는 검증 범위가 다르므로 각각 기록을 확인해야 합니다. 이 사례의 패턴은 작아서 기준점과 표본 수를 직접 계산할 수 있습니다. 입력 배열을 보존하면 언어별 결과를 같은 좌표 기준으로 비교할 수 있습니다.
