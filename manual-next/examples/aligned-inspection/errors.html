실패와 대안

잘못된 옵션, 빈 포함 마스크, 크기·원점 불일치, 비유한 영상 값, 상수 NCC 학습 ROI는 오류입니다. 정렬 실패는 Found를 먼저 확인하고 재촬영 또는 검사 불가로 처리하세요. 원본의 차분만 필요하면 정렬을 생략하되 두 영상의 같은 크기와 원점 및 마스크 기하를 보장해야 합니다. 실제 생산 기준과 조명 안정성은 별도 검증이 필요합니다.

정렬이 실패한 경우와 정렬 호출 자체가 오류인 경우는 다르게 처리합니다. 학습 무늬에 맞는 위치가 없거나 최소 유효 비율을 채우지 못하면 발견되지 않은 계산 결과가 돌아올 수 있습니다. 이때 차분을 생략하고 재촬영 또는 검사 불가 상태로 넘겨야 합니다. 발견되지 않은 계산 결과에서 정렬 이미지가나 유효 마스크를 바로 꺼내려고 하면 오류가 발생합니다.

반대로 ROI가 비어 있거나 입력 형식과 원점이 맞지 않는 경우, 잘못된 설정 또는 비유한 밝기 값은 입력 오류로 조사합니다. 포함 마스크가 모든 픽셀을 제외해도 비교할 집단이 없어 정상 합격으로 볼 수 없습니다. 실패 지점을 기록할 때에는 원본 이미지의 형식과 ROI, 검색 범위, 유효 픽셀 수를 함께 남기고, 이미 소유한 이미지와 계산 결과는 예외가 난 경로에서도 정리합니다.

정렬하지 않은 이미지를 원본 기준에 바로 비교하면 이동 때문에 넓은 차이가 발생할 수 있습니다. 재촬영 여부는 발견 상태와 입력 조건을 확인한 다음 결정합니다.

다섯 입력의 실패를 비교

normal, moved, lighting과 spot은 먼저 동일한 기준 무늬를 찾을 수 있도록 구성된 사례입니다. 이들 가운데 spot은 무늬가 아니라 유효 격자의 별도 위치를 바꾸므로 정렬 성공 뒤 결함 후보가 한 개가 되어야 합니다. 입력 배열의 점을 다른 위치에 쓰거나 학습 ROI를 바꾸었다면 동일한 NCC 점수와 후보 위치를 전제할 수 없습니다.

missing은 검사 입력을 0으로 채워 기준 무늬를 찾지 못하도록 한 사례입니다. Found=false이면 결과의 자식 영상 Aligned와 ValidMask를 요청하지 않습니다. 결과를 정상적으로 해제한 뒤 검사 불가 메시지를 남기고 다음 입력으로 넘어갑니다. 이를 성공한 차분의 빈 후보 배열과 같은 상태로 만들지 않는 것이 중요합니다.

정렬은 발견되었지만 기대한 점수가 나오지 않으면 보정 방식과 마스크를 살펴봅니다. 이동 점 사례의 25개 유효 픽셀에 OFFSET을 적용하면 bias −4, 점의 잔차 96, threshold 10에서 점수 9.6입니다. 포함 픽셀 수가 달라지거나 threshold를 바꾸면 평균과 점수가 달라지므로 새 조건으로 다시 계산해야 합니다.

사례기대 상태차이가 나면
normal / moved후보 0무늬·검색 위치 확인
lightingOFFSET 후 후보 0보정과 전체 밝기 확인
spot후보 1점 위치·유효 영역 확인
missing정렬 미발견빈 후보와 분리
