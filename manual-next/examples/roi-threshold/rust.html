Rust · ROI 기반 임계값 검사

Rust의 사용 조건과 결과 해석을 설명합니다.

상위 목차로 돌아가기

Rust

Rust
use zvision::{ZImage, ZRect};
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let image = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let roi = image.roi(ZRect::new(1, 0, 2, 1))?;
    let result = roi.threshold(11.0)?;
    assert_eq!(result.to_packed_vec()?, vec![0, 255]);
    Ok(())
}

Rust · 핵심 동작

Rust 예제는 ZRect로 부모 영상의 관심 영역을 지정하고 그 결과에 threshold를 적용합니다. 원본은 [9,10,11], ROI는 x=1부터 폭 2이므로 비교되는 값은 [10,11]입니다. 임계값 11은 같은 값을 포함하므로 출력은 [0,255]입니다. 코드의 두 원소가 전체 영상의 처음 두 픽셀이 아니라는 점이 좌표 해석의 출발점입니다.

Rust · 입력과 결과

ROI 핸들은 원본 저장소를 공유하지만 결과 마스크는 별도로 소유하는 새 영상입니다. Rust에서 입력을 빌려 임계값을 적용하고 결과를 돌려주므로 마스크를 얻기 위해 원본 픽셀을 직접 수정할 필요가 없습니다. to_packed_vec()은 보이는 Gray8 픽셀을 행 패딩 없이 독립 벡터로 복사합니다.

Rust · 좌표와 소유권

마스크가 보존하는 원점은 (1,0)이고, 로컬 두 번째 픽셀은 원본에서 x=2입니다. 이 위치를 후속 결과와 맞출 때 로컬과 전역 중 어느 좌표인지 명시하십시오. 코드의 assert_eq!는 지정 배열과 계산 결과가 다른 경우를 찾아내는 검사이며, 실제 장비의 정확도나 처리 시간을 측정하지 않습니다.

Rust · 오류와 판단

잘못된 사각형이나 영상 형식은 결과가 없는 성공이 아니라 오류로 전파됩니다. 함수가 ZResult를 반환하므로 ?는 실패를 호출자에게 넘깁니다. 원본을 그대로 남겨야 하는 검사에서는 ROI 공유와 결과 복사의 차이를 명확히 확인하는 것이 좋습니다.
