관련 API

정렬을 사용할 때는 먼저 ZImage의 AlignReference와 AlignmentSpec으로 기준 ROI와 검색 조건을 지정합니다. 분석 결과의 Found를 확인한 뒤 Aligned와 ValidMask를 획득하고, InspectionDifference에 기준과 유효 마스크를 넘겨 선택된 화소의 잔차와 점수를 계산합니다. 정렬이 필요 없는 고정 입력이라도 비교할 이미지의 크기와 원점이 같은지 확인해야 합니다.

차분 분석 결과의 Mask와 Score는 SurfaceDefects의 두 입력이고, 후보 분석 결과의 Judge는 개수·면적·허용 영역을 적용합니다. DifferenceInfo는 보정 계수와 점수 통계를, DecisionInfo는 통과 여부와 사유를 제공하므로 서로의 값으로 대체하지 않습니다. 분석 결과 객체와 획득 이미지는 각각 해제합니다. 구체적인 타입과 해당 멤버는 이 페이지의 관련 API 표에서 언어별로 선택할 수 있습니다.

호출마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

정렬 후 유효 표본 수는 위치를 맞춘 후 비교 가능한 영역을 나타내고, 후보 면적은 그 영역 안에서 검출된 전경의 크기를 나타냅니다. 두 수치는 서로 다른 목적으로 사용되므로 관련 API의 반환 타입과 단위를 함께 살펴봅니다.

점 결함을 만드는 호출 관계

AlignReference는 기준 무늬를 검사 영상에서 찾고 검사 입력을 기준 격자에 맞춥니다. 이 합성 예제에서 기준 무늬는 (1,1), 이동 입력의 무늬는 (2,2)에서 시작합니다. Found가 참이고 유효 25개라는 전제가 맞을 때 Aligned와 ValidMask를 다음 차분의 입력으로 사용할 수 있습니다. 정렬이 발견되지 않았으면 결함 수를 대신 0으로 설정하지 않습니다.

InspectionDifference는 이 예제의 DifferenceSpec(10, Offset)으로 보정 잔차와 점수를 만듭니다. 25개 표본 중 한 점의 차이가 100이면 평균 보정 bias는 −4이고 그 점의 잔차는 96입니다. 점수 9.6은 1 이상이므로 Mask의 해당 픽셀은 전경입니다. 마스크와 Score를 SurfaceDefects에 넘기는 이유는 위치뿐 아니라 그 후보의 점수 통계도 측정하기 위해서입니다.

최소 면적 1인 DefectSpec은 한 픽셀을 후보로 유지합니다. DecisionSpec에서 개수와 면적 상한을 0으로 두면 이 후보는 허용 범위를 초과합니다. AlignmentResult, DifferenceResult, 후보와 판정 결과, 각각 얻은 영상은 별도로 해제합니다. 수명과 상태를 먼저 확인한 다음 이 수치를 다른 입력에 맞게 다시 계산해야 합니다.
