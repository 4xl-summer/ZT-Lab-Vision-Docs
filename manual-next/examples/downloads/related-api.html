원리와 입력

실행 프로젝트는 ZImage 생성과 임계값, ROI와 공유, 값 스냅샷 및 Query 캡처처럼 여러 공개 객체를 연결합니다. ROI에서는 로컬 위치와 origin을 기록하고, 모델 검색에서는 Best가 비어 있을 수 있는 결과와 실제 예외를 나누어 확인합니다. 영상을 반환하는 호출과 독립 값을 반환하는 호출의 수명도 서로 다릅니다.

적용과 확인

공간 사례의 DepthMap과 PointCloud는 길이 단위, 프레임과 결측값을 함께 다룹니다. AI 결과는 모델 입력 계약과 작업별 출력 타입을 확인한 뒤 읽어야 하며, ModbusTcp는 실제 전송을 수행하지만 예제 상대는 로컬 프로그램입니다. 코드와 기대값을 보기 전에 SDK 버전과 실행 경로를 맞추고, 소유 이미지·모델을 예제의 종료 범위에 따라 정리하세요.

실행 결과를 API와 연결하기

언어별 실행 프로젝트는 영상 생성에서 출력 읽기까지 여러 API를 함께 사용합니다. ZImage가 입력을 보유하고 Threshold나 ROI가 새 영상 객체를 반환하는 경우에는 각 객체의 형식과 수명을 확인합니다. ROI의 Origin과 로컬 좌표는 결과를 부모 영상에 표시할 때 중요하며, 배열 복사와 공유 영상은 저장소를 다루는 방식이 다릅니다.

매칭 예제에서는 학습에 사용할 기준과 MatchSpec 검색 조건을 분리하고, 반환된 MatchResult에서 매치가 없을 가능성도 처리합니다. 값 스냅샷으로 반환된 측정 결과와 독립적으로 해제할 영상 결과를 동일하게 관리하지 않습니다. Query에서는 실행과 캡처를 얻는 시점 및 각 반환 객체의 소유권을 읽습니다.

공간 예제의 DepthMap과 PointCloud는 픽셀뿐 아니라 길이 단위, 프레임과 결측값을 함께 해석합니다. AI 예제는 모델이 기대하는 입력과 작업별 출력 형식을 확인해야 합니다. ModbusTcp 사례가 네트워크 전송을 사용하더라도 제공된 상대가 로컬 루프백이라는 검증 범위는 그대로 유지됩니다.

출력을 다시 그리거나 후속 처리에 사용하려면 결과 이미지가 아직 살아 있는지 확인합니다. 숫자 결과만 기록할 때도 어떤 입력과 설정에서 나온 값인지 함께 보관해야 다른 실행의 수치와 혼동하지 않습니다.
