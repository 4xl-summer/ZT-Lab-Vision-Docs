동일한 결과를 재현하는 순서 · 실행 프로젝트 다운로드

동일한 결과를 재현하는 순서의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

동일한 결과를 재현하는 순서

  1. SDK 소스를 지정 리비전으로 준비하고 --locked로 Release 네이티브를 빌드합니다.
  2. 언어별 프로젝트를 풀고 README에 따라 SDK 경로와 네이티브 로더 환경을 설정합니다.
  3. AI 예제를 실행할 때는 모델 묶음을 함께 풀고 ZVISION_MANUAL_MODELS를 설정합니다.
  4. 프로그램이 끝까지 성공하고 JSON 결과가 출력되는지 확인합니다. 실패하면 최초 오류와 런타임·아키텍처·SDK 리비전을 함께 확인합니다.

Rust는 Cargo.lock을 유지하세요. 새 의존성을 자동 선택하면 SDK에서 검증하지 않은 RTen 버전을 선택할 수 있습니다. 관리형 래퍼와 네이티브를 서로 다른 SDK 빌드에서 섞지 마세요.

원리와 입력

재현의 첫 단계는 언어 프로젝트와 같은 SDK 리비전의 네이티브 라이브러리를 준비하는 것입니다. Rust에서는 제공된 잠금 파일과 locked 빌드를 유지하고, 관리형 소스 소비에서는 SDK 경로와 네이티브 로더 설정을 README대로 지정합니다. 설치 패키지를 확인할 때에는 반대로 소스 경로 설정이 패키지의 실제 로딩을 가리지 않는지 점검합니다.

적용과 확인

AI 사례를 포함한다면 모델 묶음을 풀고 ZVISION_MANUAL_MODELS를 해당 디렉터리로 지정합니다. 프로그램이 끝나면 JSON의 각 사례와 독립 기대값을 비교하고 실패했다면 가장 먼저 발생한 오류와 실행 환경을 기록하세요. 이후 숫자만 복사해 비교하면 이전 단계가 실행되지 않았다는 사실을 놓칠 수 있습니다. 실제 장치나 외부 생산 모델을 사용하지 않은 합성 검증이라는 범위도 함께 남깁니다.

동일 조건으로 다시 실행하기

재현을 시작할 때는 프로젝트가 참조하는 SDK 리비전, 언어 런타임과 네이티브 빌드가 서로 맞는지 확인합니다. Rust 예제의 잠금 파일은 검증된 의존성 해상도를 유지하는 데 사용되므로 임의로 새 조합을 선택하지 않도록 제공된 locked 절차를 따릅니다. 소스 소비와 패키지 소비 중 선택한 경로를 기록하면 같은 이름의 라이브러리 가운데 무엇을 사용했는지 추적하기 쉽습니다.

언어별 압축을 푼 뒤 README의 경로를 자신의 환경에 맞게 설정합니다. AI 모델을 사용하는 사례는 별도 모델 묶음을 준비하고 ZVISION_MANUAL_MODELS가 해당 위치를 가리키도록 구성합니다. 모든 예제가 모델을 필요로 하는 것은 아니므로 실패한 프로그램의 입력 요구사항을 먼저 확인하세요. 프로그램이 JSON을 출력하면 종료 상태와 함께 사례별 값을 보관합니다.

결과가 다르면 입력 배열과 옵션, 사용한 SDK 리비전 및 운영체제·아키텍처를 차례로 비교합니다. 기록된 실행은 특정 환경에 한정되며 Windows 절차의 예시가 Linux에서 기록된 성공을 Windows 성공으로 바꾸어 주지는 않습니다. 첫 오류를 보존한 뒤 해결하면 이후 단계의 오류와 구별하기 쉽습니다.
