원리와 입력

객체 중심 모델은 영상, 학습 모델, 실행 계획, 결과가 서로 다른 책임을 가진다는 점에서 시작합니다. 예를 들어 3×1 ZImage에 임계값을 주면 새 마스크 영상이 만들어집니다. 반면 MatchModel에 영상을 넣어 검색하면 매치 위치와 점수를 담은 값이 반환됩니다. 호출의 반환형을 보면 이후 무엇을 읽고 무엇을 닫을지 정할 수 있습니다.

적용과 확인

ImageQuery는 별도 실행 시점을 갖는 계획입니다. 중간 결과가 필요하면 capture를 지정하고 실행에서 해당 이미지를 취득합니다. C#과 Python의 빌더는 가변이므로 다른 조건으로 나눌 때 복제가 필요합니다. Rust의 값 이동과 관리형 using·with는 같은 철자로 치환할 수 없습니다. 객체 모델 상세 페이지에서 각 언어의 소유 표현을 확인한 뒤 실제 API의 형식과 실패 조건을 읽으세요.

읽기와 적용

실행 계획이 있다는 것은 계획을 구성하는 순간 이미 최종 결과가 계산됐다는 뜻이 아닙니다. 계획에 사용할 입력과 설정을 준비하고 실행을 얻은 다음 원하는 출력이나 캡처를 읽는 순서를 확인해야 합니다. 여러 조건의 분기가 필요하다면 해당 언어의 복제 또는 값 이동 규칙을 따라야 원하지 않는 설정 공유를 피할 수 있습니다. 성공한 실행의 출력 유형과 실패 분기도 별도로 검사합니다.
