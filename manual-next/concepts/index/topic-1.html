원리와 입력

ZVision의 기본 객체를 이해하면 연산 이름을 찾기 전에 데이터가 어떻게 이동하는지 판단할 수 있습니다. ZImage는 픽셀과 보이는 영역을 나타내며, 직접 처리의 반환은 새 영상일 수 있습니다. ROI는 영역을 선택하고 origin을 보유하며 Share는 같은 저장소의 별도 핸들을 얻습니다. 깊은 복사는 저장소를 분리하는 용도입니다.

적용과 확인

모델과 설정은 또 다른 역할입니다. MatchModel은 학습 상태를 보유하고 MatchSpec은 검색 범위를 지정합니다. MatchResult는 매치 값 스냅샷이므로 모델을 닫는 것과 결과를 읽는 일을 구분합니다. Query는 계획을 만든 다음 실행과 출력을 얻는 흐름입니다. 각 객체가 누구에게 반환되고 언제 정리되는지 확인하면 픽셀 오류와 수명 오류를 별도로 진단할 수 있습니다.

읽기와 적용

작업 흐름을 설계할 때 먼저 어떤 값이 원본을 참조하고 어떤 값이 독립적인지 표시해 보세요. 예를 들어 ROI는 원본의 부분 영역과 원점을 함께 표현하고, 복사된 픽셀 배열은 이후 원본 영상의 수명과 별개로 읽을 수 있습니다. 모델을 이용한 검색에서는 입력 영상, 학습 상태, 검색 설정과 결과 값이 서로 다른 책임을 가집니다. 필요한 결과만 장기 보관할 때 이 차이가 자원 정리 순서를 결정합니다.
