관련 API

원리와 입력

핵심 개념을 실제 호출로 연결하려면 ZImage의 생성과 ROI, Share, 깊은 복사부터 살펴보세요. ROI의 크기와 Origin은 이미지에서 볼 수 있는 범위와 원본 좌표를 연결합니다. Share는 저장소를 공유하는 별도 핸들이며 깊은 복사는 픽셀 저장소를 분리합니다. 어느 반환이 소유 객체인지 확인하고 각 언어의 방법으로 정리합니다.

적용과 확인

직접 Threshold는 새 영상, MatchModel.Find는 독립 매치 값, ImageQuery.Execute는 형식별 실행 결과를 제공합니다. 이 차이를 이해하면 같은 Result라는 단어만 보고 모두 같은 수명을 가정하는 실수를 줄일 수 있습니다. 픽셀 형식이나 기본값은 각 호출에 따릅니다. 상세 API 참조와 합성 입력의 기대 결과를 함께 비교한 다음 자신의 데이터 흐름을 설계하세요.

읽기와 적용

임계값과 매칭을 비교하면 반환 유형의 차이가 분명해집니다. 임계값은 픽셀별 비교로 새 마스크를 만들고, 매칭은 학습한 템플릿을 검색해 위치·점수 같은 값을 만듭니다. 어느 쪽이든 입력을 준비하고 반환을 읽지만 모델의 수명과 영상의 수명은 같지 않습니다. Query를 선택한다면 실행 시점과 캡처 획득 단계가 추가되므로, 먼저 필요한 출력이 무엇인지 정한 뒤 상세 선언을 확인합니다.
