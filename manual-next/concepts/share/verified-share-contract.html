공개 호출의 입력·결과

호출입력·출력주의
C# Share(), Rust share()열린 이미지 → 독립 소유 이미지. 픽셀 저장소 공유.새 핸들마다 따로 해제; 원본을 먼저 해제해도 이미 얻은 공유는 유효.
C# Roi(x,y,width,height), Rust roi(ZRect)로컬 반열림 사각형 → 별도 소유 뷰. 원점은 부모의 원점에 로컬 오프셋을 더함.양의 크기, 현재 영상 안에 있어야 함. ROI가 살아 있으면 공유 저장소도 유지.
Rust clone_deep(), C# ToArrayGray8()보이는 픽셀을 복사해 각각 독립 영상 또는 관리 배열 반환.ToArrayGray8은 Gray8 형식의 연속 배열 복사이며 이미지 핸들이 아님.

원리와 입력

공개 Share 호출의 입력은 열린 영상이고 반환은 같은 저장소를 참조하는 소유 영상입니다. 반환값을 다른 변수에 단순 대입하는 것과는 별개의 핸들이므로 각 핸들의 종료 범위를 정합니다. ROI도 원본을 참조하지만 선택한 크기와 원점을 가지며, 깊은 복사는 보이는 픽셀을 독립 저장소로 복사합니다. 값을 배열로 복사하는 읽기와 영상 객체를 얻는 호출도 분리해서 생각하세요.

적용과 확인

검증할 때는 원본을 닫기 전에 공유 결과를 먼저 얻어야 합니다. 원본 종료 뒤 공유 결과로 같은 픽셀을 읽고 그 결과를 닫은 후에는 다시 쓰지 않습니다. ROI를 다룬다면 픽셀뿐 아니라 origin과 로컬 좌표를 확인해야 합니다. 공유 객체를 얻지 않고 이미 닫힌 원본에서 새 Share를 요청하는 것은 다른 경로이며 오류입니다. 각 언어의 실제 반환 형식과 해제 규칙을 함께 살펴보세요.

적용할 때 살펴볼 점

동일한 원본의 여러 ROI가 서로 다른 origin을 갖는 경우 저장소가 같아도 로컬 (0,0)이 가리키는 원본 위치는 서로 다릅니다. 표시나 측정을 병합할 때 origin을 함께 보관해야 합니다. 별도 핸들 취득에 성공하지 못한 예외 경로는 유효한 새 영상이 생긴 것으로 취급하지 말고 이미 보유한 핸들을 정리하세요.

원본과 ROI의 좌표를 혼동하면 픽셀은 올바르더라도 표시 위치가 틀릴 수 있습니다. 공유 수명 검사와 좌표 변환 검사를 각각 수행해 어떤 단계에서 문제가 생겼는지 구분합니다.
