4. C#에서 수명 분리 · Share와 복사

4. C#에서 수명 분리의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

4. C#에서 수명 분리

C#
using System;
using ZVision;

var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
using var shared = source.Share();
source.Dispose();
Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11

원리와 입력

C#에서 Share와 CloneDeep은 각각 사용자가 정리해야 할 새 ZImage를 반환합니다. 첫 호출은 픽셀 저장소를 공유하며 둘째는 독립 픽셀 복사본을 만듭니다. using 범위를 원본과 반환값 각각에 지정하면 어느 객체가 언제 Dispose되는지 코드에서 볼 수 있습니다. 원본을 Dispose한 뒤 먼저 얻은 공유 핸들이 유효하다는 점과 Dispose한 원본에 다시 접근할 수 없다는 점을 함께 확인하세요.

적용과 확인

객체 참조를 다른 변수에 대입하는 것만으로는 새 SDK 핸들을 얻은 것이 아닙니다. 별도 소유 핸들이 필요하면 Share를 호출해야 하고, 픽셀 저장소를 분리해야 하면 CloneDeep을 선택합니다. 처리 결과 영상을 얻는 경우에도 그 반환 타입의 소유권을 확인한 후 using 범위를 정하세요. 메모리가 남아 있으면 원본 외에 보관 중인 공유 핸들과 결과 영상이 있는지 점검합니다.

값과 판독 기준

단계입력 또는 결과확인할 점
대입같은 객체 참조새 소유 핸들이 아님
Share별도 ZImage같은 저장소
CloneDeep별도 ZImage복사된 저장소
using핸들마다종료 범위 지정

적용할 때 살펴볼 점

Share를 호출해 만든 변수와 원본 객체는 각각 Dispose할 수 있으나, 단순 대입한 두 변수는 같은 객체를 가리킵니다. 이 차이를 예외가 발생하는 경로에서도 유지해야 합니다. 영상 데이터를 다른 저장소에 보관하려는 요구가 있다면 Share로 이름만 나누는 대신 CloneDeep의 복사 결과를 별도로 소유합니다.
