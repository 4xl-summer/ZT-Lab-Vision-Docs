1. Share는 어떤 복사도 하지 않을까? · Share와 복사

상위 목차로 돌아가기

1. Share는 어떤 복사도 하지 않을까?

share()/Share()는 픽셀 데이터를 복사하지 않고 같은 저장소를 참조하는 별도 소유 객체를 반환합니다. roi()도 특정 사각 영역만 가리키는 소유 객체입니다. 반면 Rust clone_deep()과 관리형 언어의 픽셀 배열 복사는 별도 데이터 저장소를 생성합니다.

원리와 입력

Share는 픽셀 배열을 새로 복제하는 대신 같은 저장소를 참조하는 또 하나의 영상 객체를 만듭니다. 반환 객체는 원본과 별개로 소유하고 사용이 끝나면 정리해야 합니다. 예를 들어 [1,7,9]를 가진 영상에서 Share를 만든 후 원본 핸들을 닫더라도 공유 객체가 보유한 참조를 통해 같은 세 값을 읽을 수 있습니다. 이미 닫은 원본 자체를 다시 호출하는 것은 허용되지 않습니다.

적용과 확인

별도 픽셀 저장소가 필요한 경우에는 깊은 복사를 사용합니다. 그림의 A와 B는 그 차이를 설명하기 위한 개념으로 실제 주소나 메모리 측정치는 아닙니다. 원본과 같은 데이터를 보고 싶지만 반환 객체의 수명을 독립적으로 관리하려는 경우 Share가 적합합니다. 외부에서 같은 버퍼를 임의로 변경하거나 여러 스레드가 동시에 쓰는 경우까지 이 관계만으로 안전하다고 가정하지 말고 해당 API의 구체 계약을 확인하세요.

값과 판독 기준

단계입력 또는 결과확인할 점
원본[1,7,9]저장소 참조
Share[1,7,9]별도 핸들, 같은 저장소
원본 종료Share는 생존이미 닫힌 원본은 재사용 불가
복사CloneDeep새 저장소

같은 값을 읽는 두 객체가 반드시 같은 핸들은 아닙니다. Share가 반환한 객체를 소유하는 쪽은 원본을 소유한 쪽과 별도로 그 객체의 마지막 사용을 확인해야 합니다.
