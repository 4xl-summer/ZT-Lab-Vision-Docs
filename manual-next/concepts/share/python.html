5. Python의 같은 계약 · Share와 복사

5. Python의 같은 계약의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

5. Python의 같은 계약

Python
from zvision import ZImage

with ZImage.from_gray8(3, 1, bytes([9, 10, 11])) as source:
    with source.share() as shared:
        with source.clone_deep() as copied:
            assert shared.to_array_gray8() == bytes([9, 10, 11])
            assert copied.to_array_gray8() == bytes([9, 10, 11])

원리와 입력

Python에서 share()는 같은 픽셀 저장소를 참조하는 별도의 ZImage를 돌려주고 clone_deep()은 픽셀을 독립 저장소에 복사합니다. 두 반환 영상 모두 with 또는 close로 정리할 수 있습니다. 원본 with 블록과 반환 영상의 블록을 각각 두면 공유 객체를 쓰는 기간과 원본을 쓰는 기간이 명확해집니다.

적용과 확인

예를 들어 3×1 입력 [1,7,9]에서 공유 영상을 얻고 원본을 닫은 다음 공유 영상으로 읽으면 세 값이 유지됩니다. 그 뒤 공유 영상까지 닫아야 해당 핸들이 정리됩니다. 닫은 원본을 다시 읽으려는 호출은 실패하므로 그 오류를 빈 영상으로 해석하지 마세요. to_array_gray8에서 얻은 bytes와 아직 열려 있는 ZImage는 타입과 수명이 다릅니다. 데이터 저장이 필요한 시점에 어떤 형태를 원하는지 먼저 결정합니다.

값과 판독 기준

단계입력 또는 결과확인할 점
입력[1,7,9]Gray8 한 행
share()[1,7,9]원본과 저장소 공유
clone_deep()동일 픽셀독립 저장소
종료with / close영상별로 정리

적용할 때 살펴볼 점

원본과 공유 영상을 각각 with로 관리하면 어느 핸들을 닫았는지 명확합니다. 함수가 영상을 반환하는 구조라면 반환값이 공유인지 깊은 복사인지 함수의 계약을 문서화하고 호출자가 종료 책임을 지도록 합니다. 배열을 얻은 다음 처리한다면 복사된 bytes를 읽는 일과 영상 핸들에서 새 배열을 읽는 일을 구분하세요.

닫힌 원본에서 새 공유 객체를 만들려는 시도와 이미 얻어 둔 공유 객체를 읽는 시도는 서로 다른 호출입니다. 진단할 때 사용한 변수와 호출 순서를 함께 기록하세요.
