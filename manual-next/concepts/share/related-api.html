관련 API

원리와 입력

공유를 확인할 때는 ZImage의 Share 또는 share와 ROI 호출을 먼저 봅니다. 둘 다 원본과 같은 저장소에 연결된 별도 영상 핸들이며 ROI는 보이는 영역과 origin도 갖습니다. 독립 픽셀을 보유해야 한다면 CloneDeep 또는 clone_deep과 crop copy의 반환 계약을 확인하세요. 반환 영상은 각각의 사용이 끝났을 때 닫아야 합니다.

적용과 확인

조회 결과가 영상이 아니라 복사된 배열 또는 값 스냅샷인 경우에는 해당 값의 계약을 따릅니다. 예를 들어 MatchResult는 모델이 닫힌 뒤에도 기존 매치를 읽는 독립 값이고, Query 실행에서 얻은 캡처는 별도 소유 이미지입니다. 같은 이름에 익숙해졌더라도 반환형과 좌표 원점을 함께 확인하면 수명과 표시 오류를 줄일 수 있습니다. 언어별 선언에서 using, close 또는 Drop에 해당하는 사용 예를 확인하세요.

값과 판독 기준

단계입력 또는 결과확인할 점
Share같은 저장소독립 영상 핸들
ROI영역 선택공유와 origin
CloneDeep깊은 복사픽셀 분리
Query capture취득 영상별도 정리

적용할 때 살펴볼 점

영상을 보관할지 픽셀 값만 복사해 전달할지에 따라 적절한 반환 타입이 달라집니다. ROI의 로컬 위치는 origin과 함께 해석하고, 배열 복사 결과는 영상 메타데이터를 대신한다고 가정하지 마세요. 여러 처리를 계획할 때는 실행의 capture 취득 시점과 반환 영상의 종료 지점도 미리 정합니다.
