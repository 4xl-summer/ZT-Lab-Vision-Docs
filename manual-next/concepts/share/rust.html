3. Rust에서 저장소 공유와 깊은 복사를 직접 구분 · Share와 복사

3. Rust에서 저장소 공유와 깊은 복사를 직접 구분의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

3. Rust에서 저장소 공유와 깊은 복사를 직접 구분

Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let shared = source.share();
    let copy = source.clone_deep()?;
    assert!(source.shares_storage_with(&shared));
    assert!(!source.shares_storage_with(&copy));
    drop(source);
    assert_eq!(shared.to_packed_vec()?, vec![9, 10, 11]);
    assert_eq!(copy.to_packed_vec()?, vec![9, 10, 11]);
    Ok(())
}

원리와 입력

Rust의 영상 객체에서 공유 핸들을 얻는 경우와 깊은 복사를 만드는 경우는 반환되는 값은 둘 다 영상이지만 저장소 관계가 다릅니다. 공유는 원본의 픽셀 저장소를 계속 참조하고 깊은 복사는 새 저장소에 픽셀을 복사합니다. 해당 반환 값을 별도 변수로 보유하면 원본 변수의 수명이 끝난 뒤에도 살아 있는 공유 값의 소유권을 추적할 수 있습니다.

적용과 확인

범위가 끝나면 각 Rust 값은 Drop을 통해 정리됩니다. 코드에서 사용한 함수의 빌림과 반환 타입은 Rust 선언에 맞춰 확인하고, 값을 이동시키는 Query 체인과 단순 영상 공유를 혼동하지 마세요. ROI의 행 간격이 보이는 너비와 일치한다고 가정하여 직접 버퍼를 순회하기보다는 제공되는 읽기·packed 복사 방법을 사용하는 것이 정확한 범위에 접근하는 데 도움이 됩니다.

값과 판독 기준

단계입력 또는 결과확인할 점
공유 값별도 영상 값같은 픽셀 저장소 참조
깊은 복사새 영상 값저장소 분리
ROI보이는 부분행 간격과 폭 구분
수명 종료Drop각 값의 범위에 따름

적용할 때 살펴볼 점

공유 영상과 깊은 복사 영상이 모두 같은 픽셀을 읽는다는 검사는 저장소 관계까지 구분해 주지는 않습니다. 각각을 얻은 API의 계약과 소유 값을 확인해야 합니다. 부분 영역을 가져왔다면 origin과 보이는 크기를 별도로 읽고, 원본 좌표가 필요한 결과에는 올바른 변환을 적용하세요. 지원되지 않는 임의 쓰기나 외부 버퍼 수명은 별도 계약을 확인합니다.

원본과 공유 값의 이름이 다르더라도 실제 저장소는 같을 수 있습니다. 새 저장소가 필요한지 여부를 기준으로 함수의 반환 계약을 확인하고 각 값의 마지막 사용 지점을 코드에 남깁니다.
