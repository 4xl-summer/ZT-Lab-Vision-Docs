해제 후 접근과 독립 임대 예제 · Share와 복사

해제 후 접근과 독립 임대 예제의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

해제 후 접근과 독립 임대 예제

C#
using System;
using ZVision;

class Program {
    static void Main() {
        var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
        using var shared = source.Share();
        source.Dispose();
        Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11
        try { _ = source.Info; }
        catch (ObjectDisposedException) { Console.WriteLine("source closed"); }
    }
}

이 코드는 소스 계약을 설명하는 합성 사례입니다. 관련 검증 사례는 Rust의 rust-roi-query와 관리형의 ownership-query입니다. 원본·ROI 해제 후 계획 실행, 독립 캡처와 복제 분기를 확인합니다. 실행 결과는 통합 검증에서 확인합니다.

원리와 입력

작은 소유권 사례에서 입력 [1,7,9]에 대해 공유 영상과 오른쪽 ROI [7,9]를 먼저 얻고 원본을 닫습니다. 살아 있는 공유 영상은 [1,7,9]를 계속 읽을 수 있으며 ROI도 선택 픽셀을 읽을 수 있습니다. 반면 닫힌 원본에 대한 접근은 오류입니다. 이 순서를 바꾸어 원본이 이미 닫힌 뒤 Share를 호출하면 같은 사례가 아니므로 결과를 혼동해서는 안 됩니다.

적용과 확인

Query 출력과 capture도 실행 중에 독립 핸들로 취득한 다음 실행을 닫고, 취득한 영상을 읽은 뒤 각각 닫는 방식으로 확인합니다. 값이 맞는지뿐 아니라 어떤 핸들이 닫혔고 어느 객체가 살아 있는지 함께 기록하세요. 예외가 나는 경로에서도 이미 취득한 객체가 있으면 정리해야 합니다. 이 합성 자료는 래퍼의 문서화된 수명 관계를 점검하는 데 쓰이며 모든 외부 메모리 사용을 시험하지 않습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
원본[1,7,9]먼저 공유와 ROI 획득
원본 종료닫힌 핸들재접근 오류
Share[1,7,9]독립 핸들에서 확인
ROI[7,9]선택 영역 확인

적용할 때 살펴볼 점

예제 실행 후에는 보유 중인 Share, ROI와 취득한 출력까지 모두 정리해야 합니다. 원본 종료 후 공유 객체가 유효하다는 관찰은 종료를 생략하라는 의미가 아닙니다. 마찬가지로 닫힌 원본의 오류를 잡았다고 해서 이미 얻은 다른 핸들의 종료 책임이 사라지지 않습니다. 객체마다 생성과 마지막 사용을 짝지어 확인하세요.
