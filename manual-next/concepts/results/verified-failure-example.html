해제 후 접근과 독립 임대 예제

C#
using System;
using ZVision;

class Program {
    static void Main() {
        var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
        using var shared = source.Share();
        source.Dispose();
        Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11
        try { _ = source.Info; }
        catch (ObjectDisposedException) { Console.WriteLine("source closed"); }
    }
}

이 코드는 소스 계약을 설명하는 합성 사례입니다. 관련 검증 사례는 Rust의 rust-roi-query와 관리형의 ownership-query입니다. 원본·ROI 해제 후 계획 실행, 독립 캡처와 복제 분기를 확인합니다. 실행 결과는 통합 검증에서 확인합니다.

적용 상황과 원리

예제는 원본 Gray8 영상의 별도 공유를 먼저 얻은 뒤 원본을 해제합니다. 공유 객체는 별도 임대를 보유하므로 그 뒤에도 9,10,11을 읽을 수 있습니다. 반대로 이미 해제된 source의 Info를 다시 읽는 시도는 ObjectDisposedException으로 처리됩니다. 원본 변수가 남아 있다는 사실과 그 변수가 유효한 네이티브 소유권을 갖는지는 다릅니다.

결과를 읽는 방법

이것은 공유 임대의 수명을 설명하는 작은 합성 사례입니다. 복사된 값 스냅샷, 영상 저장소의 공유, 완전 복제는 각각 다른 작업이므로 같은 의미로 취급하지 않습니다. 이미 얻은 공유 영상도 사용이 끝나면 별도로 Dispose해야 합니다. 지연 계획과 실행 결과에서는 원본 해제 이후 계획이 유지하는 입력과 실행에서 획득한 영상을 각각 확인합니다. 실제 장비의 동시성 성능까지 이 예제로 보장하지 않습니다.

추가 점검

원본을 해제한 뒤 source.Info가 실패하는 것은 공유 객체의 데이터를 함께 지웠다는 의미가 아닙니다. 각 객체가 별도 소유권을 가지므로 shared가 유효한 것입니다. 이 예에서는 데이터가 복사되었다고 주장하지 않으며 저장소 공유와 독립적인 완전 복제를 구분합니다.
