해제와 동시 접근의 확인 범위

C#의 QueryBuilder는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.

적용 상황과 원리

동시 접근을 검토할 때는 어느 객체의 어떤 메서드가 같은 잠금을 사용하는지부터 확인합니다. 확인된 C# QueryBuilder 구현은 계획 변경, 복제, 실행과 Dispose를 같은 인스턴스 잠금으로 직렬화합니다. 해제가 먼저 끝난 뒤 그 객체를 사용하는 호출은 ObjectDisposedException이 됩니다. 어느 작업이 먼저 잠금을 얻을지는 이 설명에서 보장하지 않습니다.

결과를 읽는 방법

실행 객체에서도 획득과 해제를 해당 인스턴스의 잠금으로 보호하며, 해제 전에 얻은 독립 영상 임대와 값은 유지됩니다. Python typed 실행의 output과 get_image, close도 같은 객체 잠금으로 처리하고 닫힌 실행 접근은 ValueError입니다. 이 사실을 모든 SDK 객체나 외부 버퍼에 대한 일반적인 동시 수정 보장으로 확장하지 말고 소유자와 종료 순서를 각 작업에서 정하세요.

해제 순서 예

조건확인할 내용
먼저 얻은 값실행 정리 후에도 읽을 수 있음
먼저 얻은 공유 영상별도의 소유권으로 유지
해제 후 새로운 획득닫힌 객체 접근 오류

스냅샷과 소유 영상의 판독 순서

모멘트 쿼리를 예로 들면 C# Execute가 반환한 실행에서 Output을 먼저 읽어 얻은 MomentsResult는 독립 스냅샷입니다. 이후 실행을 Dispose해도 그 스냅샷의 값을 읽을 수 있습니다. 실행이 먼저 해제되었다면 그 실행에서 Output을 새로 읽는 호출은 ObjectDisposedException이므로, 계산 성공 여부와 출력 획득 성공 여부를 각각 확인해야 합니다.

영상 캡처는 복사된 숫자 스냅샷과 정리 방식이 다릅니다. 실행이 열려 있을 때 GetImage로 취득한 영상은 별도 소유 핸들이며 사용이 끝나면 별도로 Dispose합니다. Python typed 실행에서도 output 또는 get_image 획득과 close가 경합할 수 있고, close가 먼저 끝난 실행의 새 접근은 ValueError입니다. 반환 타입별로 값인지 소유 영상인지 확인한 다음 각자의 수명에 맞춰 보관하고 정리하세요.
