해제와 동시 접근의 확인 범위

C#의 QueryBuilder는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.

원리와 입력

동시 접근은 객체별로 확인된 범위에서만 이해해야 합니다. C# QueryBuilder의 변경, 복제, 실행과 Dispose는 같은 인스턴스 잠금을 사용하므로 먼저 잠금을 얻은 호출이 끝난 뒤 다음 호출이 진행됩니다. 실행 결과에서 이미 획득한 독립 영상이나 복사한 값은 실행 객체 해제와 별도의 수명을 갖습니다. 반대로 Dispose가 끝난 객체를 이후에 다시 사용하면 ObjectDisposedException이 발생합니다.

적용과 확인

Python typed 실행에서도 output 또는 get_image와 close는 해당 실행의 잠금으로 보호되고, 닫힌 실행에 대한 접근은 ValueError입니다. 이 사실만으로 다른 종류의 모든 영상 객체나 외부 버퍼를 임의의 스레드에서 동시에 변경해도 된다고 확대할 수는 없습니다. 작업마다 누가 빌더와 실행을 소유하는지 정하고 취득할 결과를 확보한 다음 종료하세요. 정확한 경합 순서나 실제 장비 파이프라인의 처리량은 별도 검증이 필요합니다.

값과 판독 기준

단계입력 또는 결과확인할 점
먼저 얻은 이미지실행 해제 후에도별도 핸들로 사용
C# 닫힌 실행접근 시ObjectDisposedException
Python 닫힌 실행접근 시ValueError
확인 범위해당 래퍼 메서드모든 동시 수정으로 확대하지 않음

계획 객체와 실행 객체의 경계

한 C# QueryBuilder에서 Clone과 Dispose가 동시에 시작되었다고 해도 어느 쪽이 먼저 잠금을 얻을지는 정해져 있지 않습니다. Clone이 먼저 잠금을 얻어 복제가 완료되면 반환 계획은 원본과 별도 소유 객체입니다. Dispose가 먼저 완료되면 이후 Clone은 닫힌 빌더에 접근하므로 ObjectDisposedException이 됩니다. 어느 경우든 Clone이 계산 결과를 실행하는 것은 아닙니다.

계획을 실행해 얻은 실행 객체는 빌더와 다른 소유자입니다. 실행에서 스냅샷을 읽거나 독립 영상 핸들을 취득하는 시점과 빌더를 정리하는 시점을 구분하세요. 계획이 해제되었다는 사실만으로 이미 성공해 반환된 독립 결과까지 새로 취소되었다고 해석하지 않습니다. 각 호출의 성공 또는 예외를 확인하고, 성공한 계획과 실행, 영상의 소유권을 각각 정리하는 흐름으로 연결합니다.
