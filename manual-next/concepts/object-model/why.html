상위 목차로 돌아가기

1. 객체를 기준으로 사용법을 구성하는 이유

ZVision에서는 이미지·모델·실행 계획·결과를 서로 다른 객체로 다룹니다. 입력 이미지를 객체로 보유하고 메서드 호출로 새 이미지를 얻거나, 학습 모델로 위치를 찾고 값 스냅샷을 얻습니다. 수천 개의 함수명을 먼저 외우는 대신 누가 데이터를 소유하고 어떤 결과를 반환하는가를 이해하는 것이 핵심입니다.

원리와 입력

객체를 따라가면 입력을 바꾸는 일과 새 결과를 얻는 일을 명확히 구분할 수 있습니다. 예를 들어 이미지에서 임계값을 호출하면 결과는 또 다른 ZImage입니다. 반면 NCC 학습 뒤 찾은 위치는 MatchResult의 값으로 읽으며, 이것을 영상으로 저장하거나 Dispose할 대상처럼 다루지 않습니다. 같은 검사라도 모델은 반복 검색에 재사용하고, 각 입력에서 얻은 결과는 그 프레임의 측정값으로 보관할 수 있습니다.

적용과 확인

Query는 세 번째 경로입니다. 입력을 바탕으로 처리 계획을 만들고 실행 결과에서 출력이나 이름 붙은 캡처를 얻습니다. 관리형 빌더는 변경되는 객체이므로 두 조건을 병렬로 만들 때 복제 시점을 정해야 합니다. 그림의 화살표는 이 반환 관계를 설명하기 위한 것이며 성능이나 메모리 주소 측정값은 아닙니다. 먼저 어떤 객체가 반환되는지 확인한 뒤, 그 객체가 소유 핸들인지 독립 값인지에 맞춰 수명을 정하세요.
