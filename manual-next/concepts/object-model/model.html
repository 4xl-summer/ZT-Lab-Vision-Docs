상위 목차로 돌아가기

4. 매칭: 결과가 이미지가 아닌 값 객체인 경우

MatchModel은 템플릿에서 학습한 내용을 보유합니다. find는 MatchSpec 조건으로 이미지를 검색하고 위치·점수 등의 MatchResult를 반환합니다. 매치가 없을 때는 Best가 null일 수 있으며 오류와 구분해야 합니다.

C# · 이미 준비된 영상·스펙 사용
// template, searchImage, spec: 이미 생성한 ZImage/MatchSpec
using var model = MatchModel.TrainNcc(template);
MatchResult found = model.Find(searchImage, spec);
if (found.Best is Match best)
    Console.WriteLine(best.Score);
else
    Console.WriteLine("No match");

위 코드는 모델 사용 발췌입니다. 합성 입력부터 준비한 전체 샘플은 NCC 검색 레시피에 있습니다. MatchResult는 독립 값 스냅샷으로 이미지나 모델의 네이티브 핸들을 보유하지 않습니다.

원리와 입력

매칭 모델은 템플릿의 특징을 학습한 소유 객체이고, MatchSpec은 검색에 사용할 조건입니다. 학습한 모델에 검색 영상과 설정을 전달하면 결과는 영상이 아니라 매치 목록과 최고 결과를 담은 값 스냅샷입니다. 점수는 사용된 매칭 방법의 유사도이며 확률로 해석하지 않습니다. 위치를 표시할 때에는 ROI 로컬 위치와 원점을 반영한 전역 위치 중 필요한 필드를 선택하세요.

적용과 확인

예제의 template, searchImage, spec은 이미 준비된 값이므로 이것은 호출 흐름을 보여 주는 발췌입니다. 전체 합성 입력은 연결된 NCC 레시피에서 확인할 수 있습니다. 매치가 없으면 Best는 null이고 이는 정상적으로 끝난 검색의 가능한 결과입니다. 형식이나 설정이 잘못되어 발생한 예외와 구분해야 합니다. C#에서는 모델을 using으로 정리하지만 이미 받은 MatchResult의 복사된 값은 모델 수명과 독립적으로 읽을 수 있습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
학습템플릿과 선택 마스크소유 모델 생성
검색영상과 MatchSpec위치·점수 계산
발견Best 값 존재필요한 좌표계 선택
미발견Best 없음예외와 별도 분기
