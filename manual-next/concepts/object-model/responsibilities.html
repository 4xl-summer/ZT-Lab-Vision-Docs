원리와 입력

영상, 모델, 설정과 결과는 서로 다른 시점에 만들어지고 사라집니다. ZImage는 픽셀과 ROI 정보를 통해 처리의 입력이 되며, 새 영상이 반환되면 그것도 별도의 수명 관리 대상입니다. MatchModel은 템플릿에서 학습한 상태를 보유하므로 여러 검색에 재사용할 수 있습니다. MatchSpec은 검색 각도와 배율 등 조건을 담는 값으로, 모델의 소유 핸들과 구별합니다.

적용과 확인

찾은 매치 목록은 독립 값 스냅샷이므로 모델과 입력을 해제한 뒤에도 이미 얻은 위치와 점수를 읽을 수 있습니다. 반대로 QueryExecution에서 취득한 영상은 별도 소유 핸들이어서 사용이 끝나면 따로 닫습니다. 실행 객체 자체와 그로부터 얻은 이미지를 하나의 변수처럼 생각하면 자원을 오래 보유하거나 닫힌 객체를 다시 쓰는 실수가 생깁니다. 표를 볼 때 각 행의 반환 종류와 해제 대상을 짝지어 읽으세요.

적용할 때 살펴볼 점

반환 유형을 고를 때는 생성과 종료의 책임을 호출부에 적어 보세요. 원본 ZImage와 직접 처리 결과는 각각 정리하고, 모델은 검색을 마칠 때 정리합니다. MatchResult는 복사된 값을 보관하므로 동일한 종료 절차가 필요하지 않습니다. 실행 객체에서 영상을 얻었다면 실행과 영상의 소유 범위를 따로 추적해야 중간 실패 경로도 관리할 수 있습니다.
