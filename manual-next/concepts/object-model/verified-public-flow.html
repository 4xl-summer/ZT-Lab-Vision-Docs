공개 객체별 입력과 결과의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

공개 객체별 입력과 결과

객체·호출입력과 반환소유권
ZImage.Threshold열린 영상과 유한 임계값 → 새 Gray8 영상.원본과 반환을 각각 해제.
MatchModel.TrainNcc / Find변화가 있는 템플릿과 선택 마스크로 모델 생성; 검색 영상과 MatchSpec으로 MatchResult 획득.모델은 Dispose; MatchResult는 독립 값, Best는 없을 수 있음.
ImageQuery / Execute입력 공유 → 계획 구성 → 형식별 실행 결과.빌더와 실행을 해제; 획득한 이미지·리소스는 독립 해제.
AlignmentResultFound, Info 및 성공 시 Aligned·ValidMask 제공.소유 결과와 획득 영상을 각각 해제; 미발견은 검사 불가.

원리와 입력

공개 호출을 연결할 때 첫 단계는 필요한 입력 객체의 형식과 수명을 정하는 것입니다. Threshold는 열린 영상을 받아 새 Gray8 영상을 반환하고, MatchModel의 학습은 템플릿과 선택 마스크를 받아 재사용할 모델을 만듭니다. 검색할 때는 별도의 영상과 MatchSpec을 주며, 반환된 MatchResult는 결과 값입니다. 모델과 결과를 같은 종류의 핸들로 취급하면 정리 시점이 불명확해집니다.

적용과 확인

ImageQuery에서는 빌더를 구성하고 실행을 얻은 뒤 필요한 출력과 캡처를 획득합니다. AlignmentResult는 또 다른 소유 결과이며 Found가 거짓이면 정렬 영상을 기준으로 결함 판정을 진행할 수 없습니다. 예를 들어 정렬 성공과 유효 픽셀 마스크를 확인한 다음 차이 영상을 계산해야 비교 가능한 영역을 알 수 있습니다. 표에 적힌 호출을 단계별로 따라가면서 반환된 각 핸들의 해제 지점과 빈 값 또는 실패 상태의 분기를 함께 작성하세요.

값과 판독 기준

단계입력 또는 결과확인할 점
영상Threshold새 영상의 소유권
모델TrainNcc → Find모델과 결과 값 구분
계획ImageQuery → Execute빌더와 실행 수명
정렬Found → ValidMask미발견 시 검사 중단

적용할 때 살펴볼 점

정렬 단계의 Found가 거짓이라면 차이 영상의 값이 0인지 확인하는 단계로 넘어가지 않습니다. 먼저 유효한 정렬 결과가 존재해야 기준과 입력의 대응을 해석할 수 있기 때문입니다. Found가 참인 경우에도 ValidMask로 비교 가능한 위치를 구분합니다. 이렇게 반환 객체의 상태를 먼저 판독하면 처리 실패와 결함이 없는 정상 결과를 분리할 수 있습니다.
