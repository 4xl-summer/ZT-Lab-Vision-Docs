3. 이미지 처리: 즉시 결과를 얻는 경우

3×1 Gray8 픽셀 [9,10,11]에 임계값 10을 적용하면 0,255,255입니다. 연산은 원본을 바꾸지 않고 새 소유 이미지를 반환합니다.

C#
using System;
using ZVision;

using var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
using var binary = source.Threshold(10.0);
Console.WriteLine(string.Join(",", binary.ToArrayGray8()));
// 0,255,255
Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let mask = source.threshold(10.0)?;
    assert_eq!(mask.to_packed_vec()?, vec![0, 255, 255]);
    Ok(())
}

원리와 입력

즉시 실행은 호출하는 순간 입력 영상에 연산을 적용하고 반환값을 받는 흐름입니다. 이 사례에서는 Gray8 세 픽셀 9, 10, 11과 실수 임계값 10.0을 사용합니다. 결과 0, 255, 255는 두 번째 값이 경계와 같아도 전경에 포함됨을 보여 줍니다. 반환된 binary 또는 mask는 새 영상이며 원본 밝기 배열을 덮어쓰지 않습니다.

적용과 확인

C#의 using은 source와 binary 각각의 수명을 종료합니다. Rust 코드는 오류를 결과로 전달하고 배열이 기대값과 다른 경우 assertion으로 중단합니다. 코드가 한 줄로 보이더라도 생성·처리·읽기는 서로 다른 단계이므로 오류가 생긴 지점을 나누어 확인하세요. 결과 영상 형식과 입력 크기를 확인한 다음 픽셀 배열을 비교하면, 버퍼를 잘못 만들었는지 비교 조건을 잘못 기대했는지 구별할 수 있습니다. 여러 연산을 하나의 계획에 담을 필요가 없다면 이처럼 직접 호출하는 편이 흐름을 읽기 쉽습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
입력9 / 10 / 11Gray8 한 행
기준10.0등호 포함
출력0 / 255 / 255새 Gray8 영상
실패 시생성·처리·읽기실패한 단계를 먼저 확인

적용할 때 살펴볼 점

기준을 11로 바꾸면 첫 두 표본은 기준 미만이고 마지막 11만 기준과 같으므로 기대 마스크는 [0,0,255]입니다. 이 계산은 같은 입력에서 설정 하나만 바꾸었을 때 결과가 어떻게 달라지는지 보여 줍니다. 원본의 9, 10, 11을 유지해 두면 다른 기준값을 비교하거나 원래 밝기를 별도로 분석할 수 있습니다.
