6. Share/ROI와 복사의 객체 관계

ROI·Share는 원본과 같은 픽셀 저장소를 참조하는 별도 ZImage입니다. 복사 없이 특정 영역을 처리하고 원본을 보존할 때 유리하며, Deep Copy는 저장소를 분리합니다. 결과가 보유하는 참조는 이미지 객체의 해제 순서와 구별됩니다.

원리와 입력

원본의 일부만 선택하는 ROI와 저장소를 공유하는 Share는 별도 영상 객체를 만듭니다. 이 객체들은 같은 픽셀 저장소를 참조하지만 각자 닫아야 하는 핸들을 가집니다. 따라서 원본 핸들을 닫았더라도 먼저 얻어 둔 ROI나 공유 영상이 보유한 참조가 유효한 동안에는 그 객체로 픽셀을 읽을 수 있습니다. 이미 닫은 원본 핸들에 다시 접근하는 일과 살아 있는 별도 핸들을 사용하는 일을 구분하세요.

적용과 확인

깊은 복사는 선택된 영상 데이터를 새 저장소에 복사하므로 공유 관계를 끊어 독립 픽셀을 보관하려는 경우에 쓰입니다. 예를 들어 3×2 영상의 오른쪽 두 열을 ROI로 잡으면 2×2 영상과 새로운 로컬 좌표계가 생깁니다. 원본에 표시할 위치는 ROI origin을 더해 구합니다. 개념도의 저장소 A와 B는 소유 관계를 설명하는 도식이며 주소나 실제 메모리 사용량을 나타내지 않습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
원본ZImage저장소 A 참조
Share별도 핸들저장소 A 공유
ROI별도 핸들·origin저장소 A의 선택 영역
깊은 복사새 영상독립 저장소 B

적용할 때 살펴볼 점

공유 객체가 원본과 같은 값을 읽는 것은 픽셀이 저장소에 남아 있다는 뜻이지 두 변수가 같은 핸들이라는 뜻은 아닙니다. 반대로 깊은 복사본이 처음에 같은 값을 갖는 것은 독립 저장소라는 사실과 모순되지 않습니다. 픽셀 값의 같음, 객체 수명, 저장소 관계를 각각 검사해야 어떤 선택이 필요한지 판단할 수 있습니다.
