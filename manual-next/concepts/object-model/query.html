Query는 처리가 항상 더 빠르다는 뜻이 아니라, 처리를 묶고 중간 결과를 명시적으로 다루는 별도 실행 모델입니다. Query·Capture 상세 설명을 참고하세요.

원리와 입력

Threshold 직접 호출은 즉시 결과 영상을 만듭니다. 반면 ImageQuery는 입력과 처리 단계를 계획으로 구성한 다음 execute 또는 Execute로 실행합니다. 중간 상태가 필요하다면 계획의 특정 지점에 capture 이름을 붙이고, 실행 결과에서 그 이름으로 영상을 획득합니다. 출력 영상과 캡처 영상은 각각 별도 소유 핸들이므로 사용 범위를 명확히 정해야 합니다.

적용과 확인

관리형 C#과 Python 빌더는 같은 인스턴스에 단계를 추가하므로 한 계획에서 서로 다른 두 결과를 만들 때는 분기 전에 Clone 또는 clone을 사용합니다. Rust의 체인은 값을 이동시키는 API이므로 별도로 재사용할 계획의 소유권을 고려해야 합니다. 예를 들어 7과 9의 임계값을 각각 비교할 때 하나의 가변 빌더에 연속으로 설정하면 기대한 두 독립 분기가 되지 않습니다. Query 자체가 언제나 빠르다는 보장은 없으며 실행 시점과 캡처 요구를 기준으로 선택하세요.

값과 판독 기준

단계입력 또는 결과확인할 점
구성원본에서 계획 생성아직 결과 픽셀을 읽지 않음
분기Clone / clone관리형 계획을 별도로 변경
실행Execute / execute형식별 실행 객체 획득
취득출력·capture별도 영상 핸들 정리

적용할 때 살펴볼 점

예를 들어 [1,7,9]에서 복제한 두 계획에 각각 기준 7과 9를 주면 두 번째 픽셀은 255와 0으로 달라집니다. 이 차이는 단순한 출력 길이 비교보다 조건 분기가 독립적으로 반영됐는지 확인하기 쉽습니다. 실행을 닫기 전에 필요한 캡처를 취득하고, 이후에는 취득한 영상의 수명을 별도로 관리하세요.
