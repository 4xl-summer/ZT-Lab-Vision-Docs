객체 중심 API 모델

이미지·모델·옵션·결과·Query의 책임을 분리해 ZVision을 일관되게 이해합니다.

독립 HTML 페이지코드 검토 기준 2026-11-08초기 콘텐츠

함수 목록보다 객체의 책임

ZVision의 공개 API는 객체가 무엇을 보유하고 어떤 동작을 수행하는지 중심으로 설계됩니다. Rust 공개 Facade를 기준으로 객체 의미를 정의하고 C#·Python은 각 언어에 맞게 표현합니다. Rust에서 모든 기능이 클래스에 속해야 한다는 뜻은 아닙니다.

객체주요 역할대표 동작
ZImage픽셀 데이터 및 저장소의 소유권roi, share, threshold
MatchModel학습된 템플릿 상태의 소유권train_ncc, find
MatchSpec검색 조건을 표현하는 값검색 각도, 배율, 점수, 중복 억제 조건
MatchResult검색 결과의 독립 스냅샷matches, best
ImageQuery지연 실행 이미지 처리 계획threshold, execute

객체별 데이터 흐름

ZImage입력 / ROI
→
처리 또는 MatchModel계산 주체
→
ZImage / Result처리 결과

일반 영상 변환은 새로운 ZImage를 반환하지만, 매칭은 위치·점수의 MatchResult를 반환합니다. 두 결과는 표시 방법이나 수명 계약이 다릅니다.

Rust와 관리형 언어의 차이

관점RustC#Python

설계에서 기억할 원칙

  • 이미지 처리 함수와 학습 모델의 책임을 혼합하지 않습니다.
  • Result가 입력 이미지와 독립적인지, 네이티브 자원을 보유하는지를 구분합니다.
  • 래퍼가 Rust의 메서드 철자를 무조건 복사하지 않고 의미를 유지합니다.
  • 실제로 존재하지 않는 호출 경로를 예제에 만들어 넣지 않습니다.
