객체 중심 API 모델

이미지·모델·옵션·결과·Query의 책임을 분리해 ZVision을 일관되게 이해합니다.

1. 객체를 기준으로 사용법을 구성하는 이유

ZVision에서는 이미지·모델·실행 계획·결과를 서로 다른 객체로 다룹니다. 입력 이미지를 객체로 보유하고 메서드 호출로 새 이미지를 얻거나, 학습 모델로 위치를 찾고 값 스냅샷을 얻습니다. 수천 개의 함수명을 먼저 외우는 대신 누가 데이터를 소유하고 어떤 결과를 반환하는가를 이해하는 것이 핵심입니다.

3. 이미지 처리: 즉시 결과를 얻는 경우

3×1 Gray8 픽셀 [9,10,11]에 임계값 10을 적용하면 0,255,255입니다. 연산은 원본을 바꾸지 않고 새 소유 이미지를 반환합니다.

C#
using System;
using ZVision;

using var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
using var binary = source.Threshold(10.0);
Console.WriteLine(string.Join(",", binary.ToArrayGray8()));
// 0,255,255
Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let mask = source.threshold(10.0)?;
    assert_eq!(mask.to_packed_vec()?, vec![0, 255, 255]);
    Ok(())
}

4. 매칭: 결과가 이미지가 아닌 값 객체인 경우

MatchModel은 템플릿에서 학습한 내용을 보유합니다. find는 MatchSpec 조건으로 이미지를 검색하고 위치·점수 등의 MatchResult를 반환합니다. 매치가 없을 때는 Best가 null일 수 있으며 오류와 구분해야 합니다.

C# · 이미 준비된 영상·스펙 사용
// template, searchImage, spec: 이미 생성한 ZImage/MatchSpec
using var model = MatchModel.TrainNcc(template);
MatchResult found = model.Find(searchImage, spec);
if (found.Best is Match best)
    Console.WriteLine(best.Score);
else
    Console.WriteLine("No match");

위 코드는 모델 사용 발췌입니다. 합성 입력부터 준비한 전체 샘플은 NCC 검색 레시피에 있습니다. MatchResult는 독립 값 스냅샷으로 이미지나 모델의 네이티브 핸들을 보유하지 않습니다.

특성ZImage.ThresholdImageQuery

Query는 처리가 항상 더 빠르다는 뜻이 아니라, 처리를 묶고 중간 결과를 명시적으로 다루는 별도 실행 모델입니다. Query·Capture 상세 설명을 참고하세요.

6. Share/ROI와 복사의 객체 관계

ROI·Share는 원본과 같은 픽셀 저장소를 참조하는 별도 ZImage입니다. 복사 없이 특정 영역을 처리하고 원본을 보존할 때 유리하며, Deep Copy는 저장소를 분리합니다. 결과가 보유하는 참조는 이미지 객체의 해제 순서와 구별됩니다.
