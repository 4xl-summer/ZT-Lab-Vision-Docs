ImageQuery · 지연 실행

즉시 실행과 Query의 차이, Capture 중간 이미지, Rust 및 관리형 SDK의 Builder 의미.

소주제별 독립 HTML2026-11-08 소스 확인예제 실행 재검증 대기

연산 계획과 실행을 구분한다

ZImage의 직접 이미지 변환은 호출 즉시 계산하지만, ImageQuery는 실행할 작업을 축적합니다. query()가 입력 이미지 저장소를 공유하며 threshold() 등의 연산을 추가해도, 실제 픽셀 처리는 execute()에서 발생합니다.

단계실행 의미수명·결과
이미지 직접 메서드호출 시 픽셀 계산새 ZImage 반환
Query 생성입력 저장소 공유지연 계획
Capture 추가중간 결과 보관 지점 예약문자열로 식별
execute / Execute연산 수행결과와 캡처를 가진 실행 객체

Rust — Capture와 결과 이미지

Rust
use zvision::ZImage;

fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let plan = source.query()?
        .capture("original")?
        .threshold(10)?
        .capture("binary")?;
    let execution = plan.execute()?;
    let output = execution.acquire_output();
    let captured = execution.get_image("binary")?;
    assert_eq!(output.to_packed_vec()?, vec![0, 255, 255]);
    assert_eq!(captured.to_packed_vec()?, vec![0, 255, 255]);
    Ok(())
}

Rust 공개 Facade에서는 작업 추가 메서드가 self를 소비해 새 계획을 반환합니다. 분기하려면 clone()을 명시적으로 사용합니다. execute(&self)는 계획을 빌려 여러 번 실행할 수 있습니다.

C#·Python Builder와의 차이

구분RustC# / Python
계획 연산 추가값 이동, 새 계획 반환동일 Builder 가변 수정
분기clone()명시적 Clone() / clone()
실행execute()Execute() / execute()
해제Drop/소유권Dispose() / close()

이 차이를 무시하고 var branch = query;처럼 단순 별칭으로 분기하면 C#에서는 같은 계획을 함께 변경합니다. 두 언어의 객체 식별성이 동일하다고 가정하지 않습니다.

검증 시점과 결과 수명

입력 형식과 임계값의 유한성은 계획 추가 중에 검사될 수 있지만, 비유한 부동소수 입력 픽셀은 실행 단계에서 거절됩니다. 반환된 출력·Capture 이미지는 독립적인 공유 이미지 소유권을 가질 수 있습니다. 실행 객체가 보유한 캡처를 해제할 때, 이전에 얻은 소유 이미지를 자동으로 무효화하면 안 됩니다.

!Rust 공개 ImageQuery / QueryExecution과 기존 Query 수명 테스트의 계약을 참고했습니다. C#·Python의 가변 Builder 규칙은 최신 API 이행 기록에 명시되어 있습니다.
