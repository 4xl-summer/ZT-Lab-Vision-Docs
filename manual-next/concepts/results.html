결과 객체

값 스냅샷과 소유 결과 구분

Model과 Result의 책임

MatchModel은 학습 템플릿을 보유하고 find에서 탐색을 수행합니다. 결과를 담는 MatchResult는 검출된 일치 위치·점수 등의 값 스냅샷으로, 이미 해제된 원본 이미지나 모델의 네이티브 핸들에 의존하지 않습니다.

→

언어목록 접근최고 매치

검출 결과가 없을 때

매칭 실패가 항상 함수 오류를 뜻하지는 않습니다. 검출되지 않은 경우 결과 목록은 비어 있고 best()는 Rust에서 None, C#에서 null, Python에서 None으로 표현됩니다.

C#에서 결과 읽기

C#
// model, image, spec을 정상 생성한 상태라고 가정합니다.
MatchResult result = model.Find(image, spec);
Match? best = result.Best;
if (best.HasValue)
{
    Console.WriteLine(best.Value.Score);
}

이것은 이미 준비된 객체를 사용하는 소비 코드 발췌입니다. 학습부터 전체 탐색까지 실행하는 완전한 예제는 별도 검증 후 추가합니다.

iMatch 점수는 확률이 아닙니다. ROI 지역 좌표와 원본 전역 좌표, 모델별 점수 의미를 구분해야 합니다. MatchResult의 값 스냅샷을 네이티브 자원인 MatchModel처럼 Dispose하지 않습니다.

해제와 동시 접근의 확인 범위

C#의 QueryBuilder는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.

해제 후 접근과 독립 임대 예제

C#
using System;
using ZVision;

class Program {
    static void Main() {
        var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
        using var shared = source.Share();
        source.Dispose();
        Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11
        try { _ = source.Info; }
        catch (ObjectDisposedException) { Console.WriteLine("source closed"); }
    }
}

이 코드는 소스 계약을 설명하는 합성 사례입니다. 관련 검증 사례는 Rust의 rust-roi-query와 관리형의 ownership-query입니다. 원본·ROI 해제 후 계획 실행, 독립 캡처와 복제 분기를 확인합니다. 실행 결과는 통합 검증에서 확인합니다.

관련 검증 사례

  • rust-roi-query
  • ownership-query
