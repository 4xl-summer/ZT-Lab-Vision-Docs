Share와 복사

같은 픽셀 버퍼를 공유하는 소유 이미지와 독립 복사 결과를 비교합니다.

독립 HTML 페이지코드 검토 기준 2026-11-08초기 콘텐츠

서로 다른 소유 객체, 같은 저장소

share() / Share()는 픽셀 복사 없이 같은 픽셀 저장소를 소유하는 별도 이미지를 반환합니다. 따라서 원본을 해제해도 공유 이미지에서 데이터를 읽을 수 있습니다.

sourceZImage 핸들 A
→
share()같은 저장소
→
sharedZImage 핸들 B
방법픽셀 복사결과 성격
Share아니오동일한 픽셀 영역을 공유하는 소유 이미지
ROI아니오선택된 부분만 바라보는 소유 이미지
Rust clone_deep()예독립적인 연속 픽셀 버퍼
C# ToArrayGray8()예독립적인 바이트 배열

Rust 예제

Rust
use zvision::ZImage;

fn main() -> zvision::ZResult<()> {
    let original = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let shared = original.share();
    assert!(original.shares_storage_with(&shared));
    drop(original);
    assert_eq!(shared.to_packed_vec()?, vec![9, 10, 11]);
    Ok(())
}

메모리 설계에서 주의할 점

공유는 복사 감소에 유리하지만 원본과 공유 이미지가 서로 다른 값을 갖도록 픽셀을 변경하고 싶을 때는 독립 저장소가 필요합니다. ZVision의 기본 모델은 불변 이미지 공유이며 공유 중인 데이터를 몰래 변경하지 않습니다.

!C#에 Rust의 clone_deep()과 동일한 이름의 메서드가 있다고 추정하지 마세요. 언어별 제공 API는 실제 Wrapper를 확인해 문서화해야 합니다.
