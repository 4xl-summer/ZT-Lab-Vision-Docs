Share와 복사

같은 픽셀 버퍼를 공유하는 소유 이미지와 독립 복사 결과를 비교합니다.

독립 HTML 페이지코드 검토 기준 2026-11-08설계 v1 적용 · 소스 대조

1. Share는 어떤 복사도 하지 않을까?

share()/Share()는 픽셀 데이터를 복사하지 않고 같은 저장소를 참조하는 별도 소유 객체를 반환합니다. roi()도 특정 사각 영역만 가리키는 소유 객체입니다. 반면 Rust clone_deep()과 관리형 언어의 픽셀 배열 복사는 별도 데이터 저장소를 생성합니다.

2. 복사·소유권 비교

연산반환픽셀 복사원본 해제 후
Share / share새 소유 ZImage없음결과 이미지 유효
Roi / roi새 소유 ZImage 영역 뷰없음결과 ROI 유효
Rust clone_deep새 소유 ZImage있음독립 버퍼 유효
Python clone_deep새 소유 ZImage있음독립 버퍼 유효
C# ToArrayGray8byte[]있음배열 데이터 유효
iC#에서는 다른 파일의 공개 확장/Query 메서드와 기본 ZImage 인스턴스 메서드를 혼동해서는 안 됩니다. CloneDeep의 호출 위치/확장 여부는 사용하는 SDK 버전의 실제 API를 확인합니다.

3. Rust에서 저장소 공유와 깊은 복사를 직접 구분

Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let shared = source.share();
    let copy = source.clone_deep()?;
    assert!(source.shares_storage_with(&shared));
    assert!(!source.shares_storage_with(&copy));
    drop(source);
    assert_eq!(shared.to_packed_vec()?, vec![9, 10, 11]);
    assert_eq!(copy.to_packed_vec()?, vec![9, 10, 11]);
    Ok(())
}

4. C#에서 수명 분리

C#
using System;
using ZVision;

var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
using var shared = source.Share();
source.Dispose();
Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11

5. Python의 같은 계약

Python
from zvision import ZImage

with ZImage.from_gray8(3, 1, bytes([9, 10, 11])) as source:
    with source.share() as shared:
        with source.clone_deep() as copied:
            assert shared.to_array_gray8() == [9, 10, 11]
            assert copied.to_array_gray8() == [9, 10, 11]

6. 실무 선택 기준

상황선택이유
원본 전체를 여러 읽기 전용 단계에서 참조Share버퍼 중복 할당 방지
이미지 일부만 검사ROI픽셀 복사 없는 영역 선택
다른 저장소에서 독립 처리/보관Deep Copy스토리지 분리
외부 시리얼화/디버그 출력Packed Array Copy연속된 스냅샷

원본 메모리 유지가 의도보다 길어졌다면 ROI/Share가 아직 살아 있는지 확인하세요. 외부 스레드와 수정 가능한 데이터의 동시 사용 안전성은 별도 계약 확인 없이 추정해서는 안 됩니다.
