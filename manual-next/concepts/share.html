공유 저장소와 독립 복사의 소유권

share() / Share() 는 픽셀 데이터를 복사하지 않고 같은 저장소를 참조하는 별도 소유 객체를 반환합니다. roi() 도 특정 사각 영역만 가리키는 소유 객체입니다. 반면 Rust clone_deep() 과 관리형 언어의 픽셀 배열 복사는 별도 데이터 저장소를 생성합니다.

원본 메모리 유지가 의도보다 길어졌다면 ROI/Share가 아직 살아 있는지 확인하세요. 외부 스레드와 수정 가능한 데이터의 동시 사용 안전성은 별도 계약 확인 없이 추정해서는 안 됩니다.

C#의 QueryBuilder 는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException 입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError 입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.
