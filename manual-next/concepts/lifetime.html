객체 수명과 메모리 관리

Rust Drop·C# Dispose·Python close와 결과 객체의 독립 수명 및 현장 디버깅.

독립 HTML 페이지코드 검토 기준 2026-11-08설계 v1 적용 · 소스 대조

1. 픽셀 저장소와 객체 수명은 별개다

이미지 객체가 여러 개여도 같은 픽셀 저장소를 공유할 수 있습니다. 이를 이용하면 각 단계에 고비용 이미지 복사를 반복하지 않고 안전한 참조 수명을 관리할 수 있습니다. 하지만 관리형 언어의 네이티브 핸들을 Dispose하지 않으면 현장 장시간 실행 시 메모리 증가를 경험할 수 있습니다.

3. Rust의 소유권

Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let image = ZImage::from_vec_gray8(2, 1, vec![3, 4])?;
    let shared = image.share();
    drop(image);
    assert_eq!(shared.to_packed_vec()?, vec![3, 4]);
    Ok(())
}

4. C#에서 Dispose 누락 방지

C#
using System;
using ZVision;

using var source = ZImage.FromGray8(3, 1, new byte[] { 1, 2, 3 });
using var roi = source.Roi(1, 0, 2, 1);
using var result = roi.Threshold(2.0);
Console.WriteLine(string.Join(",", result.ToArrayGray8())); // 255,255

리턴 이미지와 ROI는 네이티브 핸들 소유 객체입니다. using은 이를 스코프 종료 시 명시적으로 해제합니다. 매 프레임 새 이미지를 만드는 검사 소프트웨어라면 반복 루프의 반환 객체마다 수명을 점검합니다.

5. Python의 context manager

Python
from zvision import ZImage
with ZImage.from_gray8(2, 1, bytes([3, 4])) as image:
    with image.share() as shared:
        assert shared.to_array_gray8() == [3, 4]

6. 현장 메모리·해제 오류 점검

증상점검
프레임 처리 후 RSS 증가ZImage / QueryExecution / AiResult 등 네이티브 소유 객체 확인
원본 Dispose 후 ROI도 못 읽음ROI가 별도 소유 결과인지, 스코프 내에서 이미 해제됐는지 확인
검출은 정상인데 Best 속성에서 오류Result가 빈 경우인지, 잘못된 Nullable 접근인지 확인
Query 분기 간 간섭가변 managed Builder 별칭 여부와 Clone 호출 확인
i현재 페이지는 공개 소스에 따른 수명 계약 설명입니다. 수백 시간 누수·동시성·실장비 부하 테스트를 이 문서 개정에서 실행한 것은 아닙니다.
