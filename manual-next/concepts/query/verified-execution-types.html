C# 이미지 계획의 Threshold/Capture 등은 기존 빌더를 바꿔 같은 객체를 반환합니다. 별칭은 같은 계획이고 분기는 Clone()이 필요합니다. 변경 실패 시 기존 계획은 유지됩니다. Rust의 변환은 self를 소비하므로 사용한 이전 변수는 다시 쓸 수 없고 분기에는 미리 clone합니다. Execute는 지연 계획을 실행하며 결과 종류는 터미널에 따릅니다. 캡처하지 않은 이름을 요청하면 오류입니다.

같은 이름의 실행 동작이라도 최종 결과의 종류는 계획의 터미널에 따라 달라집니다. 영상 변환으로 끝난 계획에서는 이미지 출력이 필요하고, 프로파일이나 캘리퍼 터미널은 각각 표본이나 에지 결과를 만듭니다. 결과 타입에 맞는 접근자를 사용해야 하며, 이미지 출력을 기대하고 다른 종류의 결과를 읽으려 해서는 안 됩니다.

중간 단계를 나중에 보고 싶다면 그 지점에 이름을 지정해 캡처한 후 실행합니다. 이름은 그 실행에서 저장한 항목을 찾는 열쇠이므로 표기나 대소문자가 달라져 조회되지 않는 상황을 고려해야 합니다. 최종 출력이 정상이어도 지정하지 않은 이름의 캡처가 저절로 생성되지는 않습니다.

관리형 빌더에서는 계획을 변경할 때 같은 객체를 갱신하고, Rust에서는 이전 값을 소비해 새 계획을 만듭니다. 같은 원본에서 서로 다른 처리 순서를 만들려면 각 언어의 복제 경로를 먼저 사용하십시오. 실패한 추가를 성공한 계획 단계로 간주하지 말고 오류를 확인해야 합니다.

적용 순서와 결과 판독

실행 결과는 최종 영상 하나와 이름을 붙인 중간 결과를 구별할 수 있는 경로를 제공합니다. 원본을 캡처한 후 이진화하고 다시 캡처한 경우 두 이름이 가리키는 처리 시점이 다릅니다. 나중에 표시한 두 영상이 우연히 같더라도 같은 객체 또는 같은 처리 단계라고 가정하지 마십시오. 필요한 이미지를 결과에서 가져온 다음 결과 소유자와 이미지의 수명 조건을 해당 언어의 반환 타입에 맞게 관리합니다.
