해제와 동시 접근의 확인 범위

C#의 QueryBuilder는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.

그림으로 이해하기

수명 문제를 확인할 때는 어떤 객체의 잠금을 어떤 메서드가 사용하는지 범위를 나누어야 합니다. C#의 해당 빌더 구현은 같은 객체에 대한 변경, 복제, 실행과 해제를 잠금으로 보호합니다. 따라서 동시에 요청한 두 작업의 실제 순서는 잠금 획득 순서에 달려 있으며 호출을 시작한 시각만으로 어느 쪽이 먼저 완료될지 정할 수 없습니다.

빌더가 이미 해제된 뒤 새 호출을 하면 닫힌 객체 오류가 발생합니다. 실행 객체에서 소유 이미지를 먼저 획득했다면 그 이미지는 별도의 소유권을 가지므로 실행 객체를 닫은 뒤에도 사용할 수 있습니다. 이미지를 다 쓴 뒤에는 그 이미지도 자신의 수명 규칙에 따라 해제해야 합니다.

Python의 해당 typed 실행에서는 출력 획득과 close가 같은 잠금 아래에 있고 닫힌 실행의 조회는 ValueError입니다. 이 관찰을 외부 버퍼, 다른 종류의 객체 또는 모든 동시 수정에 대한 보장으로 확대하지 말고 작업별 소유자와 종료 순서를 설계하십시오.

적용 순서와 결과 판독

종료와 실행이 겹치는 상황은 수명 문제이므로 정상적인 순차 호출과 따로 검토해야 합니다. 작업을 시작하기 전에 입력과 실행 객체가 살아 있는지 확인하고, 사용이 끝난 뒤 해제하는 순서를 정하십시오. 여러 작업이 같은 객체를 공유한다면 호출자가 작업 종료를 기다린 다음 해제하는 방식으로 소유 관계를 명확히 할 수 있습니다. 문서에 확인된 예외는 해당 언어의 경계에서 처리하며, 실패한 호출의 결과를 유효한 영상으로 사용하지 않습니다.
