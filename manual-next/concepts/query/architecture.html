연산 계획과 실행을 구분한다

ZImage의 직접 이미지 변환은 호출 즉시 계산하지만, ImageQuery는 실행할 작업을 축적합니다. query()가 입력 이미지 저장소를 공유하며 threshold() 등의 연산을 추가해도, 실제 픽셀 처리는 execute()에서 발생합니다.

판독 기준

  • 같은 페이지의 기존 draw.io 그림과 중복하지 않습니다.
  • 정확한 실행 메서드와 반환형은 언어별 API에서 확인합니다.
  • 구성 성공만으로 실행 성공이나 특정 입력 형식의 지원이 보장되지는 않습니다.

수치와 도형은 연결된 계약의 핵심 관계를 설명하는 예입니다. 실제 SDK 출력으로 명시한 자료를 제외하면 실행 결과나 장비 실측으로 해석하지 않습니다. 좌표계·입력 형식·수명과 오류 조건은 관련 API 계약을 확인한 뒤 적용하세요.

단계실행 의미수명·결과
이미지 직접 메서드호출 시 픽셀 계산새 ZImage 반환
Query 생성입력 저장소 공유지연 계획
Capture 추가중간 결과 보관 지점 예약문자열로 식별
execute / Execute연산 수행결과와 캡처를 가진 실행 객체

계획은 처리 순서를 기술하는 객체이고 실행은 그 계획을 특정 입력에 적용한 결과입니다. 예를 들어 먼저 원본을 저장할 지점을 표시하고 임계값을 적용한 뒤 이진 결과를 다시 저장하도록 계획할 수 있습니다. 계획을 구성하는 시점에는 중간 픽셀 값을 읽을 수 없으며, 실행이 완료되어야 출력과 이름 붙인 이미지를 얻을 수 있습니다.

직접 영상 메서드는 호출에서 바로 새 영상을 만듭니다. 반면 지연 계획을 사용하면 여러 단계를 묶고 같은 계획을 다시 실행하는 구성을 명시적으로 표현할 수 있습니다. 계획이 원본 저장소를 공유한다는 사실과 반환 이미지를 독립적으로 보유하는 방식은 별개이므로 각 객체의 소유권을 확인하십시오.

설정 자체가 유효하지 않으면 계획 구성 단계에서 오류가 날 수 있고 픽셀 값 문제는 실행 중 드러날 수 있습니다. 캡처 이름을 잘못 요청한 경우에도 실제 저장된 이름과 호출 시점을 확인해야 합니다. 그림은 이 순서를 보여 주며 내부 스레드 배치를 나타내지 않습니다.
