검증 시점과 결과 수명

입력 형식과 임계값의 유한성은 계획 추가 중에 검사될 수 있지만, 비유한 부동소수 입력 픽셀은 실행 단계에서 거절됩니다. 반환된 출력·Capture 이미지는 독립적인 공유 이미지 소유권을 가질 수 있습니다. 실행 객체가 보유한 캡처를 해제할 때, 이전에 얻은 소유 이미지를 자동으로 무효화하면 안 됩니다.

!Rust 공개 ImageQuery / QueryExecution과 기존 Query 수명 테스트의 계약을 참고했습니다. C#·Python의 가변 Builder 규칙은 최신 API 이행 기록에 명시되어 있습니다.

지연 실행에서는 오류가 발생한 단계가 원인을 좁히는 단서가 됩니다. 계획에 추가하는 값의 형식이나 임계값이 유효하지 않다면 실행 전 검사에서 거부될 수 있습니다. 반면 입력 영상의 부동소수 픽셀처럼 실제 데이터를 읽어야 알 수 있는 문제는 계획을 실행할 때 나타날 수 있습니다. 같은 오류 메시지로 모든 실패를 묶지 말고 반환된 단계와 입력 설정을 함께 기록하십시오.

실행 결과에는 최종 출력과 명명된 중간 이미지가 포함될 수 있습니다. 요청한 이름이 캡처된 이름과 다르면 정상적인 출력이 있어도 해당 조회는 실패합니다. 따라서 저장 시 사용한 문자열을 확인하고 존재하지 않는 이름을 빈 영상으로 대체하지 않는 것이 좋습니다.

획득한 출력이 독립 소유 이미지라면 실행 객체를 먼저 닫은 뒤에도 그 이미지의 수명은 별도로 관리됩니다. 내부 값을 빌려 읽는 경우에는 소유자의 수명을 넘지 않도록 해야 합니다. 정확한 규칙은 사용하는 언어와 반환 타입에 따라 확인하십시오.

적용 순서와 결과 판독

계획을 만드는 단계에서의 실패와 실제 영상 처리를 실행하는 단계의 실패는 진단 지점이 다릅니다. 예를 들어 이름으로 중간 결과를 요청할 때 등록한 이름과 다르면 해당 캡처를 찾을 수 없으며, 이것은 영상의 픽셀값이 모두 0이라는 뜻이 아닙니다. 실행이 성공했는지 확인한 다음 요청 이름과 캡처 등록 시점을 대조하십시오. 이미 해제한 객체를 다시 사용하는 문제도 빈 이미지나 정상 결과로 바꾸지 말고 수명 오류로 처리해야 합니다.
