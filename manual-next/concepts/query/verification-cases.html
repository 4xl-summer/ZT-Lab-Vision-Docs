관련 검증 사례

지연 계획의 실행 사례에서는 입력, 중간 캡처와 최종 출력이 각각 어떤 값을 갖는지 비교합니다. rust-roi-query는 Rust 쪽 ROI와 계획 흐름을 확인하고, ownership-query는 결과 및 소유권 경로를 확인하는 기록에 연결됩니다. 각각의 실제 입력과 실행 언어를 확인한 뒤 기대값을 해당 사례에 적용해야 합니다.

세 픽셀 [9,10,11]에 임계값 10을 적용하는 설명 예에서는 출력 [0,255,255]를 기대합니다. 처리 전 이미지와 처리 후 이미지를 다른 이름으로 캡처한다면 최종 출력과 후자의 캡처가 같은지, 원본 캡처는 변환 전 값인지 따로 비교할 수 있습니다. 이름이 누락된 조회는 성공 결과와 별도로 오류 경로를 확인해야 합니다.

해제 순서도 결과 값만큼 중요합니다. 실행을 닫기 전에 얻은 소유 이미지가 유효한지와 닫힌 실행의 재조회가 어떻게 처리되는지를 기록하십시오. 합성 입력 검증은 실제 촬영이나 동시성 전반에 대한 성능 평가가 아닙니다.

한 번 실행한 결과가 이미 획득한 이미지의 소유권을 어떻게 전달하는지 확인한 뒤, 계획 자체를 재사용하는 실험도 별도로 구성할 수 있습니다. 입력 계획의 복제 여부와 해제 순서를 기록하면 같은 결과값이 나왔더라도 서로 다른 수명 경로를 구별할 수 있습니다. 캡처 이름의 오타는 픽셀 처리의 실패와 별개로 진단합니다.

적용 순서와 결과 판독

검증할 때는 입력 영상과 각 캡처 이름, 등록 시점을 함께 기록합니다. 예를 들어 원본을 캡처한 다음 이진화 결과를 다른 이름으로 캡처하면 한 실행에서 두 단계의 영상을 비교할 수 있습니다. 없는 이름을 요청하는 사례는 처리된 검은 영상이 아니라 캡처 조회 실패를 확인하는 사례입니다. Rust의 계획 분기는 복제 지점과 소유권을 포함해 기록하고, 관리형 결과는 사용이 끝난 뒤 수명에 맞게 해제합니다.

확인 단계판독과 조치
원본 캡처첫 단계의 이름과 입력을 대조합니다.
처리 후 캡처변경된 영상과 별도 이름을 비교합니다.
없는 이름조회 실패를 빈 영상과 구별합니다.
종료객체 사용이 끝난 뒤 해제 순서를 확인합니다.
