관련 API

이미지에서 시작하는 지연 작업은 이미지 쿼리로 만들고, 변환을 연결하거나 특정 결과를 만드는 터미널로 끝냅니다. 중간 영상을 나중에 읽고 싶다면 실행 전에 캡처 이름을 지정합니다. 실행 후에는 결과 유형에 맞는 출력 접근자와 이름 기반 이미지 조회를 사용합니다.

분기할 때는 언어별 계획 변경 방식을 구분합니다. Rust에서는 소비되는 계획을 미리 복제하고, C#과 Python의 가변 빌더에서도 별칭 대신 명시적 복제를 사용해야 독립적으로 단계를 추가할 수 있습니다. 각 실행의 출력이 이미지인지 표본·에지 같은 값 결과인지에 따라서도 읽는 방법이 달라집니다.

획득한 영상은 실행 객체와 별도로 소유될 수 있으며 해제 규칙을 확인해야 합니다. 이미 닫힌 실행이나 저장하지 않은 이름의 조회는 오류입니다. 임계값 적용 결과만 필요하다면 직접 이미지 변환도 선택할 수 있으나 여러 처리 단계와 중간 관찰을 조합할 때는 지연 계획의 구성이 더 분명합니다.

예를 들어 임계값 처리 전의 입력과 처리 후의 마스크를 둘 다 보려면 각각의 시점에 서로 다른 캡처 이름을 지정합니다. 단일 최종 결과만 필요한 호출과 달리 실행 객체는 이 이름에 따라 중간 이미지를 찾습니다. 처리 계획을 추가하는 시점의 오류와 실행 시 실제 픽셀 처리 오류도 다르게 다루어야 합니다.

적용 순서와 결과 판독

처리 계획은 연산의 순서를 정의하고 실행 결과는 그 계획을 특정 입력에 적용해 얻은 값을 제공합니다. 중간 상태가 필요한 경우 원하는 시점마다 서로 다른 캡처 이름을 지정하십시오. 실행 전에 계획을 분기할 때는 각 언어의 복제 및 소유권 규칙에 따라 두 계획의 독립성을 확보해야 합니다. 실행 이후에는 최종 영상과 이름으로 찾은 중간 영상을 구별하고, 반환된 객체의 수명이 유지되는 동안만 사용합니다.

확인 단계판독과 조치
계획 구성실행할 연산의 순서를 만듭니다.
계획 분기필요한 시점에 독립된 계획을 준비합니다.
실행과 캡처입력을 적용하고 각 중간 결과를 이름으로 구별합니다.
결과 수명언어별 반환 타입과 해제 순서를 따릅니다.
