Rust — Capture와 결과 이미지

Rust
use zvision::ZImage;

fn main() -> zvision::ZResult<()> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let plan = source.query()?
        .capture("original")?
        .threshold(10)?
        .capture("binary")?;
    let execution = plan.execute()?;
    let output = execution.acquire_output();
    let captured = execution.get_image("binary")?;
    assert_eq!(output.to_packed_vec()?, vec![0, 255, 255]);
    assert_eq!(captured.to_packed_vec()?, vec![0, 255, 255]);
    Ok(())
}

Rust 공개 Facade에서는 작업 추가 메서드가 self를 소비해 새 계획을 반환합니다. 분기하려면 clone()을 명시적으로 사용합니다. execute(&self)는 계획을 빌려 여러 번 실행할 수 있습니다.

이 예제의 입력은 한 줄에 9, 10, 11이 들어 있는 세 픽셀 영상입니다. 임계값 10은 비교 기준이며 결과로 제시된 값은 0, 255, 255입니다. 원본을 지정한 이름으로 캡처한 다음 변환을 추가하고 변환된 단계도 별도 이름으로 캡처하므로, 최종 출력과 중간 결과의 관계를 같은 실행에서 살펴볼 수 있습니다.

Rust에서 계획에 연산을 더하는 메서드는 이전 계획 값을 소비해 새 값을 돌려줍니다. 갈라지는 두 계획이 필요하면 사용하기 전에 복제해야 하며 단순히 이미 이동한 변수를 다시 사용하는 방식은 성립하지 않습니다. 실행 메서드는 계획을 빌리므로 생성된 계획을 다시 실행할 수 있습니다.

실행에서 획득한 출력과 이름 붙인 이미지는 각각 소유권을 갖는 공유 이미지입니다. 이름이 존재하지 않으면 조회 오류를 처리해야 합니다. 합성 세 픽셀은 경계값 판정을 이해하기 위한 입력이며 장비 데이터의 분포를 대표하지 않습니다.

원본 캡처와 이진 캡처의 이름은 서로 다릅니다. 최종 영상이 이진 결과와 같다고 해서 원본 캡처까지 이진 값으로 해석하면 안 됩니다. 각 이름을 지정한 처리 단계와 연결해서 읽으십시오.
