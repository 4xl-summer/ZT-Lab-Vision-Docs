상위 목차로 돌아가기

3. Rust의 소유권

Rust
use zvision::ZImage;
fn main() -> zvision::ZResult<()> {
    let image = ZImage::from_vec_gray8(2, 1, vec![3, 4])?;
    let shared = image.share();
    drop(image);
    assert_eq!(shared.to_packed_vec()?, vec![3, 4]);
    Ok(())
}

원리와 입력

Rust 예제에서 영상과 모델은 소유 값으로 범위 안에 보관되고 더 이상 필요하지 않으면 Drop으로 정리됩니다. 입력 영상을 빌려 임계값을 적용하면 반환 영상은 새 값으로 받으므로 원본 변수와 결과 변수의 범위를 각각 이해할 수 있습니다. 오류를 반환하는 호출은 물음표 연산자로 상위 함수에 전달하여 생성 실패와 이후 계산 실패를 구별합니다.

적용과 확인

Query 체인은 관리형의 가변 빌더와 표현 방식이 다릅니다. 계획을 구성하는 호출이 값을 이동시키는 경우 이전 변수를 그대로 다시 쓰려고 하면 소유권 오류가 납니다. 두 독립 흐름이 필요하면 제공된 복제 또는 새 계획을 사용하는 위치를 설계해야 합니다. ROI가 공유하는 저장소는 별도 참조를 보유한 값의 수명 동안 유지되지만 닫힌 또는 이동된 변수를 다시 사용하는 근거는 아닙니다. 빌림과 반환 형식은 실제 Rust 선언을 기준으로 확인하세요.

적용할 때 살펴볼 점

합성 입력과 반환을 서로 다른 변수에 두면 컴파일러가 어느 값이 이동되었는지 확인하는 데 도움이 됩니다. 원본 데이터와 별도로 결과 영상을 보존하려면 반환값의 소유권이 필요한 범위까지 유지되어야 합니다. 오류 전파를 사용하는 경우에도 이미 소유한 값의 정리와, 호출 결과가 실제로 생성되었는지를 함께 구분합니다.

소유 값이 이동되었다는 컴파일 오류가 생기면 오류를 억제하기보다 계획의 재사용 지점과 빌림 범위를 확인하세요. 필요한 별도 값이 무엇인지 정한 다음 제공되는 복제 경로를 선택합니다.
