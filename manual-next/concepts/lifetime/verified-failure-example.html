해제 후 접근과 독립 임대 예제의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

해제 후 접근과 독립 임대 예제

C#
using System;
using ZVision;

class Program {
    static void Main() {
        var source = ZImage.FromGray8(3, 1, new byte[] { 9, 10, 11 });
        using var shared = source.Share();
        source.Dispose();
        Console.WriteLine(string.Join(",", shared.ToArrayGray8())); // 9,10,11
        try { _ = source.Info; }
        catch (ObjectDisposedException) { Console.WriteLine("source closed"); }
    }
}

이 코드는 소스 계약을 설명하는 합성 사례입니다. 관련 검증 사례는 Rust의 rust-roi-query와 관리형의 ownership-query입니다. 원본·ROI 해제 후 계획 실행, 독립 캡처와 복제 분기를 확인합니다. 실행 결과는 통합 검증에서 확인합니다.

원리와 입력

수명 확인 사례에서는 원본 영상에서 Share와 ROI를 만든 뒤 원본을 닫습니다. 이때 이미 취득한 별도 핸들에서 보이는 픽셀은 계속 읽을 수 있어야 하지만, 닫힌 원본 핸들에 다시 접근하는 호출은 오류가 됩니다. 두 결과를 동시에 확인해야 저장소의 참조와 특정 핸들의 상태를 혼동하지 않습니다. 예제에서 원본 [1,7,9]와 ROI [7,9]를 사용하면 기대값을 손으로 계산할 수 있습니다.

적용과 확인

Query에서도 출력과 이름 붙인 캡처를 실행이 살아 있을 때 취득한 다음 실행을 닫고, 취득한 영상을 읽은 후 각각 닫는 순서를 검증합니다. 이것은 예외 처리를 생략해도 된다는 의미가 아닙니다. 취득 자체가 실패한 경로에서는 이미 얻은 다른 핸들을 정리해야 합니다. 이 사례는 SDK가 제공하는 소유 객체의 계약을 보여 주며 외부 버퍼나 임의의 동시 변경 상황에까지 범위를 넓히지 않습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
원본[1,7,9]Share와 ROI를 먼저 획득
원본 종료닫힌 원본 재접근오류 확인
공유[1,7,9]별도 핸들로 읽기
ROI[7,9]종료 전 픽셀 확인

공유 결과의 값과 원본의 닫힘 오류는 서로 다른 검증입니다. 하나가 성공했다고 다른 하나도 자동으로 확인한 것은 아니므로 두 관찰과 정리 순서를 각각 기록하세요.
