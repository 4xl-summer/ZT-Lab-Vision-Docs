해제와 동시 접근의 확인 범위

C#의 QueryBuilder는 계획 변경·복제·실행·Dispose를 같은 인스턴스 잠금 안에서 처리합니다. 따라서 해당 구현에서 먼저 잠금을 얻은 호출이 끝난 다음 다른 호출이 진행됩니다. 해제가 먼저 완료된 뒤 호출하면 ObjectDisposedException입니다. 실행 결과의 획득과 Dispose도 해당 실행 객체의 잠금으로 보호되며, 먼저 얻은 독립 영상과 값은 실행 해제 후에도 유효합니다. Python의 typed 실행도 output/get_image와 close를 같은 잠금으로 처리하며 닫힌 실행은 ValueError입니다. 이는 확인한 래퍼 메서드의 범위이지 모든 객체, 외부 버퍼, 같은 핸들에 대한 임의의 동시 수정이나 순서까지 보장하는 일반 계약은 아닙니다. 작업별 소유권과 종료 순서를 명시하세요.

원리와 입력

관리형 Query 빌더에서 계획 변경, 복제, 실행과 해제는 해당 인스턴스의 잠금으로 직렬화됩니다. 실행 객체의 출력 획득과 해제도 같은 실행에 대한 잠금으로 보호되므로, 먼저 획득한 독립 영상은 실행 해제 후 별도의 핸들로 남습니다. 해제가 먼저 완료되었다면 그 객체에 대한 다음 접근은 C# ObjectDisposedException 또는 Python typed 실행의 ValueError로 나타납니다.

적용과 확인

이 범위는 확인된 특정 래퍼 메서드에 관한 설명입니다. 모든 객체와 사용자가 제공한 외부 메모리의 동시 수정, 서로 다른 작업의 순서, 카메라 프레임 처리량까지 자동으로 보장하지 않습니다. 작업마다 누가 객체를 보유하고 언제 종료하는지 정하고, 필요한 출력을 먼저 취득한 뒤 실행을 닫는 방식으로 흐름을 명확히 하세요. 경합을 다루는 실제 응용에서는 사용하는 객체와 스레드 구조를 기준으로 별도의 검증이 필요합니다.

획득 성공과 종료 완료를 구별

C# 실행의 GetImage와 Dispose가 같은 실행 객체에서 경합할 때 두 결과를 구분할 수 있습니다. GetImage가 잠금 안에서 먼저 완료되어 독립 소유 영상이 반환되면 그 영상을 실행 정리 후에도 사용할 수 있고, 영상 소유자는 사용 후 별도로 Dispose해야 합니다. Dispose가 먼저 끝나면 이후 GetImage는 ObjectDisposedException이므로 새 영상 핸들을 받은 것으로 간주하지 않습니다.

Python typed 실행도 output 또는 get_image와 close가 같은 실행의 잠금으로 보호됩니다. 먼저 얻은 독립 영상은 나중에 따로 close하고, close가 먼저 완료된 실행에 새 접근을 시도하면 ValueError를 처리합니다. 예외 경로에서도 이미 얻은 영상만 정리하고 얻지 못한 출력을 성공 결과처럼 기록하지 마세요. 종료 책임자가 실행과 반환 영상의 마지막 사용 시점을 각각 알아야 정리 순서를 재현할 수 있습니다.
