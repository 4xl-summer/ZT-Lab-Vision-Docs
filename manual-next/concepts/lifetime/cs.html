4. C#에서 Dispose 누락 방지

C#
using System;
using ZVision;

using var source = ZImage.FromGray8(3, 1, new byte[] { 1, 2, 3 });
using var roi = source.Roi(1, 0, 2, 1);
using var result = roi.Threshold(2.0);
Console.WriteLine(string.Join(",", result.ToArrayGray8())); // 255,255

리턴 이미지와 ROI는 네이티브 핸들 소유 객체입니다. using은 이를 스코프 종료 시 명시적으로 해제합니다. 매 프레임 새 이미지를 만드는 검사 소프트웨어라면 반복 루프의 반환 객체마다 수명을 점검합니다.

원리와 입력

C#에서는 소유 영상과 모델, Query 빌더 또는 실행 객체의 사용 범위를 using으로 명확히 표현할 수 있습니다. 예를 들어 입력을 만들고 Threshold 결과를 다른 using 변수로 받으면 두 핸들은 각 범위가 끝날 때 정리됩니다. 예외가 발생하더라도 using 범위의 정리 흐름은 유지됩니다. 단순히 변수를 null로 바꾸는 것을 명시적 자원 해제와 같은 뜻으로 쓰지 마세요.

적용과 확인

ROI나 Share를 별도로 취득한 경우 그 핸들도 사용 후 Dispose합니다. 실행 결과에서 얻은 캡처 영상을 실행 객체와 별개로 보유할 때도 각각의 using 범위를 정해야 합니다. 한편 MatchResult는 독립 값 스냅샷이므로 모델의 Dispose와 같은 해제 대상으로 취급하지 않습니다. ObjectDisposedException이 발생했다면 어떤 객체가 먼저 닫혔는지 호출 경로를 추적하고, 아직 필요한 결과는 소유권이 유효할 때 취득했는지 확인하세요.

값과 판독 기준

단계입력 또는 결과확인할 점
입력 영상using source첫 소유 범위
결과 영상using result별도 소유 범위
매치 값MatchResult독립 스냅샷
닫힘 후소유 핸들 재사용ObjectDisposedException 확인

예외를 잡은 뒤에도 이미 만든 별도 핸들이 남아 있을 수 있습니다. using 범위가 각 객체를 감싸는지 확인하면 정상 경로와 예외 경로의 정리 위치를 같은 코드에서 확인할 수 있습니다.
