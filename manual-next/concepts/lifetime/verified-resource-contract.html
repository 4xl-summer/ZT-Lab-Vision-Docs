반환 자원과 실패

호출반환과 해제실패 분기
Share / Roi원본 저장소를 참조하는 별도 소유 영상. 각자 Dispose/close 또는 Drop.범위 밖이나 빈 ROI는 오류; 원본 해제 전에 얻은 ROI는 계속 유효.
Query Execute실행은 캡처 소유; AcquireOutput/GetImage로 얻은 영상은 별도 소유.닫힌 실행에서 획득 시 C# ObjectDisposedException, Python ValueError.

AlignmentResult소유 핸들 및 획득한 영상마다 각각 해제.Found=false일 때 Aligned/ValidMask를 획득하지 않음.

원리와 입력

공개 API의 반환 계약을 확인할 때는 이름보다 반환 형식을 먼저 봅니다. 영상 처리와 이미지 획득은 보통 호출자가 닫아야 할 소유 객체를 반환하지만, 모든 Result가 네이티브 핸들인 것은 아닙니다. MatchResult는 매치 값을 복사한 스냅샷이며, Query 실행의 output도 형식에 따라 값 스냅샷 또는 별도 취득이 필요한 이미지·리소스일 수 있습니다.

적용과 확인

실패 경로에서도 소유 관계를 유지해야 합니다. 실행 객체를 만든 다음 캡처를 얻는 과정에서 오류가 나면 이미 생성된 객체를 정리할 범위가 필요합니다. 성공한 경우 얻은 영상은 실행 객체를 닫은 뒤에도 독립 핸들로 사용할 수 있으나, 그 영상은 사용 후 별도로 닫아야 합니다. 빈 매치나 정렬 미발견은 결과 상태로 표현되는 경우가 있으므로 예외 처리와 상태 검사를 모두 작성하고 실제 선언에 적힌 계약을 확인하세요.

적용할 때 살펴볼 점

수명 테스트에서는 소유 결과를 취득하기 전에 실행을 닫는 경우와, 취득한 뒤 실행을 닫는 경우를 서로 다른 사례로 기록합니다. 후자는 얻어 둔 독립 핸들의 수명을 확인하는 것이고 전자는 닫힌 객체에 대한 호출 오류를 확인하는 것입니다. 같은 숫자 출력만으로 두 경우를 구별할 수 없으므로 취득과 종료 순서가 검증 입력의 일부입니다.

예를 들어 실행에서 얻은 영상이 하나라면 실행과 영상은 두 개의 소유 범위입니다. 두 범위를 구별해 기록하면 실행을 닫은 뒤 영상 사용이 끝났을 때 필요한 정리를 놓치지 않습니다.
