관련 API

원리와 입력

ZImage의 Share와 ROI는 같은 픽셀 저장소를 참조하는 별도 영상 핸들을 얻는 출발점입니다. CloneDeep 또는 clone_deep은 픽셀을 독립 저장소에 복사할 때 사용합니다. 각각의 반환 객체는 언어별 방식으로 정리하며, 닫힌 객체에 대한 접근은 더 이상 허용되지 않습니다. 배열 복사 API가 반환하는 값과 여전히 핸들 수명을 가진 영상은 구별해서 보관하세요.

적용과 확인

Query에서는 계획과 실행의 수명을 나누고, 실행에서 획득한 이미지나 리소스를 따로 정리합니다. MatchModel은 소유 모델이지만 Find의 MatchResult는 독립 값 스냅샷입니다. 정렬 검사에서 소유 AlignmentResult와 그로부터 얻은 Aligned 및 ValidMask도 각 반환의 설명을 확인해야 합니다. API 참조에서 반환 유형과 오류를 읽고, 실행 코드에서는 정상 경로뿐 아니라 중간 실패나 빈 결과에서 정리되는 경로를 함께 마련하세요.

값과 판독 기준

적용할 때 살펴볼 점

검사 결과의 이름에 Result가 들어가더라도 소유 핸들인지 값인지 선언을 확인해야 합니다. 이미지나 실행 핸들은 종료 범위를 지정하고, 이미 복사한 스냅샷은 필요한 기간 보관합니다. 이 구분은 예외가 발생한 중간 단계에서도 중요합니다. 성공적으로 취득한 객체가 있다면 이후 단계가 실패해도 그 객체의 정리는 남아 있기 때문입니다.
