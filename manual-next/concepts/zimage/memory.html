2. 메모리와 원점의 관계

layout()은 현재 영상의 행 간격과 오프셋을 나타냅니다. ROI에서 가로 폭과 바이트 stride가 다를 수 있으므로 row-major로 직접 버퍼를 해석할 때는 주의하세요. 결과를 배열로 읽을 때는 Gray8이라면 Rust to_packed_vec(), C# ToArrayGray8(), Python to_array_gray8()처럼 공개된 복사 API를 활용할 수 있습니다.

이미지의 행은 항상 보이는 너비만큼만 이어진 단일 배열로 생각하면 안 됩니다. 부모 이미지에서 잘라낸 ROI는 부모의 저장소를 공유하므로 보이는 행의 길이와 다음 행까지의 실제 간격이 다를 수 있습니다. ROI의 시작 오프셋과 부모 원점도 이미지의 로컬 좌표와 구분해야 합니다. 경계를 직접 계산하려는 대신 해당 형식의 배열 복사 메서드를 사용하면 보이는 픽셀만 연속된 스냅샷으로 얻을 수 있습니다.

Share와 ROI는 각각 새로운 소유 객체를 만들지만 픽셀 저장소를 공유하며, 깊은 복사는 별도 저장소를 만듭니다. 원본 핸들을 닫아도 이미 얻은 공유 객체는 자신의 수명을 유지합니다. 그 출력 공유 뷰가 아직 살아 있으면 전체 버퍼가 해제되지 않을 수 있습니다. 반복 처리에서는 객체 수명과 배열 복사 비용을 함께 고려해야 합니다.

연속 배열로 복사한 픽셀을 수정해도 기존 이미지 핸들의 저장소를 수정하는 호출로 간주해서는 안 됩니다. 복사 출력은 별도 데이터입니다.
