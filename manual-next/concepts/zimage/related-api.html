관련 API

이미지의 기본 정보가 필요하면 ZImage의 Info와 Origin을 살펴보고 현재 보이는 뷰의 크기와 원점을 점검합니다. 전체 저장소를 공유하면서 별도 수명이 필요하면 Share를, 일부 사각형만 사용하려면 Roi를 선택합니다. 원본 픽셀과 분리된 연속 값이 필요할 때는 해당 형식의 배열 복사 기능을 사용합니다. 이 호출들은 모두 같은 의미의 복사가 아닙니다.

Threshold는 조건에 맞는 새 마스크를 만들고, Query는 연산을 실행 전에 계획으로 구성합니다. 관리형 계획을 분기할 때는 Clone을 사용하며 실행 후 획득한 출력과 캡처는 별도로 소유합니다. 호출할 API를 고를 때 입력 형식과 반환값이 이미지 핸들인지 값 스냅샷인지 확인하면 해제 책임을 명확히 할 수 있습니다. 관련 API 표에서 각 언어의 실제 이름과 서명을 확인하세요.

호출마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

예를 들어 ROI를 만든 뒤 임계값을 적용하면 출력은 ROI 크기의 새 마스크입니다. 부모 이미지를 해제해도 이미 얻은 ROI가 살아 있을 수 있지만, 출력 마스크도 별도 소유 객체이므로 독립적으로 관리해야 합니다.

생성, 뷰, 처리의 실제 관계

ZImage.FromGray8에 폭 3, 높이 1, 세 바이트 [9,10,11]을 주면 현재 뷰가 3×1인 영상이 만들어집니다. Info로 형식과 크기를, Origin으로 전역 원점을 확인할 수 있습니다. 픽셀을 읽는 ToArrayGray8은 복사된 배열을 반환하므로 이 배열의 수명과 영상 핸들의 수명을 같은 것으로 보지 않습니다.

Roi(1,0,2,1)은 로컬 범위 [1,3)에서 마지막 두 픽셀을 보는 별도 영상이고, Share는 전체 보이는 영역을 별도 임대로 획득합니다. 둘 다 원본과 픽셀 저장소를 공유할 수 있어 원본이 닫힌 뒤에도 먼저 얻은 소유 뷰는 유지됩니다. 다만 닫힌 원본에서 새로운 Roi나 Share를 요청할 수는 없습니다.

Threshold(10)은 원본을 변경하는 대신 새 Gray8 마스크 [0,255,255]를 반환합니다. Query는 같은 처리를 지연 계획으로 묶을 때 선택하며 C# 빌더의 독립 분기에는 Clone이 필요합니다. 실행의 AcquireOutput이나 GetImage로 얻은 영상도 호출자가 정리합니다. 각 메서드의 반환이 영상인지 값인지에 따라 결과 사용 후의 책임이 달라집니다.
