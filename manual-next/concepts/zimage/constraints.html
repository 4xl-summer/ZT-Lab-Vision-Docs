5. 실패·수명·검증 항목

roi는 현재 이미지 범위 내의 양수 폭·높이를 요구합니다. from_vec_gray8은 전달 데이터 길이가 픽셀 수와 맞아야 합니다. threshold는 특정 7종 Gray 형식만 지원하며 부동소수 데이터의 비유한 값이나 비유한 임계값을 오류로 처리합니다. C#에서는 각 반환 ZImage를 using으로 관리하고, Python은 with 사용을 권장합니다.

iRust ZImage의 width/height/layout/origin은 pub const fn입니다. 기존 자동 선언 색인에서 누락된 네 함수를 이 개정과 함께 보완했습니다. 함수가 단일 Rust 소스 파일에만 모여 있다고 가정해서는 안 됩니다.

관련 문서: ROI 상세 · Share/Deep Copy · Rust 공개 선언 · Threshold 원리.

이미지 생성 시 너비와 높이 및 전달된 픽셀 수는 서로 맞아야 합니다. ROI는 현재 보이는 이미지 안에 있어야 하고 양의 너비와 높이가 필요합니다. 예를 들어 3×1 이미지에서 x가 1이고 너비가 2인 ROI는 마지막 두 픽셀을 가리키지만, 그보다 큰 너비는 바깥으로 나가므로 허용되지 않습니다. 끝 좌표가 포함되지 않는다는 점을 함께 기억하면 경계 계산이 명확해집니다.

Threshold를 호출할 때에는 지원되는 회색 형식과 유한한 임계값을 사용하고, 부동소수 이미지의 값도 해당 연산 조건을 만족해야 합니다. 잘못된 입력과 해제된 객체 접근은 정상적인 빈 검출과 구분합니다. 생성된 ROI와 처리 출력이 각각 소유 객체라는 점도 오류 처리의 일부입니다. 작은 예제에서 정상 범위와 범위를 벗어난 호출을 각각 확인하면 실제 파이프라인의 경계 문제를 줄일 수 있습니다.

특히 폭과 높이가 양수여도 x+width 또는 y+height가 현재 뷰를 벗어나면 해당 ROI는 만들 수 없습니다. 생성 전에 현재 크기를 점검합니다.

입력 크기와 좌표를 계산하기

폭 3, 높이 1인 Gray8 영상은 보이는 픽셀이 3개이므로 생성 배열에도 해당 픽셀 수가 필요합니다. ROI의 시작이 (1,0), 크기가 2×1이면 오른쪽 끝은 1+2=3이고 반열림 범위 [1,3)에 들어오는 두 픽셀을 읽습니다. 같은 위치에서 너비를 3으로 주면 끝이 4가 되어 부모 너비를 벗어나므로 요청을 처리할 수 없습니다. 폭이 0인 사각형도 검사 영역으로 사용할 수 없습니다.

형식과 크기가 맞아 생성이 성공했더라도 다음 연산의 조건을 별도로 검사해야 합니다. Threshold는 지원되는 회색 형식과 유한한 임계값을 필요로 하고, 부동소수 영상에는 해당 연산의 유한성 조건이 적용됩니다. 서로 다른 영상이나 마스크를 함께 쓰는 검사에서는 가로·세로 크기와 origin까지 맞아야 하는 API가 있습니다. 세부 조건을 확인하기 전에 배열 숫자만 같다는 이유로 두 뷰가 같은 격자라고 가정하지 않습니다.

실패한 입력으로 결과 영상을 얻지 못했다면 이미 성공적으로 만든 원본이나 ROI의 소유권은 여전히 호출자가 관리합니다. 유효한 ROI와 범위를 벗어난 ROI를 작은 합성 영상으로 각각 확인하면 이미지 로드 문제와 좌표 범위 문제를 분리할 수 있습니다.
