검사 확장의 입출력 경계

입력, 파라미터, 결과와 오류를 분리해 검사 단계를 연결합니다.

그림을 읽는 순서

  1. 결과의 의미와 허용 기준은 각 검사 도구의 계약을 따릅니다.
  2. 실행 오류와 검사 결과에 대한 업무 판정은 구분합니다.

입력과 결과의 의미

입력 영상 데이터의 픽셀 형식, 크기, 원점은 각 단계의 계산 가능 여부를 결정합니다. 정렬은 회색 입력과 기준의 학습 ROI를 받아 기준 격자에 맞춘 영상 데이터와 유효 마스크를 만듭니다. 차분은 같은 기하의 기준과 분석 영상 데이터 및 선택 마스크를 받으며, 분석 영상 데이터가 정렬 출력일 때 GrayF64를 사용할 수 있습니다. 마스크의 비제로 픽셀만 통계와 판정에 참여하므로 원점과 크기가 서로 맞는지 먼저 확인해야 합니다.

입력·출력 상세 계약 · 검사 프레임워크에서 설정과 실제 API를 이어서 확인할 수 있습니다.

예외 처리에서는 어느 단계가 소유권을 이미 넘겼는지 확인하는 것이 중요합니다. 입력 검증에 실패하면 후속 영상 데이터가나 판정이 생성되지 않을 수 있지만, 그 전에 성공적으로 얻은 출력과 이미지는 그대로 호출자가 정리해야 합니다. using이나 finally로 각 소유 객체를 감싸면 성공과 실패 분기에서 같은 자원을 빠뜨리지 않고 해제할 수 있습니다. 해제 이후 해당 객체에서 새 영상 데이터가나 정보를 요청하는 일은 허용되지 않습니다.

오류 및 해제 분기 · 검사 프레임워크에서 설정과 실제 API를 이어서 확인할 수 있습니다.

적용할 때 확인할 점

입력, 파라미터, 결과와 오류를 분리해 검사 단계를 연결합니다. 그림의 화살표는 여기에서 설명하는 데이터 또는 제어 관계를 나타냅니다. 실제 호출에서 사용할 수 있는 입력 형식과 반환 객체는 연결된 API 문서의 선언과 파라미터 표를 확인하세요.
