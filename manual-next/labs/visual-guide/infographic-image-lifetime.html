실제 API에 적용하기

수명 매트릭스는 객체마다 무엇을 소유하는지 나누어 읽기 위한 기준입니다. 영상, 매칭 모델, Query 빌더와 실행 결과는 네이티브 자원을 보유할 수 있으며 관리형 코드에서는 닫기 또는 Dispose가 필요합니다. 임계값 결과처럼 새로 받은 영상도 원본을 닫는 것과 별도로 정리해야 합니다. ROI와 Share는 새로운 핸들이면서 저장소를 공유한다는 두 사실을 함께 기억하세요.

반환된 위치, 점수, 통계처럼 문서에서 독립 스냅샷으로 정의한 값은 모델이나 실행 핸들과 별도로 사용할 수 있습니다. 예를 들어 모델을 닫기 전에 얻은 매치 목록은 이후 읽을 수 있지만, 닫힌 모델에서 새 검색을 요청할 수는 없습니다. Query 실행에서 이미지 핸들을 얻었다면 실행을 닫기 전에 취득하고 이미지 사용 후 별도로 닫습니다. 호출할 때마다 반환 종류를 확인하면 해제 누락과 조기 해제 양쪽을 줄일 수 있습니다.

한 작업의 소유 관계를 점검하려면 생성한 핸들마다 마지막 사용과 종료 위치를 적어 보세요. 원본 하나에서 ROI 두 개를 얻었다면 원본과 두 ROI는 세 객체입니다. 저장소를 공유해도 종료 책임은 각각 존재합니다. 반대로 이미 복사한 매치 값이나 배열을 영상 핸들로 보고 닫으려 하면 반환 유형을 잘못 이해한 것입니다.

설명과 실행 결과의 범위

수치와 도형은 연결된 계약의 핵심 관계를 설명하는 예입니다. 실제 SDK 출력으로 명시한 자료를 제외하면 실행 결과나 장비 실측으로 해석하지 않습니다. 좌표계·입력 형식·수명과 오류 조건은 관련 API 계약을 확인한 뒤 적용하세요.
