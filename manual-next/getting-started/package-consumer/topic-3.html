Python: 별도 환경에 wheel 설치

CPython 3.14의 별도 가상 환경에 다음 파일을 설치합니다. 소스 PYTHONPATH와 외부 네이티브 경로 지정을 제거해야 설치 패키지의 파일을 검사할 수 있습니다.

Bash
python3.14 -m venv consumer-python
consumer-python/bin/python -m pip install --no-index "$PACKAGE_DIR/zvision-0.1.0-cp314-none-linux_x86_64.whl"
unset PYTHONPATH ZVISION_NATIVE_LIBRARY
export ZVISION_MANUAL_MODELS=/absolute/path/downloads/models
consumer-python/bin/python -I /absolute/path/downloads/python/runner.py

검증에서는 별도 CPython 3.14 환경에 생성 wheel을 설치하고 위와 같은 격리 실행으로 22개 사례를 확인했습니다.

원리와 입력

Python 패키지 소비 검증은 CPython 3.14의 별도 가상 환경에서 wheel을 설치하고 그 환경의 인터프리터로 runner를 실행합니다. 예시의 linux_x86_64 wheel은 해당 빌드용 파일이며 다른 플랫폼에서 같은 이름을 사용한다고 가정하지 않습니다. 모델을 사용하는 사례는 ZVISION_MANUAL_MODELS가 실제 모델 디렉터리를 가리켜야 합니다.

적용과 확인

실행 전에 PYTHONPATH와 ZVISION_NATIVE_LIBRARY를 제거하는 이유는 소스 래퍼나 외부 DLL이 설치된 wheel의 자산을 대신하지 않도록 확인하기 위해서입니다. -I 실행은 격리된 소비 경로를 확인하는 예입니다. 표시된 검증에서는 22개 합성 사례가 통과했습니다. 실패하면 먼저 인터프리터 버전, 설치된 wheel과 네이티브 플랫폼을 살펴보고, 실행된 SDK와 결과 JSON을 함께 기록하세요. 이 결과는 실장비 시험이 아닙니다.

읽기와 적용

검증하려는 대상이 설치 wheel이라면 실행기 파일의 위치와 라이브러리의 로딩 위치를 혼동하지 않는 것이 핵심입니다. 다운로드한 runner는 테스트 프로그램이고 가상 환경에 설치된 wheel은 SDK 래퍼와 네이티브 자산입니다. 모델을 쓰는 AI 사례는 별도 모델 경로가 있어야 실행되며, 모델 경로가 빠진 실행을 전체 사례가 실행된 결과로 해석하지 않습니다. 출력된 사례와 기대 JSON의 항목을 대조하면 실행되지 않은 사례도 구분할 수 있습니다.
