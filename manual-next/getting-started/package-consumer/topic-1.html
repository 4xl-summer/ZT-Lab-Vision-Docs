소스 참조와 설치 패키지의 차이

소스 프로젝트를 직접 참조하는 실행과, 네이티브 라이브러리를 포함한 패키지를 설치하는 실행을 각각 확인했습니다. 아래 절차는 Linux x64에서 생성한 로컬 배포물 기준입니다. 공개 PyPI나 NuGet 서버에 해당 패키지가 배포되어 있다는 뜻은 아닙니다. SDK 소스 저장소의 접근 권한이 필요합니다.

원리와 입력

소스 참조 방식은 소비 프로젝트가 SDK 체크아웃의 래퍼 또는 크레이트를 직접 가리킵니다. 이때 네이티브 라이브러리 경로와 체크아웃 리비전을 따로 맞춰야 합니다. 설치 패키지 방식은 wheel 또는 NuGet에 포함된 래퍼와 런타임 자산을 소비합니다. 같은 예제 코드가 성공해도 어느 경로의 라이브러리를 불렀는지에 따라 검증의 의미가 달라집니다.

적용과 확인

이 실습의 패키지는 표시된 SDK에서 Linux x64용으로 로컬 생성한 배포물입니다. 공개 패키지 서버에 이미 게시되어 있다는 약속이 아닙니다. 패키지 소비를 확인할 때 소스 PYTHONPATH와 외부 네이티브 override가 남아 있으면 원하지 않는 파일을 읽을 수 있으므로 격리 환경과 로더 설정을 확인합니다. 다른 OS와 아키텍처는 일치하는 패키지와 별도 검증이 필요합니다.

읽기와 적용

소스 참조는 개발 중인 체크아웃의 코드를 곧바로 바꾸어 확인할 때 유용하지만, 다른 환경에서 패키지를 설치한 사용자가 같은 런타임 자산을 받는지까지 확인해 주지는 않습니다. 반대로 설치 패키지 검사는 배포물의 래퍼와 네이티브 구성, 로딩 경로를 함께 시험합니다. 두 결과를 기록할 때는 SDK 리비전, 실행한 프로젝트, 실제로 선택한 네이티브 파일과 플랫폼을 함께 남기면 같은 예제의 성공이 무엇을 검증했는지 구분할 수 있습니다.

실행할 때 확인할 점

패키지 소비 예제에서는 설치된 패키지의 버전과 실행 환경을 함께 기록하세요. 다른 컴퓨터에서 실행할 때도 같은 패키지와 운영체제용 구성 요소를 준비하면 첫 영상 처리 결과를 재현하기 쉽습니다.
