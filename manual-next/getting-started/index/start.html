상위 목차로 돌아가기

첫 실행 경로

  1. SDK 환경 준비에서 언어와 플랫폼을 선택합니다.
  2. 첫 이미지 처리에서 세 픽셀의 경계값을 확인합니다.
  3. ROI 예제로 좌표와 영상 수명을 익힙니다.

검증 가능한 예제와 다운로드는 예제 목록에서 확인합니다.

환경별 실행 결과와 적용 범위는 검증 기록을 확인하세요.

원리와 입력

첫 실행은 입력 영상이 어디에서 오는지와 사용 언어의 SDK를 어떻게 연결하는지 결정하는 데서 시작합니다. 설치 패키지를 사용한다면 운영체제와 아키텍처가 일치하는 wheel 또는 NuGet 자산을 준비합니다. Rust 소스 예제는 SDK 체크아웃의 경로를 지정합니다. 실행 환경을 고정하면 나중에 픽셀 처리 결과와 로딩 문제를 분리하기 쉽습니다.

적용과 확인

그다음 합성 Gray8 영상 [9,10,11]에 임계값 10을 적용해 [0,255,255]를 확인합니다. 원본과 결과는 별도 영상이므로 각각의 수명도 확인하세요. 정상 출력이 나온 뒤 ROI 또는 매칭 예제로 확장하면 한 번에 너무 많은 설정을 바꾸지 않고 입력, 연산, 결과를 점검할 수 있습니다. 실제 장비를 사용하기 전에는 해당 환경의 별도 검증이 필요합니다.

한 번에 하나씩 연결 확인

첫 단계는 실행할 언어와 SDK 소비 경로를 선택하는 것입니다. Rust 프로젝트가 소스를 참조한다면 실제 체크아웃의 크레이트 경로를 지정합니다. Python은 선택한 CPython 환경과 wheel이 맞는지, C#은 프로젝트가 실행할 운영체제에 맞는 NuGet 런타임 자산을 참조하는지 확인합니다. 설치 파일의 예시 경로는 현재 컴퓨터에 그대로 존재한다고 가정하지 않습니다.

환경이 준비되면 폭 3, 높이 1의 Gray8 입력 [9,10,11]을 만들고 임계값 10을 적용합니다. 기대 마스크는 [0,255,255]입니다. 결과가 다르다면 영상 생성에 전달한 배열과 선택한 임계값을 먼저 확인합니다. 호출이 아예 실패한다면 출력값 비교보다 먼저 래퍼와 네이티브 라이브러리가 같은 환경에서 로드되었는지 살펴봅니다.

정상 결과를 얻은 뒤 Roi를 적용하면 현재 뷰의 좌표와 origin을 구분하는 연습을 할 수 있습니다. 생성한 입력과 새 출력 영상은 각각의 소유 수명을 갖습니다. 합성 배열에서 예상한 숫자가 나왔다고 실제 카메라 연결이나 생산 판정 기준이 검증된 것은 아니므로 다음 작업의 범위를 따로 정합니다.

다음 예제로 이동하기 전에 실행한 프로젝트 경로와 사용한 런타임을 기록하세요. 처음 예상과 달랐던 입력을 다시 살펴볼 수 있으면 설치 환경의 문제와 개별 예제의 데이터 문제를 나누기 쉽습니다.
