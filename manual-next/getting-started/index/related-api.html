관련 API

원리와 입력

첫 프로그램은 ZImage 생성과 Threshold, 결과 읽기라는 세 단계로 구성됩니다. [9,10,11]을 폭 3, 높이 1의 Gray8로 만들고 임계값 10을 적용하면 새 Gray8 영상 [0,255,255]를 기대합니다. 반환 영상과 원본은 각각 수명이 있으므로 언어별 정리 예제를 함께 확인하세요.

적용과 확인

이후 ROI API로 선택 영역을 만들면 로컬 좌표와 원본 origin을 함께 다뤄야 합니다. 모델 기반 검색은 MatchModel과 MatchSpec을 준비하고 MatchResult에서 빈 결과를 확인하는 별도 흐름입니다. 언어별 참조는 실제 메서드와 매개변수, 반환·오류 조건을 제공합니다. 설치 경로를 선택한 다음 간단한 입력으로 실행을 확인하고 필요한 개념과 가이드로 이동하세요.

첫 프로그램에서 각 객체의 역할

첫 영상 처리 프로그램은 ZImage 생성, Threshold 실행, 새 영상의 픽셀 읽기로 나눌 수 있습니다. Gray8 입력 [9,10,11]과 임계값 10을 사용하면 기대되는 출력은 [0,255,255]입니다. 입력의 세 숫자는 밝기이고 출력의 0과 255는 마스크 값입니다. 이 구분을 통해 설치 문제, 입력 데이터 문제, 연산 결과 문제를 차례대로 확인할 수 있습니다.

Info와 Origin은 현재 보이는 영상의 크기·형식과 좌표 해석에 사용합니다. Roi는 부분 뷰, Share는 독립 수명의 공유 영상을 제공하며, 배열 읽기는 값 복사입니다. Threshold는 원본을 대신 수정하는 설정이 아니라 새 영상 결과를 반환하므로 원본과 결과를 각자 정리해야 합니다. 언어별 호출 이름과 소유권은 해당 참조에서 확인하세요.

좀 더 복잡한 흐름에서는 Query로 작업을 계획하거나 MatchModel과 MatchSpec으로 기준을 검색할 수 있습니다. 검색 결과가 없을 때와 오류가 발생했을 때는 다른 분기가 필요합니다. 먼저 작은 합성 입력의 처리와 해제를 확인한 뒤 ROI, Blob, 매칭 중 필요한 주제로 넘어가면 문제를 좁혀 볼 수 있습니다.
