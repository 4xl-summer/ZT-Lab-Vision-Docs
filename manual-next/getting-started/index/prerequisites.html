원리와 입력

다음 단계로 넘어가기 전에 선택한 언어 런타임과 SDK 소비 경로가 맞는지 점검하세요. Python에서는 가상 환경에 설치한 wheel과 실행하는 인터프리터를 연결하고, C#은 운영체제에 맞는 패키지와 .NET 환경을 사용합니다. Rust 경로 의존성은 실제 체크아웃 위치를 가리켜야 합니다. 예제의 경로 표시는 그대로 존재하는 파일을 뜻하지 않습니다.

적용과 확인

소유 객체와 ROI를 이해하면 첫 실행 뒤 발생하는 오류를 해석하기 쉽습니다. 반환 영상을 닫는 시점, 부분 영역의 origin, 픽셀 형식을 각각 확인하세요. 입력 크기와 버퍼 길이가 맞지 않으면 알고리즘 비교 전에 생성이 실패할 수 있습니다. 검증 기록에서 사용한 플랫폼과 SDK 리비전을 확인하고, 다른 환경에서는 같은 명령이 반드시 같은 결과를 낸다고 가정하지 말고 실행 결과를 기록합니다.

다음 주제로 넘어가기 전

기본 예제가 실행되었다면 다음 단계는 무엇을 얻고 싶은지에 따라 달라집니다. 영상 일부를 처리할 목적이라면 ROI의 로컬 사각형과 부모 원점을 먼저 이해합니다. 로컬 (1,2)를 원본에 표시하려면 ROI origin과의 관계를 확인해야 하며, 이미 전역 좌표인 값에 원점을 다시 더하면 위치가 어긋납니다.

전경의 크기와 개수를 알고 싶다면 임계값으로 마스크를 만든 다음 Blob 연결 방식을 선택합니다. 위치를 찾는 목적이라면 NCC 모델의 학습 무늬와 검색 조건을 지정하고, 찾지 못했을 때 빈 결과를 처리해야 합니다. 픽셀 면적, 매치 점수, 판정 통과 여부는 다른 종류의 결과이므로 하나로 바꾸어 해석하지 않습니다.

각 단계에서 필요한 영상이나 모델을 누가 소유하는지도 확인합니다. Rust 소유 값의 이동, C#의 using과 Dispose, Python의 with와 close는 표현이 다르지만 반환 객체의 수명은 모두 중요합니다. 검증 기록의 플랫폼과 현재 플랫폼이 다르면 표시된 명령의 적용 조건과 자신의 실행 결과를 구분해 기록하세요.

예를 들어 임계값 마스크가 예상과 다르면 먼저 입력 배열과 임계값을 비교합니다. 마스크가 예상과 같은데 Blob 개수가 다르다면 다음으로 4연결 또는 8연결 선택을 확인합니다.
