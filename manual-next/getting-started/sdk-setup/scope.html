설치 경로 선택

Rust는 SDK 소스 체크아웃의 Cargo 경로 의존성을 사용합니다. C#과 Python은 각각 해당 운영체제와 아키텍처용 NuGet 또는 wheel 소비자 패키지를 사용할 수 있습니다. 소스 빌드 출력과 패키지 설치는 서로 다른 경로입니다. 아래 명령은 배포 파일을 이미 확보한 경우의 흐름이며, 사용자의 파일 위치로 경로를 바꾸세요.

확인 항목살펴볼 내용설치 후 점검
플랫폼대상 OS와 아키텍처에 맞는 배포물네이티브 라이브러리 로딩
Rust프로젝트와 SDK 버전 및 feature최소 예제 실행
C#대상 런타임과 네이티브 라이브러리패키지 참조와 로딩 확인
Python지원 Python 버전과 wheelimport 및 네이티브 로딩 확인
추가 기능모델 파일·선택 feature·플랫폼 조건사용하려는 경로를 별도 확인

판독 기준

  • 사용 환경과 함수별 계약은 연결된 상세 문서를 확인합니다.

수치와 도형은 연결된 계약의 핵심 관계를 설명하는 예입니다. 실제 SDK 출력으로 명시한 자료를 제외하면 실행 결과나 장비 실측으로 해석하지 않습니다. 좌표계·입력 형식·수명과 오류 조건은 관련 API 계약을 확인한 뒤 적용하세요.

소비 방식전제
Rust 소스Rust 1.85 이상, edition 2024 지원. 저장소 전체가 경로 의존성에 필요합니다.
Python wheelCPython 3.14, 운영체제 및 아키텍처와 일치하는 wheel. native 라이브러리가 패키지에 포함됩니다.
C# NuGet실행 OS와 일치하는 ZVision.linux-x64 또는 ZVision.win-x64 패키지와 호환 .NET. 해당 native 파일이 패키지에 포함됩니다.

원리와 입력

어떤 파일을 실행 환경에 넣을지 먼저 정하면 이후 로딩 경로를 설명할 수 있습니다. Rust 예제는 SDK 소스 체크아웃의 Cargo 경로 의존성을 사용합니다. Python과 C#은 각각 플랫폼에 맞는 wheel과 NuGet 패키지를 소비할 수 있으며, 문서의 패키지 예에는 네이티브 런타임 자산이 포함됩니다. 실제 파일명과 경로는 자신의 환경에서 확보한 배포물로 바꾸어야 합니다.

적용과 확인

소스 빌드 결과와 설치된 패키지를 동시에 지정하면 어느 네이티브 파일이 로드되었는지 판단하기 어렵습니다. 확인하려는 소비 경로를 먼저 선택하고 나머지 설정을 점검하세요. Python wheel은 해당 인터프리터와 플랫폼에 맞아야 하고, C# 패키지는 실행 운영체제와 아키텍처에 맞아야 합니다. Linux x64에서 확인된 기록을 Windows 또는 다른 플랫폼의 실행 보증으로 확대하지 않습니다.

소비 경로를 구분하는 기준

설치 전에 실행할 프로젝트가 SDK 소스를 참조하는지, 배포된 패키지를 설치하는지 먼저 정합니다. Rust 경로 의존성은 예제 프로젝트의 위치가 아니라 실제 SDK 체크아웃의 crates/zvision을 가리킵니다. 예제가 보조 타입을 직접 사용한다면 crates/zvision-ops 경로도 필요하지만, 단순한 모든 프로그램에 이를 일괄 추가할 필요는 없습니다. 경로가 달라지면 Cargo.toml의 참조를 현재 파일 시스템에 맞추어야 합니다.

Python wheel은 설치 대상 인터프리터, 운영체제와 아키텍처가 일치해야 합니다. C# 소비자는 실행 플랫폼에 맞는 NuGet 런타임 자산과 프로젝트의 .NET 환경을 선택합니다. 두 경로 모두 네이티브 파일이 패키지에 포함될 수 있으므로 소스 빌드를 먼저 해야 한다고 가정하지 않습니다. 설치한 환경과 실행하는 환경이 다르면 모듈을 못 찾거나 다른 네이티브 파일이 로드될 수 있습니다.

확인은 작은 영상 생성과 임계값 적용처럼 입력과 출력을 직접 계산할 수 있는 프로그램으로 시작합니다. 폭 3인 Gray8의 [9,10,11]에 임계값 10을 적용하면 [0,255,255]가 기대됩니다. 이 숫자는 연결 확인용 합성 결과이며 카메라나 특정 설비가 검증되었다는 뜻은 아닙니다.
