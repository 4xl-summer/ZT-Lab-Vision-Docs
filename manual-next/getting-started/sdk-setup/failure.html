상위 목차로 돌아가기

문제 해결

로드 실패 시 프로세스 아키텍처, 패키지 플랫폼, native 파일과 override 경로를 확인합니다. 형식 오류는 픽셀 형식과 입력 크기를 확인합니다. 의존성 복원 오류는 피드 설정과 패키지 파일을 확인합니다.

실제 실행 프로젝트와 별도 설치 검증은 패키지 소비자 실습을 확인하세요. Windows 명령은 해당 도구 체인이 필요한 사용 예이며 이번 실행 검증 플랫폼은 Linux x64입니다. 환경별 실행 결과와 적용 범위는 검증 기록을 확인하세요.

첫 이미지 처리 · 객체 모델 · ROI

원리와 입력

문제를 처음 발견한 단계로 나누면 점검 범위가 작아집니다. 의존성 복원이 실패하면 NuGet 피드 또는 wheel 파일명과 런타임 버전을 확인합니다. 모듈은 열리지만 네이티브 라이브러리를 찾지 못한다면 패키지에 포함된 자산, 프로세스 아키텍처와 수동 override의 실제 경로를 살펴봅니다. 소스 래퍼와 다른 빌드의 네이티브 파일을 혼합했는지도 기록하세요.

적용과 확인

영상 생성이나 연산에서 오류가 나면 설치 문제와 구분해 입력 폭·높이·버퍼 길이와 PixelFormat을 확인합니다. ROI의 범위 오류라면 시작점과 크기를 보이는 입력 영역에 대조합니다. 합성 첫 예제가 실행된다면 [9,10,11]과 임계값 10의 출력 [0,255,255]를 비교해 계산 경로를 확인할 수 있습니다. 첫 오류 메시지와 SDK 리비전, OS와 런타임을 함께 남기면 재현에 도움이 됩니다.

어느 단계에서 실패했는지 분리

실패 메시지를 처음 관찰한 시점을 기준으로 문제를 나누면 불필요하게 모든 설정을 바꾸지 않아도 됩니다. 의존성 복원 전에 파일을 못 찾았다면 프로젝트 경로와 배포물 이름이 우선입니다. NuGet 복원 단계라면 ID와 버전뿐 아니라 로컬 피드와 다른 필요한 소스가 구성되어 있는지 확인합니다. Python에서는 설치한 가상 환경과 실제 실행한 인터프리터가 같은지 점검합니다.

모듈 또는 관리형 어셈블리는 열리지만 native 로딩이 실패한다면 운영체제, 아키텍처, 패키지에 포함된 자산 및 수동으로 설정한 ZVISION_NATIVE_LIBRARY의 파일 경로를 함께 확인합니다. 다른 리비전의 래퍼와 네이티브 라이브러리를 섞은 경우도 호출되는 API의 기대와 맞지 않을 수 있으므로 어떤 빌드를 선택했는지 기록합니다.

영상 생성까지 성공한 뒤 처리에서 오류가 나면 폭·높이와 배열 길이, 픽셀 형식, ROI의 양수 크기와 경계부터 살펴봅니다. 비어 있는 정상 검출 결과와 API 오류는 다르게 기록해야 합니다. 최소 합성 입력으로 각 단계를 재현하면 환경 오류와 검사 데이터 조건을 구분하는 데 도움이 됩니다.

예를 들어 같은 프로젝트에서 인터프리터만 바꿔 실행하면 먼저 설치된 환경과 다른 모듈 검색 경로를 사용할 수 있습니다. 실행 경로와 최초 오류를 함께 보관하면 설치 단계와 처리 단계를 다시 구분할 수 있습니다.
