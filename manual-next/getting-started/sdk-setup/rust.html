Rust 소스 소비

소비자 프로젝트의 Cargo.toml에서 아래 경로를 실제 체크아웃의 절대 경로로 바꿉니다. Windows에서도 Cargo 경로에 슬래시를 사용할 수 있습니다. zvision-ops는 일부 보조 열거형과 설정을 직접 사용하는 예제에 필요하며 직접 쓰지 않으면 생략할 수 있습니다. 기본 full 기능은 이미지 I/O, recognition, acquisition을 포함합니다.

TOML
[dependencies]
zvision = { path = "/path/to/sdk/crates/zvision" }
zvision-ops = { path = "/path/to/sdk/crates/zvision-ops" }

프로젝트 디렉터리에서 cargo run을 실행합니다. 체크아웃 루트는 예제 프로젝트 위치로 추측하지 말고 실제 경로를 지정하세요.

원리와 입력

Rust 소비 프로젝트의 Cargo.toml에서 zvision 경로는 실제 SDK 체크아웃의 crates/zvision을 가리켜야 합니다. 문서에 표시된 /path/to/sdk는 바꾸어야 할 예시 경로입니다. 일부 보조 타입을 직접 사용하는 코드에서는 zvision-ops 경로 의존성도 필요하지만, 사용하지 않는 소비자가 무조건 추가해야 한다는 뜻은 아닙니다. 전체 체크아웃이 필요한 이유는 해당 크레이트가 저장소 안의 다른 경로 의존성과 연결되기 때문입니다.

적용과 확인

의존성을 지정한 뒤 프로젝트 디렉터리에서 실행하고 첫 합성 영상 결과를 확인합니다. Cargo가 경로를 찾지 못하면 소스 루트와 Cargo.toml 기준 상대 경로를 먼저 점검합니다. 사용한 체크아웃 리비전과 Cargo.lock을 유지하면 실행 결과를 다시 비교하기 쉽습니다. 기본 full 기능 구성과 선택 기능의 차이는 해당 SDK 선언을 확인하고 예제에서 요구하지 않는 기능을 임의로 가정하지 마세요.

경로 의존성을 적용하는 순서

기존 예제의 경로는 복사해서 그대로 쓸 실제 위치가 아니라 교체할 자리입니다. 프로젝트의 Cargo.toml에서 zvision 항목은 체크아웃의 crates/zvision 디렉터리를 가리켜야 하며, zvision-ops를 직접 쓰는 예제는 그 크레이트의 경로도 필요합니다. 저장소 내부의 다른 크레이트를 참조하므로 해당 디렉터리 하나만 따로 옮긴 불완전한 복사본 대신 전체 체크아웃을 준비합니다.

Rust 2024 edition을 지원하는 도구 체인에서 소비자 프로젝트 디렉터리로 이동해 원래 예제에 제시된 실행 절차를 따릅니다. Cargo.lock을 제공하는 실행 프로젝트는 잠금 파일을 함께 유지하여 의도치 않게 다른 의존성 조합이 선택되지 않도록 합니다. 경로를 읽지 못하면 알고리즘 출력 이전에 복원 또는 컴파일 단계에서 실패하므로 SDK 루트와 crates 폴더의 실제 위치를 먼저 점검합니다.

실행이 성공하면 입력 [9,10,11]과 임계값 10의 예상 마스크 [0,255,255]를 비교할 수 있습니다. 영상 값은 생성된 마스크와 별도의 소유 값이며 ROI나 Query로 확장할 때도 각 값의 수명을 확인합니다. 경로 예시가 Windows의 절대 경로와 다르더라도 내용을 자신의 체크아웃 위치로 바꾸어야 합니다.
