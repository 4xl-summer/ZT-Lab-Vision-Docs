소스에서 네이티브 빌드

패키지 소비자는 통상 이 단계를 반복할 필요가 없습니다. SDK 소스 루트에서 Windows x64 MSVC 도구 체인을 사용한 소스 빌드 예입니다.

PowerShell
cargo build -p zvision-ffi --release --locked --target x86_64-pc-windows-msvc
dotnet build wrappers/dotnet/ZVision.slnx -c Release
$env:ZVISION_NATIVE_LIBRARY = (Resolve-Path "./target/x86_64-pc-windows-msvc/release/zvision_ffi.dll").Path

Linux 소스 빌드 산출물은 플랫폼에 맞는 libzvision_ffi.so입니다. 수동 override를 사용한다면 실제 파일의 절대 경로를 ZVISION_NATIVE_LIBRARY에 지정하세요. 운영체제·아키텍처가 일치해야 합니다.

원리와 입력

이 절은 SDK 소스에서 Windows x64 MSVC 대상 네이티브 라이브러리를 직접 만들 때의 예입니다. 이미 네이티브 자산이 포함된 일치하는 소비자 패키지를 사용하는 경로라면 보통 동일 빌드를 다시 수행할 필요가 없습니다. 명령의 현재 위치는 SDK 소스 루트이며 Rust 대상 도구 체인과 해당 C# 빌드 환경이 준비되어 있어야 합니다.

적용과 확인

Release 산출물의 실제 DLL 절대 경로를 ZVISION_NATIVE_LIBRARY로 지정하는 줄은 수동 로더 override입니다. 경로를 지정했는데 로드되지 않으면 파일 존재 여부뿐 아니라 프로세스와 DLL 아키텍처의 일치도 확인하세요. Linux에서는 이름과 경로가 다르므로 Windows DLL 경로를 그대로 적용할 수 없습니다. 이 명령은 Windows 사용 예이며 표시된 Linux 실행 기록을 Windows 테스트 결과로 해석하지 않습니다.

직접 빌드한 파일을 선택할 때

이 절의 PowerShell 예시는 SDK 소스 루트에서 Windows x64 MSVC 대상을 빌드하는 흐름입니다. 첫 줄은 zvision-ffi의 Release 라이브러리를 지정 대상용으로 만들고 잠금 파일을 사용합니다. 다음 줄은 관리형 솔루션을 빌드하며, 마지막 줄은 빌드된 DLL의 실제 절대 경로를 네이티브 로더 override에 지정합니다. 현재 위치가 SDK 루트가 아니면 상대 경로가 의도한 파일을 가리키지 않을 수 있습니다.

예제에서 지정한 결과 경로는 대상별 target 디렉터리 안의 zvision_ffi.dll입니다. Linux에서 빌드한 libzvision_ffi.so는 같은 파일이 아니므로 운영체제와 프로세스 아키텍처를 맞추어야 합니다. 수동 경로를 설정했다면 설치된 패키지의 다른 자산보다 그 경로가 어떤 영향을 주는지 확인하고, 변경한 환경 변수와 실행한 프로세스를 기록합니다.

패키지의 적합한 네이티브 자산을 소비하는 경우에는 같은 목적의 소스 빌드를 무조건 반복할 필요가 없습니다. 제공된 Windows 명령은 해당 도구 체인에서 실행할 수 있는 예시입니다. 이 문서의 기록된 소비자 검증 플랫폼은 Linux x64이므로 Windows에서의 실행 성공으로 바꾸어 읽지 않습니다.
