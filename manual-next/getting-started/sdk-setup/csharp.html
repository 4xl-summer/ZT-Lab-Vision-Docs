상위 목차로 돌아가기

C# NuGet 소비

다운로드한 .nupkg를 로컬 피드 디렉터리에 놓고, 프로젝트의 PackageReference에 실행 플랫폼에 맞는 ID와 버전을 지정합니다. 예시는 Linux이며 Windows에서는 ZVision.win-x64로 바꿉니다. 피드 경로는 실제 위치로 바꿉니다.

XML
<ItemGroup>
  <PackageReference Include="ZVision.linux-x64" Version="0.1.0" />
</ItemGroup>

로컬 피드를 포함하는 NuGet.Config를 지정하여 프로젝트 디렉터리에서 복원하고 빌드합니다. 필요한 프레임워크 의존성의 다른 패키지 소스도 환경에 맞게 구성하세요.

Shell
dotnet restore Consumer.csproj --configfile NuGet.Config
dotnet build Consumer.csproj -c Release --no-restore

원리와 입력

C# 소비자는 프로젝트의 PackageReference에 실제 플랫폼용 패키지 ID와 버전을 지정합니다. 예시의 ZVision.linux-x64 0.1.0과 Windows용 ZVision.win-x64는 서로 다른 런타임 자산을 선택하므로 실행 OS에 맞춰야 합니다. 내려받은 nupkg를 로컬 피드에 넣고 NuGet.Config에 해당 경로와 필요한 나머지 의존성 소스를 구성합니다.

적용과 확인

restore가 성공한 뒤 Release 빌드와 실행 결과를 확인하세요. 패키지를 찾지 못하면 로컬 피드 경로와 파일을, 로드 단계에서 실패하면 프로세스 아키텍처와 선택한 패키지의 네이티브 자산을 점검합니다. --no-restore 빌드는 앞선 복원이 성공했다는 전제에서 사용합니다. 문서에 있는 로컬 패키지 검증은 명시된 Linux x64 환경의 결과이며 공개 NuGet 서버 배포나 다른 플랫폼 실행을 의미하지 않습니다.

로컬 피드에서 복원하기

NuGet 소비는 프로젝트의 PackageReference가 패키지 ID와 버전을 지정하고, 복원 단계가 구성된 피드에서 해당 패키지를 찾는 방식입니다. 제공된 예제의 Linux ID와 Windows ID는 운영체제별 네이티브 자산을 선택하므로 실행 환경에 맞는 패키지를 사용해야 합니다. 실제 nupkg가 놓인 디렉터리와 NuGet.Config의 피드 경로도 일치시킵니다.

복원과 빌드는 서로 다른 단계입니다. 패키지를 찾지 못하면 먼저 ID, 버전, 로컬 피드 경로 및 필요한 다른 의존성 소스를 확인합니다. 복원이 성공한 뒤 빌드가 실패한다면 프로젝트 대상 프레임워크와 참조를 살펴봅니다. 빌드가 성공했는데 실행 시 라이브러리 로드가 실패한다면 프로세스 아키텍처, 패키지의 native 자산과 수동 override 경로를 점검합니다.

처리 예제에서는 ZImage를 만든 뒤 새 Threshold 결과를 얻고 각각을 using으로 해제합니다. [9,10,11]과 임계값 10의 출력은 [0,255,255]입니다. 이는 패키지 연결과 기본 호출의 합성 확인이지 장비 취득이나 생산 판정을 시험한 결과는 아닙니다.

단계확인할 것실패 지점
복원패키지 ID·버전·피드참조할 패키지를 찾지 못함
빌드대상 .NET과 프로젝트 참조컴파일 또는 프레임워크 불일치
실행플랫폼 native 자산과 로더 경로네이티브 파일 로드 실패
