Rust · 첫 이미지 처리

Rust의 입력과 결과, 적용 방법을 설명합니다.

상위 목차로 돌아가기

Rust

Rust
use zvision::ZImage;
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let source = ZImage::from_vec_gray8(3, 1, vec![9, 10, 11])?;
    let result = source.threshold(10.0)?;
    assert_eq!(result.to_packed_vec()?, vec![0, 255, 255]);
    Ok(())
}

원리와 입력

아래 프로그램은 먼저 너비 3, 높이 1인 Gray8 영상을 만들고 그 객체에 threshold를 호출합니다. 숫자 10.0은 실수 임계값이며 각 픽셀과 비교됩니다. 결과를 별도 변수로 받은 뒤 packed 벡터로 복사하여 세 바이트가 정확히 0, 255, 255인지 검증합니다. 마지막 Ok는 생성과 연산과 읽기가 모두 성공한 경로를 표시하며, 각 물음표는 실패를 호출자에게 전달합니다.

적용과 확인

이 예제에서 source와 result는 서로 다른 영상 값입니다. 결과를 읽은 뒤에도 source를 다시 사용할 수 있고, 두 값은 각자의 수명이 끝날 때 정리됩니다. 패키지 참조나 네이티브 실행 환경을 준비하지 못하면 픽셀 비교에 도달하기 전에 빌드 또는 로딩 오류가 발생할 수 있습니다. 먼저 설치 안내의 Rust 경로를 확인하고, 실행은 되지만 assertion이 실패하면 배열 순서와 임계값을 비교하세요. 이 코드는 기존 실행 프로젝트의 합성 사례이며 카메라 입력을 가정하지 않습니다.

값과 판독 기준

단계입력 또는 결과확인할 점
생성3×1, [9,10,11]세 Gray8 표본
연산threshold(10.0)입력은 그대로 보존
읽기to_packed_vec결과 픽셀을 순서대로 복사
검사[0,255,255]가운데 경계값 포함

적용할 때 살펴볼 점

예상 결과를 직접 계산하면 첫 표본 9는 10 미만이라 0이고, 나머지 10과 11은 기준 이상이라 255입니다. 세 값의 순서와 영상 크기가 모두 일치해야 assertion이 통과합니다. 이 검사는 이진 마스크의 실제 바이트를 비교하므로 화면의 색상 표시 설정에 의존하지 않습니다. 소스와 결과는 별도 변수로 보유하며 두 수명이 끝나는 지점을 확인할 수 있습니다.
