설치 패키지로 예제 실행

직접 만든 Linux wheel·NuGet 패키지를 소스 참조와 분리해 설치하고 실행하는 방법.

소스 참조와 설치 패키지의 차이

소스 프로젝트를 직접 참조하는 실행과, 네이티브 라이브러리를 포함한 패키지를 설치하는 실행을 각각 확인했습니다. 아래 절차는 Linux x64에서 생성한 로컬 배포물 기준입니다. 공개 PyPI나 NuGet 서버에 해당 패키지가 배포되어 있다는 뜻은 아닙니다. SDK 소스 저장소의 접근 권한이 필요합니다.

동일 SDK에서 패키지 만들기

Rust와 CPython 3.14 및 .NET 10 SDK가 설치된 Linux 환경에서 실행합니다. SDK_SOURCE와 PACKAGE_DIR은 실제 절대 경로로 바꾸세요. 두 생성 스크립트는 기존 배포물 덮어쓰기를 거부하므로 새 출력 폴더를 사용합니다.

Bash
export SDK_SOURCE=/absolute/path/ZT-Lab-Vision
export PACKAGE_DIR=/absolute/path/packages
cd "$SDK_SOURCE"
git checkout ce902e85c3405eb63df40c699ddbdf70ee1d03bd
cargo build -p zvision-ffi --release --locked
export NATIVE_LIBRARY="$SDK_SOURCE/target/release/libzvision_ffi.so"
python3.14 scripts/build-python-package.py --output-dir "$PACKAGE_DIR" --native-library "$NATIVE_LIBRARY"
python3.14 scripts/build-nuget-package.py --output-dir "$PACKAGE_DIR" --native-library "$NATIVE_LIBRARY"

사용자가 Cargo 출력 경로를 변경했다면 NATIVE_LIBRARY도 실제 Release 파일 위치로 지정하세요. wheel에는 네이티브 파일과 제3자 고지가 포함됩니다. Linux wheel은 해당 호스트 형식이며 manylinux 호환성을 별도로 주장하지 않습니다.

Python: 별도 환경에 wheel 설치

CPython 3.14의 별도 가상 환경에 다음 파일을 설치합니다. 소스 PYTHONPATH와 외부 네이티브 경로 지정을 제거해야 설치 패키지의 파일을 검사할 수 있습니다.

Bash
python3.14 -m venv consumer-python
consumer-python/bin/python -m pip install --no-index "$PACKAGE_DIR/zvision-0.1.0-cp314-none-linux_x86_64.whl"
unset PYTHONPATH ZVISION_NATIVE_LIBRARY
export ZVISION_MANUAL_MODELS=/absolute/path/downloads/models
consumer-python/bin/python -I /absolute/path/downloads/python/runner.py

검증에서는 별도 CPython 3.14 환경에 생성 wheel을 설치하고 위와 같은 격리 실행으로 22개 사례를 확인했습니다.

C#: 로컬 NuGet 피드에서 설치

다운로드에 포함한 consumer/ConsumerExamples.csproj는 ZVision.linux-x64 버전 0.1.0을 참조합니다. 소스 참조 프로젝트와 별도입니다.

Bash
unset ZVISION_NATIVE_LIBRARY
export ZVISION_MANUAL_MODELS=/absolute/path/downloads/models
dotnet restore /absolute/path/downloads/csharp/consumer/ConsumerExamples.csproj --source "$PACKAGE_DIR" --source https://api.nuget.org/v3/index.json
dotnet run --no-restore --project /absolute/path/downloads/csharp/consumer/ConsumerExamples.csproj -c Release

생성한 Linux x64 패키지의 런타임 자산을 사용해 22개 사례를 실행했습니다. Windows 네이티브 파일을 Linux 패키지에 넣거나 그 반대로 사용하지 마세요. 다른 OS·아키텍처·런타임 조합은 별도 검증이 필요합니다.
