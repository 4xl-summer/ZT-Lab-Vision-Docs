SDK 환경 준비 및 첫 빌드

SDK 환경 준비 및 첫 빌드 사용 안내

설치 경로 선택

Rust는 SDK 소스 체크아웃의 Cargo 경로 의존성을 사용합니다. C#과 Python은 각각 해당 운영체제와 아키텍처용 NuGet 또는 wheel 소비자 패키지를 사용할 수 있습니다. 소스 빌드 출력과 패키지 설치는 서로 다른 경로입니다. 아래 명령은 배포 파일을 이미 확보한 경우의 흐름이며, 사용자의 파일 위치로 경로를 바꾸세요.

소비 방식전제
Rust 소스Rust 1.85 이상, edition 2024 지원. 저장소 전체가 경로 의존성에 필요합니다.
Python wheelCPython 3.14, 운영체제 및 아키텍처와 일치하는 wheel. native 라이브러리가 패키지에 포함됩니다.
C# NuGet실행 OS와 일치하는 ZVision.linux-x64 또는 ZVision.win-x64 패키지와 호환 .NET. 해당 native 파일이 패키지에 포함됩니다.

Rust 소스 소비

소비자 프로젝트의 Cargo.toml에서 아래 경로를 실제 체크아웃의 절대 경로로 바꿉니다. Windows에서도 Cargo 경로에 슬래시를 사용할 수 있습니다. zvision-ops는 일부 보조 열거형과 설정을 직접 사용하는 예제에 필요하며 직접 쓰지 않으면 생략할 수 있습니다. 기본 full 기능은 이미지 I/O, recognition, acquisition을 포함합니다.

TOML
[dependencies]
zvision = { path = "/path/to/sdk/crates/zvision" }
zvision-ops = { path = "/path/to/sdk/crates/zvision-ops" }

프로젝트 디렉터리에서 cargo run을 실행합니다. 체크아웃 루트는 예제 프로젝트 위치로 추측하지 말고 실제 경로를 지정하세요.

Python wheel 소비

CPython 3.14 가상환경을 만들고 다운로드한 현재 플랫폼용 wheel의 실제 파일명으로 설치합니다. Linux/macOS 형식과 Windows PowerShell 명령은 각각 다음과 같습니다. 패키지 테스트는 CPython 3.14 wheel 설치 방식을 사용합니다. 모든 배포 환경에서 실행되었다는 의미는 아닙니다.

Shell
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install --no-index --no-deps /path/to/zvision-0.1.0-cp314-none-PLATFORM.whl
PowerShell
py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --no-index --no-deps C:/path/to/zvision-0.1.0-cp314-none-PLATFORM.whl

PLATFORM은 문자 그대로 입력하지 말고 실제 파일명으로 바꿉니다. Linux wheel에 manylinux 호환성을 가정하지 마세요.

C# NuGet 소비

다운로드한 .nupkg를 로컬 피드 디렉터리에 놓고, 프로젝트의 PackageReference에 실행 플랫폼에 맞는 ID와 버전을 지정합니다. 예시는 Linux이며 Windows에서는 ZVision.win-x64로 바꿉니다. 피드 경로는 실제 위치로 바꿉니다.

XML
<ItemGroup>
  <PackageReference Include="ZVision.linux-x64" Version="0.1.0" />
</ItemGroup>

로컬 피드를 포함하는 NuGet.Config를 지정하여 프로젝트 디렉터리에서 복원하고 빌드합니다. 필요한 프레임워크 의존성의 다른 패키지 소스도 환경에 맞게 구성하세요.

Shell
dotnet restore Consumer.csproj --configfile NuGet.Config
dotnet build Consumer.csproj -c Release --no-restore

소스에서 네이티브 빌드

패키지 소비자는 통상 이 단계를 반복할 필요가 없습니다. SDK 소스 루트에서 Windows x64 MSVC 도구 체인을 사용한 소스 빌드 예입니다.

PowerShell
cargo build -p zvision-ffi --release --locked --target x86_64-pc-windows-msvc
dotnet build wrappers/dotnet/ZVision.slnx -c Release
$env:ZVISION_NATIVE_LIBRARY = (Resolve-Path "./target/x86_64-pc-windows-msvc/release/zvision_ffi.dll").Path

Linux 소스 빌드 산출물은 플랫폼에 맞는 libzvision_ffi.so입니다. 수동 override를 사용한다면 실제 파일의 절대 경로를 ZVISION_NATIVE_LIBRARY에 지정하세요. 운영체제·아키텍처가 일치해야 합니다.

문제 해결

로드 실패 시 프로세스 아키텍처, 패키지 플랫폼, native 파일과 override 경로를 확인합니다. 형식 오류는 픽셀 형식과 입력 크기를 확인합니다. 의존성 복원 오류는 피드 설정과 패키지 파일을 확인합니다.

실제 실행 프로젝트와 별도 설치 검증은 패키지 소비자 실습을 확인하세요. Windows 명령은 해당 도구 체인이 필요한 사용 예이며 이번 실행 검증 플랫폼은 Linux x64입니다. 환경별 실행 결과와 적용 범위는 검증 기록을 확인하세요.
