합성 예제 · DepthMap · 깊이 지도

결측을 유지하는 깊이 격자와 거리 단위·원점·프레임.

상위 목차로 돌아가기

합성 예제

다음 합성 입력의 기대값은 좌표식으로 계산할 수 있습니다. 실측 정확도 검증은 아닙니다.

Python
from zvision import DepthMap, Point3, LengthUnit

with DepthMap.from_values(3, 2, [1, None, 3, 4, 5, 6],
                          2, 3, Point3(10, 20, 30),
                          LengthUnit.MILLIMETER, 7) as depth:
    with depth.roi(1, 0, 2, 2) as roi, roi.to_point_cloud() as cloud:
        assert roi.info.origin == Point3(12, 20, 30)
        assert cloud.to_points()[1] == Point3(14, 20, 33)

관련 합성 실행 사례: spatial-depth.

예제의 격자는 첫 행이 1, None, 3이고 둘째 행이 4, 5, 6입니다. 폭 3과 높이 2에 맞는 여섯 슬롯이 행 우선으로 제공됩니다. 간격은 X 2, Y 3이고 원점은 (10,20,30), 단위는 밀리미터, frame은 7입니다. ROI (1,0,2,2)는 각 행의 두 번째와 세 번째 셀을 포함하므로 새로운 원점 X는 12입니다.

ROI 점군의 두 번째 슬롯은 원본 첫 행 세 번째 셀의 높이 3입니다. ROI의 로컬 x=1을 적용해 X=12+2=14, Y=20, Z=30+3=33이 됩니다. 예제는 이 좌표를 assert로 확인합니다. 원본의 결측이 첫 ROI 슬롯에 남는다는 것도 자료를 읽을 때 구별해야 합니다. with는 지도, ROI, 점군의 소유 기간을 감싸며, 이 합성 결과는 실제 센서 보정 정확도를 뜻하지 않습니다.

배열에서 ROI 점까지 계산

원본의 첫 행은 [1,None,3], 둘째 행은 [4,5,6]입니다. 너비 3이므로 각 행에서 두 번째와 세 번째 셀을 고른 ROI는 첫 행 [None,3], 둘째 행 [5,6]입니다. ROI는 x=1에서 시작하므로 원점 X가 10에서 12로 이동하고 Y와 Z 원점은 각각 20과 30으로 유지됩니다. 표의 점 좌표는 새 ROI의 로컬 인덱스와 이 이동된 원점으로 계산한 값입니다.

첫 슬롯의 None은 점 좌표가 없는 위치입니다. 두 번째 슬롯에는 3이 있어 X=12+1×2=14, Y=20, Z=30+3=33이 됩니다. 아래 두 슬롯은 각각 X 12 또는 14, Y=20+3=23이고 Z에 5 또는 6을 더합니다. 이 계산은 코드가 비교하는 한 점뿐 아니라 전체 네 슬롯의 대응을 눈으로 확인하는 방법입니다. 결과와 원본이 공유하는 저장소와 별도 점군 객체의 수명은 각각 관리합니다.

항목값 또는 조건해석
(0,0)NoneNone
(1,0)3(14,20,33)
(0,1)5(12,23,35)
(1,1)6(14,23,36)
