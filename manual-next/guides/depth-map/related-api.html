관련 API

깊이 지도 작업의 출발점은 격자 생성입니다. 배열의 각 높이와 결측 위치, spacing과 origin을 묶어 둔 다음 info 또는 대응 접근자로 크기와 단위를 확인합니다. 부분 영역만 필요하면 roi를 적용하고, 이웃 처리 목적에 따라 median과 fill_holes 중 선택합니다. 전자는 유효 중심의 중앙값 필터이고 후자는 원본 이웃으로 결측 중심을 채우는 경로라 결과의 의미가 다릅니다.

직교 공간점이 필요하면 to_point_cloud를 사용하고, 카메라 광선에 따른 점을 원하면 camera와 깊이 convention을 지정하는 원근 project를 검토합니다. 둘은 동일 입력이라도 좌표 모델이 달라 출력이 달라질 수 있습니다. 점군 생성 후 피팅이나 정합을 하기 전에 unit과 frame을 확인하고, 새 소유 객체의 수명을 언어에 맞게 관리합니다. 결과 슬롯의 결측은 정상적인 자료 상태일 수 있으므로 오류와 구분합니다.

데이터 경로 선택

격자 값과 메타데이터를 먼저 준비한 다음, 자료의 목적에 맞는 변환을 선택합니다. 원본을 그대로 보존하면서 관심 영역만 다루려면 roi가 현재 격자의 로컬 사각형을 선택합니다. roi의 물리 원점은 시작 셀만큼 이동하므로 로컬 인덱스와 위치를 함께 읽습니다. share는 저장소를 공유하는 별도 핸들을 만들지만 일부 영역을 지정하거나 값을 채우는 연산은 아닙니다.

median은 유효 중심의 이웃 통계를 적용하고 fill_holes는 원본의 유효 이웃으로 결측 중심을 보완합니다. 가로나 세로로 둘러싸인 결측 구간을 선형 보간하려면 directional 경로를 검토합니다. to_point_cloud는 격자 간격을 이용한 직교 변환이며 project는 카메라 모델에 따른 원근 변환입니다. 새 객체의 수명과 결측을 확인한 뒤 단위와 frame이 맞는 점군 연산으로 전달합니다.
