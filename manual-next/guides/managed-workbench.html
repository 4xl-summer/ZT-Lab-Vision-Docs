관리형 Workbench

입력, ROI, 단계 결과와 기록을 다루는 샘플

실행과 구성

Workbench는 제공된 Windows 샘플로 WPF 입력·결과와 WinForms 결과 뷰를 함께 표시합니다. ZInspectionHost에서 검사하고 ZInspectionDisplayAdapter로 결과를 표시합니다. 입력이 없으면 합성 데모를 선택할 수 있습니다. 실제 장비 취득과 외부 합격 신호는 별도로 구성해야 합니다.

검사 절차

  1. 이미지 열기 또는 합성 데모로 입력을 선택합니다.
  2. 입력 뷰에서 ROI를 지정하거나 ROI 해제로 전체를 선택합니다. 좌표는 입력 로컬입니다.
  3. 임계값과 최소 면적을 설정하고 검사 실행을 선택합니다. Gaussian 및 Close 설정은 설정 파일에서 가져올 수 있습니다.
  4. 결과 단계와 Blob 수, 시간 및 픽셀 값을 확인합니다. 맞춤과 1:1은 표시 배율을 바꾸며 검사 데이터를 변경하지 않습니다.
  5. 필요하면 결과 저장 또는 시도 기록 저장을 사용합니다. 기록 재실행은 현재 입력이 기록과 같은지 확인하고, 기록 비교는 저장된 조건과 결과를 비교합니다.

상태와 종료

대기열 포화 또는 종료 시 요청은 거절됩니다. 취소는 단계 사이에서 확인하며 이미 실행 중인 네이티브 연산을 중단하지 않습니다. 입력 또는 설정 세대가 바뀌면 오래된 결과가 새 화면을 덮지 않도록 게이트로 확인합니다. 해당 샘플 결과는 실장비 성능 또는 양산 판정의 증거가 아닙니다.

검사 연결 예제

C#
using System;
using System.Threading;
using ZVision;
using ZVision.Inspection;

class Program {
    static void Main() {
        byte[] pixels = new byte[64];
        for (int y=2; y<6; y++) for (int x=2; x<6; x++) pixels[y*8+x]=255;
        using var image = ZImage.FromGray8(8,8,pixels);
        var recipe = new ZInspectionRecipe(gaussianKernel:1, gaussianSigma:1, threshold:128, closeKernel:1, minArea:1);
        var executor = new ZInspectionExecutor();
        using var result = executor.Execute(image, 1, 1, recipe, CancellationToken.None);
        using var frame = result.CreateDisplayFrame("Close");
        using var stage = result.AcquireStage("Close");
        Console.WriteLine($"frame={result.FrameId}, blobs={result.Blobs.Count}, size={frame.Width}x{frame.Height}");
    }
}

관리형 입력·결과와 오류 표

항목입력·출력·수명
RecipeRoi는 null 또는 양의 너비·높이를 가진 입력 로컬 ZPixelRect; GaussianKernel·CloseKernel은 양의 홀수 int, GaussianSigma는 유한 양수, Threshold는 byte 0–255, MinArea는 양의 ulong 픽셀. 설정은 불변 스냅샷.
Executor.Execute입력 Gray8/Rgb8/Bgr8/Rgba8/Bgra8을 호출 중 빌림. frameId·recipeVersion은 양의 long, 취소 토큰은 단계 사이에 검사. 반환 ZInspectionResult는 호출자가 Dispose.
ResultFrameId·RecipeVersion, StageNames, 닫기 영상 Statistics, 선택 Blobs, 단계별 Name/Elapsed Metrics, 전체 Elapsed. AcquireStage는 별도 소유 영상, CreateDisplayFrame은 별도 소유 프레임. 단계명은 Input, 선택 Roi, Gray, Blur, Threshold, Close.
Host.Submitcapacity 1–16, 기본 2. Accepted는 Completion Task를 제공하고 QueueFull/Closed는 null. 수락된 입력 임대는 호스트가 해제하며 완료 결과는 호출자가 해제.

null 인수는 ArgumentNullException, 잘못된 생성 범위는 ArgumentOutOfRangeException, 지원하지 않는 입력 형식은 NotSupportedException입니다. 없는 단계명은 KeyNotFoundException이고 해제 후 획득은 ObjectDisposedException입니다. 완료 Task는 실행 오류를 전달하거나 취소될 수 있습니다. UI에서 종료 시 StopAsync를 기다리세요.

표시 입력·결과와 오류 표

항목입력·출력·수명
Frame입력 이미지와 양의 frameId·recipeVersion, 선택 overlays. Width·Height는 픽셀, PixelFormat은 원본 형식, IsDisposed는 해제 상태. Frame과 AcquireImage/Share 결과는 각각 Dispose.
RasterGray8/16/F32/F64, GrayI16/I32/U32, Rgb8/Bgr8/Rgba8/Bgra8, Rgb16/Bgr16/RgbF32 지원. Width·Height·StrideBytes(4×폭)·PixelFormat은 스냅샷; CopyBgra32는 독립 배열, GetPixel은 원본 채널 문자열.
OptionsMinimum 0, Maximum 65535 기본. 비바이트 채널의 유한 범위이며 최댓값이 더 커야 함. 바이트 채널은 직접 사용. NaN은 0, 범위 밖은 표시값을 0 또는 255로 제한.
Viewport와 GateScale 기본 1, PanX/PanY 기본 0; 배율 범위 1/16777216–64. Expect는 양의 프레임·레시피 하한을 각각 감소시키지 않음. TryAccept는 두 하한 이상인 세대만 수락하고 하한 갱신.

null 영상은 ArgumentNullException, 부적합 세대·범위·좌표는 ArgumentOutOfRangeException, 해제된 프레임의 영상 획득은 ObjectDisposedException, 지원하지 않는 래스터 형식은 NotSupportedException, 픽셀 수 한도 초과는 InvalidOperationException입니다. Raster는 관리 메모리 복사본이며 Frame 해제 뒤에도 유효합니다.

검증 범위

이 안내는 제공된 프로젝트 소스의 정적 확인을 기반으로 합니다. 아래 콘솔 예제의 실행 여부와 별개로 WPF·WinForms 창 조작, 장비 연결과 실제 생산 판정은 여기에서 실행 확인하지 않았습니다.
