관련 검증 사례

관리형 검사 예제는 가운데에 밝은 사각형을 넣은 작은 Gray8 입력과 명시적인 레시피를 이용합니다. 커널 1, 임계값 128, 최소 면적 1인 경우 처리 단계와 Blob의 연결을 관찰할 수 있습니다. 실행 처리 결과의 프레임 식별자와 레시피 버전, Close 단계와 Blob 목록은 어떤 입력과 설정에서 나왔는지 함께 살펴보아야 합니다.

처리 결과에서 얻은 프레임과 단계 영상 데이터는 독립 소유 객체이므로 예제에서는 각각 수명을 마칩니다. 이 사례의 콘솔 계산을 실행하는 것과 WPF·WinForms 창에서 선택이나 확대를 직접 확인하는 것은 별개의 작업입니다. 관련 검증 기록에서 실제 실행 여부를 확인하고, 화면 조작이나 장비 연결이 검증되었다고 추정하지 않습니다. 실물 입력의 통과 기준도 별도로 정해야 합니다.

사례의 적용 범위와 기대 출력이 현재 이용하는 입력·설정과 일치하는지 비교한 다음 실행 기록을 해석합니다.

처리 결과를 저장하거나 화면에 표시할 때 프레임 세대와 레시피 버전이 동일한 실행의 것인지 검토합니다. GUI 확인이 필요한 항목은 해당 창에서의 실행 증거를 따로 남기고, 단순한 값 계산 처리 결과와 합치지 않습니다. 기록된 콘솔 처리 결과는 창에서의 이용자 입력과 화면 렌더링을 보증하지 않습니다.

Workbench 사례의 확인 범위

Workbench 설명은 샘플 화면과 검사 호스트, 결과 표시를 연결하는 소스 경로를 다룹니다. 기록된 개별 코드 블록은 실행이 완료되었으나 결과 단언은 없습니다. WPF와 WinForms 화면을 실제로 열어 모든 버튼을 조작했다는 실행 기록으로 해석하지 않습니다.

비동기 요청에서는 입력을 바꾼 뒤 이전 결과가 늦게 도착할 수 있습니다. 요청의 식별자와 수락 상태를 결과 및 표시 프레임에 연결하고, 현재 표시 중인 입력과 같은 요청인지 확인합니다. 화면에서 선택한 ROI가 실제 전달된 영상 좌표와 일치하는지도 별도 확인점입니다.

종료 및 취소 경로는 실행 결과와 보유 영상의 해제에 영향을 줍니다. 사용 환경에서 실행 중 창을 닫거나 새로운 입력을 선택할 때 이전 프레임이 남지 않는지 검토해야 합니다. 장치 연결, 작업자 조작 및 생산 데이터 검증은 콘솔 기록의 범위 밖입니다.

대상관찰 또는 절차해석
소스 연결호스트와 화면정적 경로 확인

대화형 동작별도 시험화면 실행 기록 아님
