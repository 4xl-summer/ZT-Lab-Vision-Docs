상태와 종료

대기열 포화 또는 종료 시 요청은 거절됩니다. 취소는 단계 사이에서 확인하며 이미 실행 중인 네이티브 연산을 중단하지 않습니다. 입력 또는 설정 세대가 바뀌면 오래된 결과가 새 화면을 덮지 않도록 게이트로 확인합니다. 해당 샘플 결과는 실장비 성능 또는 양산 판정의 증거가 아닙니다.

제출 요청이 수락되지 않았을 때는 대기열 포화와 호스트 종료를 구분해 상태를 기록합니다. 수락된 작업은 완료, 취소 또는 오류로 끝날 수 있으며 완료 처리 결과를 받은 쪽이 그 소유권을 정리해야 합니다. 취소는 대기 중이거나 처리 단계가 바뀌는 지점에서 확인되므로 이미 시작한 네이티브 호출이 즉시 멈춘다고 가정하지 않습니다. 종료 중에는 새로운 요청을 받지 않고 정리 완료를 기다립니다.

표시 시점에 입력이나 설정이 바뀌었다면 늦게 도착한 과거 처리 결과가 현재 화면을 덮지 않도록 프레임과 레시피 세대를 검토합니다. Gate의 하한은 양수이며 감소시키지 않습니다. 영상 데이터 형식이 지원되지 않거나 단계 이름이 없으면 처리 결과를 조용히 빈 화면으로 취급하기보다 오류를 검토합니다. 실장비의 재시도와 외부 신호는 애플리케이션에서 별도로 정해야 합니다.

작업 취소 뒤 프레임을 다시 제출할 때에는 이전 처리 결과의 완료 여부와 새 세대를 구분하여 표시 상태를 갱신합니다.

실패 원인별 다음 확인

대기열이 꽉 찬 경우는 검사 알고리즘이 불량을 발견했다는 뜻이 아닙니다. Submit이 QueueFull을 반환하면 Completion이 없는 거절 요청이고, Closed는 호스트가 더 이상 새 작업을 받지 않는 상태입니다. Accepted 작업만 완료 결과, 취소 또는 오류를 기다릴 수 있습니다. 이 상태를 구별해 기록하면 실제로 처리되지 않은 입력을 정상 또는 불량으로 잘못 표시하는 일을 줄일 수 있습니다.

검사가 취소되면 대기 요청이나 처리 단계 사이에서 취소가 관찰될 수 있습니다. 네이티브 호출 하나가 진행 중인 동안에는 즉시 중단되지 않을 수 있으므로 새 프레임을 기다리는 화면과 자원 정리의 완료를 혼동하지 않습니다. 결과가 늦게 완성된 경우 프레임과 레시피 세대가 현재 기대 범위인지 비교하고, 표시하지 않을 결과도 소유권에 따라 해제합니다.

영상 형식이 지원되지 않거나 ROI가 범위 밖이면 입력 또는 설정 오류를 조사해야 합니다. 결과의 단계 이름이 없을 때도 빈 마스크를 보여 주는 대신 실제 존재하는 StageNames를 확인합니다. 기록 재실행에서는 저장된 입력과 현재 입력이 다르면 먼저 그 불일치를 해결한 다음 검사를 진행합니다.
