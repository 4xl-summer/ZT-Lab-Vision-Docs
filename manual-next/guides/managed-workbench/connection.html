검사 연결 예제 · 관리형 Workbench

관리형 Workbench에서 검사 연결 예제을 이해하기 위한 입력, 동작과 결과 설명

상위 목차로 돌아가기

검사 연결 예제

C#
using System;
using System.Threading;
using ZVision;
using ZVision.Inspection;

class Program {
    static void Main() {
        byte[] pixels = new byte[64];
        for (int y=2; y<6; y++) for (int x=2; x<6; x++) pixels[y*8+x]=255;
        using var image = ZImage.FromGray8(8,8,pixels);
        var recipe = new ZInspectionRecipe(gaussianKernel:1, gaussianSigma:1, threshold:128, closeKernel:1, minArea:1);
        var executor = new ZInspectionExecutor();
        using var result = executor.Execute(image, 1, 1, recipe, CancellationToken.None);
        using var frame = result.CreateDisplayFrame("Close");
        using var stage = result.AcquireStage("Close");
        Console.WriteLine($"frame={result.FrameId}, blobs={result.Blobs.Count}, size={frame.Width}x{frame.Height}");
    }
}

검사 처리 결과에서 단계 이름을 선택하면 해당 단계의 독립 영상 데이터 임대를 얻거나 표시 프레임을 만들 수 있습니다. 기본 실행기는 Input, 선택적인 Roi, Gray, Blur, Threshold, Close를 순서대로 기록합니다. 처리 결과의 StageNames를 확인한 뒤 원하는 단계를 선택하면 존재하지 않는 이름을 추측해 접근하는 실수를 피할 수 있습니다. 프레임에는 프레임 식별자와 레시피 버전이 함께 담겨 어느 입력과 설정에서 나왔는지 추적할 수 있습니다.

Threshold와 Close 표시 프레임에는 선택된 Blob의 로컬 경계가 오버레이됩니다. 이 경계는 영상 데이터 픽셀을 직접 수정하는 것이 아니라 표시 장면에 추가되는 도형입니다. 프레임과 AcquireStage로 얻은 영상 데이터는 각각 별도 소유이므로 처리 결과를 해제하는 것과 구분해 정리합니다. 예제에서 구성한 합성 입력은 연결 과정을 보여 주기 위한 것이며 실제 양산 검증은 별도의 입력과 기준이 필요합니다.

예를 들어 Close 단계를 표시할 때 해당 단계가 처리 결과에 존재하는지 확인한 다음 프레임을 얻고, 프레임 이용이 끝나면 별도로 해제합니다.
