실행과 구성

Workbench는 제공된 Windows 샘플로 WPF 입력·결과와 WinForms 결과 뷰를 함께 표시합니다. ZInspectionHost에서 검사하고 ZInspectionDisplayAdapter로 결과를 표시합니다. 입력이 없으면 합성 데모를 선택할 수 있습니다. 실제 장비 취득과 외부 합격 신호는 별도로 구성해야 합니다.

Workbench의 목적은 영상 데이터 처리 단계와 처리 결과를 한 화면에서 살펴보는 것입니다. 입력을 연 다음 ROI와 설정을 정하고 기본 검사 실행기에 전달하면, 처리 결과 단계의 영상 데이터와 Blob 정보를 표시 프레임으로 연결합니다. WPF 입력·처리 결과 뷰와 WinForms 처리 결과 뷰는 동일 검사 처리 결과를 보여 주는 샘플 구성으로, 두 표시 방식의 좌표와 수명을 확인하는 데 이용할 수 있습니다.

합성 데모는 외부 파일 없이 화면 흐름을 살펴보기 위한 입력입니다. 실제 입력에 대해서는 조명, 피사체 위치와 허용 기준을 별도로 정해야 합니다. 기본 실행기는 임계값과 형태학 처리로 영역을 찾는 예시이며 기준 정렬 차분의 자동 판정과는 별도입니다. 화면에서 보인 Blob의 수만으로 제품 합격을 선언하기 전에 목적에 맞는 처리 결과 해석 규칙을 정합니다.

예제에 연결된 실행기와 화면은 직접 확인할 수 있는 구성 요소이므로 먼저 합성 입력으로 단계별 흐름을 익힌 다음 실제 데이터에 적용합니다.

구성 요소의 책임

이 샘플에서 입력을 보여 주는 부분과 검사를 수행하는 부분은 서로 다른 책임을 가집니다. 표시 뷰는 확대·이동과 ROI 선택, 픽셀 확인을 다루고, 검사 실행기는 레시피에 따라 Gray, Blur, Threshold, Close와 분석을 수행합니다. 한쪽을 살펴볼 때 다른 쪽의 값을 자동으로 바꾸는 것으로 생각하면 화면의 모양과 실제 처리 조건을 혼동할 수 있습니다.

결과는 단계별 영상을 소유한 ZInspectionResult로 전달됩니다. 단계 이름을 확인한 뒤 화면에 사용할 프레임을 얻으면, Threshold나 Close에서는 선택된 Blob 경계가 오버레이에 포함됩니다. 이 그림은 후보를 설명하는 표시 자료이며, 결함의 허용 여부를 외부 장치에 통지하는 생산 로직은 애플리케이션이 별도로 정해야 합니다.

합성 데모를 선택하면 파일 없이도 기본 처리와 화면 연결을 익힐 수 있습니다. 실제 대상에서는 입력 형식, ROI 및 임계값이 장면에 맞는지 점검하고 결과의 성공·취소·오류와 세대를 기록합니다. 샘플이 제공하는 기록 재실행이나 비교는 동일 조건을 확인하는 데 도움이 되지만 실장비 성능 평가를 대신하지 않습니다.
