Rust typed Query 예제 · Blob Analysis · 연결 영역

Rust typed Query 예제의 사용 조건과 결과 해석을 설명합니다.

상위 목차로 돌아가기

Rust typed Query 예제

Rust
use zvision::{Connectivity, ZImage};

fn main() -> zvision::ZResult<()> {
    let image = ZImage::from_vec_gray8(3, 1, vec![0, 5, 5])?;
    let plan = image.query()?.threshold(1)?.find_blobs(Connectivity::Four);
    let execution = plan.execute()?;
    assert_eq!(execution.output().blobs().len(), 1);
    assert_eq!(execution.output().blobs()[0].area, 2);
    Ok(())
}

이 수치는 공개 Facade의 기존 v23_query 테스트와 같은 입력·조건입니다. Rust Facade의 Blob 경로는 이 예제에서 ImageQuery를 사용하지만, C#/Python에는 직접 FindBlobs 호출도 있습니다.

Rust typed Query 예제 · 핵심 동작

Rust 예제는 원본 [0,5,5]를 임계값 1로 분할한 다음 Four 연결 성분 계획을 실행합니다. 비교는 경계를 포함하므로 두 값 5는 255가 되고 첫 값 0은 배경입니다. 인접한 전경 두 칸이 한 객체를 이루어 목록 길이는 1, 면적은 2입니다. 이 결과는 밝기 합이 아니라 전경 셀 수를 센 것입니다.

Rust typed Query 예제 · 입력과 결과

질의는 단계가 연결된 계획이며 execute()를 호출한 뒤 결과를 읽습니다. output().blobs()는 실행 결과가 가진 목록을 빌리기 때문에 그 참조를 쓰는 동안 실행 결과가 살아 있어야 합니다. 계획의 소비형 빌더와 값 스냅샷을 구별하면 분기나 재사용 시 소유권을 명확히 할 수 있습니다.

Rust typed Query 예제 · 좌표와 소유권

임계값을 6으로 바꾸면 두 픽셀은 모두 미만이어서 전경이 사라집니다. 빈 목록은 이 입력에서는 정상적인 계산 결과이며 오류와 다릅니다. 4와 8의 차이를 보려면 가로 이웃 대신 대각으로만 접촉하는 입력을 사용해야 합니다.

Rust typed Query 예제 · 오류와 판단

합성 예제의 단언은 알려진 수치가 그대로 나오는지 확인하는 데 쓰입니다. 실제 ROI의 위치, 경계 절단, 불균일 조명에 대한 검사 레시피를 이 작은 배열만으로 결정하지 마십시오.
