관련 검증 사례

rust-ai-fixtures는 작은 결정론 그래프로 분류, 검출, 분할과 이상 맵의 호출 경로를 시험합니다. 분류에서는 어두운 입력과 밝은 입력에 서로 다른 클래스를 기대하고, 다른 작업에서는 해당 결과나 맵을 얻을 수 있는지 확인합니다. 이 그래프는 학습된 현장 모델이 아니므로 결과가 맞더라도 결함 검출률을 나타내지 않습니다. 테스트할 때 모델 파일과 스펙의 클래스 수·입력 크기가 서로 맞는지 먼저 확인합니다.

경계 확인에는 비어 있는 ROI, 허용되지 않는 픽셀 형식, 모델 메타데이터의 입출력 수 또는 shape 불일치가 포함됩니다. 무검출은 정상적인 빈 검출 결과이고 모델이나 입력 계약 위반은 오류입니다. 이 둘을 구분해 결과와 실패를 기록해야 합니다. 모델 버전 번호는 호출자가 지정한 식별자이므로 해당 바이트와 설정을 별도로 연결해 보관하고, 실제 생산 데이터 평가는 별도 기준으로 수행합니다.

기대값을 모델과 묶기

결정론 분류 사례는 입력의 밝기를 바꾸어 클래스 결과가 어떻게 바뀌는지 점검합니다. 검은 입력은 0, 흰 입력은 1 클래스를 기대하며, 합성 모델의 출력에 softmax를 적용한 약 0.7311의 점수도 비교합니다. 이 기대는 그 모델의 그래프와 스펙에 묶여 있습니다. 다른 모델 파일을 같은 8×8 입력에 사용했다고 동일한 클래스와 점수가 나와야 하는 것은 아닙니다.

검출, 분할, 이상 탐지 사례는 각 작업이 예상된 결과 또는 맵을 내는지도 확인합니다. 실행 기록에는 모델 파일, 입력 형식과 ROI, 각 결과의 상태를 남기고 모델 파일이 빠져 사례가 생략된 실행을 전체 통과로 세지 않습니다. shape 오류와 정상 빈 검출을 분리하고, 현장 평가에서는 독립적인 실물 데이터와 공차를 사용합니다. 합성 모델은 학습된 정확도나 장비 성능을 뜻하지 않습니다.
