개념과 사용 흐름

AiEngine은 모델 바이트와 입출력 스펙을 소유하고 run에서 이미지 ROI를 추론합니다. AiResult는 classification, detections, anomaly 또는 acquire_map으로 도메인별 결과를 제공합니다.

기본 추론은 신뢰할 수 있는 RTen 모델 바이트와 모델 스펙으로 엔진을 만든 뒤 영상의 사각형 영역을 실행하는 흐름입니다. 스펙에는 작업, 입력 폭과 높이, 채널 수, 클래스 수, model_version을 지정합니다. 입력과 출력의 메타데이터가 스펙과 맞지 않으면 엔진 생성이 실패하므로, 파일 확장자만 보고 모든 모델이 호환된다고 판단할 수 없습니다. 실행 전에는 모델이 학습된 전처리와 SDK의 ROI 크기 조정 및 값 정규화가 일치하는지 확인합니다.

작업에 따라 결과의 형태가 다릅니다. 분류는 클래스별 점수, 검출은 상자와 클래스, 분할은 클래스 맵, 이상 탐지는 점수와 맵을 반환합니다. 모델 버전은 호출자가 지정한 추적 번호이며 내용의 해시가 아닙니다. 결과와 입력 영상, 엔진의 수명은 언어별 소유 규칙을 따라 관리하고 빈 검출 결과와 모델 실행 오류를 따로 처리합니다.

모델 준비부터 결과 선택까지

기본 엔진을 만들 때 작업 종류, 입력 폭과 높이, 채널 수, 클래스 수, model_version이 모델 메타데이터와 맞아야 합니다. 예를 들어 단일 채널 8×8 분류 모델이라면 입력 텐서는 [1,1,8,8], 두 클래스면 출력은 [1,2]이어야 합니다. 이때 model_version은 호출자가 지정한 0이 아닌 추적 값입니다. 번호 자체가 모델의 바이트가 동일하다는 증거는 아니므로 파일 식별 정보도 따로 보관합니다.

엔진에 영상을 전달할 때는 1채널의 Gray8 또는 3채널의 RGB8과 유효한 ROI를 준비합니다. 후처리 결과는 작업에 따라 클래스 점수, 상자 목록 또는 맵으로 다르므로 결과 종류를 확인한 뒤 읽습니다. 모델 로딩과 실행의 오류, 조건을 통과한 상자가 없는 정상 빈 목록을 구별합니다. 결과 객체와 영상·엔진의 소유 기간을 각각 정하고 필요 없는 객체는 사용 언어의 방식으로 닫습니다.

항목조건·값판독
스펙분류, 8×8, 1채널클래스 2
입력Gray8 ROIF32 NCHW로 변환
모델고정 [1,1,8,8]출력 [1,2]
결과점수·class_id라벨은 별도 관리

AiEngine.from_bytes는 모델 바이트를 읽고 선언된 작업 및 고정 텐서 모양을 검사합니다. AiModelSpec의 channels가 1이면 입력은 Gray8, 3이면 RGB8입니다. 영상과 ROI를 준비한 뒤 run을 호출하면 지정 영역을 모델 크기로 최근접 조정하고 F32 NCHW 텐서로 만듭니다. 픽셀은 255로 나뉘므로 학습 모델이 다른 평균·표준편차를 기대한다면 기본 경로의 전처리와 맞지 않을 수 있습니다.

반환 결과는 작업별로 선택해 읽습니다. 분류에서는 class_id와 scores, 검출에서는 좌표와 score, class_id를 확인합니다. 맵을 얻는 경우 별도 소유 객체의 해제 조건을 따라야 합니다. 고급 텐서 엔진은 명시적 텐서와 별도 전처리 옵션을 사용하는 다른 경로입니다. API 이름만 보고 모델 입력 형식이나 가속 장치 지원을 추정하지 말고 실제 사용한 경로와 모델 스펙을 함께 남깁니다.

모델 로딩은 인식할 이미지가 없어도 모델 바이트와 스펙을 검사하는 단계입니다. 기본 엔진은 비어 있지 않은 최대 64 MiB 바이트와 하나의 입력·하나의 출력, 고정 F32 메타데이터를 요구합니다. 분류에서 클래스 수가 2이면 출력 모양은 [1,2]입니다. 모델에 출력이 두 개이거나 스펙의 채널과 메타데이터가 다르면 이미지 처리 전에 문제를 해결해야 합니다.

run은 영상과 ROI가 모델 입력 조건에 맞는지 검사하고 결과를 작업별 표현으로 제공합니다. 분류 결과의 class_id는 숫자 인덱스이므로 라벨 목록과 모델을 함께 버전 관리합니다. 검출은 score와 IoU 설정 이후 남은 상자 목록을 읽고, 맵 결과는 획득한 영상의 소유 기간을 확인합니다. 기본 이미지 전처리와 AdvancedAiEngine의 명시적 텐서 경로는 다른 계약이므로 호출 이름과 실제 설정을 같이 기록합니다.
