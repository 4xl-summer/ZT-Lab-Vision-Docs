출력의 좌표와 점수

분류는 logits에 softmax를 적용해 scores와 최대 class_id를 제공합니다. 검출의 각 모델 출력 행은 [x_min,y_min,x_max,y_max,score,class_id]이며 모델 입력 좌표를 ROI 범위로 되돌립니다. 결과 좌표는 전달한 이미지 기준입니다. 점수와 같은 클래스의 IoU 기준으로 후보를 걸러내며 빈 목록은 검출이 없다는 결과입니다. 형식이나 모델 오류와 구별하세요.

판독 기준

  • 기본 AiEngine은 letterbox를 하지 않습니다. 고급 전처리는 별도 옵션입니다.

수치와 도형은 연결된 계약의 핵심 관계를 설명하는 예입니다. 실제 SDK 출력으로 명시한 자료를 제외하면 실행 결과나 장비 실측으로 해석하지 않습니다. 좌표계·입력 형식·수명과 오류 조건은 관련 API 계약을 확인한 뒤 적용하세요.

관련 합성 실행 사례: rust-ai-fixtures.

검출 모델은 각 행에 모델 입력 크기 기준의 네 경계, 점수와 클래스 ID를 제공합니다. 후처리는 상자를 모델 범위로 제한하고 점수 임계값 미만 또는 유효 면적이 없는 후보를 제외합니다. 같은 클래스의 후보가 겹칠 때는 IoU 기준을 적용하고 남긴 결과를 입력 이미지의 ROI 좌표로 환산합니다. 따라서 ROI 원점이 (100,50), 크기가 모델 입력의 두 배라면 모델 좌표 (1,2)는 입력 좌표 (102,54)에 대응합니다.

class_id는 숫자이며 모델과 함께 관리하는 라벨 목록으로 의미를 해석해야 합니다. 분류의 scores는 logits를 softmax로 바꾼 값이며 가장 큰 항목의 ID가 선택됩니다. 검출 목록이 비어 있으면 조건을 통과한 후보가 없다는 뜻이고, 잘못된 행이나 비유한 출력은 별도 오류입니다. 분류 점수나 상자 점수를 현장 합격 공차로 쓰기 전에는 해당 모델과 데이터로 검증해야 합니다.

상자 환산 예

검출 상자는 모델 입력의 좌표를 ROI에 맞게 다시 매핑합니다. 모델 폭·높이가 8×8이고 입력 ROI가 (100,50)에서 시작하는 16×16이라면 모델의 x 좌표는 두 배 한 뒤 100을 더하고 y 좌표는 두 배 한 뒤 50을 더합니다. 따라서 모델 상자 (1,2,3,4)는 입력 이미지 좌표에서 (102,54,106,58)이 됩니다. 이 좌표는 전달한 이미지 기준이므로 이미지 자체가 ROI라면 원본에 표시할 때 그 영상의 원점을 추가로 확인해야 합니다.

후처리는 먼저 모든 행의 좌표 순서와 0–1 점수, 정수 클래스 ID를 검증합니다. 이후 모델 범위로 상자를 제한하고 score 기준 및 같은 클래스의 IoU 기준으로 후보를 걸러냅니다. 클래스가 다른 상자에는 같은 클래스 억제 규칙을 그대로 적용하지 않습니다. 최종 상자 목록이 비어 있는 것은 유효 후보가 없다는 뜻일 수 있고, 형식이 잘못된 행은 오류이므로 구분해 판독합니다.
