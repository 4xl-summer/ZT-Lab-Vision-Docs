검증 기준

입력 크기·채널·전처리·모델 버전 및 결과 이미지 소유권을 기록하세요. GPU 성능은 미검증입니다.

관련 설명 열기

재현 가능한 검증에는 모델 바이트의 출처와 사용자 지정 버전, 스펙, 입력 픽셀 형식과 ROI, score 및 IoU 임계값을 함께 기록합니다. model_version은 호출자가 제공하는 0이 아닌 번호이지 모델 파일의 내용 해시가 아닙니다. 동일한 번호를 서로 다른 모델에 재사용하면 결과를 추적하기 어려우므로 모델 파일 자체의 식별 정보도 별도로 보관하는 편이 좋습니다.

합성 분류 모델은 어두운 입력과 밝은 입력의 클래스 결과가 예상대로 바뀌는지, 점수 합이 softmax 해석에 맞는지 확인하는 데 사용합니다. 검출이라면 모델 좌표가 입력 ROI로 되돌아온 위치를 별도 계산해 비교합니다. 분할·이상 맵은 소유권과 크기도 확인해야 합니다. 이러한 사례는 API와 전후처리 경로의 재현을 뜻하며 학습 품질, 실제 장면 성능 또는 GPU 처리량을 입증하지 않습니다.

기록할 검증 조건

동일한 이미지라도 ROI, 모델 바이트와 후처리 설정이 바뀌면 결과를 같은 실험으로 비교할 수 없습니다. 기본 score_threshold와 iou_threshold는 각각 0.5이며 max_detections 기본값은 100입니다. 분류는 이 상자 수 제한이 아니라 클래스별 점수와 최댓값을 읽습니다. 실험 기록에는 작업 종류와 클래스 수, 입력 크기, 모델 추적 버전, ROI, 실제 사용한 임계값을 함께 남깁니다.

작은 결정론 모델에서는 검은 영상과 흰 영상을 각각 입력해 클래스가 바뀌는지, 검출이나 맵의 모양이 계약에 맞는지 확인할 수 있습니다. 이 비교는 전처리·모델 호출·후처리가 연결되었는지를 확인합니다. 데이터가 실제 생산품의 분포를 대표한다는 뜻은 아니므로, 실물의 정밀도나 오검출률을 정할 때는 별도 보류 데이터와 합격 기준을 사용합니다. CPU 실행 결과를 GPU 성능 검증으로 간주하지 않습니다.
