바코드·OCR 인식

인식 문자열뿐 아니라 상태·실패 이유·좌표를 분석하는 방법.

개념과 사용 흐름

ZImage::read_barcode는 BarcodeSpec을 받아 BarcodeRead를 생성하고 OcrEngine::read_text는 OcrSpec에 따라 OcrRead를 만듭니다.

ReadStatus, reasons, text, confidence, points 등의 값으로 실패 이유를 추적해야 합니다. Rust recognition Cargo feature와 모델 자원을 구분합니다.

검증 기준

텍스트만 기록하지 말고 인식 영역과 조명 조건·상태를 함께 저장하세요.

관련 설명 열기

모델·문자와 판정

OCR은 신뢰할 수 있는 호환 RTen 인식 모델 바이트가 필요합니다. 인식 입력은 NCHW 4차원이며 배치 1, 고정 회색 채널 1, 높이 1–4096입니다. 출력 메타데이터가 있으면 [sequence,batch,labels]이며 고정 label 차원은 CTC 공백을 포함해 97입니다. 이는 임의 언어나 글꼴의 인식 정확도를 뜻하지 않습니다.

OcrSpec의 min_contrast는 유한한 0–1, min_length는 1 이상, max_length는 min_length 이상입니다. allowed_chars는 비어 있지 않은 출력 가능 ASCII(0x20–0x7e) 문자열입니다. 결과의 status와 reasons를 먼저 확인하고 text, chars의 codepoint와 네 모서리, contrast, 선택적 confidence를 사용하세요. 문자가 없거나 조건에 맞지 않으면 빈 문자열만으로 정상 판정하지 마세요. 대비가 임계값 미만이면 Rejected/LOW_CONTRAST, 대비가 0이고 임계값을 통과하면 NoRead/NOT_FOUND 및 EMPTY입니다.

OCR 영역과 좌표

OcrRegionSpec의 roi는 입력 이미지 내부의 비어 있지 않은 사각형, quarter_turns는 0–3인 90도 회전 횟수입니다. light_text는 밝은 문자를 어두운 문자로 반전하고 normalize는 대비 범위를 확장합니다. 대비는 원본 ROI의 (최대−최소)/255입니다. 회전된 전처리 영상의 테두리 좌표는 결과의 변환을 통해 입력 로컬 또는 원본 글로벌 좌표로 되돌립니다. 결과 텍스트 및 문자 모서리와 상태를 함께 기록하세요.

별도 글꼴 템플릿 경로

FontOcrModel은 라벨과 잘라낸 글자 셀을 학습하는 별도 방법입니다. FontOcrOptions의 threshold는 u8, light_text는 극성, closing_radius는 0–8, 최소 너비·높이는 1 이상, 최대값은 각 최소값 이상입니다. split_touching은 넓은 연결 성분을 분할합니다. allowed_chars는 비어 있지 않아야 하고 position_chars는 비어 있거나 위치별 비어 있지 않은 문자 집합입니다. min_glyph_score 및 min_string_score는 유한한 0–1입니다. NearestExample 또는 ClassMean으로 학습하며 결과 점수는 보정된 확률이 아니라 유사도입니다. 각 글자의 label, cell, score, accepted와 전체 accepted를 확인합니다.

무검출 합성 예제

균일한 Gray8 입력에 QR 코드가 없어 NoRead/NOT_FOUND를 기대합니다. 이 예는 OCR 정확도 검증이 아닙니다.

Python
from zvision import ZImage, BarcodeSpec, BarcodeFormat, ReadStatus, ReadReason

with ZImage.from_gray8(8, 8, bytes([127] * 64)) as image:
    result = image.read_barcode(BarcodeSpec(BarcodeFormat.QR_CODE))
    assert result.status == ReadStatus.NO_READ
    assert result.reasons == ReadReason.NOT_FOUND

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

글꼴 학습 합성 예제

rust-font-ocr는 3×5 합성 글자 A를 학습해 동일 입력의 A와 accepted를 기대합니다. 학습과 평가가 같은 영상이므로 독립 정확도 시험은 아닙니다. recognition feature가 필요합니다.

Rust
use zvision::{FontOcrModel, FontOcrOptions, FontSample, FontTrainingAlgorithm, ZImage, ZRect};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let options = FontOcrOptions {
        threshold: 100, light_text: false, closing_radius: 0,
        min_width: 1, max_width: 10, min_height: 1, max_height: 10,
        split_touching: false, allowed_chars: "A".into(), position_chars: vec![],
        min_glyph_score: 0.9, min_string_score: 0.9,
    };
    let glyph = ZImage::from_vec_gray8(3, 5, vec![255,0,255, 0,255,0,
        0,0,0, 0,255,0, 0,255,0])?;
    let samples = [FontSample { label: 'A', image: glyph.share(), cell: ZRect::new(0,0,3,5) }];
    let model = FontOcrModel::train(&samples, FontTrainingAlgorithm::NearestExample, &options)?;
    let read = model.read(&glyph, &options)?;
    assert!(read.accepted());
    assert_eq!(read.lines().next().unwrap()[0].label, 'A');
    Ok(())
}
