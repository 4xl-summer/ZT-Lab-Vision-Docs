관련 API

관리형 처리 설정을 만들 때는 ZInspectionRecipe의 ROI, 가우시안, 임계값, 닫기 및 최소 면적을 선택합니다. ZInspectionExecutor는 입력을 빌려 단계 검사 결과와 통계를 생성하고, 비동기 제출이 필요하면 ZInspectionHost가 대기열과 작업 수락 상태를 관리합니다. Accepted인 경우의 완료 작업과 QueueFull 또는 Closed 상태를 구분해야 합니다.

ZInspectionResult의 AcquireStage는 별도로 해제할 이미지 임대를, CreateDisplayFrame은 표시할 프레임을 제공합니다. ZDisplayFrame은 이미지와 세대 정보를 묶고, ZViewport는 화소 중심과 화면 좌표를 변환하며, ZDisplayFrameGate는 오래된 세대를 거르는 데 사용합니다. 각 객체의 수명과 표시 좌표를 구분해야 화면과 검사 검사 결과가 일치합니다. 개별 속성과 메서드는 관련 API 표에서 찾아볼 수 있습니다.

호출마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

표시 프레임이 입력한 레시피 버전과 다른 검사 결과를 담고 있다면 화면을 갱신하기 전에 세대가 유효한지 살펴봅니다. 프레임 Gate가 통과한 값과 사용자가 현재 선택한 조건을 함께 관리해야 검사 결과를 올바르게 해석할 수 있습니다.

표시 프레임과 좌표 변환

ZDisplayFrame은 표시할 영상 임대와 오버레이 장면을 함께 다룹니다. Share는 별도 프레임을 만들고 AcquireImage는 별도 영상 임대를 돌려주므로 각각 사용이 끝나면 해제합니다. 화면에 복사한 배열은 프레임이 보유한 영상 핸들과 수명이 다른 관리 메모리 결과입니다.

ZDisplayOptions의 범위는 바이트가 아닌 채널을 화면 밝기로 옮길 때 사용합니다. 기본 0–65535와 더 좁은 범위는 같은 원본 값도 다른 밝기로 표시할 수 있습니다. 표시색으로 정량 판정을 내리기보다 GetPixel의 원본 채널 값과 사용한 표시 범위를 함께 읽습니다.

ZViewport는 영상 픽셀 중심과 화면의 배율·이동을 연결합니다. 예를 들어 배율 2, 이동 0이면 x=0 픽셀 중심은 화면 x=1입니다. 화면에서 만든 ROI가 영상 밖이거나 빈 겹침이면 결과가 없을 수 있습니다. 결과를 검사에 넘기기 전 존재 여부와 원본 영상 좌표를 확인합니다.
