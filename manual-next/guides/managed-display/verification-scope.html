검증 범위

이 안내는 제공된 프로젝트 소스의 정적 확인을 기반으로 합니다. 아래 콘솔 예제의 실행 여부와 별개로 WPF·WinForms 창 조작, 장비 연결과 실제 생산 판정은 여기에서 실행 확인하지 않았습니다.

이 페이지의 사례는 공개된 설정과 샘플 코드를 이해하기 위한 합성 입력을 사용합니다. 검증 사례에서 확인하는 대상은 정해진 이미지와 조건에서 반환되는 상태, 화소 또는 후보 수처럼 구체적으로 재현 가능한 항목입니다. 검증 페이지의 사례 식별자를 통해 언어와 실제 실행 상태를 확인하고, 실행하지 않은 환경에 대해서는 소스 설명과 실행 검사 결과를 구분해서 읽어야 합니다.

관리형 표시와 Workbench의 경우 콘솔에서 처리 검사 결과를 계산하는 것과 WPF 또는 WinForms 창을 직접 조작하는 것은 다른 검증입니다. 화면 배치, 마우스 입력, 물리 카메라, 설비와의 연결 또는 실제 제품의 합격 판정은 합성 콘솔 출력만으로 확인되지 않습니다. 새 환경에 적용할 때는 사용하는 형식과 ROI, 표시 배율 및 해제 순서를 해당 환경에서 다시 살펴봅니다.

검증 기록에는 사용한 사례와 실행 여부를 함께 남기고, 정적 소스 대조만 한 영역을 GUI 실행 성공으로 표시하지 않습니다.

처리 결과와 화면 확인 구분

검사 결과를 표시 프레임으로 바꾸는 합성 코드는 단계 이름과 소유권의 연결을 확인하는 데 사용됩니다. Close 단계의 프레임을 요청하면 영상과 선택된 Blob 경계 장면이 준비됩니다. 이 객체가 생성되었다는 결과는 표시 데이터의 수명 계약에 관한 것이며, 특정 모니터에서 도형이 실제로 어떻게 보였는지까지 단정하지 않습니다.

뷰포트 계산은 픽셀 중심과 화면 좌표 사이의 수식으로 확인할 수 있습니다. Scale 2, Pan 0에서 로컬 첫 픽셀 중심은 화면 좌표 (1,1)입니다. 실제 GUI에서는 창의 크기, 사용자가 선택한 확대와 장치 환경이 별도로 영향을 주므로 현재 화면에서 선택한 좌표를 직접 확인해야 합니다. 검사 결과의 픽셀 좌표는 화면 확대만으로 변경되지 않습니다.

WPF와 WinForms에 대한 소스 설명, 콘솔 코드의 실행 결과, 브라우저나 화면에서 조작한 결과를 같은 검증으로 합치지 않습니다. 각각에 실행 환경과 사례를 남기고, 확인하지 않은 카메라 입력 또는 생산 판정을 완료한 것처럼 표시하지 않습니다.
