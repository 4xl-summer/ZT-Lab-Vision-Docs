상위 목차로 돌아가기

관리형 검사 파이프라인

ZInspectionExecutor는 Input → 선택 Roi → Gray → Blur → Threshold → Close → 통계 및 Blob 순서입니다. Gray8과 RGB/BGR/RGBA/BGRA 8비트 입력을 받습니다. 이것은 정렬 차분 판정기가 아니라 단계 영상과 분석 결과를 제공하는 별도의 실행기입니다. ZInspectionRecipe 기본값은 전체 ROI, GaussianKernel 3, GaussianSigma 1, Threshold 128, CloseKernel 3, MinArea 1입니다. 두 커널은 양의 홀수, sigma는 유한한 양수, 면적은 양수입니다. ROI는 입력 로컬 좌표이며 결과 Blob 경계도 단계 로컬 좌표입니다.

결과의 FrameId, RecipeVersion, StageNames, Statistics, Blobs, Metrics, Elapsed는 스냅샷입니다. AcquireStage는 별도 해제할 영상 임대이며 없는 이름은 오류입니다. Threshold와 Close의 CreateDisplayFrame은 선택 Blob 경계를 오버레이합니다. 프레임은 결과와 독립 소유입니다.

관리형 기본 실행기는 입력을 공유하고 선택된 ROI를 적용한 뒤 회색 변환, Gaussian 블러, 임계값 처리, 닫기와 분석 순서로 진행합니다. 입력이 Gray8이면 회색 단계에서 이미지를 공유하고, 지원되는 8비트 컬러 입력이면 회색 이미지으로 변환합니다. Threshold와 Close 단계의 이미지는 중간 검사 결과로 보관되므로 어느 단계에서 예상과 다른 마스크가 생겼는지 살펴볼 수 있습니다.

ZInspectionRecipe의 기본값은 전체 ROI, Gaussian 커널 3과 sigma 1, 임계값 128, 닫기 커널 3, 최소 면적 1입니다. 두 커널은 양의 홀수, sigma는 유한한 양수이고 최소 면적은 양수입니다. 실행 검사 결과에는 선택된 Blob과 통계, 단계 이름 및 시간 정보가 담깁니다. 이 기본 실행기는 기준 이미지 정렬과 차분 판정을 자동으로 수행하지 않으므로 그런 검사가 필요하면 별도 정렬·차분 레시피를 구성합니다.

시간 값은 해당 단계의 경과 시간이며 이 한 번의 합성 사례만으로 다른 입력이나 장비의 처리 속도를 보증할 수 없습니다.

표시할 중간 단계를 고르기

같은 검사 실행에서도 표시하는 단계에 따라 화면의 의미가 달라집니다. Input은 제출한 영상의 임대이고 Gray는 회색 처리의 입력입니다. Blur는 Gaussian 설정이 반영된 영상이며 Threshold와 Close는 그 뒤에 생긴 이진 결과입니다. 원본이 RGB8 계열이면 Gray 단계에서 채널이 변환되므로 원본의 색과 이진 마스크를 같은 수치로 비교하지 않습니다.

예를 들어 입력에서는 작은 밝은 점이 보이지만 Threshold 단계에 없으면 임계값 또는 이전 블러의 영향을 먼저 점검합니다. Threshold에는 있지만 최종 선택 목록에 없다면 Close와 최소 면적 조건을 살펴봅니다. Threshold와 Close의 표시 프레임은 선택된 Blob 경계 오버레이를 제공하므로 픽셀 영상과 선택된 후보를 같은 뷰에서 비교할 수 있습니다. 오버레이는 영상의 원본 픽셀을 바꾸는 연산이 아닙니다.

결과에서 AcquireStage로 얻은 영상과 CreateDisplayFrame으로 얻은 프레임은 각각 독립 소유입니다. 결과를 닫기 전에 필요한 객체를 획득하고, 획득한 프레임과 영상도 사용을 마친 후 해제합니다. 결과의 프레임과 레시피 버전은 표시할 조건이 현재 화면의 입력과 일치하는지 확인하는 데 사용합니다.

표시 단계의미검토 질문
Input제출 입력원본에 대상이 보이는가
Blur가우시안 결과작은 변화가 얼마나 남는가
Threshold이진 전경임계값 경계가 맞는가
