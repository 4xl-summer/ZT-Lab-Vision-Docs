관련 검증 사례

관리형 검사 예제는 가운데에 밝은 사각형을 넣은 작은 Gray8 입력과 명시적인 레시피를 사용합니다. 커널 1, 임계값 128, 최소 면적 1인 경우 처리 단계와 Blob의 연결을 관찰할 수 있습니다. 실행 검사 결과의 프레임 식별자와 레시피 버전, Close 단계와 Blob 목록은 어떤 입력과 설정에서 나왔는지 함께 살펴보아야 합니다.

검사 결과에서 얻은 프레임과 단계 이미지는 독립 소유 객체이므로 예제에서는 각각 수명을 마칩니다. 이 사례의 콘솔 계산을 실행하는 것과 WPF·WinForms 창에서 선택이나 확대를 직접 확인하는 것은 별개의 작업입니다. 관련 검증 기록에서 실제 실행 여부를 확인하고, 화면 조작이나 장비 연결이 검증되었다고 추정하지 않습니다. 실물 입력의 통과 기준도 별도로 정해야 합니다.

사례의 적용 범위와 기대 출력이 현재 사용하는 입력·설정과 일치하는지 비교한 다음 실행 기록을 해석합니다.

검사 결과를 저장하거나 화면에 표시할 때 프레임 세대와 레시피 버전이 동일한 실행의 것인지 살펴봅니다. GUI 확인이 필요한 항목은 해당 창에서의 실행 증거를 따로 남기고, 단순한 값 계산 검사 결과와 합치지 않습니다. 기록된 콘솔 검사 결과는 창에서의 사용자 입력과 화면 렌더링을 보증하지 않습니다.

관리형 표시 예제의 확인 범위

표시 예제의 코드 블록 실행 기록은 프레임과 관련 코드가 지정 환경에서 끝났음을 나타냅니다. 해당 블록에 결과 단언은 없으며, 이 기록만으로 화면을 열어 마우스로 확대하거나 ROI를 끌었다고 말할 수 없습니다. 코드 경로와 대화형 동작은 각각 확인해야 할 대상입니다.

표시 이미지의 밝기는 원본 채널 형식과 선택한 표시 범위에 영향을 받습니다. 따라서 눈에 보이는 색뿐 아니라 원본 값, 화면 래스터와 범위를 함께 비교해야 합니다. 프레임의 영상 임대를 해제하는 시점과 복사된 픽셀 배열의 수명도 구별합니다.

좌표 변환의 확인에는 영상 크기, 배율과 이동량을 기록하고 알려진 픽셀 중심을 화면 위치와 비교합니다. ROI를 드래그하는 화면 시험은 별도이며 영상 경계 밖의 입력이나 빈 영역도 확인해야 합니다. 콘솔 실행 결과를 GUI 통과로 해석하지 않습니다.

대상관찰 또는 절차해석
코드 블록실행 완료단언 없음
원본 값채널 값 읽기표시색과 구분
좌표배율·이동 확인픽셀 중심 비교
GUI별도 조작 시험콘솔과 구분
