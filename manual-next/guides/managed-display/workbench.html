Workbench 연결

제공되는 Workbench는 입력을 열고 ROI와 검사 설정을 조정하며 단계 영상, 통계와 Blob을 확인하는 예제 애플리케이션입니다. 검사 실행, 표시와 오버레이는 각각 Inspection 및 Display 구성요소를 연결합니다. 이는 장비 취득이나 합격 신호를 자동으로 구성하는 제품 루프가 아닙니다. 실제 시스템은 취득 실패, 프레임 세대, 재시도, 판정 정책과 종료를 애플리케이션에서 정해야 합니다.

Workbench 예제는 이미지 입력, ROI 지정, 검사 설정, 단계별 검사 결과 확인을 연결하는 Windows 샘플입니다. 이미지 열기 또는 합성 데모로 입력을 준비하고 임계값과 최소 면적을 조절한 뒤 검사를 실행할 수 있습니다. 검사 결과 창의 Blob 경계는 선택된 영역을 시각화하며, 맞춤과 1:1은 표시 배율을 조절하는 기능입니다. 표시 배율을 바꾸어도 검사에 쓰인 화소가나 설정이 바뀌지는 않습니다.

설정 저장과 열기는 실행 조건을 보존하는 데 쓰이고, 검사 결과나 시도 기록은 별도로 저장할 수 있습니다. 기록 재실행에서는 현재 입력이 저장된 기록과 일치하는지 살펴봅니다. 취소나 오류, 오래된 세대의 검사 결과는 화면의 현재 입력과 섞지 않도록 구분해야 합니다. 이 기능은 제공된 샘플의 동작 범위이며 카메라 취득이나 외부 설비 신호가 자동으로 구성된다는 의미는 아닙니다.

입력과 검사 결과 탭에 보이는 좌표가 다르다면 먼저 현재 ROI와 화면 배율을 확인하고 원본 이미지와 검사 결과 단계의 식별자를 대조합니다.

샘플 화면에서 검사의 경로

Workbench의 입력 뷰에서 영상이나 합성 데모를 선택한 다음 ROI와 레시피 조건을 정합니다. 실행 후 결과 뷰에는 해당 단계의 영상과 선택된 Blob 경계가 표시됩니다. WPF 입력·결과와 WinForms 결과 탭은 동일한 검사 결과를 서로 다른 표시 구성으로 보여 주는 샘플입니다. 화면을 맞춤이나 1:1로 바꾸는 것은 보기 배율을 조절하며 원본 검사 데이터나 임계값을 다시 계산하지 않습니다.

설정 저장은 레시피 조건을 나중에 불러오기 위한 작업이고 결과 저장은 완료 또는 시도의 산출물을 보존하는 별도 작업입니다. 기록 재실행은 현재 입력이 저장된 기록과 일치하는지 확인한 뒤 설정을 적용합니다. 입력이 다르면 같은 조건으로 다시 실행했다는 설명이 성립하지 않으므로 오류를 확인하고 올바른 입력을 선택해야 합니다.

Workbench가 쓰는 검사 호스트의 결과는 frameId와 recipeVersion으로 식별됩니다. 설정을 빠르게 바꾸는 동안 이전 작업이 늦게 끝났다면 현재 기대 세대와 대조합니다. 이 샘플의 소스 동작 설명은 실제 사용자의 Windows 화면에서 버튼을 조작했다는 검증 기록이 아닙니다. 카메라와 생산 장비를 연결하려면 해당 환경에서 별도 확인이 필요합니다.
