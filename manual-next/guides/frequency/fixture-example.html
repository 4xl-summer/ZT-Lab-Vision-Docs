합성 입력 전체 예제

이 예제는 합성 입력을 사용합니다. 실제 촬영 데이터나 실행 성능을 나타내지 않습니다.

Rust
use zvision::{FftNormalization, FftOptions, ZImage, ZResult};
fn main() -> ZResult<()> {
    let image = ZImage::from_vec_gray8(2, 2, vec![1, 1, 1, 1])?;
    let spectrum = image.fft(FftOptions { width: 2, height: 2,
        normalization: FftNormalization::Backward })?;
    let (real, imaginary) = spectrum.parts();
    println!("real={real:?}, imaginary={imaginary:?}");
    let (_, _, restored) = spectrum.inverse_values(true)?;
    println!("restored={restored:?}");
    Ok(())
}

기대 실수부는 [4, 0, 0, 0], 복원값은 [1, 1, 1, 1]입니다. 부동소수점 허용 오차로 비교하십시오.

기존 Rust 예제는 네 픽셀이 모두 1인 합성 2×2 입력으로 순변환과 역변환을 확인합니다. 이 입력에는 위치에 따른 밝기 변화가 없으므로 합인 DC만 남고 다른 주파수 성분은 0이 됩니다. Backward 순변환의 기대 실수부가 [4,0,0,0]인 이유는 네 개의 1을 더하기 때문입니다.

역변환은 정규화에 따라 복원 크기를 맞추므로 기대 배열은 다시 [1,1,1,1]입니다. 실제 부동소수 결과는 비교 허용 오차 안에서 확인하고, 출력 배열의 순서와 크기도 같이 검사하십시오. 변환 전후의 개별 값과 기대값을 모두 확인해야 총합만 같은 잘못된 배열을 통과시키지 않습니다.

입력은 실제 카메라 데이터가 아니며 필터 선택의 시각적 효과까지 검증하지 않습니다. 경계나 반복 무늬의 억제 효과가 필요하면 별도의 알려진 패턴을 준비해 위상과 공간 결과를 함께 평가하십시오.

네 원소의 순서는 행 우선 배열을 기준으로 읽습니다. DC만 맞는지 보는 것뿐 아니라 나머지 세 위치가 0에 가까운지, 역변환의 크기가 2×2로 유지되는지 함께 확인하십시오.
