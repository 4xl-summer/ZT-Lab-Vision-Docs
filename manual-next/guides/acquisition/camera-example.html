합성 프레임 예제 · SimulatedCamera · 취득 모의

모의 카메라 상태와 트리거·프레임 소유권을 설명합니다.

상위 목차로 돌아가기

합성 프레임 예제

Python
from zvision import ZImage, SimulatedCamera, CameraSpec, TriggerMode, OfferDisposition

with ZImage.from_gray8(8, 8, bytes([127] * 64)) as image:
    with SimulatedCamera.create(CameraSpec(1, 2, 1000, 2, TriggerMode.SOFTWARE)) as camera:
        camera.connect()
        camera.start()
        camera.trigger(1, 100)
        assert camera.offer_frame(image, 1, 10, 101, 1) == OfferDisposition.ACCEPTED
        with camera.try_get_frame() as frame:
            assert frame.info.frame_id == 1
        assert camera.try_get_frame() is None

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

이 합성 입력은 8×8 Gray8 영상을 모든 픽셀 127로 채웁니다. 카메라 설정은 source_id 1, clock_domain 2, tick_hz 1000, 용량 2, 소프트웨어 트리거입니다. connect와 start 후 트리거 ID 1을 등록하고 같은 ID의 frame_id 1을 제안합니다. 기대되는 반환은 ACCEPTED이며 첫 번째로 꺼낸 프레임의 ID는 1입니다. 두 번째 시도는 정상적인 빈 큐를 나타내는 None입니다.

trigger에 전달한 host 시간 100과 프레임의 host 시간 101은 증가 순서를 만족합니다. device_ticks 10은 장치 틱이므로 host 나노초와 값만으로 직접 비교하지 않습니다. with 블록은 입력 이미지, 카메라, 꺼낸 프레임의 소유 범위를 명시합니다. 큐가 복사본을 소유하므로 입력 이미지를 결과 자체로 착각하지 않도록 실제 사용에서는 프레임의 이미지와 메타데이터를 함께 읽고 각각 필요한 기간 동안 보관합니다.

예제의 시각과 순서

제공된 예제에서는 트리거 ID 1을 host 시각 100에 등록하고, frame_id 1의 영상을 장치 10틱·호스트 101 ns로 제안합니다. host 시각이 100에서 101로 증가하므로 모의 객체가 검사하는 시간 순서를 만족합니다. FreeRun이 아닌 Software 설정이므로 제안에 지정한 trigger_id도 1이어야 하며 등록되지 않은 ID를 사용하면 정상적인 ACCEPTED가 아닙니다.

입력 영상의 64개 샘플이 모두 127이라는 점은 복사 여부를 확인하기 좋은 합성 조건입니다. 수락 후 큐에서 프레임을 꺼내면 해당 ID가 1인지 검사하고, 다음 읽기에서 None을 기대합니다. 필요하다면 획득한 이미지의 픽셀 배열도 원래 64개 값과 비교할 수 있습니다. 프레임의 image를 별도로 얻는 경우 그 이미지 핸들의 범위까지 정리해야 하며, 틱값과 호스트 시각의 수치를 같은 단위로 해석하지 않습니다.
