오류·주의사항

OfferFrame이 수락되면 독립 픽셀 복사 프레임을 저장합니다. AcquiredFrame은 이미지를 별도 소유로 획득할 수 있습니다.

프레임이 수락되면 제공한 픽셀을 복사해 큐에 넣습니다. 따라서 원본 이미지를 재사용하거나 닫는 일과 큐의 프레임을 소비하는 일은 구분됩니다. 꺼낸 프레임의 이미지도 별도 소유 경로로 얻으므로 언어별 close 또는 using 범위를 지켜야 합니다. 큐가 가득 찼을 때는 새 프레임이 QueueFull로 보고되며, 이 상태를 이미지가 정상 전달된 것으로 계산하면 프레임 손실을 놓치게 됩니다.

frame_id 중복이나 역순은 별도의 반환 상태와 통계로 구분됩니다. host_ns는 이전 값보다 작을 수 없고 device_ticks도 역행하면 오류입니다. 트리거 모드에서는 유효한 대기 ID가 필요하며 FreeRun에서는 ID가 0이어야 합니다. 취득 중이 아닌 상태의 호출과 빈 큐는 다릅니다. 빈 큐는 취득 중 try_get_frame의 정상적인 빈 결과이지만, 상태가 잘못된 호출은 오류로 처리해야 합니다.

제안 결과별 후속 처리

이미지 제안의 반환을 확인하지 않고 프레임을 꺼내려 하면 입력을 한 번 넣은 사실과 실제 전달된 사실을 혼동합니다. ACCEPTED는 복사본이 큐에 들어갔음을 뜻합니다. QUEUE_FULL은 공간이 없어 새 프레임을 넣지 못한 결과이고 통계의 queue_dropped가 증가합니다. 같은 frame_id의 재제안은 DUPLICATE, 이전보다 작은 ID는 OUT_OF_ORDER로 별도 판정합니다.

입력 상태가 잘못된 경우는 이 네 결과와도 다릅니다. 취득이 시작되기 전의 제안, 0인 frame_id, FreeRun에서 0이 아닌 trigger_id, 소프트웨어 모드에서 등록되지 않은 ID 등은 오류로 처리해야 합니다. 호출자가 공급하는 host_ns가 역행해도 유효하지 않습니다. 정상 빈 큐를 예외로 바꾸거나 오류를 빈 프레임으로 대체하면 손실 진단이 어려워지므로 반환과 오류를 따로 기록합니다.

항목조건 또는 값판독
ACCEPTED프레임 복사소비 가능
QUEUE_FULL새 프레임 미보관손실 통계 확인
DUPLICATE동일 frame_id중복 통계 확인
OUT_OF_ORDER이전보다 작은 ID순서 오류 확인
