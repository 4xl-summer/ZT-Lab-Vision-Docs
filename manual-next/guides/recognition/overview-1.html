개념과 사용 흐름

ZImage::read_barcode는 BarcodeSpec을 받아 BarcodeRead를 생성하고 OcrEngine::read_text는 OcrSpec에 따라 OcrRead를 만듭니다.

인식에는 서로 다른 입력과 결과를 갖는 바코드와 문자 읽기가 있습니다. 바코드는 영상과 BarcodeSpec의 형식 선택, 회전 시도, 최소 대비를 이용해 판독합니다. OCR은 호환 인식 모델과 OcrSpec에 지정한 영역, 회전과 문자 규칙이 필요합니다. 영상에 기호가 없거나 대비가 부족한 결과는 처리 경로에서 구분되므로 문자열만 확인해서 성공을 판단하면 안 됩니다.

결과에는 status와 reasons 외에 텍스트와 위치 정보가 들어갑니다. OCR은 각 문자의 코드포인트와 네 모서리, 대비와 선택적 confidence를 제공하고 바코드는 형식과 위치 등 판독 정보를 반환합니다. ROI는 현재 이미지의 범위에 있어야 하며 영상이 원본의 ROI라면 로컬과 글로벌 좌표가 다를 수 있습니다. 모델 파일과 설정을 기록하고, 소유한 영상과 엔진의 수명을 언어별 규칙에 맞춰 관리합니다.

판독 경로를 고르는 기준

바코드 읽기는 인쇄된 코드 형식을 선택해 그 형식의 기호를 찾고 디코딩합니다. 예를 들어 QR만 선택하면 Code 39를 찾아야 하는 작업과 검색 조건이 다릅니다. OCR은 이미지 속 문자를 읽는 모델과 ROI, 길이 및 문자 집합 규칙을 준비합니다. 두 경로 모두 입력에 대상이 없을 수 있으므로 정상 호출의 빈 결과와 잘못된 모델 또는 영상 인자의 오류를 먼저 구분합니다.

판독한 위치를 원본 위에 그릴 때는 결과의 local과 global 좌표를 확인합니다. 이미 원본의 ROI를 영상으로 잘라 전달했다면 local (0,0)은 원본의 (0,0)이 아니라 그 ROI의 원점입니다. 예를 들어 원점이 (100,50)이고 로컬 모서리가 (3,4)이면 글로벌 위치는 (103,54)입니다. 상태가 수용인지 확인한 다음 문자열과 위치를 사용하고, 판독 실패를 제품에 코드가 없다는 물리적 결론으로 확대하지 않습니다.

BarcodeSpec은 읽을 형식과 전처리 조건을 정하고, BarcodeRead는 판독 상태와 텍스트·위치 등 결과를 담습니다. 형식 선택은 여러 비트를 조합할 수 있지만 선택했다고 모든 장면에서 읽기가 보장되는 것은 아닙니다. 대상이 없는 합성 영상에서는 정상 호출이라도 NO_READ가 될 수 있습니다. 오류가 발생한 호출과 무검출 결과를 분리해야 후속 검사에서 미판독을 정상 제품으로 처리하지 않습니다.

OCR 경로의 OcrEngine은 호환 모델 바이트로 준비하고 OcrSpec은 ROI, 대비와 허용 문자 및 길이를 지정합니다. OcrRead의 status와 reasons를 먼저 확인한 뒤 text와 문자 모서리를 사용합니다. 이미지 ROI 원점이 있는 경우 위치의 local과 global을 구별해야 합니다. 템플릿 글꼴 모델은 별도의 학습 방식이므로 일반 OCR 모델의 문자 집합이나 정확도를 대체한다고 가정하지 않습니다.

BarcodeSpec의 형식 선택은 탐색할 기호 종류를 지정합니다. QR과 Code 128은 같은 값이 아니며 여러 비트를 조합할 수 있습니다. 모델이 필요한 OCR 경로에서는 OcrEngine을 준비하고 OcrSpec의 ROI와 회전, 허용 문자 및 길이를 정합니다. 이때 allowed_chars는 판독 결과의 수용 규칙이지 모델에 새 문자를 학습시키는 방법이 아닙니다.

결과를 사용하는 순서는 먼저 status와 reasons를 읽고, 그 다음 text 및 문자 또는 바코드 위치를 확인하는 것입니다. 낮은 대비, 대상 없음, 길이 또는 문자 집합 위반은 서로 다른 이유로 기록됩니다. 문자 confidence는 선택적이므로 항상 숫자가 있다는 가정을 두지 않습니다. 모델이나 ROI 계약 위반이 예외인 경우에는 읽힌 빈 문자열을 얻은 것과 다른 경로로 처리해야 합니다.
