오류·주의사항

ReadStatus, reasons, text, confidence, points 등의 값으로 실패 이유를 추적해야 합니다. Rust recognition Cargo feature와 모델 자원을 구분합니다.

빈 문자열은 여러 상태에서 나타날 수 있으므로 text만으로 성공을 추론하지 않습니다. 판독 대상이 없어 NO_READ가 나올 수 있고, 대비나 문자·길이 규칙에 맞지 않아 REJECTED가 될 수도 있습니다. reasons는 해당 이유를 나타내는 비트이며 여러 조건이 동시에 설정될 수 있습니다. 예를 들어 대비가 임계값 미만인 경우 낮은 대비 사유를 기록하고, 원본 ROI와 설정한 최소 대비를 함께 확인합니다.

모델 바이트와 영상 형식이 잘못된 경우는 정상 판독 상태가 아니라 호출 오류입니다. OCR은 호환 RTen 인식 모델과 단일 회색 채널 입력 계약을 요구합니다. 결과 문자 위치는 ROI 회전을 거친 전처리 좌표를 입력 좌표로 되돌린 값이므로 local과 global을 혼동하지 않습니다. confidence는 선택값이어서 항상 존재하거나 서로 다른 모델 사이에서 같은 의미라고 가정하지 않습니다.

상태와 이유를 분리

같은 빈 텍스트라도 왜 비었는지를 확인해야 합니다. 영역의 대비가 최소값보다 낮으면 낮은 대비로 거절될 수 있고, 대상을 찾지 못하면 NO_READ와 관련 이유가 반환될 수 있습니다. 길이 또는 허용 문자 조건을 통과하지 못하는 경우는 규칙 위반입니다. reasons는 비트 조합이므로 한 번에 한 원인만 존재한다고 전제하지 않습니다.

예를 들어 균일한 Gray8 영역의 최소값과 최대값이 모두 127이면 대비는 (127−127)/255=0입니다. min_contrast가 양수이면 낮은 대비 분기가 먼저 적용되고, 0을 허용해 이를 통과한다면 대상 없음과 빈 텍스트를 구분해 보아야 합니다. 잘못된 ROI, 호환되지 않는 모델, 형식 오류는 결과 상태로 바꿔 성공처럼 처리하지 말고 호출 오류로 기록합니다.
