무검출 합성 예제 · 바코드·OCR 인식

인식 문자열뿐 아니라 상태·실패 이유·좌표를 분석하는 방법.

상위 목차로 돌아가기

무검출 합성 예제

균일한 Gray8 입력에 QR 코드가 없어 NoRead/NOT_FOUND를 기대합니다. 이 예는 OCR 정확도 검증이 아닙니다.

Python
from zvision import ZImage, BarcodeSpec, BarcodeFormat, ReadStatus, ReadReason

with ZImage.from_gray8(8, 8, bytes([127] * 64)) as image:
    result = image.read_barcode(BarcodeSpec(BarcodeFormat.QR_CODE))
    assert result.status == ReadStatus.NO_READ
    assert result.reasons == ReadReason.NOT_FOUND

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

코드는 각 픽셀이 127인 8×8 Gray8 영상을 만들고 QR 형식의 읽기를 요청합니다. 영상이 균일해 기호 패턴을 포함하지 않으므로 기대 결과는 NO_READ와 NOT_FOUND입니다. 호출 자체가 정상적으로 돌아온 뒤 두 값을 assert로 비교하기 때문에, 검출된 빈 문자열을 성공으로 간주하거나 예외와 무검출을 혼동하지 않는지 확인할 수 있습니다.

BarcodeSpec의 형식은 탐색 대상의 선택이며 실제 판독 성공을 보장하지 않습니다. 이 예제는 영상, 스펙, 결과 상태라는 최소 경로에 집중합니다. 결과를 실제 검사에 연결할 때는 읽지 못한 부품을 어떻게 재시도하거나 별도 처리할지 정하고, 상태와 원본 영역을 함께 기록해야 합니다. 합성 균일 영상의 통과는 QR의 실제 조명·해상도·손상 조건에서의 판독률을 평가하지 않습니다.

균일 입력의 판독 과정

영상의 모든 픽셀이 127이므로 밝기 최소와 최대가 같고 원본 대비는 0입니다. 예제의 BarcodeSpec은 QR 형식으로 읽기를 요청하지만 영상에는 QR의 명암 모듈 패턴이 없습니다. 따라서 정상 호출 결과의 상태가 NO_READ, 이유가 NOT_FOUND인지를 assert로 확인합니다. 이 예는 판독한 코드의 내용을 비교하는 성공 사례가 아니라 대상이 없는 입력에 대한 분기 확인입니다.

이 코드에서 요청한 형식과 결과 상태를 둘 다 확인해야 합니다. 형식 선택은 검색 범위를 정할 뿐 무조건 기호를 생성하거나 찾는 설정이 아닙니다. 입력 타입이나 ROI가 잘못되어 호출이 실패한 경우에는 결과의 NO_READ가 반환됐다고 해석하면 안 됩니다. 실제 설비에서는 미판독을 재촬영, 보류 또는 별도 판정으로 연결할 수 있으며 그 정책은 이 합성 예제의 기대값과 별도로 정합니다.
