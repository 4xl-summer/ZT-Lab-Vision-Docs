다중 페이지 합성 예제

Rust의 io feature가 필요합니다. 사례 rust-tiff-pages에서 두 번째 페이지는 [3,4], 범위를 벗어난 페이지는 오류를 기대합니다. 실행 환경에서 확인해야 하는 예제입니다.

Rust
use zvision::{TiffSaveOptions, ZImage};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let first = ZImage::from_vec_gray8(2, 1, vec![1, 2])?;
    let second = ZImage::from_vec_gray8(2, 1, vec![3, 4])?;
    let path = std::env::temp_dir().join("zvision-example-pages.tiff");
    ZImage::save_tiff_pages(&[first, second], &path, TiffSaveOptions::default())?;
    let page = ZImage::load_tiff_page(&path, 1)?;
    assert_eq!(page.to_packed_vec()?, vec![3, 4]);
    assert!(ZImage::load_tiff_page(&path, 2).is_err());
    std::fs::remove_file(path)?;
    Ok(())
}

이 페이지는 기준 SDK 소스와 대조했습니다. 예제는 실행 환경에서 별도로 검증해야 하며 합성 데이터 결과는 실장비 정확도를 뜻하지 않습니다.

적용 상황과 원리

이 Rust 예제는 폭 2, 높이 1인 Gray8 영상 두 개를 각각 1,2와 3,4 값으로 만듭니다. 페이지 배열의 첫 번째는 인덱스 0, 두 번째는 인덱스 1입니다. 파일을 저장한 뒤 1을 읽으면 3,4가 되어야 하며 인덱스 2는 존재하지 않으므로 오류가 기대됩니다. 이 두 검사는 페이지 순서와 범위 밖 처리를 서로 독립적으로 확인합니다.

결과를 읽는 방법

예제는 운영체제의 임시 디렉터리에 파일을 만들고 검사가 끝나면 삭제합니다. 실행 전에 io 기능과 해당 디렉터리의 쓰기 권한이 필요하며 파일명 충돌 가능성은 실행 환경에서 관리해야 합니다. 입력 두 영상과 읽은 영상은 각각 소유 값입니다. 작은 정수 픽셀을 사용하는 합성 사례이므로 대형 TIFF, 모든 압축 조합이나 외부 장비와의 교환을 전부 검증하지 않습니다.

추가 점검

첫 페이지 값 1,2와 두 번째의 3,4를 다르게 정한 이유는 인덱스 오류가 있어도 우연히 같은 값이 나오는 상황을 피하기 위해서입니다. 존재하지 않는 페이지의 오류 확인은 픽셀 값 일치와 별도의 경계 조건이며 둘 다 필요합니다.
