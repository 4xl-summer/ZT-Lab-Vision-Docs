페이지 배열은 비어 있으면 오류이고 페이지는 입력 순서대로 저장됩니다. 각 치수는 u32 범위에 들어야 합니다. 저장 전용 경로의 픽셀 형식과 코덱 제약을 확인하세요. 페이지 밖 인덱스, 잘못된 파일, 읽기·쓰기 실패는 오류로 처리합니다. 원본 영상 객체와 로드된 영상 객체는 별도로 소유합니다.

적용 상황과 원리

TIFF 파일의 페이지 순서는 호출자가 넘긴 배열 순서입니다. 첫 페이지가 인덱스 0이므로 두 번째 페이지를 다시 읽으려면 1을 사용합니다. 빈 배열은 저장할 페이지가 없어서 오류이며 각 영상 치수는 u32 범위에 들어야 합니다. 페이지 크기나 타입을 프로그램이 기대한 값과 비교해 데이터가 올바른 순서로 저장되었는지 확인하세요.

결과를 읽는 방법

기본 설정은 BigTIFF가 아닌 형식, 무압축, 네이티브 바이트 순서, chunky 채널 구성입니다. 옵션으로 BigTIFF와 LZW, Deflate, Packbits 압축 및 바이트 순서와 planar 구성을 고를 수 있습니다. 선택한 인코더와 입력 픽셀 형식의 조합이 지원되는지 확인하고, 파일 권한이나 인코딩 오류는 호출 오류로 처리합니다. 서로 다른 프로그램의 TIFF 지원 범위까지 자동 보장되는 것은 아닙니다.
