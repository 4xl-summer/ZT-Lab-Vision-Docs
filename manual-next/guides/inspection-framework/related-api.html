관련 API

정렬을 사용할 때는 먼저 ZImage의 AlignReference와 AlignmentSpec으로 기준 ROI와 검색 조건을 지정합니다. 출력의 Found를 확인한 뒤 Aligned와 ValidMask를 획득하고, InspectionDifference에 기준과 유효 마스크를 넘겨 선택된 픽셀의 잔차와 점수를 계산합니다. 정렬이 필요 없는 고정 입력이라도 비교할 영상 데이터의 크기와 원점이 같은지 확인해야 합니다.

차분 출력의 Mask와 Score는 SurfaceDefects의 두 입력이고, 후보 출력의 Judge는 개수·면적·허용 영역을 적용합니다. DifferenceInfo는 보정 계수와 점수 통계를, DecisionInfo는 통과 여부와 사유를 제공하므로 서로의 값으로 대체하지 않습니다. 출력 객체와 획득 영상 데이터는 각각 해제합니다. 구체적인 타입과 해당 멤버는 이 페이지의 관련 API 표에서 언어별로 선택할 수 있습니다.

호출마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

정렬의 유효 표본 수는 위치를 맞춘 후 비교 가능한 영역을 나타내고, 후보 면적은 그 영역 안에서 검출된 전경의 크기를 나타냅니다. 두 수치는 서로 다른 목적으로 사용되므로 관련 API의 반환 타입과 단위를 함께 살펴봅니다.

검사 단계를 나누는 객체

AlignmentSpec은 기준 로컬 ROI와 검색 조건, 보간 및 최소 유효 비율을 묶습니다. AlignReference는 매치가 없거나 표본 비율이 부족하면 Found=false를 나타낼 수 있습니다. 성공 결과의 ReferenceToInspection은 전역 좌표 사이의 변환이고, Aligned와 ValidMask는 기준 격자의 소유 영상입니다. 변환 정보와 비교 가능한 픽셀 수를 먼저 확인하는 것이 파이프라인의 입구입니다.

DifferenceSpec은 밝기 보정, 잔차 극성과 점수 허용치를 정의하고 InspectionDifference는 해당 격자에서 SignedDifference, Score와 Mask를 만듭니다. 점수 1 이상인 전경을 DefectSpec의 4 또는 8 연결로 묶으면 SurfaceDefect의 면적·경계·회전 길이와 폭을 얻습니다. 후보 필터를 통과한 사실은 제품 한도를 통과했다는 뜻이 아닙니다.

DecisionSpec은 허용 후보 수와 면적, 로컬 영역을 정의하고 Judge 결과의 Reasons는 위반 이유를 조합합니다. 예를 들어 최대 수가 0인데 후보가 하나면 COUNT가 설정됩니다. 동시에 면적이나 위치 조건도 어길 수 있습니다. 단계마다 반환 객체가 독립 수명을 가지므로 처리 상태를 기록하면서 각 객체를 별도로 정리합니다.
