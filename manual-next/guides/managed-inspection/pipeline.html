상위 목차로 돌아가기

관리형 검사 파이프라인

ZInspectionExecutor는 Input → 선택 Roi → Gray → Blur → Threshold → Close → 통계 및 Blob 순서입니다. Gray8과 RGB/BGR/RGBA/BGRA 8비트 입력을 받습니다. 이것은 정렬 차분 판정기가 아니라 단계 영상과 분석 결과를 제공하는 별도의 실행기입니다. ZInspectionRecipe 기본값은 전체 ROI, GaussianKernel 3, GaussianSigma 1, Threshold 128, CloseKernel 3, MinArea 1입니다. 두 커널은 양의 홀수, sigma는 유한한 양수, 면적은 양수입니다. ROI는 입력 로컬 좌표이며 결과 Blob 경계도 단계 로컬 좌표입니다.

결과의 FrameId, RecipeVersion, StageNames, Statistics, Blobs, Metrics, Elapsed는 스냅샷입니다. AcquireStage는 별도 해제할 영상 임대이며 없는 이름은 오류입니다. Threshold와 Close의 CreateDisplayFrame은 선택 Blob 경계를 오버레이합니다. 프레임은 결과와 독립 소유입니다.

관리형 기본 실행기는 입력을 공유하고 선택된 ROI를 적용한 뒤 회색 변환, Gaussian 블러, 임계값 처리, 닫기와 분석 순서로 진행합니다. 입력이 Gray8이면 회색 단계에서 영상 데이터를 공유하고, 지원되는 8비트 컬러 입력이면 회색 영상 데이터으로 변환합니다. Threshold와 Close 단계의 영상 데이터는 중간 실행 결과로 보관되므로 어느 단계에서 예상과 다른 마스크가 생겼는지 살펴볼 수 있습니다.

ZInspectionRecipe의 기본값은 전체 ROI, Gaussian 커널 3과 sigma 1, 임계값 128, 닫기 커널 3, 최소 면적 1입니다. 두 커널은 양의 홀수, sigma는 유한한 양수이고 최소 면적은 양수입니다. 실행 실행 결과에는 선택된 Blob과 통계, 단계 이름 및 시간 정보가 담깁니다. 이 기본 실행기는 기준 영상 데이터 정렬과 차분 판정을 자동으로 수행하지 않으므로 그런 검사가 필요하면 별도 정렬·차분 레시피를 구성합니다.

시간 값은 해당 단계의 경과 시간이며 이 한 번의 합성 사례만으로 다른 입력이나 장비의 처리 속도를 보증할 수 없습니다.

단계별로 원인을 좁히기

입력 영상에서 어떤 픽셀이 최종 Blob으로 이어졌는지 살펴보려면 한 번에 최종 숫자만 비교하지 말고 단계별 영상을 같은 위치에서 읽습니다. 예를 들어 8×8의 가운데 4×4를 255, 주변을 0으로 둔 입력에서는 ROI가 전체이고 커널이 1이면 공간적으로 확장된 주변부가 생기지 않습니다. Threshold 128은 가운데를 전경으로 남깁니다. Close 결과와 선택된 Blob을 함께 보면 최소 면적 필터가 어떤 후보를 남겼는지 알 수 있습니다.

GaussianKernel을 3으로 바꾸면 임계값에 들어가는 값은 원본이 아니라 블러 출력입니다. 따라서 임계값 경계가 달라졌을 때 원본과 Threshold만 비교하기보다 Blur 단계에서 해당 픽셀을 확인해야 합니다. Close 커널이나 최소 면적이 달라졌다면 Threshold는 그대로여도 최종 요소가 달라질 수 있습니다. 각 설정의 효과를 관찰할 때는 한 번에 하나씩 바꾸고 실행의 프레임과 레시피 세대를 기록합니다.

결과의 StageNames에는 실제 생성된 단계가 들어갑니다. ROI를 지정하지 않은 실행에서는 선택 단계가 없을 수 있으므로 무조건 그 이름을 요청하지 않습니다. AcquireStage로 얻은 영상은 결과의 별도 임대이고, 결과는 통계와 Blob 및 시간 스냅샷을 가집니다. 결과나 단계 영상이 더 이상 필요하지 않을 때 각각 해제하여 다음 입력 처리와 섞이지 않게 합니다.
