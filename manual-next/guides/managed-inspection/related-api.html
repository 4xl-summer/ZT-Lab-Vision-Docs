관련 API

관리형 처리 설정을 만들 때는 ZInspectionRecipe의 ROI, 가우시안, 임계값, 닫기 및 최소 면적을 선택합니다. ZInspectionExecutor는 입력을 빌려 단계 실행 결과와 통계를 생성하고, 비동기 제출이 필요하면 ZInspectionHost가 대기열과 작업 수락 상태를 관리합니다. Accepted인 경우의 완료 작업과 QueueFull 또는 Closed 상태를 구분해야 합니다.

ZInspectionResult의 AcquireStage는 별도로 해제할 영상 데이터 임대를, CreateDisplayFrame은 표시할 프레임을 제공합니다. ZDisplayFrame은 영상 데이터와 세대 정보를 묶고, ZViewport는 픽셀 중심과 화면 좌표를 변환하며, ZDisplayFrameGate는 오래된 세대를 거르는 데 사용합니다. 각 객체의 수명과 표시 좌표를 구분해야 화면과 검사 실행 결과가 일치합니다. 개별 속성과 메서드는 관련 API 표에서 찾아볼 수 있습니다.

실행마다 입력 객체가 살아 있는지와 반환 객체를 누가 정리하는지 확인하면 이 표를 실제 처리 흐름에 연결하기 쉽습니다.

표시 프레임이 입력한 레시피 버전과 다른 실행 결과를 담고 있다면 화면을 갱신하기 전에 세대가 유효한지 점검합니다. 프레임 Gate가 통과한 값과 사용자가 현재 선택한 조건을 함께 관리해야 실행 결과를 올바르게 해석할 수 있습니다.

관리형 검사 구성 요소

ZInspectionRecipe는 ROI와 단계 설정을 한 묶음으로 전달합니다. 기본 예제의 가우시안 크기 3, 시그마 1, 임계값 128과 닫기 크기 3은 그 예제의 선택입니다. 입력 영상의 형식과 제품의 대비가 달라지면 값을 그대로 적용하기 전에 중간 결과를 살펴봐야 합니다.

실행기는 입력에서 필요한 ROI를 고르고 회색 변환, 블러, 임계값과 닫기, Blob 통계를 이어갑니다. 각 단계가 어떤 영상을 받는지 알면 최종 Blob이 예상과 다를 때 처음 달라진 단계를 찾을 수 있습니다. 작은 점이 사라졌다면 블러와 임계값의 결과를 먼저 비교하고, 두 점이 합쳐졌다면 닫기 결과도 확인합니다.

ZInspectionResult는 단계 영상과 검사 결과를 묶습니다. AcquireStage로 얻은 영상은 별도 임대이므로 사용자가 해제합니다. 호스트의 제출 및 수락 상태는 검사 계산 결과와 별도이며, 요청이 취소되거나 교체된 경우 이전 결과를 현재 입력의 결과로 표시하지 않도록 연결합니다.
