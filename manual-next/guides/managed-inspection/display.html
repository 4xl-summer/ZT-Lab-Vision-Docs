표시, 좌표 및 프레임

ZDisplayFrame은 영상의 독립 임대를 갖고 AcquireImage, Share는 각각 별도 소유권을 반환합니다. FrameId, RecipeVersion, Width, Height, PixelFormat, Overlays가 스냅샷입니다. CreateRaster는 최대 16,777,216 픽셀을 허용하며 CopyBgra32는 복사본을 돌려줍니다. Gray16 표시 범위의 기본값은 0–65535이며 최소·최대는 유한하고 최대가 더 커야 합니다. 표시 변환과 원본 측정값을 혼동하지 마세요.

ZViewport는 픽셀 중심을 사용해 화면 좌표 = (영상 좌표 + 0.5) × Scale + Pan으로 변환합니다. Fit, ZoomAt, PanBy, ScreenToImage를 사용하고 ROI는 CreateRoiFromScreen으로 생성합니다. ZOverlayScene은 선, 사각형, 원, 다각형, 라벨의 스냅샷입니다. ZDisplayFrameGate의 Expect와 TryAccept로 프레임 및 레시피 세대를 확인하고 오래된 결과를 표시하지 않도록 합니다.

표시 프레임은 검사 영상 데이터의 독립 임대와 프레임·레시피 세대 및 오버레이 장면을 묶습니다. 실행 결과 단계에서 프레임을 만든 뒤 원래 검사 실행 결과를 해제해도 이미 얻은 프레임은 자신의 영상 데이터 임대를 갖습니다. 반대로 프레임을 해제한 뒤 그 프레임에서 새 이미지를 얻을 수는 없습니다. AcquireImage로 얻은 영상 데이터도 별도의 소유 객체이므로 사용이 끝나면 정리합니다.

화면 확대와 이동은 검사 좌표를 바꾸지 않습니다. 뷰포트는 로컬 픽셀 중심에 0.5를 더한 뒤 배율과 이동량을 적용하여 화면 좌표를 계산합니다. 마우스가 가리키는 픽셀이나 드래그 영역을 다시 이미지 좌표로 바꿀 때는 제공되는 역변환과 ROI 생성 기능을 사용합니다. 표시용 색 범위와 원본 숫자 값을 구분하면 화면의 명암을 측정값으로 오인하지 않습니다.

예를 들어 같은 숫자 영상 데이터가라도 표시 범위의 최대값을 바꾸면 화면의 밝기가 달라집니다. 원본 픽셀을 읽어 표시 변환과 비교합니다.

단계 영상과 화면 좌표

Close 단계의 프레임을 만들면 영상과 함께 선택된 Blob 경계 장면을 얻습니다. 이 경계는 현재 결과 단계의 로컬 픽셀 좌표로 구성됩니다. 해당 영상이 입력의 ROI라면 원본 전체 화면에 도형을 표시할 때 부모 origin과의 관계를 확인해야 합니다. 반대로 ROI 영상 자체를 같은 로컬 좌표로 표시한다면 원점을 임의로 다시 더하지 않습니다.

뷰포트의 영상→화면 변환은 픽셀 중심 (x+0.5, y+0.5)에 Scale을 곱하고 Pan을 더합니다. 예를 들어 Scale이 2이고 Pan이 0이면 로컬 (0,0) 픽셀의 중심은 화면 (1,1)에 놓입니다. 역변환은 화면 위치에서 Pan을 빼고 배율로 나눈 뒤 0.5를 빼므로, 화면 드래그와 영상의 사각형 범위를 직접 혼동하지 않습니다.

프레임의 CreateRaster는 표시용 BGRA 픽셀을 복사합니다. 비바이트 값은 표시 범위로 변환될 수 있으므로 GetPixel의 원본 채널 수치와 화면에 보이는 밝기를 구분합니다. 프레임을 해제한 뒤 새 AcquireImage는 불가능하지만 그 전에 획득한 독립 영상은 별도 수명으로 사용할 수 있습니다.
