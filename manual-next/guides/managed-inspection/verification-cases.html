관련 검증 사례

관리형 검사 예제는 가운데에 밝은 사각형을 넣은 작은 Gray8 입력과 명시적인 레시피를 사용합니다. 커널 1, 임계값 128, 최소 면적 1인 경우 처리 단계와 Blob의 연결을 관찰할 수 있습니다. 실행 실행 결과의 프레임 식별자와 레시피 버전, Close 단계와 Blob 목록은 어떤 입력과 설정에서 나왔는지 함께 살펴보아야 합니다.

실행 결과에서 얻은 프레임과 단계 영상 데이터는 독립 소유 객체이므로 예제에서는 각각 수명을 마칩니다. 이 사례의 콘솔 계산을 실행하는 것과 WPF·WinForms 창에서 선택이나 확대를 직접 확인하는 것은 별개의 작업입니다. 관련 검증 기록에서 실제 실행 여부를 확인하고, 화면 조작이나 장비 연결이 검증되었다고 추정하지 않습니다. 실물 입력의 통과 기준도 별도로 정해야 합니다.

사례의 적용 범위와 기대 출력이 현재 사용하는 입력·설정과 일치하는지 비교한 다음 실행 기록을 해석합니다.

실행 결과를 저장하거나 화면에 표시할 때 프레임 세대와 레시피 버전이 동일한 실행의 것인지 점검합니다. GUI 확인이 필요한 항목은 해당 창에서의 실행 증거를 따로 남기고, 단순한 값 계산 실행 결과와 합치지 않습니다. 기록된 콘솔 실행 결과는 창에서의 사용자 입력과 화면 렌더링을 보증하지 않습니다.

관리형 검사 예제의 확인 범위

관리형 검사 예제는 레시피, 실행기와 결과 객체를 연결하는 코드 경로를 설명합니다. 기록된 개별 코드 블록은 실행이 완료되었지만 별도의 결과 단언을 포함하지 않습니다. 따라서 실행이 끝난 사실과 어떤 Blob 개수 또는 생산 판정을 확인한 사실을 구분해서 읽어야 합니다.

입력에서 ROI를 선택하고 단계 결과를 얻는 흐름을 살펴볼 때는 각 AcquireStage의 반환 영상과 결과 소유 객체의 수명을 확인합니다. 임계값이나 닫기 크기를 변경했다면 그 설정으로 새로 실행하고 해당 단계의 영상을 비교하는 것이 결과 변화의 원인을 찾는 데 도움이 됩니다.

합성 정렬 검사의 별도 통합 사례에는 다섯 입력의 결과 단언이 있으나, 그것은 이 관리형 샘플의 모든 화면이나 제품 레시피를 시험했다는 의미가 아닙니다. 실제 입력 형식, 취소 및 장치 조건은 해당 환경에서 확인할 범위로 남습니다.
