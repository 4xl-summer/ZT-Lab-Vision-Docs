개념과 사용 흐름

ZImage.to_hsv와 to_lab은 ColorPlanes 결과를 반환하며 white_balance, color_correct, color_statistics는 색상 보정과 영역 통계를 제공합니다.

색 처리에서는 입력 채널의 순서와 수치 인코딩을 먼저 알아야 합니다. RGB와 BGR은 같은 세 성분을 다른 순서로 저장하므로 형식을 무시하면 빨강과 파랑을 서로 바꿔 해석할 수 있습니다. SDK는 영상을 HSV 또는 Lab 채널로 변환하고, 보정이나 영역 통계 같은 후속 처리를 제공합니다. 변환 결과의 각 채널이 어떤 색 공간의 성분인지 확인한 다음 거리 또는 임계값을 적용합니다.

HSV의 색상과 Lab의 명도·색상 성분은 숫자의 의미가 다릅니다. 예를 들어 빨강과 파랑을 HSV로 변환한 합성 사례는 색상각 0도와 240도를 기대합니다. Lab에서 ΔE76은 세 성분 차이의 유클리드 거리입니다. 채널 결과는 소유 객체이므로 이미지와 채널의 수명을 각각 관리하고, 센서 조명 변화나 실제 색 재현성은 별도 자료로 검증해야 합니다.

같은 바이트의 다른 해석

세 바이트 [255,0,0]을 RGB8로 읽으면 빨강입니다. 같은 순서를 BGR8로 해석하면 첫 성분이 파랑이므로 색이 달라집니다. 색 공간 변환의 계산을 검토하기 전에 영상의 픽셀 형식과 성분 순서를 확인해야 하는 이유입니다. 변환으로 얻은 HSV의 H는 각도이고 Lab의 L*, a*, b*는 서로 다른 축이므로 같은 채널 번호라도 의미는 현재 공간에 따라 달라집니다.

예를 들어 합성 RGB 빨강의 HSV 색상각은 0도, RGB 파랑은 240도입니다. 흰색이나 회색처럼 무채색인 경우에는 색상각의 의미를 채도와 함께 해석해야 합니다. 후속 검사에 Lab 거리를 사용할 경우에는 두 색이 같은 입력 인코딩과 기준 백색으로 변환됐는지도 기록합니다. 합성 원색의 기대값은 채널 순서와 계산을 확인하는 데 유용하지만 장비의 색 재현성 평가를 대신하지 않습니다.

항목값 또는 단계해석
RGB8[255,0,0]빨강
BGR8[255,0,0]파랑
빨강 HSVH=0°합성 원색
파랑 HSVH=240°합성 원색

to_gray는 컬러 입력을 회색 영상으로 바꾸는 경로이며 to_hsv와 to_lab은 색 공간별 채널을 제공하는 경로입니다. 색의 밝기만 다루는지, 색상각이나 Lab 성분 차이가 필요한지를 먼저 정해야 합니다. 변환한 ColorPlanes에서 채널을 획득하면 원본과는 별도 소유 경로가 생기므로 결과를 읽는 동안 해당 객체의 수명을 보장해야 합니다.

white_balance와 color_correct는 입력을 보정하는 호출이고 color_statistics는 영역의 색상 수치를 요약하는 호출입니다. 보정한 영상에서 통계를 구할지 원본에서 구할지에 따라 측정 대상이 달라집니다. 색차 계산은 선택한 색 공간의 값과 기준색을 비교하는 단계입니다. 같은 숫자의 임계값이 다른 색차식이나 다른 조명에서 같은 판정을 뜻하지 않으므로 입력 형식과 처리 순서, 기준색을 함께 기록합니다. 출력 채널의 형식과 원점도 표시 위치나 다른 영상과의 비교에 필요합니다.

색 작업의 첫 단계는 결과에 무엇이 필요한지 정하는 일입니다. 밝기 기반 이진화가 목적이면 회색 변환 후 임계값을 검토하고, 색상각을 비교할 때는 HSV 성분을 읽습니다. 기준색과 Lab 거리를 계산하려면 Lab 변환과 기준색의 백색점이 맞아야 합니다. 같은 원본 이미지에서 시작해도 각 단계가 내는 객체와 값의 단위는 다릅니다.

ColorPlanes 결과에서 채널을 얻을 때는 인덱스와 현재 색 공간을 같이 확인하고, 획득한 영상의 수명을 명시합니다. 화이트 밸런스나 색 보정은 입력 픽셀을 바꾸는 처리이므로 보정 전후 통계를 서로 다른 대상으로 기록합니다. color_statistics가 요약한 영역과 원본 ROI 좌표를 함께 남기면 검사 조건을 재현하는 데 도움이 됩니다. 지원 형식은 각 호출의 선언과 오류 조건을 확인합니다.
