합성 입력 전체 예제

이 예제는 합성 입력을 사용합니다. 실제 촬영 데이터나 실행 성능을 나타내지 않습니다.

Rust
use zvision::{ZImage, ZResult};
fn main() -> ZResult<()> {
    let red = ZImage::new_rgb8(1, 1, [255, 0, 0])?;
    let lab = red.to_lab()?;
    let l = lab.acquire_channel(0)?;
    println!("{:?} {:?}", lab.space(), l.pixel_format());
    Ok(())
}

빨간색의 Lab은 대략 (54.29, 80.81, 69.89)이며 채널 인덱스는 0부터 2입니다. 결과와 획득한 채널은 소유 객체입니다.

예제는 1×1 빨간 RGB 영상을 직접 만들어 색 변환을 호출하는 합성 경로입니다. 픽셀이 하나이므로 위치나 조명 불균일의 영향 없이 API가 채널과 색 공간을 어떻게 내놓는지 확인할 수 있습니다. RGB 순서로 (255,0,0)을 사용했다는 전제가 중요하며, 이를 BGR로 잘못 선언하면 다른 색을 뜻합니다. 이 코드는 Lab의 첫 채널을 얻어 색 공간과 채널의 픽셀 형식을 출력합니다. 위의 Lab 수치는 비교를 위한 참고값이며 코드 자체는 수치를 단언하지 않습니다.

이 작은 입력은 자료 형식과 변환 호출의 재현을 위한 것입니다. 실물의 반사 스펙트럼, 조명, 노출 및 센서 보정은 포함하지 않습니다. 따라서 기대값이 맞아도 특정 제품의 색상 허용 범위를 확인한 것은 아닙니다. 결과 객체나 획득한 채널은 사용 후 언어별 소유 규칙에 따라 정리하고, 실제 검사에서는 동일한 입력 인코딩과 참조 조건을 보존해야 합니다.

한 픽셀 예제의 출력

제공된 Rust 코드는 RGB8 빨강 (255,0,0)을 만들고 Lab으로 변환한 다음 첫 번째 채널을 얻습니다. 마지막 출력은 공간 종류와 채널의 픽셀 형식입니다. 코드 자체가 Lab 세 성분을 모두 읽어 수치 일치를 단언하는 것은 아니므로 실행 결과를 해석할 때 출력한 항목과 본문에 적힌 참고값을 구분해야 합니다. 첫 채널은 Lab의 L*에 해당합니다.

본문의 빨강 Lab 근삿값은 D50 기준 변환의 참고 수치로, 배열 순서와 변환 조건을 함께 보아야 합니다. 1×1 입력은 위치 의존적인 조명이나 노출 차이를 포함하지 않아 형식과 호출 흐름을 단순하게 확인합니다. 공간 결과 및 획득한 채널은 소유 객체이고 Rust에서는 범위를 벗어날 때 정리됩니다. 실제 색 공차는 별도 표본으로 확인해야 합니다.
